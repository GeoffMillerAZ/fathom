# timoni — provenance and divergences

LB-Q-timoni (wave fx, owner request 2026-10-02), design `docs/design/language-breadth.md` §13/§18.3 (T3), engine
`native`, grammar_source `native:cuelang.org/go` (Apache-2.0, a library dependency, unmodified). A Timoni module,
bundle or runtime is plain CUE with a contract, so `internal/extractor/timonidialect.go` composes
`NewCUEExtractor()`: every CUE node and reference edge is the CUE extraction's, unchanged, and the Timoni entities,
calls and cross-file references ride on top. Neither `cueextract.go` nor `typedcue.go` is edited (item cue owns them);
when the CUE extractor becomes a `DocResulter` the composed extractor carries its cross-file references too.

## Why native, not the tags or doc engine

The files are CUE: no tags grammar for CUE is pinned, and the doc engine reads YAML, JSON, TOML and XML. The CUE
extractor already parses with `cuelang.org/go/cue/parser`; a dialect over it needs no new grammar.

## Classification

- Manifest (`dialect.json`): the basenames `timoni.cue`, `bundle.cue`, `runtime.cue`, `values.cue`,
  `debug_values.cue`, `images.cue`, and the globs `**/templates/**/*.cue` and `**/bundles/*.cue`. **No `match.sniff`**:
  a sniff on `.cue` makes every `.cue` file it does not match `ambiguous`, which ingest's gate excludes, and every
  other CUE file would stop being read (O495). The manifest therefore only says what the harness owns; it decides
  nothing about extraction.
- Dispatch (`internal/fusion/timonidispatch.go`, `classifyCUE`): a `.cue` file is Timoni's when its basename is
  `timoni.cue`, its content has a top-level `bundle:` struct or a `runtime:` struct with a `"v1alpha1"` apiVersion, or
  it sits under a directory holding a `timoni.cue` (a module's `templates/`, `values.cue`, `images.cue`,
  `debug_values.cue`). Never under `cue.mod/`: that directory holds the module's vendored Kubernetes types and the
  `timoni.sh/core` link, the module's dependencies. This is what makes "`values.cue` only inside a module" true:
  a `values.cue` outside any module is plain CUE, whatever the manifest basename says.

## What it models

- `timoni/module` (`TimoniModule`, canonical `package`): a top-level `timoni:` field.
- `timoni/values` (`TimoniValues`, `variable`): a top-level `values:` field.
- `timoni/object/#Def` (`TimoniObject`, `resource`): a top-level definition whose value, through `&` and parentheses,
  has a struct with a literal `kind:` (the signature is `apiVersion kind`). A definition that builds its kind from
  another definition (minimal's `#ConfigMap`, from `timoniv1.#ImmutableConfig`) names none and is not an object.
- `timoni/bundle` (`TimoniBundle`, `package`) and `timoni/bundle/instance/<n>` (`TimoniBundleInstance`, `target`).
- `timoni/runtime` (`TimoniRuntime`, `package`) and `timoni/runtime/cluster/<n>` (`TimoniCluster`, `target`).

Names are slash-separated so they never collide with a CUE field's dotted name; `name_match` is `bare`, so an oracle
writes the segment the harness keeps (`values`, `Deployment`).

## References

- L2 (Calls): a struct-literal `values:` calls `#Config.<k>` for each top-level key (Timoni validates the values
  against #Config); a template definition with `#config: #Config` calls `#Config`; `#Instance.config -> #Config` and
  `values: templates.#Config` are the CUE extraction's own edges.
- L3 (DocResult.CrossFile): a bundle instance's `module.url` of `file://<path>` is a `repo-path` reference to
  `<bundle dir>/<path>/timoni.cue` (Timoni reads the path from the bundle file's directory); `#Instance` is a
  `label-selector` reference, scope `timoni:<module root>` (the parent of the nearest `templates` directory, else the
  file's directory), labels `{pkg, def}`, to each object template it names anywhere in its body (a bare `#X` of its
  own package or an import selector `m.#X`), each object declaring the label set the reference selects. Timoni renders
  the objects `#Instance` names, so this is "module -> the rendered Kubernetes kinds" at the template's file.
- Counted, never guessed (`TimoniUnresolvedRefs`): `external:oci` (a registry module), `external:other`, `expression`
  (a url that is not a string literal), `absolute-path`, `outside-repo`.

## Divergences

- `oci://` modules need a registry: a bundle instance naming one has no truth and no reference, and the reading
  cannot carry the count (the notes' per-dialect counts live in `cmd/indexbench/langoracle_iac.go`, wave lg's, O497).
- A `timoni.cue` that says `Code generated by timoni. DO NOT EDIT.` is skipped by ingest's generated-file gate, as
  every dialect-owned generated file is (O496): its module and values entities, and a bundle's reference to it, are
  absent.
- Objects whose kind is not a literal in the definition (and CRDs the module renders from elsewhere) are not entities.
- The oracle's tier (`calibration/oracles/timoni/README.md`): the definitions and references are tier C (a parse walk
  gated by the tool), the cross-references tier A, so L1 and L2 cap at good (O498).
