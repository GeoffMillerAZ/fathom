# nix — provenance

LB-Q-nix, design `docs/design/language-breadth.md` §13. A new tags-engine tool format (no incumbent): every `.nix`
file (`default.nix`, `flake.nix`, `shell.nix` and modules alike) was unclassified and skipped.

- Grammar: `nix-community/tree-sitter-nix` tag `v0.3.0`, commit `ea1d87f7996be1329ef6555dcacfa63a69bd55c6` (MIT; the
  top-level `LICENSE`, Charles Strahan 2019), ABI 13, an external scanner, `src/parser.c` shipped (no generate step),
  built into `internal/extractor/tsengine/grammars/nix.wasm.gz` (201,641 bytes raw, 68,442 gzip). Its own
  `queries/tags.scm` names function bindings and calls only; the tag is the repository's newest release, and the
  default branch (ABI 15) was not taken because a release tag is what the recipe pins.
- `tags.scm`: written in this repository and GENERATED by `gen_tags.py` beside it. Node shapes came from
  `indexbench lang-probe`, never `grammar.js`. A tree-sitter query cannot say "no binding encloses this one", so the
  rule "a file's definitions are its root expression's own names" is enumerated: the root expression is the file's
  expression peeled through at most three wrappers (a function, a let, a with), and each chain is one pattern for
  the let bindings or attribute-set keys it ends in and for the formals of its functions. A key at depth one is a
  definition, a deeper key is not; a dotted key `a.b.c = v` is the definition `a` (as the reference parser merges
  it), once per binding.
- Kinds: `NixFunction` (the key's value is a function), `NixOption` (the key is `options`, or its value is
  `mkOption` / `mkEnableOption` / `mkPackageOption` applied), `NixPackage` (its value is `callPackage`,
  `mkDerivation` or a `build*` helper applied), `NixAttribute` (any other key of an attribute set), `NixVariable` (a
  let binding), `NixParam` (a formal or the single argument of a function on the chain). A kind other than attribute
  and variable needs the key to be a single identifier, since a dotted key's value belongs to a deeper key.
- References: an application's head is a call, the identifier or the selected name as written (`lib.mkIf`); the
  innermost application of a curried call is the one that matches.
- `imports.scm`: a path literal (`./x.nix`, `../lib`, plain text) that can name a Nix file is an import through
  `relative-path` with `index_files: ["default.nix", "flake.nix"]`. It binds names only where Nix binds them:
  `u = import ./u.nix;` is an alias of the file (`u.f 1` calls `f` of it), `inherit (import ./u.nix) f;` names `f`;
  a path that is a `callPackage` argument or an `imports` element is the file as a whole and binds no name. The
  file-symbol strategy was built first and left: it brings every top-level name of an imported file into scope, and
  measured on home-manager it drew 11 edges Nix does not (a `pkgs.callPackage` call joined to a `callPackage` let
  binding of the file it imported). A flake input `url = "./dir"` is the directory. The `path:` form is not read: a
  capture cannot drop the scheme.
- Not read: a path with an interpolation, a quoted or interpolated first attribute (`"a.b" = 1;`), `inherit` as a
  definition, a definition below the root expression (the keys of `config = { ... }`, the body of a function binding),
  `with import ./x.nix;`, and any expression a wrapper chain longer than three reaches.
- `testdata/`: fixtures written in this repository (`module`, `lib`, `pkg`, `flake`, `default`, `scope`, `broken`),
  each golden written from reading the fixture; `broken.nix` is a syntax error the grammar recovers from, and the
  binding after the error is lost with it (the grammar reads `(1 + ;` into the next binding).
- Oracle: `calibration/oracles/nix-parse` (tier C, the reference parser; the parse prints no positions, so the lines are
  the oracle's lexer's and the parse attests the names, O1475; excellent is out of reach for that reason).
- **Measurement** (`docs/bench/readings/lang/nix.json`, `calibration/corpus.d/nix.yaml`): level_met L3, good at L1, L2
  and L3, over home-manager (3,254 files) and mitchellh/nixos-config (19). sym_recall 1, sym_precision 1,
  ref_recall 1, ref_precision .9988, xref_precision 1 and xref_recall 1 over 38 import-and-select pairs (all home-manager;
  nixos-config has none), kind agreement 15,357 of 15,361, 3.21 MB/s CPU, max file 18 ms, peak 319 module pages, no
  faults. Holdouts, each read once with the rule fixed: disko (`holdout/nix.json`, L2 good: no cross-file pair on either
  side) and flake-parts with nixvim (`holdout/nix-2.json`, L3 good, 5 of 5 pairs, sym_precision .9975: a file the
  parser refuses is read by the dialect). `nix flake show --json --offline` ran on every subject's root flake (the
  inputs sit in the store at the lock's hash) and its top-level outputs are disclosed in the reading. The
  cross-reference truth is narrow (Nix files link by `imports` and `callPackage`, which bind no name), O1477.
