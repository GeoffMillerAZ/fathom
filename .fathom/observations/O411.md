### O411 — an ingest run under an EPERM wedge passes footprint.md's validity rule while its passes skipped files silently

- **Symptom:** a whole-tree LB-M5 run read `read_failed: 0` and no failed doc unit, footprint.md's whole validity rule, yet cost 443.1 G instructions against 1,418.0 G for a complete run of the same build (docs/bench/readings/efficiency-wave/ingest-linear.md, wave ic).
- **Evidence:**
  - **Tool:** `fathom ingest --json --store <fresh> --service poly --path <polyglot tree>` (c8a99868), the external volume's TCC wedge (EPERM) mid-run.
  - **Expected:** a run that lost reads to EPERM is named invalid by the envelope: a read failure, a failed doc unit, or a pass that did not finish.
  - **Actual:** the envelope said `read_failed: 0`, `docs.failures: []`, `outcome: ok`; only `docs.skipped` ("doc index not finished: IngestDocUnits: corpus walk: open <root>: operation not permitted") and the counts showed it: `file_resolved` 6,865 against 27,368 and 6,865 typed_edges rows against 30,098. The file-resolved, doc-xref and route-ref passes fetch each file again through the connector and skip a fetch error without counting it (internal/fusion/fileresolve.go `enrichFileResolvedEdges`: "A read failure fetching one file here is best-effort skipped"; docxref.go `enrichDocXrefEdges` `continue`s past it).
  - **Repro:** wave ic's `measure.sh` runs under `w-linear/` while the wedge recurs (it did on most whole-tree runs on 2026-10-02).
- **Root cause:** the pass-2 read is the only read whose failure is counted (IT-14); the later passes' re-reads are best-effort and silent, so a wedge that starts after pass 2 shortens their output with nothing in the report but smaller counts.
- **Fix:** measurement side, in this wave's reading: a run is valid only when `read_failed` is 0, the doc pass neither failed a unit nor was skipped, and the store's row counts (observations, typed_edges, file_imports, doc_links, doc_units, symbol_centrality, service_routes, fingerprints) equal a complete reference run's. Product side, open: count and name each later pass's fetch failures on the report, as pass 2's are (I38).
- **Status:** open (product side)
- **Impact:** any footprint or cost reading on the external volume (LB-M5 and its successors) can read a shortened run as valid and report a cost that is too low; footprint.md's rule needs the row-count check.
