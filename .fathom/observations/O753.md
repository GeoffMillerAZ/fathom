### O753 — a Rust module file edge is drawn between two file anchors, so a symbol-level reader sees a file's first definition as the edge's end

- **Symptom:** K25 ruling 4 asks for a FILE edge to a module's defining file, never a symbol, and `core.Edge` (and `typed_edges`) can only join two symbol keys
- **Evidence:**
  - **Tool:** `internal/fusion/rustcrate.go` `rustModuleEdges`, `TestResolveFileEdges_RustModuleFileEdges`, `TestIngest_RustDialect`
  - **Expected:** an edge from a file to a file
  - **Actual:** the edge runs from the definition around the reference (a `mod x;` declaration's RustMod, a function holding a `use`) or, at a file's top level, the file's first definition, to the module file's first definition (`rustFileAnchor`, the doc-xref "first root entity" precedent, D4): `src/lib.util -> src/util.Helper` for `mod util;`. L3's scorer (file pairs) and blast_radius over a changed file read it right; `symbol_context` on `Helper` lists `mod util;` and every `use crate::util::..` as referrers, and a file defining nothing (only `pub use` lines) draws no edge
  - **Repro:** ingest the fixture `internal/fusion/testdata/rustmodfixture` and read the typed edges
- **Root cause:** the store has no file node; K18 chose not to mint a Rust module symbol
- **Fix:** none here (no new store table, edge kind or symbol in this wave): a file node or a module-edge kind the callers views leave out would let a reader tell the two apart
- **Status:** open
- **Impact:** module dependencies reach blast_radius and the file-edge metrics; a symbol's referrer list can include module references to its file
