### O626 — the doc engine has no absence test and no value filter, so three telemetry rules overreach or cannot be data

- **Symptom:** (1) the otel-collector dialect names a span-metrics connector's default families even when the connector sets its own `namespace`; (2) an identity written `${env:SERVICE_NAME}` is a TelemetryIdentity named so; (3) the kubernetes dialect cannot declare a container's telemetry identity, so k8sextract.go does (LB-F314)
- **Evidence:** `internal/extractor/dialects/otel-collector/testdata/layer.yaml.golden.json` (six derived families for one connector), `gateway.yaml.golden.json` (the `${env:SERVICE_NAME}` identity); schema/dialect/doc.cue #DocWhere has `has_key` but no lacks-key, and no value predicate
- **Root cause:** §4's selector subset: `where` filters keys and equal values only; a value cannot be split (`k=v,k=v`, `a;b`) or refused for a template
- **Fix:** an engine predicate (`lacks_key`, a value regex) owned by the doc engine's item, or the side pass; TL-5's consumer already refuses a non-literal name (`telemetryIdentityLiteral`), so (2) never joins
- **Status:** open
- **Impact:** a few over-claimed platform families (harmless to the census: none is an alert's), and the kubernetes dispatch switch must port the identity reader
