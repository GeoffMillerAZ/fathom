### O533 — a doc-comment reference `[Request]` is a reference scip-dart attests and no tree-sitter query can capture: 26 Dart file-edge pairs

- **Symptom:** 26 of the 133 Dart file-edge pairs fathom misses (and 36 with others) are scip-dart references written inside a `///` comment (`/// use [Request] instead`, `[BaseClient.send]`)
- **Evidence:**
  - **Tool:** the scratch classifier over bloc and http at fathom cd4c1e9e, occurrences whose line starts `///`
  - **Expected:** a `[Name]` link resolves like a reference to Name in scope
  - **Actual:** the references query captures nodes; the comment is one node and its text is no name path, so nothing is captured
  - **Repro:** `indexbench lang-probe -dialect dart` on http's lib/http.dart: the doc comment is a single `documentation_comment` node
- **Root cause:** the capture vocabulary has no capture that reads a name out of a node's text
- **Fix:** none this wave (internal/extractor/tsrefs.go is shared): a `@ref.doc` capture that scans the node's text for `[` name-path `]` (a path as refPath reads it, not followed by `(` or `:`) and yields each as a RefSpec on the comment's line
- **Status:** open
- **Impact:** about 4 points of Dart file_edge_recall; a doc-link edge is a weak edge, so the item is a choice, not a defect
