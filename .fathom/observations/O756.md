### O756 — a shell script with no extension is classified as bash by its shebang and then extracted by nothing

- **Symptom:** the bash manifest claims `.sh`, `.bash` and the shebangs `bash` and `sh` (the queue row reads "Shell / Bash (.sh .bash, shebangs)"); discovery returns an extensionless script and the dialect gate classifies it bash by its shebang, but `resolveExtractor` dispatches it to no extractor, so its functions and calls are never indexed, before the switch to the dialect (LB-F391) as after it
- **Evidence:** bats-core 713504bc: `connector.Discover` returns `bin/bats` and the eleven `libexec/bats-core/*` scripts; `TestBashDialectIsWhatFusionDispatches` (internal/fusion) pins `ClassifyDialect` = bash by shebang and `resolveExtractor("bin/run")` not ok for `#!/bin/bash`; the bash reading leaves 387 (bats-core) and 966 (nvm) tool-oracle entries out of scope on files fathom does not read (`docs/bench/readings/lang/bash.json` notes)
- **Root cause:** dispatch is by key (basename, then extension) and, for a file no key claims, by `sniffedExtractor`, which takes only a sniff, glob, extension or basename verdict and only for an extension in `sniffExt`; a shebang verdict and an empty extension reach neither
- **Fix (done, wave lf4 item shell, LB-F417, LB-F418):** `sniffedExtractor` accepts `ClassifiedByShebang` for a file with no extension and dispatches it to the extractor already registered for the dialect's first extension (`internal/fusion/shebangdispatch.go`: bash's .sh, python's .py, ruby's .rb, javascript's .js; the python, ruby and javascript manifests now declare `python`/`pypy`, `ruby`/`jruby`, `node`/`nodejs`); ReingestFile reaches the same path; a file with an extension, a text file with no shebang and a binary file are untouched, and perl and zsh (O792) stay unextracted; lang-oracle's `ownedSourceRefs` measures the files the rule dispatches (`fusion.Pipeline.ShebangDialect`). Such a script has no language tag and draws no file edges (O793). Epoch need: every extensionless shebang file is newly extracted
- **Status:** fixed (D4, wave lf4)
- **Impact:** a repository whose shell lives in extensionless scripts (`bin/`, `libexec/`, git hooks) has none of it in the index: find_symbol and the callers of a shell function miss it
