### O1310 — `circleci config process` is offline only for a config without orbs, and drops what no workflow runs

- **Symptom:** the tier-A oracle for CircleCI is not purely offline, and it attests fewer definitions than a config declares.
- **Evidence:**
  - **Tool:** circleci-cli 1.7.0 `config process` (`calibration/oracles/circleci`)
  - **Expected:** `circleci config process` compiles a file from the toolcache with no network (the plan row says "tier A, offline")
  - **Actual:** an orb-free config compiles with no network; an orb is fetched from the registry (cimg-base, cypress resolve `circleci/*` orbs at run time), and an orb from a URL outside the organization's allow-list fails the file (mui/material-ui). The output also lacks a job no workflow runs, a workflow whose `when` is false, and every command and executor (inlined)
  - **Repro:** `HOME=<scratch> circleci config process .circleci/config.yml` in a subject with an orb, with and without network
- **Root cause:** the compiler resolves orbs through the registry API and emits only the instantiated pipeline.
- **Fix:** the oracle attests a job through the workflow entries that run it (name, matrix expansion) and leaves an uncalled job unattested (it counts against sym_precision: cimg-base's gated `monthly-release` workflow is the reading's one miss). Commands and executors are outside the oracle kinds and their references are a tier-C source walk.
- **Status:** open
