### O986 — A tsconfig paths alias in an .astro file is never resolved

- **Symptom:** `import Logo from '~/components/Logo.astro'` (withastro/docs) and `@/components/...` (astro-paper) resolve to nothing for an `.astro` importer, though the subject's tsconfig maps the alias.
- **Evidence:** `tsConfig.includes` (internal/fusion/tsresolve.go) admits only TypeScript and JavaScript extensions to a project, so an `.astro` importer has no tsconfig and resolves with the compiler's defaults (no `paths`). astro-paper v6.1.0 writes 53 of its 64 component imports through `@/`; withastro/docs 12 of 57.
- **Root cause:** TypeScript's include rule (supported extensions only) is the right reading for the compiler, but Astro's language tools put `.astro` files in the project of the tsconfig that holds them.
- **Fix:** none in wave lf7 (tsresolve.go is shared). Design 1.8's Astro paragraph makes an alias unjudged in astro.json (out of both sides, counted: `astro_alias_imports`).
- **Status:** open
- **Impact:** component edges through an alias are missing in the product; trigger: an `.astro` importer read as a member of the tsconfig that holds it.
