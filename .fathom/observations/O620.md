### O620 — lang-oracle measured a dialect that claims names only on its named files, so content-claimed files were out of scope, never misses

- **Symptom:** the first prometheus reading measured `prometheus.yml` and `*.rules.yml` files only; thanos' `examples/alerts/alerts.yaml` and `rules.yaml`, which ingest claims by content through the late-YAML hub, were not measured, and the oracle's definitions on them were dropped as "files fathom does not read" instead of scored
- **Evidence:**
  - **Tool:** `indexbench lang-routes -dialect prometheus` (wave c1, item prom)
  - **Actual:** `ownedSourceRefs` read a file by content only for a doc dialect with no extension, basename or glob (`byContent` required an empty match block), the cloudformation case
  - **Repro:** a dialect with `basenames` whose files ingest also claims by content; `TestOwnedSourceRefsNamesAndContent`
- **Root cause:** the content route was written when every content-claimed dialect claimed no name; the late-YAML hub claims by name OR content
- **Fix:** `cmd/indexbench/langoracle.go` `ownedSourceRefs`: a doc dialect is also measured on the files `Pipeline.ContentDialect` names it for, whatever its names (ContentDialect names only content-claimed dialects, so every other dialect's measured set is unchanged)
- **Status:** fixed (wave c1, item prom)
- **Impact:** a late-YAML dialect's reading covers what ingest reads; without it a detection miss would read as a smaller subject, never as lost recall
