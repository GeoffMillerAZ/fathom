### O1237 — verify's `wired` criterion does not see net/http calling the hook guard's RoundTrip, so every hookguard transport function reads library-only

- **Symptom:** `fathom verify --strict` reports RT-190 (`rpcDeadlineHeader`, internal/hookguard) as `library-only`, which is Unknown and refused under `--strict`: "no product entry point reaches it". The product does run it. cmd/fathom/hookguard.go's `init` sets `http.DefaultTransport = &hookguard.Transport{...}`, so every hook RPC goes through `Transport.RoundTrip`, then `Guard.roundTrip`, then `rpcDeadlineHeader`.
- **Evidence:** a scratch ingest of 9b8ed233 (wave btm1, reqpath). A probe plan of claimed rows: `RoundTrip`, `roundTrip`, `halfOpen`, `RecordSuccessSince` and `callerGaveUp` all read `?` (library-only), and `BreakerAllows`, which has a direct product caller, reads `✓`. `deadcode ./cmd/...` (RTA over real types) reports none of them dead. The same row's `test_reaches` passes through an in-module interface dispatch ("7 implementer(s)").
- **Root cause:** `http.RoundTripper` is a standard-library interface, and the only caller of its `RoundTrip` that the product reaches is net/http's `Client.send`, which fathom does not index. So no dispatch edge leads into `Transport.RoundTrip`, even though reached code (an `init`) creates the value. docs/plans/README.md excludes only "an interface dispatch into a type no reached code instantiates". This type is instantiated, so by that rule it should count.
- **Fix:** in the product-reach walk, treat a method that implements a standard-library interface as reached when reached code creates its type and assigns the value to that interface: `http.RoundTripper`, `http.Handler`, `io.Reader` and the like. Until then RT-190 stays open, because `library: true` would be false.
- **Status:** open
- **Impact:** a row whose function runs only behind a standard-library interface cannot be proven `wired`. This entry measured only `http.RoundTripper`.
