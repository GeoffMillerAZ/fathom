### O1307 — Markdown: what the queue item names and the dialect does not build

- **Symptom:** the queue entry's notes list a fenced-code language census and link edges to non-Markdown files; the row (headings, intra-repo link edges to files and heading anchors) is met without them.
- **Evidence:** a link edge needs a target the doc-xref pass reads, and only doc files are read (a .md or .mdx target); a link to a source file, an image or a directory draws none (the resolver would otherwise read a directory link as "the one doc file in it"). An anchor within the file draws no cross-file edge (it is a heading's Calls). MDX `import` lines and JSX props (`<Link to="x.md">`) are not links. No fenced-code census exists: no consumer reads one.
- **Root cause:** scope of LB-Q-markdown as the row words it; the census and a code-file edge are separate decisions (a doc-to-code edge would need the file resolver, not the doc-xref pass).
- **Fix:** open a row for a doc-to-code link edge if blast radius should see "README documents src/x.go"; the census waits for a consumer.
- **Status:** open
- **Impact:** blast_radius from a source file does not reach the Markdown that links to it.
