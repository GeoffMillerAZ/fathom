### O382 — two files of one directory declaring one package and rule name share a SymbolKey, so a same-file call is scored to the other file

- **Symptom:** 3 file-resolved pairs on open-policy-agent/opa that the import dump does not hold (file_edge_precision .9949)
- **Evidence:**
  - **Tool:** `langbench.ScoreFileEdges` on the rego reading; v1/format/testfiles/v1/test_every.rego and test_future_kw_import.rego (both `package p`, both defining `is_odd`)
  - **Expected:** a call to `is_odd` in test_every.rego binds the file's own `is_odd` and draws no cross-file pair
  - **Actual:** the key `s::v1/format/testfiles/v1/p.is_odd` names both files' rules; the scorer's `fileOf[key]` keeps the last, so the same-file edge reads as one to the other file
  - **Repro:** ResolveFileEdges("rego") over the opa subject, then each edge's ToSymbol file
- **Root cause:** SymbolKey is directory + package + name (core.QualifiedPackage), not file; the scorer maps a key to one file
- **Fix:** none here; a C# partial class and a Ruby reopened class meet the same key sharing (fileresolve.go keyFiles)
- **Status:** open
- **Impact:** small (3 of 584 pairs); larger where a Rego package defines one rule across several files of one directory
