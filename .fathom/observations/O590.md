### O590 — scip-dotnet 0.2.14 writes a constructor (`.ctor`) reference only where an attribute is applied; at `new X(..)` it references the type

- **Symptom:** of the 1,689 C# call pairs scip-dotnet's truth held that the dialect did not find (wave lh), 1,158 were `.ctor` callees (O463), and call_precision read .794 on Polly 8.8.0 and Newtonsoft.Json 13.0.4
- **Evidence:**
  - **Tool:** the scip-dotnet occurrence dump (`scipjson`) of both subjects, each `.ctor` reference read at its written range (wave lf1)
  - **Expected:** a constructor reference at every construction, the way scip-java writes `<init>` at `new X(`
  - **Actual:** 9,000 `.ctor` references (Polly 3,700, Newtonsoft.Json 5,300), every one at an attribute application (`[Obsolete("x")]`, `[Benchmark]`, `[Fact]`); at `new X(..)`, `new X<T>(..)` and `new N.X { .. }` the occurrence names the type (`X#`), 12,130 of them
  - **Repro:** `indexbench lang-oracle -dialect csharp -scip <index>` and the counts `scip_csharp_ctor_not_calls`, `scip_csharp_constructions`
- **Root cause:** scip-dotnet visits an object creation's type name, not the constructor symbol the semantic model binds; an attribute's name binds its constructor
- **Fix:** the harness reads scip-dotnet's leaf in the dialect's names (`internal/langbench/scip_csharp.go`, LB-F286): a `.ctor` reference not written `new X(` is no call site (an attribute's constructor runs when reflection reads it), and a type reference written `new X(` is a call to X; the dialect records a construction as a call to X (LB-F288, Java's O268 shape)
- **Status:** fixed (wave lf1)
- **Impact:** with the compiler's sites (O591), L2 call_precision .794 to .9997
