### O1327 — universal-ctags tags Elixir code inside heredocs and ends modules at it, so it cannot grade the elixir dialect's L1

- **Symptom:** against ctags 6.2.1 the elixir dialect reads sym_recall .9302 (Phoenix v1.8.9) and range_agreement .5965, level none, though the dialect's definitions are the ones the language parses.
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect elixir` with the default ctags oracle on phoenixframework/phoenix and elixir-ecto/ecto
  - **Expected:** an oracle definition is a definition of the file
  - **Actual:** 119 `def`, 50 `defmodule` and 22 `defp` oracle-only on Phoenix are example code in `@moduledoc """` heredocs and file templates in tests; `Phoenix.Socket` (lines 1-921) is given `end:38` because ctags closes it at a heredoc `defmodule`
  - **Repro:** `ctags -f - --fields=+ne --languages=Elixir lib/phoenix/socket.ex`
- **Root cause:** the Elixir parser in ctags is textual (no string or heredoc state), and it counts `end` tokens to end a module.
- **Fix:** design D2: the reading is graded against Elixir's own parser (`calibration/oracles/elixir-ast`, tier B), and keeps the ctags numbers in its notes. ctags also writes ExUnit `test` names with spaces, which the harness's last-segment name rule cannot compare, so the dialect's test kind (canonical `test`) is outside the scored kinds.
- **Status:** closed (disclosed)
