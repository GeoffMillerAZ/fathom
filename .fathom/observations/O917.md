### O917 — tree-sitter-powershell v0.26.5 leaves an ERROR node in a quarter of the PowerShell files measured, an unquoted `$PSScriptRoot\dir\x.psm1` argument among the causes

- **Symptom:** the lang harness, which now records files_with_error for every reading, counts 133 of the tuning subjects' 496 measured PowerShell files (26.8%) and 173 of the holdout's 394 (wave lf6, branch `lf6-shell-l3`), where PowerShell's own parser reports errors in 4 and 0. That is over §14.2's 5% line, which was never read for this dialect (its readings predate the field).
- **Evidence:** `tree-sitter parse` at the lock's pin (d3984418): `Import-Module $PSScriptRoot\axiom\Axiom.psm1` is an `array_literal_expression` holding a `member_access` (`$PSScriptRoot`, an ERROR over `\axiom`, the member `psm1`); the quoted form and `. $PSScriptRoot\x.ps1` parse cleanly.
- **Root cause:** for this construct, the grammar reads `\` after a variable as no path character; the other causes are not broken down here.
- **Fix:** none needed for L3: the argument's text is still the path, and dialects/powershell/imports.scm captures the argument node whatever it holds (branch `lf6-shell-l3`). Disclosed.
- **Status:** open (grammar). Trigger: a tree-sitter-powershell release parsing the bareword path, or a per-construct breakdown of the 133 files deciding whether §14.2 reaches the dialect.
- **Impact:** the ERROR count overstates the dialect's parse failures; L1 and L2 read as before (sym_recall .9961, call_recall .9949).
