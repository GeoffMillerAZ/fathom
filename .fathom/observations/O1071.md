### O1071 — blast_radius on a file the index does not hold answered an empty success

- **Symptom:** blast_radius with changed_files naming a file the index does not hold (a typo, an absolute path, a file added since the ingest) returned zero symbols and zero tests, indistinguishable from a file nothing depends on.
- **Evidence:**
  - **Tool:** MCP blast_radius (kind change)
  - **Expected:** an explicit not-indexed answer
  - **Actual:** `depth 0: 0 changed symbols; affected tests: 0`
  - **Repro:** internal/mcp/blast_radius_notindexed_test.go
- **Root cause:** the change answer walked the graph from whatever symbols the files carried and never asked whether the files were in the index.
- **Fix:** a changed file no symbol carries and the corpus does not list is named: every file unheld is a params error naming the repo-relative form; some unheld are listed in not_indexed and the summary beside the held files' radius.
- **Status:** fixed (wave fic, item verify)
