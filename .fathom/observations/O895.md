### O895: `fathom map append` accepts an end line one past a file's last line

- **Symptom:** in wave rf1 (item evx1), `fathom map append rf1-evx1-seed --anchor "internal/verify/testdata/sarif/README.md#L1-L19"` was filed (th-d4d21c68) for an 18-line file whose last line ends with a newline, while `cmd/fathom/sarifrun.go#L1-L28` on a 26-line file was refused ("has no lines 1-28").
- **Expected:** an anchor past the last line is refused the same way at every distance, as the receipt anchor core refuses it (`internal/verify/excerpt.go`: a file ending in a newline has no line after it).
- **Likely cause:** the line count splits on "\n" and counts the empty string after the final newline as a line.
- **Repro:** `wc -l internal/verify/testdata/sarif/README.md` (18), then `fathom map append <map> --anchor "internal/verify/testdata/sarif/README.md#L1-L19" --why x --agent a`.
- **Status:** open
