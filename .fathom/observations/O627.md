### O627 — no pinned public corpus pairs an AuthorizationPolicy with the workloads and ServiceAccounts it names

- **Symptom:** the kubernetes reading scores no AuthorizationPolicy, PodMonitor or Probe pair: those joins are proven on fixtures only (TestIngest_MeshRouteRefs)
- **Evidence:** istio/istio 1.31.1 `samples/` holds no AuthorizationPolicy; GoogleCloudPlatform/istio-samples' security-intro policies select workloads its repository does not declare; GoogleCloudPlatform/anthos-service-mesh-samples' online-boutique policies and ServiceAccounts carry no `metadata.namespace` (a kustomization sets `onlineboutique`), so `cluster.local/ns/onlineboutique/sa/frontend` meets `ServiceAccount/frontend` in `default` and is undeclared
- **Root cause:** an object without a namespace is read in `default`; a kustomization's `namespace:` is not applied to the objects it lists
- **Fix:** none here: applying a kustomization's namespace to its resources is a kustomize-aware join (the kustomize dialect's), or a subject that writes namespaces
- **Status:** open
- **Impact:** AuthorizationPolicy joins in kustomize-namespaced repositories count undeclared
