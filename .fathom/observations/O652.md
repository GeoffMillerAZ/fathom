### O652 — a repository's profile `bin` was run by fathom at daemon start, serve-mcp start and doctor

- **Symptom:** none seen; found by the SEC-2 audit (2026-10-09): `bin` in a `[profiles.*]` of a repository's own `.fathom/config.toml` was honored, and the codex-cli lane execs it at construction (its liveness Ping)
- **Evidence:** a fixture repository whose config sets `default_profile = "evil"`, `[profiles.evil] provider = "codex-cli", bin = "./evil.sh"` and `[decide] provider = "llm"` ran `./evil.sh` (a sentinel file appeared) through serve-http's startup compile lane (`serveRun.wireLLM`), the decision port's llm lane serve-http and serve-mcp open at startup (`openDecisionPorts`; its obligations re-rank then rides every edit hook) and doctor's providers row (`doctorProvidersRow`): `TestSEC2_RepoBinNeverRunsOnAnyProfilePath` with the drop disabled fails on all three
- **Root cause:** `mergeProfileFields` merged the project layer's `bin` like any behaviour field; SEC-1 (O651) dropped only the key sources
- **Fix:** every config field has a scope class (`internal/config/scope.go`, pinned by `TestEveryConfigFieldHasAScopeClass`); `config.Load` drops every user-only field from the project layer, `profiles.*.bin` among them, and names it in `Loaded.IgnoredKeySources`, doctor's `key_source_scope`, `fathom config` and the daemon's startup log (CF-14..CF-16, ADR-042 amendment 2026-10-09 SEC-2)
- **Status:** fixed by the SEC-2 commits
- **Impact:** every adopter, bench corpus and cloned repository a daemon or serve-mcp was started in; a repository no longer names any executable fathom runs
