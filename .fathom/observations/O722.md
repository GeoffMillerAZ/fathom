### O722 — the doc engine reads a template cfn-lint (and CloudFormation) reject: a duplicate key, an empty Resources

- **Symptom:** serverless-patterns at a6cb0af2 read whole gives sym_precision .9691 (fathom 6,481 definitions, the oracle 6,281): 200 definitions in 17 templates the oracle never decodes
- **Evidence:** 12 templates with a duplicate mapping key (`Duplicate found 'Name'`, `'Handler'`, `'Description'`, ...: public-nlb-or-alb-private-api-cfn, multi-account-private-apigw/centralAccount, vpc-lattice-lambda, sam-webapp-cognito, ...), which cfn-lint rejects; 5 with `Resources:` and nothing under it (_pattern-model and four CDK patterns' stubs), which are no template to cfn-lint; the doc engine's YAML decode keeps the last of two equal keys, and `detect.require_keys` holds for a null `Resources`
- **Root cause:** the engine's decode is lenient where the format's reference parser is not; CloudFormation itself refuses both
- **Fix:** none in wave c3: the recorded subset (calibration/corpus.d/cloudformation.yaml) leaves those 13 patterns out, disclosed. A doc-engine decode refusing duplicate keys would change every YAML dialect's reading and is its own decision
- **Status:** open
- **Impact:** an agent sees entities in a template that would not deploy; harmless for impact, wrong for "is this valid"
