### O521 — `import a.b.C.Companion.member` resolves to no file: the unnamed companion has no symbol, so 269 Kotlin imports read unresolved

- **Symptom:** import_resolution .9649 on Kotlin, with 269 unresolved statements (okhttp 264, Exposed 5), every one a `Class.Companion.member` path (`okhttp3.HttpUrl.Companion.toHttpUrl`).
- **Evidence:**
  - **Tool:** `-unmatched` `imports` (cmd/indexbench importMisses): 269 entries with an empty `targets` and `Companion` as a module segment; the other 46 misses bind a different file of a name two files declare.
  - **Actual:** memberImport's parent is `okhttp3.HttpUrl.Companion`, which names no type; the dialect folds a companion's members into the class (`C.make`, not `C.Companion.make`).
  - **Repro:** internal/fusion/testdata/ktcompanion with `import a.b.C.Companion.make`; the failing test and the fix (memberImportParent drops a trailing `Companion` segment) are in /Volumes/m2ext/tmp/fathom-build/w-pkc/ts-needs/kotlin-namespace-dir.patch.
- **Root cause:** `Companion` is Kotlin's name for the unnamed companion object, and the namespace-dir split does not know it.
- **Fix:** open, item ts's file (internal/fusion/fileresolve.go).
- **Status:** open (handed to item ts through the integrator)
- **Impact:** 3.5% of in-repo Kotlin imports; with it import_resolution would read about .9996.
