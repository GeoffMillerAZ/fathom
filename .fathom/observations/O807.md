### O807 — Scala's first L3 reading: imports resolve (.9832), but file edges are drawn from calls alone and read recall .0112

- **Symptom:** read once (K19) on typelevel/cats v2.13.0 + http4s/http4s v0.23.38 after LB-F438 (imports.scm, package clauses) and LB-F439 (the scalameta import truth with same-package references), Scala L3 reads import_resolution .9832 and file_edge_precision .9763 but file_edge_recall .0112 (329 of 29,261 truth pairs), so L3 is unmet and level_met stays L2.
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect scala -subject <clone> -tool-oracle out/scala-<subject>.json -unmatched <file>` at fathom 35bff928, the dump from `ScalametaDump -calls -imports` (calibration/oracles/scalameta, 5eab8294); the unmatched file's `oracle_only` pairs joined to the dump's entries.
  - **Actual:** of the 28,932 undrawn truth pairs (cats 10,996, http4s 17,936): 22,563 a wildcard import's pairs to every file of the package or object it names (`import cats._`, `import org.http4s._`), 4,292 same-package references, 2,077 named imports. fathom draws 337 file pairs, 8 the truth lacks. import_resolution misses: 28 unresolved, 32 bound to another file of a name two files declare (the scala-2.12/2.13/3 source copies).
  - **Repro:** the commands in calibration/oracles/scalameta/README.md with `-imports`, then lang-oracle with `-unmatched`.
- **Root cause:** a file edge is a binding drawn from a definition, and the scala dialect gives the resolver its calls only: it has no references.scm (a type in a signature, an extends clause, a pattern or a type argument draws no edge) and stores a call by its callee's last identifier (LB-F396: `NonEmptyList.one(x)` is `one`, which neither the named import `NonEmptyList` nor a wildcard binds), so a resolved import becomes an edge only where its name is called bare. The wildcard pairs are the truth's (a wildcard names every file of the package, as Kotlin's star imports do, LB-Q-kotlin-rest), and no reference pass reaches most of them.
- **Fix:** none here (the reading is the one K19 reading; no change after it). Recall needs a Scala references.scm (type identifiers, stable identifiers, extends clauses) and qualified call text (`calls.qualify`, as Kotlin and Java store `Foo.bar`), each an extraction change measured under K17/K26, then a re-read on a holdout.
- **Status:** open
- **Impact:** Scala's imports resolve to files (L3 import_resolution excellent) and package clauses name the package, so `find_symbol` packages and a file's import bindings are right; caller/callee reach between Scala files stays sparse until references are extracted.
