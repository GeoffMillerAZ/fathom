### O452 — retrofit's javadoc HTML cost 36 G in four tag and attribute patterns the guest ran at every node and the host then dropped

- **Symptom:** footprint.md's LB-M5 profile: retrofit (square/retrofit e27d855b) costs 4.38x its base, `extract` 5.6 of 6.2 s, "its javadoc HTML and CSS".
- **Evidence:**
  - **Tool:** per-extension extraction timers, then instructions retired for the html grammar alone over the 536 pages (3.6 MB): parse 13.3 G; tags and imports query 36.4 G (parse-only vs the query, then one pattern group at a time: id 11.5 G, custom element 10.5, form and field 19, imports 5.2, a trivial `(document) @d` 4.1); 308,188 structural matches of which 18,181 survived the host predicates (94% dropped). The javadoc injections (1,297 script ranges) and CSS are 0.2 s of 3 s; they were not the cost.
  - **Expected:** a pattern's cost follows the matches it keeps.
  - **Actual:** each pattern is `(element (start_tag (tag_name) @_tag (#eq? ...) (attribute ...)))`: structurally it matches every tag or attribute of every page and `#eq?`, `#match?` and `#any-of?` are evaluated host-side after the guest has built each match. 0 of 536 pages hold a hyphenated tag or a form, 4 hold a field.
  - **Repro:** phase runs (parse only, then one query) under `/usr/bin/time -l`; the numbers are in docs/bench/readings/lang/footprint.md section "LB-M5 profile, wave le item pycost".
- **Root cause:** the query engine has no way to tell the guest a pattern cannot match this source, so its cost is paid per structural match.
- **Fix:** LB-F180 (`#requires-text!`, a necessary condition the engine tests against the source, running a source it fails in a variant of the query compiled without that pattern) and LB-F181 (guards on HTML's custom-element, form, field and self-closing-id patterns). HTML alone: 50 G to 31 G; retrofit 113.5 G to 94.4 G; captures identical (goldens; TestHTMLGuardsAreNecessary).
- **Status:** fixed for HTML; open as a technique: any dialect whose patterns match broadly and are cut by predicates (gradle: 107 predicates, cmake: 24, commonlisp, emacs-lisp, helm, meson, conan, ruby) can carry guards, each with its own guarded-vs-unguarded test.
- **Impact:** a markup-heavy tree pays for the patterns it can satisfy.
