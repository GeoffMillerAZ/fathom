### O603 — Go's file_edge_precision .5625 scored two facts the source never writes: 3,175 false pairs were dispatch fan-out and instantiation

- **Symptom:** go.json read L3 unmet on file_edge_precision .5625 (4,088 of 7,268 typed-pass file edges) against .90 good; the pairs had never been diagnosed
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect go -scip <scip-go index> -unmatched` (wave lf1, fathom 01d9b581; -unmatched now writes Go's file edges and `fathom_only_kinds`) on cli/cli v2.69.0 (45ffa3c6) and spf13/cobra 40b5bc14
  - **Expected:** each file edge fathom draws is a reference the source writes to a definition in another file (design §1.2)
  - **Actual:** of cli/cli's 3,175 fathom-only pairs 2,580 are drawn only by `iface-dispatch` edges (one per implementer, to the implementer's file; the call names the interface method, in the interface's file), 578 only by `instantiates` facts (a held value's type), 8 by both, 4 by a direct call, 5 by a function value; 1,630 come from a `_test.go` file and 48 join files of one directory, the same kinds; build tags, generated code, cgo and vendored code drew none
  - **Repro:** calibration/oracles/scip-go/README.md, then the command above
- **Root cause:** Go's file edges are the typed pass's edges, and the pass stores two kinds that are not file-granularity references (what may run, what is held), served by the call graph by design
- **Fix:** Go's file-edge set is the edges that name their target (`EdgeDirect`, `EdgeFuncValue`); the rest are counted in the notes and the edges stay stored and served (design §1.7, LB-F297, LB-F298). file_edge_precision .9972, recall .7034 (880 true pairs of the instantiation facts leave recall's numerator)
- **Status:** fixed (scoring rule, no product change)
- **Impact:** Go reads L3 excellent
