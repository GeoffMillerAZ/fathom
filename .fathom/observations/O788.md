- **Symptom:** the holdout reading (wave lf4, owner ruling D2, LB-F415) on eslint/eslint v10.12.0 lib/ reads level_met none (L1 unmet, L2 unmet, L3 excellent, L4 unmet), where the tuning subjects (axios + express + webpack) read L4 good under the same rules.
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect javascript -scip-defs -only lib/**` at eed026d0 against scip-typescript 0.4.0 (`docs/bench/readings/lang/javascript.json`), its `-unmatched` diagnosis, and a scratch classifier (never committed) over the index and the dialect's definitions.
  - **L1 (sym_recall .7589, 2,005 of 2,642):** of the 637 oracle-only definitions, 520 are object-literal methods (every rule's `create(context) {`, `const cli = { async execute() {`), 109 require bindings scip-typescript kinds as a function or class (`const { mkdir } = require(...)`, a declarator list of requires), 8 accessors.
  - **L2 (call_precision .5959, call_recall .6357):** 2,273 pairs are one call given to different callers: fathom's is a function declared inside an object-literal method (`function report()` inside `create`) or `module.exports = function` (LB-F384's exports), the truth's the file module, because scip-typescript defines a nested function only as a local (O443) and the dialect defines no object-literal method around it; 425 fathom-only and 490 oracle-only pairs have no counterpart at the callee; 651 oracle-blind pairs are left out (under LB-F203's cap).
  - **L4 def_mapping (.7348, 2,045 of 2,783; 9,467 object-literal properties out, D2):** 712 of the 738 unmapped definitions are in lib/types/*.d.ts, TypeScript documents the index holds under `-only lib/**` and no javascript file is; without them .9874. The other 26: 17 properties, 5 vars, 4 methods.
  - **L4 typed_recall (.5972, 9,659 of 16,175):** about 4,000 unmapped references run to or within those .d.ts documents and 1,105 to an object-literal property (D2 left typed_recall's references in).
  - **TypeScript too:** the TypeScript holdout's only level below excellent is L1 (good): rxjs's 210 oracle-only definitions are object-literal methods.
- **Root cause:** O747's other half (the dialect names no object-literal method; the ruling took def_mapping's properties only), O443's enclosure decision for a nested function's calls, and O749's scope rule (the reading measures the dialect's extensions while def_mapping and typed_recall read every document under `-only`).
