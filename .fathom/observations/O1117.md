### O1117 — Session findings outbox sync does not enforce configured producer allowlist

- **Symptom:** Session findings outbox sync does not enforce configured producer allowlist
- **Evidence:**
  - **Tool:** session-hook
  - **Expected:** [findings] producers restricts accepted outbox events as docs/configuration.md promises
  - **Actual:** Config decodes Findings.Producers but syncFindingsOutbox never reads it; findingsImportRunner invokes findings import without --producer, whose default accepts any catalogued producer
  - **Repro:** Read cmd/fathom/findings_outbox.go findingsImportRunner and syncFindingsOutbox, compare internal/config/config.go FindingsConfig.Producers and pkg/client/findings.go ImportFindingsRequest.Producer default; rg Findings.Producers reveals no runtime consumer
- **Root cause:** syncFindingsOutbox loads the configuration but forwards only subject/outbox to findingsImportRunner; the runner supplies no producer restriction, and ImportFindingsRequest.Producer defaults to any catalogued producer.
- **Fix:** Pending a separate hook/import boundary change with a producer-list refusal test. Until then, use explicit CLI --producer for single-producer outboxes; configuration/adoption docs now disclose this limitation.
- **Status:** open
- **Impact:** A configured producers list is not an enforcement boundary for automatic session imports. Subject binding and trusted catalog caps still apply; no runtime consumer of Findings.Producers exists in the inspected source.
