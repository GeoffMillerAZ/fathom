### O456 — the Rust dialect captures a const or type alias inside an inline `mod { }` twice, and the 16 duplicates alone refuse its dispatch on sym_precision

- **Symptom:** `indexbench lang-parity -dialect rust -incumbent rustextract` refuses the switch on sym_precision alone, dialect 0.9746 < incumbent 0.9756 (-0.0010), while every other L1 and L2 metric is level or ahead (sym_recall 0.8909 to 0.9984, call_recall 0.8125 to 0.9479, call_precision 0.9332 to 0.9846)
- **Evidence:**
  - **Tool:** `indexbench lang-parity -dialect rust -incumbent rustextract -subject BurntSushi/ripgrep=<14.1.1> -subject clap-rs/clap=<v4.6.1> -scip <name>=<rust-analyzer index, cargo.features all> -scip-defs` (wave ld, 2026-10-02, `docs/bench/readings/lang/parity/rust.json`), with each side's L1 misses written through lang-oracle's `-unmatched` shape for diagnosis
  - **Expected:** the dialect emits each definition once, so a definition both sides emit pairs with the oracle's
  - **Actual:** the dialect leaves 260 definitions unpaired (ripgrep 48, clap 212), the incumbent 222 (24, 198); the 38 only the dialect leaves are (a) 16 duplicates: `const CASEI`, `const SHERLOCK`, `const ROOT`, `const CODE` and `pub(crate) type Result<T>` inside a `mod tests { }` (globset glob.rs, printer json.rs/standard.rs/summary.rs, searcher, ignore) are captured as `RustConst` (paired with rust-analyzer's `glob/tests/CASEI.`, kind const, line 1210) AND as `RustAssocConst` (canonical field, the unpaired copy), a type alias as `RustTypeAlias` and `RustAssocType`; (b) 21 real items under a cfg rust-analyzer does not analyze with `cargo.features all` (`#[cfg(windows)] fn imp`, `#[cfg(not(feature = "suggestions"))] static PV_ERROR`, `#[cfg(not(feature = "cargo"))] macro_rules! command`, a `#[cfg(all(target_env = "musl", ..))] static ALLOC`), in kinds or positions (const, static, macro, a nested fn) the incumbent never emits; (c) one raw identifier, clap's `r#type` field, spelled without `r#` on the dialect side
  - **Repro:** `NewTSExtractor("rust").Extract` over `mod tests {\n    const A: i32 = 1;\n    type R = i32;\n}\n` returns `RustConst A`, `RustAssocConst A`, `RustTypeAlias R`, `RustAssocType R` (two symbols per item; a top-level `const B` returns one)
- **Root cause:** in tree-sitter-rust a `mod` body and an `impl`/`trait` body are both a `declaration_list`; dialects/rust/tags.scm's associated-item patterns (a const or type alias whose parent is a `declaration_list`) also match a module's items, beside the module-item patterns
- **Fix:** none here (items calls and xfile own the dialect queries): restrict the associated-const and associated-type patterns in `internal/extractor/dialects/rust/tags.scm` to a `declaration_list` whose parent is an `impl_item` or `trait_item` (or exclude a `mod_item` parent), with a golden of an inline mod holding a const and a type alias. Counterfactual: the 16 duplicates gone, the dialect reads sym_precision 0.9761 (9,964 of 10,208) against 0.9756, and lang-parity reads MERGE; then the `.rs` switch bumps `ExtractorEpoch` (LB-Q-rust-rest). The cfg-inactive 21 are real definitions; under D1 they only matter if the duplicates are not fixed
- **Status:** open
- **Impact:** Rust stays on the CGO rustextract.go although the dialect is ahead on six of the seven gated metrics; every .rs file in an index carries the incumbent's output (no signatures, no consts, statics, macros or type aliases)
