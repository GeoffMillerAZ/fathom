### O1434 — The edit hook said a rule was ignored when it was only served again, and asked for a verdict on rules nobody can answer

- **Symptom:** after an edit, the edit hook printed `🔁 served rule ignored — still applies after this edit: <rule>` and asked the user to corroborate ("the violation is real") or refute, on the second edit of any file a rule governs. The rule was most often a raw document heading or paragraph (a maintainer-workflow section, a commands section) served with no claim id, so the user could not answer it: the fallback told them to find an id in `fathom claim list`, and none existed.
- **Evidence:**
  - **Reports:** 13 adopter-filed reports, theme hook-false-ignored, all open; for example app-kit O85, O98, O106, O115, O123 and conjure O19, O22 (each: a raw heading such as "Maintainer-only workflow" or "Commands" called ignored with no claim id and no violated clause, while the edit followed the rule).
  - **Tool:** `askRuleVerdict` (cmd/fathom/askruleverdict.go) fired when the same rule text and citation topped the file's obligations two turns running; the edit hook passes `govRules[0]`'s Rule, Src and ClaimID, and a raw-tier fallback row (`Tier: "raw"`) never carries a ClaimID. This worker's own edits in fathom drew the same line for a raw ADR-066 row on every edit.
- **Root cause:** two faults. The same-rule proxy: a rule that governs a file governs it on every edit, so being served again is not evidence the edit ignored it, yet the line alleged it. The claimless ask: a rule with no claim id was still asked about, though nothing can corroborate or refute it. No caller passes evidence of a violation (RO-25's missed-flag line is a Bash readout, not this ask).
- **Fix:** the ask fires only for a rule that has a claim id, so a raw heading or paragraph is never asked about, and the line reads `🔁 served again after this edit: <rule> (<src>) [claim <id>]` with the same one-key c/r ask; no line says ignored or violated. The reply path (`withRuleVerdictAskAt`, the prompt hook's one-key reply, the recorded verdict) is unchanged. Pinned by `TestRuleVerdictAskNeedsAClaimAndAllegesNoViolation`.
- **Status:** fixed
- **Impact:** adopters stop seeing a false allegation on every second edit of a governed file, and every ask they do see names a claim they can answer in one key.
