### O679 — a Python traceback's `in <module>` frame now has a symbol to join, and stackframe.ShortName still drops it

- **Symptom:** internal/stackframe.ShortName returns "" for a frame function that is no identifier (`<module>`, `Object.<anonymous>`, `{main}`), so an incident's top-level frame resolves to no definition.
- **Evidence:**
  - **Code:** internal/stackframe/stackframe.go ShortName; core.ModuleSymbolName is `<module>` since K18 (wave lf2), Python's own name for the frame, and every Python file now has a symbol of that name at `<dir>/<stem>.<module>`.
- **Root cause:** the frame name predates the module symbol.
- **Fix:** none here (not this item's surface). A frame whose function is `<module>` and whose file is indexed could take that file's module symbol; JS/TS's `Object.<anonymous>` would follow when their module symbol is on.
- **Status:** open (future, not pre-built)
- **Impact:** an incident's top-level Python frame names no symbol; every frame below it is unaffected.
