### O605 — scip-go indexes the testmain `go test` writes into the build cache, a document outside the subject that scored as 1,428 unmapped definitions

- **Symptom:** go.json's def_mapping and typed_recall counted `init()`, `main()` and package variables no extractor of the subject reads
- **Evidence:**
  - **Tool:** a debug listing of scip-go's unmapped definitions on cli/cli (wave lf1)
  - **Expected:** every definition counted sits in a file the subject holds
  - **Actual:** 204 documents (2 on cobra) named by a path that leaves the subject (`../../../<go cache>/e1/…-d`, one per test package) held 1,428 unmapped definitions (204 packages, 816 variables, 408 init and main) and the calls into each package under test
  - **Repro:** `calibration/oracles/scip-go/run.sh` on cli/cli, then list the documents whose path starts with `../`
- **Root cause:** `scip-go index ./...` indexes the testmain each test package's build generates into GOCACHE
- **Fix:** documents outside the subject are dropped before any count and counted (`scip_go_docs_outside`; design §1.4 amendment, LB-F299)
- **Status:** fixed (scoring rule)
- **Impact:** def_mapping .4867 to .5494 and typed_recall .5637 to .5805 together with O608's parameter shape; L2 reads as before
