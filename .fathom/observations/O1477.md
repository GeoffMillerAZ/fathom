### O1477 — The `file-symbol` strategy joins a Nix call to a same-named binding of any file the importing file names

- **Symptom:** built first on `file-symbol` (a whole-file import brings every top-level name of the target into scope), the Nix dialect drew 11 edges on home-manager that Nix does not: `pkgs.callPackage ./home-manager { }` in six files was joined to a `callPackage` let binding of `home-manager/default.nix`, and `i3.nix` and `sway.nix` were joined to same-named bindings of `lib/functions.nix` by name alone (xref_precision .7755 against 38 oracle pairs, recall 1).
- **Evidence:** `fathom` run of `fusion.ResolveFileEdges` over home-manager before and after; the reading's xref_precision 1 and xref_recall 1 (38 pairs) with `relative-path`.
- **Root cause:** in Nix a path brings no name into scope unless it is bound: `u = import ./u.nix;` makes `u.f` the file's `f`, `inherit (import ./u.nix) f;` makes `f` its, and `callPackage ./x.nix` or an `imports` element is a derivation or a module. `file-symbol` has no such distinction. `relative-path` with `@import.alias` (the `u` binding) and `@import.name` (the inherited names) has it, and a bare path import binds no name.
- **Fix:** made: `imports: {strategy: relative-path, relative: true, index_files: ["default.nix", "flake.nix"]}`, `calls.qualify: true` (a call is `u.f`), `name_match: bare`. Not covered: a flake input written `url = "path:./dir"` (a capture cannot drop the scheme), `with import ./x.nix;` and a path with an interpolation. The disko holdout drew no cross-file reference on either side (L3 not attempted there); flake-parts and nixvim (two further holdouts, pinned before the dialect ran on them) read L3 good, 5 of 5 pairs, 0 extra.
- **Status:** closed for the shapes above; open for `path:` inputs and `with import` (revisit when a measured subject's xref_recall falls below .80 for them)
- **Impact:** the import-and-select shape is rare in Nix (scouting eight MIT repositories with the oracle alone found it in two); most files link by `imports` and `callPackage`, which are file-level imports with no name, so L3 here measures a narrow truth. The row reads L3 good on that truth.
