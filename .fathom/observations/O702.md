### O702 — pass-times cannot name a new ingest pass without editing a pinned test, so TL-4's template pass is folded into "extract"

- **Symptom:** the ingest report's `pass-times` names each pass by a lap mark, and `TestIngestReportsPassTimes` (internal/fusion/passtimes_test.go) pins the exact lap list; TL-4's log-template pass therefore runs before the "extract" mark and its cost reads as extraction
- **Evidence:**
  - **Tool:** `fathom ingest` (pass-times), internal/fusion/passtimes.go
  - **Expected:** a new pass is one mark line after its call (passtimes.go's own comment) and shows as its own lap
  - **Actual:** adding the mark fails the pinned list in a file outside the item's brief; the reader's first cut cost 1.35 s per pass over celery's 387 Python files and showed only as a slower "extract" (3.3 s against 2.4 s), caught by the ingest wall-time measurement the brief asked for, not by the disclosure
  - **Repro:** add `passes.mark("log_template")` after `enrichLogTemplates` in ingest.go and run the fusion tests
- **Root cause:** the pin protects the lap order (no pass counted twice), but it also makes every new pass a cross-item edit
- **Fix:** none in TL-4 (its pass is fast now: 32 ms for the same files). The pin could assert the order of the laps it names and allow named laps it does not, or the integrator adds the `log_template` mark and the test row in the wave's merge
- **Status:** open
- **Impact:** a slow new pass hides inside a neighbour's lap until someone measures wall time by hand
