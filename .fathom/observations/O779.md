### O779 — a nested Go module's main reached nothing: the typed pass loaded only the root module

- **Symptom:** in platform-engineering's index, no call edge left `kits/env-kit/cmd/bosun/main.go`, so `fathom verify` read every env-kit symbol `wired: library-only`, `cmd.NewRoot` included; review-kit and ci-kit did have edges (F-REACH, K15)
- **Evidence:** a clone at 70d88ddb ingested by fathom fb7d9f3f: `typed_edges` held rows for the root module's packages only (2,819 rows; 0 in all 22 nested modules). `bosun`'s main is a product entry (entry detection takes every `func main` of a package main outside testdata), and its syntax calls were `cmd.NewRoot`, `context.Background`, `os.Exit` and its own `execute`. Four kits (docs, env, image, test) each declare `internal/cmd.NewRoot`, so the syntax resolver's `pkg.Name`, `dir.Name` and suffix lookups are all ambiguous and bind nothing. review-kit's main calls uniquely named functions (`cli.RunWithContext`), so its syntax edges resolved: 516 of 695 functions reached against env-kit's 2 of 436. Not a replace-directive load error, a go-directive mismatch (1.26.3 against a local 1.26.3) or entry detection
- **Root cause:** the typed pass was one `packages.Load(cfg, "./...")` with `Dir` at the repository root, and `./...` never enters a directory that holds its own go.mod (`loadableByRootPattern` and `zeroPackagesDisclosed` exclude nested modules by design). The syntax pass cannot bind a call that names a package by its last segment when several packages share it
- **Fix (EW-59, EW-60):** `typedModules` finds every go.mod governing a discovered Go file outside testdata, vendor, `_` and `.` directories; each module the repository owns (its path, less a major-version suffix, is the root's plus its directory; with no root go.mod, every nested module) is loaded from its own root, one after another, under the same `TypedEdgeEnv` and governor. A call into another in-repo module through a replace directive is first-party. A nested module's packages are stored under `gomod:<dir>//<id>`; a module whose load fails is disclosed under its go.mod and keeps its rows; a module named otherwise is listed in `ForeignModules` and one stderr line. TypedEdgeEpoch 5. Fixture `internal/fusion/testdata/nestedmodules` (example.com names)
- **Status:** built in 4bf63e3a and e0da3f75 (merge 03d4ff57); held for an owner ruling on the K26 cost gate (fathom's ingest wall +17% median, bar +15%; platform-engineering 12.2 to 67.7 s; see `docs/bench/readings/efficiency-wave/nested-module-reach.md`). K26 reads "absent that ruling, revert": the h4 integration reverted the code before it shipped, so main still loads the root module alone; an ACCEPT ruling re-lands it by reverting the revert
- **Impact:** platform-engineering env-kit reads 22 of 22 symbol rows wired (was 0), image-kit 3 of 3 (was 0); env-kit's `verify --strict` goes from 0 to 3 claimed rows verified and image-kit's from 0 to 2. Any repository whose binaries live in nested modules gains typed edges, and pays one module load per nested module on every typed pass
