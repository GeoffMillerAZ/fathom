### O671 — verb help exits 0 but no longer lists the verb's flags

- **Symptom:** `fathom verify --help` (and `-h` on any verb) prints the verb, its summary and its subcommands, and nothing about `--plan`, `--strict` or any other flag; before K11 S1 the verb's own flag set printed `Usage of verify:` and every flag with its default (on stderr, exit 1 or 2)
- **Evidence:** w2a2 integration critic, 2026-10-09: `printVerbHelp` (cmd/fathom/verbhelp.go) renders from the verb registry, which carries no flags; 169 `newFlagSet` call sites build each verb's flags inside its handler, 35 of them after other statements, so no help path can read them without running the handler
- **Root cause:** S1 intercepts help centrally so that no verb runs (the O668 defect), and the flag definitions live only in the handlers it no longer calls
- **Fix:** none yet. CL-2's row and the CHANGELOG line say so; S2's cli-kit move declares flags per command, which the help renders. Today an undefined flag prints the list (`fathom verify -x`, exit 2)
- **Status:** open (cli-kit-adoption S2)
- **Impact:** every user and agent that learns a verb's flags from `--help`
