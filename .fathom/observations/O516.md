### O516 — the C# dialect names a property bare (`Name`) where it names a method by its type (`Worker.Run`), now what ingest stores for `.cs`

- **Symptom:** after the `.cs` switch an ingest stores `src/App/Worker.cs|CSharpProperty|Name` beside `CSharpMethod|Worker.Run`
- **Evidence:**
  - **Tool:** `go test ./internal/fusion -run TestIngest_CSharpDialect` (wave lh); `dialects/csharp/testdata/shapes.cs.golden.json` (Radius, Diameter beside Circle.Area)
  - **Expected:** a member named under its type, as methods are, so `find_symbol Worker.Name` answers and two types' same-named properties stay apart by name
  - **Actual:** a property (as a Java field, `count`) is named by its identifier alone: the dialect's qualification chains containers for callables only
  - **Repro:** the test above
- **Root cause:** the tags engine's qualify rule (`qualify.chain_containers`) names a non-callable member bare; L1 compares bare names, so no reading saw it
- **Fix:** none here (a naming change re-keys every C# and Java member and bumps ExtractorEpoch: an owner call on the convention); find_symbol by the bare name still answers
- **Status:** open
- **Impact:** the CGO walker stored no property at all, so nothing is lost; a qualified lookup of a property misses
