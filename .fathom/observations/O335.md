### O335 — the typed Go pass purged the doc-xref edges on any Go-only change, and the one-file refresh never re-armed the doc-xref pass

- **Symptom:** the typed Go pass purged the doc-xref edges on any Go-only change, and the one-file refresh never re-armed the doc-xref pass
- **Evidence:**
  - **Tool:** ingest (internal/fusion/typedcalls.go reconcile; typedgate.go isNamespacedTypedKey, passKeysFor)
  - **Expected:** an ingest whose only change is a .go file keeps the doc-xref edges (and, from wave px, the route-ref edges) the gated passes stored
  - **Actual:** after the second ingest of a repo with a package.json workspace and a main.go, the stored file-tier edges read `[]`: the Go pass's reconcile deletes every typed_edges key that is not a Go package unless isNamespacedTypedKey names it, and "doc-xref" carries no prefix; the doc-xref pass, gated on its own state row (kept), skipped
  - **Repro:** TestRouteRefEdgesSurviveTheGoPass and TestRouteRefPassRerunsAfterOneFileRefresh (internal/fusion/routeref_test.go), red before the typedgate.go change
- **Root cause:** LB-F30's "doc-xref" key was never added to isNamespacedTypedKey or passKeysFor
- **Fix:** wave px (LB-F97): isNamespacedTypedKey names "doc-xref" and "route-ref"; passKeysFor names both passes' state rows for their candidates
- **Status:** fixed — LB-F97 (wave px, branch px-routeref)
- **Impact:** in a Go repository every Go edit silently dropped the cross-file edges of its tool formats until a doc file next changed
