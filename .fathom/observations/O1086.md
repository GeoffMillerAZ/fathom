### O1086 — A TypeScript file with no interface/type/enum still reads "javascript" in the primer and list_services languages

- **Symptom:** the SessionStart primer listed fathom's languages as c/csharp/cue/go/java/javascript/python/ruby though it holds .ts files.
- **Evidence:**
  - **Tool:** fathom prime / list_services
  - **Expected:** typescript listed for .ts/.tsx
  - **Actual:** languages derive from stored SourceKinds (internal/mcp kindToLang); JSFunc/JSClass/JSMethod are shared by .js and .ts, so only TSInterface/TSType/TSEnum can say typescript (fixed in this change)
  - **Repro:** index a .ts file holding only functions; languages shows javascript
- **Root cause:** the stored kind carries no file extension; the summary row aggregates kinds, not paths.
- **Fix:** read-time, no schema change: store.ServiceSummary carries FileLangs (distinct js/ts classes of the non-excluded JSFunc-class files in file_stats, classified by connector.LanguageForPath, the extractors' one extension table); mcp langStringsForSummary uses them to split the shared JS* kinds into javascript and/or typescript (kind-only answer when file_stats is absent). Measured on a scratch ingest of fathom (54125 symbols, 5679 file rows): the added query is about 1 ms warm (17 ms cold). Known imprecision: a .js file holding no symbols still lists javascript when another file's JS* symbols exist.
- **Status:** closed
