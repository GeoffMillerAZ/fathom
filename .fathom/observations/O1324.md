### O1324 — ctags writes no end line for a Perl definition, so Perl L1 cannot read excellent

- **Symptom:** perl.json reads L1 good (sym_recall .9997, sym_precision .9982 on mojo and Perl-Critic) and `range_agreement` is null.
- **Evidence:** `ctags --output-format=json --fields=+nKzSe` on a Perl file carries `line` and no `end` for a package or a subroutine; the reading's `range_eligible` is absent. Also on the oracle: it names `sub Pkg::name` `Pkg`, misses `async sub` (Mojo::Base `-async_await`, 5 subs in t/mojo/promise_async_await.t) and `package main;` in bin/perlcritic, reads `subroutine` in a `qw< package subroutine >` list as a package (Perl::Critic Capitalization.pm 212) and does not read `.t` unless mapped (`--map-Perl=+.t` is in the manifest).
- **Root cause:** universal-ctags 6.2.1's Perl parser emits no scope end; the L1 grade needs a measured range agreement to reach excellent.
- **Fix:** none here. A tier-B Perl definitions oracle with ranges (PPI's `PPI::Statement::Sub` reads a sub's block span) would lift L1 to excellent, as an `-adjudicate`-free `-tool-oracle` definitions list; ppi_calls.pl emits an empty `definitions` today.
- **Status:** open
- **Impact:** LB-Q-perl is met at L2 (the row pattern is L[234]); the tracker names the cap in its limits cell.
