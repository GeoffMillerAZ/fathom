### O391 — IAM and Azure Policy have no offline tier-A oracle: parliament's own "test policies" are Python strings, and the Azure oracle is a JSON walk, so both read at most good

- **Symptom:** `aws-iam-policy` and `azure-policy` read L1 good and L2 good (every metric 1.0, `sym_precision` .9999 for Azure) with `metric_tiers` C
- **Evidence:**
  - **Tool:** parliament 1.6.4 (tier C, an IAM linter whose `jsoncfg` reader and `make_list`/`Statement` classes list statements; reads JSON only) and an independent JSON walk over the Azure Policy definition structure (`calibration/oracles/azure-policy`)
  - **Expected:** an offline reference parser whose output carries source lines (tier A, which can prove excellent)
  - **Actual:** IAM Access Analyzer is online; parliament's tests (tests/unit/*.py) carry every policy as a Python string, so its test policies are no subject for a file reader; no Azure tool evaluates a definition offline; no measured IAM subject is YAML
  - **Repro:** `calibration/oracles/parliament/parliament_oracle.py`, `azure_policy_oracle.py`; subjects camp (4,713 documents), awslabs/terraform-iam-policy-validator (6) and Azure/azure-policy (5,658)
- **Root cause:** the formats are linted online or by services; the reading's tier is the oracle's, whatever the agreement
- **Fix:** none; LB-Q-aws-iam-policy-rest and LB-Q-azure-policy-rest carry the ceiling
- **Status:** open
- **Impact:** both rows meet L2 at good; excellent needs a tier-A oracle
