### O1271 — the daemon's ingest neither compiles nor sweeps certificates

- **Symptom:** the TC-8 brief named two call sites of the certifications compile, the CLI ingest and serve-http's ingest. Only the CLI has one. The daemon's `ingest` MCP tool and its auto-refresh run `Client.IngestService` and `Client.IngestServiceAt` (pkg/client/client.go), which run `semantic.Sweep` over cited claims and never `certify.CompileCertifications` or `certify.SweepCertifications`.
- **Evidence:**
  - **Tool:** `grep -rn "CompileCertifications(\|SweepCertifications(" --include=*.go cmd internal pkg`
  - **Expected:** a certificate in the daemon's store goes `stale` when the daemon re-ingests a moved test
  - **Actual:** production callers are cmd/fathom/tests_ingest.go and cmd/fathom/certify_compile.go only, both store-direct CLI paths. A certificate in the daemon's store changes only when a CLI verb writes to that store.
  - **Repro:** the grep above at 10a63138
- **Root cause:** stage 1 wired the compile into the CLI verbs only. pkg/client does not import internal/certify.
- **Fix:** TODO. Run the same `certifyNextStep` choice after `IngestService` and `IngestServiceAt`, with the marker scan the CLI ingest does first.
- **Status:** open
