### O1505 — a pre-push gate run from a linked worktree rewrote that worktree's git index: 2836 tracked files dropped from the index and test fixtures (clean, clean file, testdata/conflict) staged

- **Symptom:** a pre-push gate run from a linked worktree rewrote that worktree's git index: 2836 tracked files dropped from the index and test fixtures (clean, clean file, testdata/conflict) staged
- **Evidence:**
  - **Tool:** pre-push hook (lefthook) running task validate
  - **Expected:** the gate's tests touch only their own scratch repositories, and the pushing worktree's index is unchanged
  - **Actual:** git exports GIT_DIR to a hook run from a linked worktree; 8 shell tests and about 111 Go test files run git in scratch directories without scrubbing it, so their git add and git rm went to the pushing worktree's index. scripts/check-merge-debris_test.sh run with GIT_DIR set staged 'clean file' in the victim repository and exited 1. A cloud lane's gate failure with every step passing and clean=0 may be this or a file a test left behind
  - **Repro:** GIT_DIR=<scratch repo>/.git bash scripts/check-merge-debris_test.sh at the parent commit, then git ls-files in that repo
- **Root cause:** githooks exports GIT_DIR (and in a linked worktree points it at .git/worktrees/<name>) so the hook's own git calls find the repository; every child inherits it. O48 fixed this once inside scripts/stranger-check.sh and scripts/clean-clone-check.sh, never at the hook, so each new test that creates a scratch repository reopened it
- **Fix:** both pre-push commands in lefthook.yml unset the git location variables before running anything; the 8 shell tests that create repositories unset them too; scripts/git-env-scrub_test.sh (in task validate) fails when either scrub is missing
- **Status:** fixed
- **Impact:** an integration worktree's index lost 2836 entries after one hook-run gate (the files on disk were intact; git reset restored it), and the gate itself fails, since the merge-debris test exits 1 under an inherited GIT_DIR
