### O678 — the call truth now gives the module symbol calls inside definitions scip-python's index covers with no range: 18 new oracle-only pairs

- **Symptom:** with K18's module symbol, Python's call_recall moved from .9936 to .9922 (call truth 12,333 to 12,496, found 12,254 to 12,399; LB-F349): 18 new oracle-only pairs (fastapi 3, flask 15), every one with caller `<module>`.
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -unmatched` before and after, `calls.oracle_only` and `calls.fathom_only`.
  - **The pairs:** `<module> -> AttributeError` in src/flask/__init__.py is a call inside `def __getattr__` under a module-level `if not t.TYPE_CHECKING:`; `<module> -> iter/update_wrapper/generator` in src/flask/helpers.py are inside the third, implementing `def stream_with_context` after two `@t.overload`s; `<module> -> NoAppException/find_app_by_string/__import__/format_exc` in src/flask/cli.py likewise. Fathom gives each to its real definition, and those pairs were already fathom-only before the change (32 in the same flask files before and after).
- **Root cause:** the harness's innermostDef finds no scip definition covering the call (no enclosing_range, and the D5 line span applies only to a mapped definition), so before K18 the call had no owner and left the truth; the module symbol's whole-file span now owns it. The oracle deficiency is the one python.json already names ("a definition no enclosing range covers, an @overload implementation"), now counted as a miss instead of dropped.
- **Fix:** none here. The same 6 new fathom-only pairs are module-level calls scip-python writes no occurrence for (O450's classes: an untyped loop variable's receiver, a dict value, `os.path.dirname` resolved to posixpath).
- **Status:** open (disclosed oracle deficiency)
- **Impact:** call_recall .9922, call_precision .9184; L2 stays excellent.
