### O916 — tree-sitter-bash v0.25.1 glues a backslash-led line to the statement before it

- **Symptom:** `\. ../../nvm.sh` after `set -ex` (or after `X="..."`) is no command of its own in the tree, so neither its source statement nor its call is read where it is written.
- **Evidence:** `tree-sitter parse` at the lock's pin (a06c2e44): `set -ex\n\n\. ../../nvm.sh` is one `command` (`set`) whose words are `-ex`, `\n\n\.` and `../../nvm.sh`; after an assignment the glued word is the command's name. No ERROR node either way. A redirect's destination swallows the following lines the same way: nvm's `test/fast/Running 'nvm unload' should unset all function and variables` lines 12-17 are one statement, so its `\. ../../nvm.sh` (line 16) is the one import of 342 the oracle pairs and fathom misses.
- **Root cause:** the grammar's external scanner (no newer release; v0.25.1 is master).
- **Fix:** dialects/bash/imports.scm reads the two glued shapes (a word, or a command name, ending a run of whitespace with `\.`) on branch `lf6-shell-l3`; the redirect shape is left, disclosed. The tags query still records a call named `\n\n\.`.
- **Status:** open (grammar). Trigger: a tree-sitter-bash release that ends the statement at the newline.
- **Impact:** one nvm import; calls and statements after such a line are attributed to the line before.
