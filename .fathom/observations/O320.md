### O320 — the doc-xref label-selector join compares every reference with every label set

- **Symptom:** the doc-xref label-selector join compares every reference with every label set
- **Evidence:**
  - **Tool:** doc-xref pass (internal/fusion/docxref.go ResolveDocXrefs, label-selector case)
  - **Expected:** a join whose cost grows with the references times the label sets *in the reference's scope* (an index by scope, then by label), so a repository of many terraform modules costs what its largest module costs
  - **Actual:** each label-selector reference loops over every file's every label set; terraform (LB-F84) labels every definition, so the pass is references × definitions across the whole repository: 2659 × 1877 in 48 ms (terraform-aws-vpc), 4449 × 3111 in 80 ms (vpc and eks together); a monorepo of 50k definitions and 80k references extrapolates to about 4·10⁹ comparisons, seconds per pass, and the pass reruns whenever any doc candidate changes
  - **Repro:** ResolveDocXrefs over HCLExtractor.ExtractDoc of every .tf file of a subject, timed (LB-Q-terraform's measurement, 2026-10-01)
- **Root cause:** the label-selector case (docxref.go L171-L178) has no index on Scope; Kubernetes, its first user, has few label sets per scope
- **Fix:** open — index label sets by Scope (and by one selector label) before the join; docxref.go belongs to item dk
- **Status:** open
- **Impact:** doc-xref pass time on a large terraform repository; correctness unaffected
