### O513 — Java's 9 fathom-only file edges are a same-package class the file does not mean: a single-type import or a nested type shadows it, and the resolver binds the package's class anyway

- **Symptom:** `indexbench lang-parity -dialect java -incumbent javaextract` refuses the Java dialect on file_edge_precision alone (0.9978 < the incumbent's 1.0; every other gated metric level or ahead)
- **Evidence:**
  - **Tool:** lang-oracle on google/guava v33.7.1 (guava/) and square/retrofit 3.0.0 against scip-java 0.12.3, wave lh, 2026-10-02, with the fathom-only file pairs listed (4,134 fathom pairs, 4,125 in the truth)
  - **Expected:** a reference resolves to the type the file sees (JLS 6.4.1: a single-type import shadows a type of the same package; a member type declared in the file shadows it too)
  - **Actual:** 8 pairs bind a name a single-type import of a JDK type binds to the subject's same-package class: `import java.util.Objects;` then `Objects.hash(..)` in guava's base/{Equivalence,FunctionalEquivalence,Functions,Predicates,Suppliers}.java to base/Objects.java, `import java.nio.file.Files;` in io/MoreFiles.java to io/Files.java, `import java.lang.reflect.Type;` in retrofit's jaxb and jaxb3 JaxbConverterFactory.java to the test source set's Type.java; 1 binds CharMatcher.java's own nested `Ascii` to base/Ascii.java
  - **Repro:** the run above with ScoreFileEdges' fathom-only pairs printed (a local debug print, not committed)
- **Root cause:** `internal/fusion/fileresolve.go` falls back to the caller's package (`matchPackage`, LB-F74) for a name whose import resolves to no file of the subject, and for a type the file itself declares inside another; neither shadows
- **Fix:** open, item ts (sole owner of fileresolve.go/resolvestrategy.go this wave), via the integrator: a name a single-type import binds, resolved or not, is never looked up in the package scope, and a type the file declares at any depth shadows the package's same-named type. No imports.scm or references.scm change can express either
- **Status:** open
- **Impact:** these 9 are the whole gap: with them fixed Java's file_edge_precision reads 1 and lang-parity can re-read MERGE, which switches `.java` to the dialect (LB-Q-java-rest)
