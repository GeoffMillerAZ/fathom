### O1068 — `fathom verify` through the daemon read `?` on every `gone:` row that `--store` proved over the same index

- **Symptom:** `fathom verify --plan docs/plans/retire-unused-analyzers.md` through the daemon (the default --url) read `?` on 18 of 18 `gone:` rows and `--strict` exited 1, while `--store <the same index>` verified 18 of 18; `fathom plans status` over the daemon showed 46 claimed-unproven rows on fathom's own plans (2026-10-15, v0.11.0).
- **Evidence:**
  - **Tool:** fathom verify / plans status (daemon path), MCP verify_plan
  - **Expected:** the daemon path returns the direct store's verdict for every row
  - **Actual:** every gone: row Unknown "no gone evidence available on this evidence source"; runtime_pass Unknown "this backend holds no store of attested runs" where --store read the attested run; a self-skipped row carried a skip_test Pass beside the overlaid Fail
  - **Repro:** cmd/fathom/verify_daemon_parity_test.go (one fixture plan with every evidence kind, through both paths over one index)
- **Root cause:** internal/mcp's verifyEvidence implemented no verify.GoneEvidence (only cliEvidence did); the auto-refresh wrapper every daemon serves through did not forward Store(), so every store-backed capability read "no store"; OverlaySelfSkip/OverlaySelfDeclared appended a Fail instead of replacing the Pass.
- **Fix:** internal/verify/goneev is the one GoneEvidence both paths build; verify_plan takes the caller's plan tree (plan_tree) so a gone: row is held to the tree the plan came from; autoRefreshBackend forwards Store() (storeOf); the overlays replace in place; a corpus file that cannot be read is named (verify.GoneReadEvidence), never scored as an absence.
- **Status:** fixed (wave fic, item verify)
