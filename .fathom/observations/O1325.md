### O1325 — R: the harness's bare name rule cuts a leading dot, and universal-ctags misreads some R

- **Symptom:** with the default `name_match`, r.json's first run read sym_precision .9622 and sym_recall .9772: `.onLoad`, `.rlang_check_is_string` and the quoted and backtick names were dialect-only and oracle-only pairs.
- **Evidence:** `langbench.BareName` takes the last segment after `.:#/\ )`, so the dialect's `.onLoad` is `onLoad`, while `oracleMatchName` leaves the oracle's `.onLoad` whole (it is not a dotted identifier path). With `name_match: identity` the same files read .9994 and .9841. ctags 6.2.1 also tags nothing in dplyr R/grouped-df.R after compute_groups (a body holding `".rows" := new_rows`; 20 definitions) and no backslash lambda (`f <- \() ...`).
- **Root cause:** a dot is part of an R name (`print.point`, `.onLoad`), not a segment separator; the bare rule's both sides do not agree on a leading dot.
- **Fix:** the manifest sets `name_match: identity` (internal/extractor/dialects/r/dialect.json). A harness change would make `oracleMatchName` and `BareName` agree on a leading separator.
- **Status:** open
- **Impact:** none on the grade once identity is set; any later R/Ruby-style dialect with dotted names meets the same trap.
