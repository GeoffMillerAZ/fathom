### O1207 — Replay counts a workflow run's journal.jsonl as a transcript

- **Symptom:** `fathom readout replay` opens every `*.jsonl` under a project directory, so `corpus.files` counts each workflow run's `<session>/subagents/workflows/<run>/journal.jsonl`, which is the workflow's step journal, not a transcript.
- **Evidence:** a path-shape count of the local transcript root, made while grounding the sizing sections (2026-10-18, wave sz1, shapes only, no content read): 1,599 `agent-*.jsonl` and 172 `journal.jsonl` under `subagents/workflows/<run>/`. `replayAgg.file` increments `Corpus.Files` for every file it opens.
- **Root cause:** `replayAgg.walk` matches on the `.jsonl` suffix alone. The new `spawns` section classes subagents by `agent-*.jsonl` and so is not affected.
- **Fix:** none in this wave (replay's existing sections stay byte-identical). Skip `journal.jsonl` under `subagents/workflows/` in the walk, or count it apart, in the next change to the replay corpus figures.
- **Status:** open
- **Impact:** `corpus.files` overstates transcripts by about one in ten workflow files. Call, byte and rule figures are unaffected unless a journal line carries a tool block.
