### O1294 — `cue vet -d '#X' schema.cue file.cue` silently passes any `.cue` instance

- **Symptom:** a `.fathom/*.cue` instance with an unknown key or a failing value vetted clean against a closed definition.
- **Evidence:**
  - **Tool:** cue v0.16.1
  - **Expected:** `-d` checks the file against the definition
  - **Actual:** `-d` validates data files only (JSON, YAML); a `.cue` file is unified into the schema package, so `made_up_key: true` passes, rc 0
  - **Repro:** `cue vet -d '#Project' schema/project/schema.cue bad.cue` rc 0, after `cue export --out json bad.cue` the same check rc 1
- **Root cause:** CUE files are schema inputs, not data, under `-d`.
- **Fix:** `task cue-vet` exports the `.fathom/*.cue` files to JSON first, and asserts three inline negatives so an open `#Project` fails the gate.
- **Status:** fixed
