### O1444 — `task calibrate-clone` fails for every shard while one shard's YAML is invalid

- **Symptom:** `task calibrate-clone -- thrift` stopped at `Error: bad file calibration/corpus.d/html.yaml: yaml: line 40, column 15: mapping values are not allowed in this context` before cloning anything. The folded `notes: >` scalar at html.yaml line 40 carries `: ` inside the text, which yq reads as a mapping.
- **Evidence:** clone.sh reads every shard before it filters by the argument, so a shard that belongs to another item blocks them all. Worked around by cloning the two thrift subjects with the same `git clone --filter=blob:none --no-checkout` plus `sparse-checkout set --no-cone` commands clone.sh runs.
- **Fix (not made):** html.yaml is another item's file. Quote or re-wrap its notes, and have clone.sh parse only the shard it was asked for.
- **Status:** open
- **Impact:** A worker cannot use the task for any shard until html.yaml is repaired.
