### O486 — a row of the ingest transaction spilled its statement journal to a temp file, and the driver started a goroutine per statement

- **Symptom:** `PutObservations` was 4.7 s of the polyglot set's 27.5 s CPU profile at wave le's head and 4.9 s of the 17.2 s base profile (LB-M5, 1.77x); 3.5 s of it was `_subjournalPage` writing a temp file through `pwrite`, all system time.
- **Evidence:**
  - **Tool:** a CPU profile of `fathom ingest` over the 17-repository set (a `runtime/pprof` hook patched into main for the run, not committed), base 56c18502 and head 90f0a01f; `go tool pprof -peek`.
  - **Actual:** an INSERT into `observations` fires `trg_observation_calls_ai` (derived.go), so inside the explicit transaction every row is a multi-write statement and SQLite opens a statement journal of the original image of each page it touches; a row with hundreds of calls writes hundreds of random `observation_calls` index pages and the journal passes SQLITE_STMTJRNL_SPILL (64 KiB), so each such row created, wrote and unlinked a temp file. Separately modernc's `stmt.exec` starts a goroutine, a channel and a wake-up for every statement run under a cancellable context (`interruptOnDone`).
  - **Measured:** with the spill at 4 MiB (`sqlite3_config` before the first connection, 0 bytes of change to any row), interleaved against the default on one binary, load 4 to 17: CPU 26.2 s mean against 29.0 s, system time 3.8 against 5.9 s; 16 MiB and 64 MiB read the same as 4 MiB. Instructions 443.2 G to 415.5 G.
- **Root cause:** the call-index trigger makes every observation row a statement-journalled statement, and the default spill is sized for a row with a handful of pages.
- **Fix:** LB-F208 (`raiseStatementJournalSpill`, `TestStatementJournalSpillIsRaisedBeforeFirstOpen`). The per-row loops of observations, typed edges, doc units, centrality, fingerprints and file imports run under `context.WithoutCancel` and check `ctx.Err()` between rows; that change measured no CPU (the wake-ups it was aimed at, 2.6 s of `pthread_cond_signal` over base, are not these rows; their source is open, a goroutine per `tsengine.Parser.bounded` op being the candidate).
- **Status:** fixed; what remains of the statement journal is in memory, 1.9 s of `_memjrnlWrite` and `modernc.org/memory` mmap/munmap churn, which only fewer journalled pages per row (or a call index maintained after the bulk insert, not by trigger) removes.
- **Impact:** about 2.8 s of 29 s CPU on the polyglot set; every ingest of a call-heavy tree.
