### O1258 — verify's edge_wired says "does not reach" when reachable_from names two tests

- **Symptom:** RT-180's `reachable_from: TestStatGateReadsFileStatsAcrossRestart` failed `verify --strict` with "TestStatGateReadsFileStatsAcrossRestart does not reach fathom::internal/fusion/Pipeline.Pipeline.WithStatSource", though the typed edges test → `Pipeline.WithStoreStats` → `Pipeline.WithStatSource` were in the scratch store.
- **Evidence:** wave stat1's stat worker, 2026-10-19. A second test of the same name lived in cmd/fathom. `(*Graph).canonicalize` (internal/analysis/callgraph/graph.go) drops a bare name held by two nodes from `byName` and returns "" for an ambiguous suffix match, so `ReachableTyped` returns `(false, nil)` and `verify.go`'s edge_wired detail reads as a missing path, not an ambiguous name.
- **Root cause:** the edge_wired failure text does not tell "the name resolves to nothing or to several symbols" from "no typed path".
- **Fix:** worked around here by renaming the CLI test (`TestCLIIngestReadsOnlyStatChangedFilesAcrossRuns`). Open: edge_wired could name the ambiguity and the candidate keys (`byNameAll`), as find_symbol does.
- **Status:** open (the workaround landed; the message is unchanged).
- **Impact:** a worker reading the message hunts a missing call edge that exists.
