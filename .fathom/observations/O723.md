### O723 — the one-file refresh of a script, Makefile or handler file left the doc-xref pass state standing

- **Symptom:** after `ReingestFile` of a file a doc-xref edge targets but which is no doc candidate (a run step's script or Makefile, LB-F310; a Lambda handler module, LB-F370), the next ingest skipped the pass and kept the edge to the old symbol
- **Evidence:** `passKeysFor` (typedgate.go) invalidated docXrefStateKey for `isDocCandidate(path)` while the pass's own gate (`passNeeded`) read `isDocXrefInput` (doc candidates and image build candidates); `TestReingestFile_LambdaHandlerParity` fails with the old predicate (a handler renamed in the code keeps its edge)
- **Root cause:** two predicates for one pass's inputs, the refresh's narrower
- **Fix:** `passKeysFor` reads `isDocXrefInput`, which now also names a Lambda handler source (.py, .js, .mjs, .cjs, .ts, .mts, .cts, .java, .rb); the pass re-runs on those changes (the file-resolved pass already reads every such file each ingest); the same one-line fix was found independently as O730 (wave c3, item jenkins) and merged once
- **Status:** closed (wave c3, item cw)
- **Impact:** a stale run-step or handler edge until the next doc change
