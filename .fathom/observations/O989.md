### O989 — A destructured const with a default value is no TypeScript definition

- **Symptom:** `const { size = "sm", className } = Astro.props;` yields a JSConst for `className` and none for `size`; `const { variant: Heading = "h2" } = ...` none for `Heading`. TypeScript declares every one of them.
- **Evidence:** the Astro tuning reading (docs/bench/readings/lang/tuned/astro.json, astro-paper v6.1.0, wave lf7): sym_recall .9448, all ten oracle-only definitions destructured names with a default (Layout.astro's `title`, `description`, `ogImage`, `canonicalURL`; Datetime.astro's `size`, `className`; ...). The typescript dialect's destructuring patterns (dialects/typescript/tags.scm, LB-F382) take a `shorthand_property_identifier_pattern`, a `pair_pattern` whose value is an identifier and a `rest_pattern`, never an `object_assignment_pattern` or a pair whose value is an `assignment_pattern`.
- **Root cause:** the TypeScript dialect's module-level constant patterns (LB-F382) leave a defaulted binding out.
- **Fix:** none in wave lf7 (a TypeScript extraction change: TS cost gate, K29 for the TypeScript readings, a .ts epoch need). Two patterns would read them.
- **Status:** open
- **Impact:** an Astro component's props read with defaults (the common shape of `Astro.props`) are missing as definitions: Astro's L1 recall is below excellent where frontmatters default their props; TypeScript files lose the same names.
