### O1443 — A qualified Thrift type binds through the names an include brings in, not through the include's file name

- **Symptom:** `include "zipkincore.thrift"` and `include "jaeger.thrift"` in jaeger-idl's agent.thrift, then `zipkincore.Span` and `jaeger.Batch`: the thrift dialect reads 1 of the 2 cross-file references (xref_recall .5 on that subject, .9574 over both tuning subjects). `Span` is defined by both included files and the file resolver binds nothing for a name two files define.
- **Root cause:** `file-symbol` makes a whole-file import a wildcard: the file's top-level names enter scope unqualified, and the reference is read as its last identifier (`Span`). In Thrift the qualifier is the included file's stem (`zipkincore`), which no `imports` parameter reads (type_paths `package-dir` reads a directory, a whole import's local name is the whole path `zipkincore.thrift`). Never a wrong binding: an ambiguous name binds nothing.
- **Fix (not made):** a strategy parameter binding `stem.Type` to the file whose stem it is would close it; `internal/fusion`'s strategy code is outside this item. Revisit when a measured Thrift subject loses more than a few percent of its cross-file references to it.
- **Status:** open (revisit when a Thrift subject's xref_recall falls below .95)
- **Impact:** Two included files that define one type name leave references to it unbound.
