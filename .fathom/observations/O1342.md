### O1342 — the F82 replay classes every plan-file conflict as an append point and a generated board as OTHER

- **Symptom:** Sizing F88's design against the F82 replay, the path rule over-counts and under-counts append points at once: every `docs/plans/*.md` conflict is APPEND-POINT, while `internal/extractor/tsengine/grammars/PROVENANCE.md`, a generated board, is OTHER.
- **Evidence:**
  - **Tool:** `docs/bench/readings/f82-overlap-replay.py` (its APPEND-POINT path rule)
  - **Expected:** an append point is two lines adding at one point or bumping one derived line, whatever the path
  - **Actual:** of 64 `docs/plans/language-breadth.md` merges, 49 are add-only at one point and 13 edit the same or touching queue rows; after the append-points design about 51 merges conflict on nothing but plans, mostly same-row edits, yet they count against F88. PROVENANCE.md's 14 merges (12 on its derived total row) count against neither future.
  - **Repro:** `git merge-tree --write-tree m^1 m^2` on any replay merge naming a plan, then read the hunks' base side (empty for an append)
- **Root cause:** the classifier keys on the path, not on the hunk shape.
- **Fix:** a hunk-shape class beside the path class (add-only at one point vs an edit of a shared line), reported next to the unchanged path class so AP-M1 stays comparable with the 2026-10-19 reading. Not built here (`docs/design/append-points.md` section 8).
- **Status:** open
