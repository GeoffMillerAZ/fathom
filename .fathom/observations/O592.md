### O592 — the C# file-edge truth drew a partial type's reference to its first file, and lacked the edges scip-dotnet writes no occurrence for

- **Symptom:** C# L3 file_edge_precision .9049 and file_edge_recall .4346 (wave lc to lh), most fathom-only edges "references scip-dotnet does not attest" (O276) and the misses unexplained
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect csharp -unmatched` on Polly 8.8.0 and Newtonsoft.Json 13.0.4, each edge classed by the Roslyn semantic model's binding of every name (calibration/oracles/roslyn calls mode, wave lf1)
  - **Expected:** an edge from a referencing file to the one file declaring what the name binds
  - **Actual:** scip-dotnet gives a partial type one symbol for all its files (Polly's `Policy`, 30 files) and a generic type and its non-generic namesake one symbol (`Outcome` and `Outcome<TResult>`); the harness drew each such reference to the first document defining the symbol, an arbitrary file (1,580 edges drawn only that way). It writes no occurrence for a generic type used as a type argument (`Func<CircuitBreakerPredicateArguments<T>, ..>`) or a generic method called with type arguments (O271), nor in code its one target framework does not compile (1,925 edges the compiler binds)
  - **Repro:** the counts `scip_csharp_file_edges_multi_defined` and `csharp_compiler_file_edges_added` in `docs/bench/readings/lang/csharp.json`
- **Root cause:** an index symbol is not a declaration; scip-dotnet indexes one target framework
- **Fix:** LB-F287: an index edge drawn only by references to a symbol two documents define is left out of the truth, counted, as the import truth already holds; the compiler's own cross-file edges over every target framework (the calls mode's `file_edges`, a symbol two files declare drawing none) join it from the documents the index holds, counted
- **Status:** fixed (wave lf1)
- **Impact:** file_edge_precision .8982 to .9804 and recall .4355 to .4577 before the property fix (O595)
