- **Symptom:** `indexbench lang-policies -dialect gatekeeper` against the tier-A engine oracle (wave ox): 608 truth pairs, fathom finds 605; the 3 missed are one constraint's
- **Evidence:**
  - **Tool:** `indexbench lang-policies -dialect gatekeeper` on open-policy-agent/gatekeeper-library d2b86f87 `library/`, oracle `calibration/oracles/gator` (Gatekeeper's `pkg/target` ToMatcher and Match, gatekeeper/v3 v3.23.1)
  - **Expected:** `NoUpdateServiceAccount/no-update-kube-system-service-account` (`spec.match.namespaces: [kube-system]`, kinds include apps StatefulSet) joins the three StatefulSets in `general/storageclass/samples/storageclass/` (`example_allowed_ss.yaml`, `example_disallowed_ssvct_badnamename.yaml`, `example_disallowed_ssvct_nonamename.yaml`), which declare no `metadata.namespace`: Gatekeeper's `match.namespacesMatch` cannot disqualify an object that names no namespace ("Fall back to the Namespace the Object declares … such as for the gator CLI"; no namespace: match)

  - **Repro:** the gatekeeper reading's command in `calibration/oracles/gator/README.md`; the oracle's stderr counts 7 Match verdicts that would change under the `default` placement
- **Root cause:** two readings of an object as written: fathom models where `kubectl apply` would put it (the context namespace, conventionally `default`), Gatekeeper's match (gator, and admission when the request carries no namespace) treats the namespace as unknown, never disqualifying. Neither `namespaces` nor `excludedNamespaces` disqualifies a namespace-less object in Gatekeeper; fathom reads no `excludedNamespaces` at all
- **Fix:** open, for the next wave (internal/fusion is wave ic's): either treat a namespace-less object as matching any namespace scope (Gatekeeper's rule) for a Gatekeeper constraint, or keep `default` and record the divergence in design §4
