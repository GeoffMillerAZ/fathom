### O623 — the Prometheus parser refuses a Grafana dashboard's expression for a variable outside a string; the selector scanner reads it

- **Symptom:** of 1,592 corpus expressions, the parser refused 596 at first (Grafana's `$__rate_interval`, `$job`, `$__interval_ms` written where PromQL wants a duration, a label or a number); the differential could compare only the rest
- **Evidence:**
  - **Tool:** `calibration/oracles/prometheus/selectors_diff_test.go` (`FATHOM_PROMQL_REFUSED=1` lists the refusals)
  - **Actual:** with the range variables read as `5m` on both sides, 141 remain refused (136 a template variable, 3 empty), 1,451 agree, 0 disagree
  - **Repro:** `FATHOM_PROMQL_CORPUS=<thanos>:<kube-prometheus>:<node_exporter>:<opentelemetry-demo> go test -run TestSelectorsAgreeWithParser -v .`
- **Root cause:** a dashboard expression is a Grafana template, not PromQL; `promql.Selectors` reads `$` as punctuation and the next identifier as a selector, so a bare `$var` reads as a metric named `var`
- **Fix:** the census reads Grafana's variables first (`degrafana`: a range variable is `5m`, a count `1`, any other a placeholder never counted as a metric name); a dashboard dialect would need the same before its expressions are references
- **Status:** fixed in the census; disclosed for a future dashboard dialect
- **Impact:** without it the census counted `__interval_ms` as a metric name
