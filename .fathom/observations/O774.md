### O774 — React Router paths as imported constants: resolved; the lazy handler through `.then(convert(qc))` is a ceiling

- **Symptom:** bulletproof-react's v7 router stored 1 of 9 routes (the splat) and bound none: every path is `paths.app.users.path`, imported from `@/config/paths` (O735, LB-F380)
- **Evidence:** `docs/bench/readings/routes/react-router-consts.json` (fathom a458cef0, the LB-F380 oracles regenerated): bulletproof route recall .1111 to 1.0, route precision 1.0, bound recall 0 to .2 (2 of 10); react-router's 22 example apps identical to `react-router.json`; pooled bound recall .8879 to .9065, pooled bound precision .95 to .8899
- **Fix (SG-46):** the route seam's constant half. The reader emits a route whose path is an imported binding's member chain as a deferred path (`Result.Deferred`); a module whose exported constants include a string starting with "/" emits its string leaves (literal, or object-literal member chains, no call, template substitution or spread; at most 256 leaves, 200 bytes each) as `CONST` rows of `service_routes` (a pseudo-row kind like `MOUNT`, no table); `Compose` resolves a deferred path on read: relative import, or an alias (`@/`, `~/`, `#/`, `src/x`) as the unique path-suffix match nearest the importing file (no tsconfig read). An unresolved route stays unread, as before. Stored rows change for TS/JS files with such a route or constants module, so the integrator's one ExtractorEpoch bump covers it
- **Ceiling (handler):** the 9 bulletproof routes are `lazy: () => import('./routes/x').then(convert(queryClient))`; the component is what `convert`, a function of the app, makes of the module (`default` becomes `Component`), so naming it means evaluating the app's own function. Not a missing cross-file row: even with each module's default export named, the reader would guess `convert`'s meaning. A `DEFAULT` row per default-exporting module would also cost a row for 21 of the app's 128 TS files to serve 9. The pooled bound precision fell for the same reason: the 7 newly found lazy routes carry an empty handler where the oracle names one
- **Status:** SG-46 done (resolver); handler ceiling written. Trigger to revisit: an app whose lazy routes name the component without a user transform (`import('./x').then(m => ({ Component: m.Name }))` already reads), or a measured need for default-export names across files
- **Impact:** apps that centralize route paths in a config module now serve their routes to `route:` keys, hops and inventory; their lazy handlers bind only when the route names the component
