### O699 — the legacy express-regex reader reads routes out of the JavaScript bundled in PHP and Python repositories

- **Symptom:** an ingest of a PHP or Python application stores false routes from its front-end JavaScript: BookStack 71, koel 37, CTFd 322 (`GET /align`, `GET /Content-Type`, `DELETE /width`, all unbound)
- **Evidence:** `indexbench route-oracle` on the six c2-phppy subjects without `-only`: BookStack route precision .8285 against 1.0 with `-only '**/*.php,**/*.yaml,**/*.yml'`, koel .8892 against .9967, CTFd .4019 against .9954. The extras are `x.get('…')` and `x.delete('…')` calls (jQuery, axios, chart and editor option lookups) in BookStack's and koel's `resources/js/` and in CTFd's `CTFd/themes/*/assets/` and `static/` bundles, which the `express-regex` pattern set (moved unchanged into a reader at the seam) reads as routes
- **Root cause:** the express-regex reader matches any `<ident>.get|post|put|delete|patch|head|options|all|use('<literal>'` with no receiver or framework check, so client-side calls and minified option reads match
- **Fix:** item node owns JavaScript and the express-regex reader; proposed there: replace it where the Express/Fastify/Nest readers read, as phppy did for python-regex, or require a receiver bound to `express()`/`Router()` in the file, and skip minified and vendored bundles (`*.min.js`, `static/`, `dist/`)
- **Status:** open (item node's; the PHP and Python readings use `-only` and name it)
- **Impact:** a `route:` key or a service_ref hop can be minted from a front-end option read in any repository that ships JavaScript; precision of route keys on such repositories is far below what the PHP and Python readers alone read
