### O1180 — Stop and SubagentStop context re-opens the turn, so H2's advisory line costs a model turn and needs the re-entry guard

- **Symptom:** RO-V1 (docs/bench/readings/readouts/stop-facts.md, Claude Code 2.1.302): a Stop hook returning `hookSpecificOutput.additionalContext` makes the main agent answer it at once, and Stop fires again with `stop_hook_active: true`; emitted on every Stop it looped to the turn cap (7 of 9 turns). SubagentStop's context does the same inside the subagent before it returns; the main agent gets none of it.
- **Evidence:** the captured inputs and both transcripts of that one session: a `hook_additional_context` attachment, then a model request carrying "Stop hook additional context: ...", per fire.
- **Root cause:** in this harness `additionalContext` at a stop is a continuation, not a note held for the next prompt.
- **Fix:** RO-39 prints at most once per stop chain (silent when `stop_hook_active` is true, as `cmd/fathom/stophook.go` already is) and reads the message from the input's `last_assistant_message`, not the transcript's last message as the row says. RO-39's per-agent rows need TR-7's row to record the input's `agent_id`, which `logTestRunRow` does not do today.
- **Status:** open
- **Impact:** RO-38 and RO-39's design: each line H2 prints costs one model turn ("never a block" still holds, but it is not free), and without the guard a claim check would loop.
