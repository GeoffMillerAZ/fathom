### O376 — `fusion.includeRoots` reads `-isystem`, `-iquote` and `-idirafter` only when the directory is a separate argument, though clang reads each joined as well (`-isystem/usr/include`)

- **Symptom:** a compilation database written with joined `-isystem/dir` flags names include roots the include-path strategy never sees
- **Evidence:**
  - **Tool:** `internal/fusion/resolvestrategy.go` includeRoots (L709 to L763), against libclang 18.1.1's CompilationDatabase and clang's driver (`-I`, `-iquote`, `-isystem`, `-idirafter` and `-D` are JoinedOrSeparate)
  - **Expected:** `{"command": "cc -isystem/opt/inc -c a.c"}` yields the include root `/opt/inc`
  - **Actual:** only `-I` is also read joined; `-isystem/opt/inc` yields nothing (the compile-commands dialect reads the file the same way on purpose, `TestCompileCommandsFlagGrammarIsIncludeRoots` pins the two together, and the clang-compdb oracle reads the joined forms)
  - **Repro:** a one-entry database with a joined -isystem; cmake writes the separate form, so neither calibration subject exercises it (fmt 12.2.0 and libuv v1.53.0)
- **Root cause:** the loop special-cases `flag == "-I"` for the joined form
- **Fix:** none here: item cinc owns resolvestrategy.go this wave; when it changes the grammar, change `compdbIncludeFlags` handling in `internal/extractor/docdecode_compdb.go` and the test table in the same commit
- **Status:** open
- **Impact:** an include directory a build writes joined is invisible to C and C++ file edges and to the compile-commands dialect's references
