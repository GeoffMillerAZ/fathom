### O621 — a Prometheus `rule_files` file glob resolves to nothing at ingest: the doc-xref resolver matches globs to directories

- **Symptom:** `rule_files: ["rules/*.yml"]` in a configuration or promtool test file draws no edge to the rule files it names
- **Evidence:**
  - **Tool:** the prometheus dialect's golden (`testdata/prometheus.yml`: Target `monitoring/rules/*.yml`) and `fusion.ResolveDocXrefs`
  - **Actual:** `fileTargets` (internal/fusion/docxref.go) matches a target with `*?[` against the directories of the set (`packages/*`, a workspace glob) and takes the one doc file in each, never against files
  - **Repro:** a configuration whose `rule_files` is a file glob; the oracle (promtool's own glob expansion) names the files, the store has no edge
- **Root cause:** repo-path globs were designed for workspace directories (package.json workspaces, Cargo members)
- **Fix:** none here (docxref.go is the hub's file, outside item prom's lane); a file glob resolving to every matching doc file, or a `glob: files` mode on the cross-file reference, would lift it
- **Status:** open
- **Impact:** the measured corpora name rule files exactly (11 rule_files pairs, none a glob that resolves in the subject), so the reading is unaffected; an adopter with `rules/*.yml` gets no rule_files edges (LB-Q-prometheus-rest)
