### O1281 — a corpus shard's `subpath` is not a measurable subject root for an import oracle

- **Symptom:** Kong's shard sets `subpath: kong`, and the clone dir is the whole repository. Measuring the subdirectory (`workspace/calibration/lua/kong/kong`) makes `require "kong.pdk"` unresolvable, because the module name starts at the repository root.
- **Evidence:**
  - **Tool:** lang-oracle with `-subject` at the clone vs at its `kong/` directory
  - **Expected:** one subject root for the L1, L2 and L3 oracles
  - **Actual:** L1 and L2 readings so far were taken on the subdirectory, L3 needs the clone root
  - **Repro:** run lua_require_dump.js on each root: the subdirectory resolves none of Kong's own `kong.*` modules
- **Root cause:** `subpath` restricts the files, but a module system roots its names above that.
- **Fix:** the lua reading uses the clone root with `-only 'kong/**'` and filters every oracle file to `kong/` first (calibration/oracles/lua-require/README.md). Same shape will recur for Luau and Roblox projects (`src/` under a Rojo project).
- **Status:** open
