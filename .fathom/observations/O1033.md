### O1033 — fathom draws one Service selector join into a template kubectl rejects

- **Symptom:** kubernetes.json re-read under design 1.8's label-selector rule (wave lf8, LB-F456): xref_precision 1 to .9981 (536 of 537); kubernetes/examples' Service/vtgate to ReplicationController/vtgate is a fathom pair and a yaml.v3-walk pair, but no apimachinery pair.
- **Evidence:** the target is `_archived/storage/vitess/vtgate-controller-template.yaml`, a `{{...}}` template kubectl v1.36.1 rejects (`invalid map key`) and apimachinery's decode cannot read, so under the rule it carries no pod label set; the walk (yaml.v3 parses `{{replicas}}` as a flow mapping) read its labels. On the other five subjects apimachinery and the walk agree pair for pair (12, 158, 0, 13, 6).
- **Root cause:** the kubernetes doc dialect, like the walk, decodes with yaml.v3, which reads a document no Kubernetes decoder accepts.
- **Fix:** none taken: the rule is the one committed before the reading (K19), and the pair is the docker-compose rule's case (a file the tool rejects contributes nothing, its extraction counts against precision). A dialect that skipped a document kubectl rejects would need its own ruling.
- **Status:** open
- **Impact:** xref_precision .9981 on kubernetes.json, above the .95 bar; the grade is set by the tier (C), not the figure.
