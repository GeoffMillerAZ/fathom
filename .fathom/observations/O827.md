### O827 — runtime_pass (TC-29): two limits of the first cut

- **Symptom:** TC-29 reads the newest attested run of a row's certifying tests. Two edges are by design and worth a reading before anyone relies on them.
- **Evidence:**
  - **Tool:** `fathom verify` (store and daemon mode), internal/verify/runtime.go `runtimeTests`/`evalRuntimePass`.
  - **Actual:** (1) a row naming no certifying test (no `certified_by`, no `Test*` `reachable_from`) falls back to every test that statically reaches its symbol; the newest run among them answers, so a distant test's pass can read as the row's. (2) `fathom gen-status-cue` renders criterion details, and runtime_pass's detail carries the run's age, so a regenerated status file changes as runs age (its doc now says so).
  - **Repro:** a row `{symbol: X}` reached by many tests, two attested runs of different tests; `fathom verify --row <ID> --json`.
- **Root cause:** the row grammar has no field naming the test that proves it except `certified_by` and a `Test*` `reachable_from`.
- **Fix:** none here; informational by I8, so nothing gates on it. Revisit with the reading I8's amendment asks for (attested runs agree with local reruns).
- **Status:** open
- **Impact:** a reader of runtime_pass on a row with no named test sees "some reaching test passed", not "this row's test passed"; the detail names the test, so it is visible.
