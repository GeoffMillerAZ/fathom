### O1223 — The outline join's 150 ms deadline classifies a miss; it does not cut the Read's wait

- **Symptom:** the Read outline hint runs `readout.Outline` under a 150 ms context, but the join checks the context only before and after the extraction, so a slow extraction (O1200's cold tree-sitter grammar, 161 ms for Bash; a large file) still runs to completion while the PreToolUse(Read) hook holds the Read. The hint is then silent and its row says `missed`, but the Read waited the whole extraction, bounded only by the entry's 2 s timeout.
- **Evidence:** internal/readout/join_outline.go `Outline` (ctx read twice, no cancellation inside `ExtractForBench`); cmd/fathom/readouthint.go `readOutlineHint`; the tenancy lint's bare-go rule keeps a cancellable goroutine out of cmd/fathom.
- **Root cause:** the extraction pipeline takes no context, and a one-shot hook process cannot abandon it without a goroutine.
- **Fix:** none in this wave. The hint's rows carry `join_ms`, `ms` and `lang`, so RO-M15 can read the added PreToolUse latency and the miss rate by language before the seam is judged; a context-aware extraction or a kept compiled grammar (O1200) is the lever if either is high.
- **Status:** open
- **Impact:** only while `[hooks] read_outline_hint` is on, and only on whole reads of long, unedited source files.
