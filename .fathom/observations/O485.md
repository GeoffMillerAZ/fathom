### O485 — scip-python could not resolve a src-layout subject's own package, so Python L2 read good; with the source root on its import path it reads excellent, and exposes a src-layout gap in fathom's Python resolver

- **Symptom:** Python L2 read call_precision .8751 against .90 (O450 classified every fathom-only pair as the oracle's, and measured .9201 with `PYTHONPATH=<flask>/src`).
- **Evidence:**
  - **Tool:** `calibration/oracles/scip-python/run.sh` (now with `srcroots.py`) over fastapi 864b569 and flask 22d9247 (3.1.3), scip-python 0.6.6, then `indexbench lang-oracle -dialect python -scip` at fathom 90f0a01f.
  - **Actual:** call_precision .9201 (12,233 of 13,296; flask 757 fathom-only pairs, from 1,355), call_recall .9942, L2 excellent; extraction unchanged. fastapi has no `src/` and its index is the same. OracleBlindSites was not needed, so SCIPOptionsFor's python branch is untouched.
  - **Side effect:** with flask resolvable, scip-python now names flask's own package in tests/ and examples/: flask in-repo imports 181 to 305, import_resolution .9906 to .951 (124 `from flask import ...` lines fathom leaves unresolved: 135 unresolved vs 11), file_edge_recall .5462 to .5119 (flask's file edges 131 to 352). L3 stays excellent, by .001.
- **Root cause:** the oracle's environment (the subject's source root was off its import path), then, newly visible, fathom's Python import resolver does not treat `src/` (a root holding a package) as a module root, so `import flask` / `from flask import X` from outside the package resolves to nothing.
- **Fix:** run.sh (LB-F207). The resolver gap is internal/fusion's (wave ld owns it): bind a Python module name through a source root (`src/`, pyproject package-dir) as the file resolver already does for protobuf buf.yaml roots.
- **Status:** oracle fixed; resolver gap open
- **Impact:** Python L2 excellent; L3 excellent with .001 of headroom until the resolver reads src layouts (every src-layout Python repo's tests and examples importing their own package lose those edges).
