### O793 — an extensionless script read by its shebang carries no language tag and draws no file edges

- **Symptom:** after D4 (O756, `internal/fusion/shebangdispatch.go`) an extensionless script's functions, calls and signatures are stored, but `connector.LanguageForPath` gives it no language tag and the file-resolved pass draws no edge from or to it
- **Evidence:** `TestIngest_ShebangDispatch` (internal/fusion): `bin/tool` (`#!/usr/bin/env bash`) stores `usage` as a BashFunction, `scripts/report` (`#!/usr/bin/env python3`) `render` as a PythonFunc; `fileResolveLangFor` and the connector's `extClassMap` key on the extension (the path's last `.`), so a path with none has no entry
- **Root cause:** the file resolver and the language table are keyed by extension; the shebang is content, read only by the dialect classifier (`connector.ClassifyDialect`) and the dispatch rule
- **Fix:** wave lf6, 9a912b31 (LB-F494): the file-resolve pass reads each extensionless file no basename claims (`shebangScriptPath`, after the size and binary gates) and puts the ones `ShebangDialect` dispatches into their dialect's language (`shebangResolveLang`, the dialect's language tag), in the files' own order, as importers and as targets; an edit to such a file is a pass input (`fileResolveInput`). `TestIngest_ShebangFileResolve`: a python3 script's `from pkg.util import fmt_row` binds pkg/util.py, a Ruby file's `load 'bin/helper'` binds the ruby script's method, and an edit to the script alone re-runs the pass. Cost on bats-core and nvm (cold, medians of three): store identical, wall -6% and -3.5%. The connector's `LanguageForPath` and `file_stats.lang` stay extension-keyed (a stat-skipped file is never re-read, so a content-derived tag there would flip between ingests). A bash script's `source` resolves once the bash dialect has an imports query (branch `lf6-shell-l3`, stopped at the cost gate, O918).
- **Status:** closed (fixed in fusion)
- **Impact:** `find_symbol` and the callers of a function in an extensionless script work; its imports and file-level dependencies do not
