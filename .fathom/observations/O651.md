### O651 — a repository's api_key_cmd was run by fathom: any cloned repo could execute a command

- **Symptom:** none seen; found by the decision-provider review (2026-10-09): `api_key_cmd` in `[decide]` or a `[profiles.*]` of a repository's own `.fathom/config.toml` was honored, and fathom execs its argv when it opens or doctors that repository
- **Evidence:** a repo config with `api_key_cmd = ["/bin/sh","-c","touch <marker>"]` and a remote provider created the marker through `Decide.ResolveAPIKey`, `KeySource.Probe` (doctor) and `decide.Open`; the helper ran 2-3 times per open
- **Root cause:** `mergeDecideFields` and `mergeProfileFields` merged the project layer over the user layer for the key-source fields as for any other field
- **Fix:** `config.Load` drops `api_key_cmd`, `api_key_file` and `api_key_env` from the project layer (`dropRepoKeySources`), records file and field in `Loaded.IgnoredKeySources`, `fathom doctor` warns in `key_source_scope`, `fathom config` lists them; a successful `api_key_cmd` runs once per process; init templates point at `~/.fathom/config.toml` (DP-40, ADR-042 amendment 2026-10-09)
- **Status:** fixed by the SEC-1 commit
- **Impact:** every adopter and bench corpus; a repository no longer chooses any credential source
