### O1351 — a json-schema `$ref` outside every definition and root property has no source, and cross-file evidence is 3 pairs

- **Symptom:** a root `allOf`/`oneOf`/`$ref` (draft-07 schemas put the whole body there) draws no edge, and the xref family is scored on 3 file pairs.
- **Evidence:**
  - **Tool:** reading counts and the oracle summary (`refs_outside_entities` 637 on SchemaStore, 17 on the Test-Suite remotes)
  - **Expected:** a `$ref` anywhere in a schema is an edge from the nearest entity, the document when none
  - **Actual:** references run from `JSONSchemaDef` and `JSONSchemaProperty` only, as openapi's do from its entities and never its document, because the doc engine's `$..$ref` from the document entity would re-walk every child entity and count each `$ref` twice. SchemaStore resolves 3 file `$ref`s in the subject (all to itself) and 434 outside the sparse tree, 134 are URLs; only the Test-Suite remotes (3 pairs) draw a cross-file edge
  - **Repro:** `summary-out` of the oracle on each subject
- **Root cause:** no entity-exclusive `..` in the selector subset (`docengine.go`), and public schema sets reference each other by URL, not by relative file.
- **Fix:** none now. L3 excellent holds on 3 xref pairs at precision and recall 1, which proves the path (`repo-path` resolution of a `$ref` file part), not its coverage. A subject with relative-file `$ref`s across many schemas would move the bar from proven-path to measured-coverage.
- **Status:** open
