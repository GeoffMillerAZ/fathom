### O405 — a content-claimed doc dialect is measured only if Pipeline.ContentDialect names it

- **Symptom:** `lang-oracle` on a dialect whose manifest claims no name, extension or glob (argo, flux, crossplane, ansible) reads "no files fathom would extract", though ingest dispatches them
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect flux` (cmd/indexbench/langoracle.go ownedSourceRefs)
  - **Expected:** the harness measures exactly the files ingest's dispatch sends the dialect
  - **Actual:** ownedSourceRefs asks `Pipeline.ContentDialect`, whose switch (fusion/classify.go) answers only "cloudformation" and "openapi"; a new content-claimed dialect needs a case there or the harness measures nothing
  - **Repro:** add a content-claimed dialect without a `ContentDialect` case; lang-oracle fails with `no <id> files`
- **Root cause:** ContentDialect is a hand-written switch over two ToolKinds, not the set of dialects the dispatch can return
- **Fix:** the iac wave adds one case for ansible, argo, flux and crossplane (a ToolKind named as the dialect id); a table read from the dispatch would remove the next edit
- **Status:** worked around
- **Impact:** every future content-claimed dialect (wave pc's gatekeeper and kyverno) must add its ToolKind to ContentDialect, or its reading cannot be taken
