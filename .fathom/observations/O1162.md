### O1162 — a verify_plan call made while the daemon is at refuse fails claimed rows that pass in store mode, and says nothing about why

- **Symptom:** `fathom verify --plan docs/plans/language-breadth.md` through a scratch serve-http reported 9 claimed rows failing. The same binary over the same store in `--store` mode reported 0 failing, three runs per binary (v0.15.2 and v0.15.3).
- **Evidence:**
  - **Tool:** `verify_plan` (daemon), the CLI's follow-up calls (O1161).
  - **Expected:** a call that could not use the typed call graph either answers with the graph verify needs or marks the reachability rows it could not check Unknown, with a partial that names the cause (I38).
  - **Actual:** the scratch serve-http was v0.15.3 (78157704), unmanaged with a 512 MiB budget, over a fresh ingest of 78157704. It went `shed → refuse: footprint+children 640.7 MiB ≥ refuse mark 512 MiB` at 03:38:53Z. Call 3 of 54, at 03:39:20Z, logged `verdict_outcome {claimed 512, failing 277, verified 10}`. Every other call logged 0 failing. The CLI kept the rows that call answered: LB-F136..LB-F144, LB-F377, LB-F452 and LB-F453 read ✗. Their details read `edge_wired: TestIngest_PolicyRefs does not reach …enrichPolicyRefEdges`, `… (tier heuristic, syntax-only): verify passes on no heuristic edge`, and `test_reaches: no Test* statically reaches it`. The answer carried no `partial`.
  - **Repro:** start an unmanaged `serve-http --store <fresh ingest> --auto-refresh=false` and run `fathom verify --url <it> --service fathom --plan docs/plans/language-breadth.md` until the daemon log shows refuse. Then compare the result with `--store`.
- **Root cause:** not verified. `loadVerifyStage` (internal/mcp/verify_plan_tool.go) falls back to the syntax graph when the typed-edge read fails (`typedErr`), and the handler adds no partial for that fallback. A read refused or cut at refuse would produce exactly these rows. The call log does not record which branch ran.
- **Fix:** proposed, not made, because this brief changes no tenancy or verify_plan semantics. Either name the fallback in a `partial` and render its reachability failures Unknown, or refuse the call when the typed graph cannot load.
- **Status:** fixed (branch fx6-vfallback). `loadVerifyStage` records the typed-read failure; `test_reaches`, `edge_wired` and product reach that did not pass read Unknown with the cause (`[graph-fallback]`), the answer carries a `partial` and a `graph_fallback` aggregate, and the verdict_outcome call-log line carries `graph_fallback` 0/1. One predicate, `verify.OperationalRow`, drives strict exit 2 for index-stale, graph-fallback and verdict-elided rows.
- **Impact:** under memory pressure, which is when O1161 struck, the daemon-mode gate can fail claimed rows that hold. A loaded machine reads as broken code.
