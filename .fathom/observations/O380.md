### O380 — the file-resolved pass and the harness's import scoring served the tags engine only: a native dialect could not reach L3

- **Symptom:** a native Rego extractor's imports could be neither resolved at ingest nor scored by `indexbench lang-oracle` (`import_resolution not measured: the dialect names no import strategy`)
- **Evidence:**
  - **Tool:** `fusion.ResolveFileEdges`, `fusion.ResolveImportSpecs`, `Pipeline.enrichFileResolvedEdges`, `extractor.FileResolveLangs`
  - **Expected:** a dialect whose manifest names an import strategy reaches the file-resolved pass whatever its engine
  - **Actual:** every entry built `extractor.NewTSExtractor(lang)`, and `FileResolveLangs` listed only tags dialects with an imports query
  - **Repro:** a native manifest with `imports.strategy` before wave pc: no `FileResolveLang` row, no stored `file-resolved:` edges
- **Root cause:** the pass's extractor type was `*extractor.TSExtractor`, not what it needs of one
- **Fix:** `extractor.FileSpecExtractor` (symbols, `ExtractFileSpecs`, `ExtractImportSpans`) and `NewFileSpecExtractor`, a native dialect's own reader when it implements it; the pass, `ResolveImportSpecs` and the harness take it (LB-F131)
- **Status:** fixed
- **Impact:** Rego reaches L3 (good) through the same pass and harness the tags languages use; any later native reader can
