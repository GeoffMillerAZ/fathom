### O770 — a qualified query for an ordinary bare-stored name ignores a wrong qualifier

- **Symptom:** `find_symbol "zzz.get_debug_flag"` on flask 3.1.3 answers exact with src/flask/helpers.py's function: the qualifier `zzz` names no file or package of it
- **Evidence:**
  - **Tool:** find_symbol, exact tier (measured in wave h3 beside O743; same before and after the module-symbol fix)
  - **Expected:** no exact match, or a match only when the qualifier ends the symbol's package or file stem path
  - **Actual:** 1 row (helpers.py), the same as the bare name
  - **Repro:** ingest flask 3.1.3; `find_symbol {service: flask, name: "zzz.get_debug_flag"}`
- **Root cause:** `symbolMatches` (internal/query/engine.go) keeps its suffix rule (`strings.HasSuffix(name, "."+o.Symbol)`) for every name but `<module>`; verify's plan-row resolution reads FindSymbol and a plan row may spell a qualifier the index stores differently (a Go package path, a receiver), so narrowing it needs its own measurement across the plan corpus
- **Fix:** none (wave h3 narrowed module symbols only, SR-74). Candidate: the module-qualifier test for any bare-stored name whose package is known, measured by `fathom verify` over every plan first
- **Status:** open
- **Impact:** an agent naming a wrong qualifier gets an exact answer with no hint it was ignored; low (the bare name is right)
