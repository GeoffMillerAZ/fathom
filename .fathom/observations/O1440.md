### O1440 — the graphql-js oracle reads a fragment spread sharing a type's name as that type

- **Symptom:** the reaction holdout (`docs/bench/readings/lang/holdout/graphql.json`) reads xref_recall .9912 (113 of 114); the one oracle pair fathom does not draw is `apps/reaction/tests/integration/api/queries/navigation/navigationTreeByIdQuery.graphql` NavigationTreeById to `packages/api-plugin-navigation/src/schemas/schema.graphql`.
- **Evidence:**
  - **Tool:** the file defines `fragment NavigationTreeItem on NavigationItem` and its query spreads `...NavigationTreeItem`; the navigation plugin defines `type NavigationTreeItem`
  - **Tool:** `calibration/oracles/graphql-js/graphql_oracle.mjs`: a spread is a reference (enclosing definition, fragment name), and `cross_references` looks every reference's name up among type definitions
- **Root cause:** the oracle's cross-reference pass does not tell a fragment reference from a type reference; fathom's global-name binds named types only, never a spread, which is the GraphQL meaning.
- **Fix:** none here: the holdout is read once. The oracle fix (cross references from type references only) changes no tuning reading (no tuning subject has the collision); a later wave that applies it re-reads the readings it touches (K29).
- **Status:** open
