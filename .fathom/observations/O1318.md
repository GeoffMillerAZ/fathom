### O1318 — the project loader costs 3.5 ms per edit if the edit hook adopts it; today it adds 0 ms

- **Symptom:** none yet. `projectdir.Load` validates every `.fathom/*.cue` key against `#Project`, and the edit hook reads `guard.cue` on every edit (`loadGuardSet`, `loadLayerRuleSet`). The question was what the load adds to that path.
- **Evidence:** on this repository (owner's darwin machine, `go test -bench`, 30 iterations x 3): `Load` alone 5.4 ms; the hook's guard reads by path (`LoadGuards` + `LoadLayerRules`) 0.70 ms; the same readings through `Load` + `GuardsFromProject` + `LayerRulesFromProject` 3.5 ms (compiling the embedded schemas dominates). `fathom edit-hook --pre` end to end, daemon down, 30 runs: base median 21.4 ms (p90 22.8), head median 22.0 ms (p90 29.5). Budget: `preHookBudget` 2 s.
- **Root cause:** the hook paths still call the path readers, which parse their one file and do not validate. Only `doctor`'s `project` row calls `Load`.
- **Fix:** none needed now. If the edit hook moves to one shared `Load`, it adds about 2.8 ms per edit, about 0.14% of its 2 s budget. Validation is the cost, and the hook does not need it, so the switch can decode without validating.
- **Status:** open (measurement on record for the hook switch)
