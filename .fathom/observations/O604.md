### O604 — scip-go's package symbol is defined at every file's package clause, so a reference to a package named an arbitrary first file in the file-edge truth

- **Symptom:** 1,255 of cli/cli's 1,975 oracle-only file pairs were references to a package symbol alone, and file_edge_recall read .6702
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect go -scip <scip-go index> -unmatched` and a scratch classifier of the oracle-only pairs by the referenced symbol's descriptor (wave lf1)
  - **Expected:** a file edge ends in the file that defines what the reference names
  - **Actual:** `` `pkg`/ `` is defined in each file of its package; `definedIn` kept the first document, so `main.go -> pkg/a.go` was truth when `main.go` called `pkg.Foo` defined in `pkg/z.go`: 1,306 file edges (1,106 after the documents outside the subject left) drawn by such a reference alone
  - **Repro:** as O603
- **Root cause:** the harness's `definedIn` takes the first defining document of any symbol; the Go package is the one symbol defined in every file of its package
- **Fix:** a reference to a symbol defined in more than one document draws no file edge under scip-go, counted (`scip_file_edges_multidef`; design §1.7, LB-F298). The same rule keeps scip-typescript's ambiguous module out of the import truth
- **Status:** fixed (scoring rule)
- **Impact:** file_edge_recall .7034 on a truth without the guesses
