### O743 — a qualified exact query for one file's module symbol answers every file's

- **Symptom:** `find_symbol "signals.<module>"` (or `"zzz.<module>"`) on flask 3.1.3 answers exact with all 83 `<module>` symbols, not signals.py's one; `symbol_context "signals.<module>"` resolves the right one
- **Evidence:**
  - **Tool:** find_symbol, exact tier (found measuring O741; same on the deployed binary and on 361e3113)
  - **Expected:** the module symbol of the file whose package the qualifier names, or no exact match when none does
  - **Actual:** 83 rows for `signals.<module>` and for `zzz.<module>`. The same rule answers `zzz.get_debug_flag` with helpers.py's function: a qualifier is not checked against a bare stored name
  - **Repro:** ingest flask 3.1.3; `find_symbol {service: flask, name: "signals.<module>"}`
- **Root cause:** `symbolMatches` (internal/query/engine.go) matches a qualified query against a stored bare name by suffix alone (`strings.HasSuffix(name, "."+o.Symbol)`) and never compares the qualifier with the symbol's package; dialects that store bare names with a package (Python, the tags engine) all take this path, and a name every file shares turns one row into one per file
- **Fix:** none in wave h2: the qualifier rule is the exact tier's for every bare-stored name, and verify's plan-row resolution reads FindSymbol, so narrowing it is its own change with its own measurement (filter a qualified match to nodes whose package or package path ends with the qualifier, or answer none). Wave h2 held the exact tier unchanged by contract
- **Status:** open
- **Impact:** an agent naming one file's module symbol the way symbol_context accepts gets every file's; for an ordinary name the same rule silently ignores a wrong qualifier
