### O1383 — a registry switch needs a read at each hook, or capabilities.cue records intent and nothing changes

- **Symptom:** surfacing test_run, pin_check and guards.enforce as Switchable capabilities failed TestEverySwitchableCapabilityHasAnEnforcementCase: the hooks read config.toml directly, so a capabilities.cue value changed nothing.
- **Evidence:** cmd/fathom testrunhook.go, edithook_pin.go (pinCheckMode), enforce.go (enforceEnabled), claimcheck.go and gatepreflight.go each read config.Hooks/Guards.
- **Root cause:** FD-34's "capabilities.cue wins" is only true if each read resolves through the capability.
- **Fix:** capabilityOnAt(root, id, fallback) resolves capabilities.cue over the config.toml switch over the built-in Default; the five reads call it, and a broken capabilities.cue keeps the caller's own config value. hooksKeyOn (hook wiring at init) still reads config.toml only.
- **Status:** fixed in FD-34, wiring half open
- **Impact:** capabilities.cue turning test-run-hook on over a config that never names test_run takes effect for the hook, claim check and gate preflight, but fathom init does not wire the hook entry for it.
