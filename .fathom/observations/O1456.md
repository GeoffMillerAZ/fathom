### O1456 — verify's lexical oracle reads the working tree, not the ingested commit, so one report judges symbol rows and lexical rows against different trees

- **Symptom:** a lexical plan row (`pattern` over a file) is judged on the file as it is on disk when verify runs, while symbol rows in the same report are judged on the ingested store. Verifying a scratch store of commit C from a tree that has moved on passes a lexical row on uncommitted text. A `--store` run whose recorded root cannot be read reports every lexical row unknown. Adopters filed 2 reports, on 2026-09-28 and 2026-10-01 (theme T15 in docs/bench/readings/feedback/adopter-triage-2026-10-20.md).
- **Evidence:**
  - **Reports:** agentic-kit O8 (against a store ingested at the base commit, the oracle read "2 match(es) total (51932 bytes)", the working tree's file. `git show <base>:<file>` is 49755 bytes with 0 matches). Adopter repository C O9 (direct-store verification: "five lexical rows report no repo file access and unknown; symbol rows verify").
  - **Code:** `DirFiles.ReadRepoFile` (internal/verify/lexical.go) is `os.ReadFile` under the root. `evalLexicalOracle` takes its body from that `FileEvidence`. Nothing records or compares the ingested commit's copy of the file. O1069's fix (b49f26d58) reads a `plan_path` plan's lexical oracles "from that tree", the same working tree.
- **Root cause:** lexical evidence has no tie to the index. Symbol evidence comes from the store at its watermark, lexical evidence from the disk at verify time, and the report does not say which tree each row was judged on.
- **Fix:** proposed, not built. When the tree differs from the store's index commit, read the oracle's file at that commit (`git show <index_commit>:<path>`) or refuse the row as `tree-differs`. Name the source (`working tree` or `<commit>`) in the detail line. The wave contract's "verify on a fresh scratch ingest of HEAD" then pins lexical rows the way it already pins symbol rows.
- **Status:** open
- **Impact:** a row can verify on uncommitted text, against the gate's own definition of done.
