### O596 — switching C++ to the tags dialect left every unqualified reference to a namespaced header definition unbound: the include-path resolver looked names up as the incumbent wrote them

- **Symptom:** with `.cc/.cpp/.hpp` dispatched to the cpp dialect, `TestIngest_CppReferencesReachTheStore` lost `TEST_F(Point, area) -> lib::Point`, and a call `scale(v)` inside `namespace lib` bound nothing in another header; the dialect's own L3 reading had been taken with the same gap (file_edge_recall .2608)
- **Evidence:**
  - **Tool:** `go test ./internal/fusion` after the register.go switch; `indexbench lang-oracle -dialect cpp` on fmt 12.2.0, json v3.12.0 and spdlog v1.17.0, wave lf1 item ccpp
  - **Expected:** an unqualified name inside `namespace lib`, or written where one header candidate holds it, binds `lib::Point` as it bound the incumbent's `Point`
  - **Actual:** crefs.go's matchCppRef and the own-name check looked a reference up by `qualified[file][name]`, the full Name; the dialect names a definition through its namespaces (`lib.Point`), the incumbent did not (`Point`)
  - **Repro:** `go test ./internal/fusion -run TestIngest_CppReferencesReachTheStore` at 67837387 with crefs.go reverted
- **Root cause:** the dialect makes a namespace a container (dialects/cpp/PROVENANCE.md), so a namespaced definition's Name carries its namespace path; the resolver was written for the incumbent's names
- **Fix:** LB-F294: each C++ definition is also read by its name inside its namespaces (`cppLocalNames`), a namespace chain is one segment per level whichever way it is named, and a dotted call binds through a scope only when the file writes it with the scope operator (`cppCallScoped`)
- **Status:** fixed (wave lf1, item ccpp)
- **Impact:** C++ file_edge_recall .2608 -> .4218 on the three subjects; the dispatch would otherwise have dropped most cross-header C++ edges the incumbent drew
