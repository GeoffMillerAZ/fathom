### O368 — file-edge precision is scored against one build configuration without the line scoping L1 and L2 already apply: curl's precision reads .6708 where its edges from active lines read .90

- **Symptom:** file-edge precision is scored against one build configuration without the line scoping L1 and L2 already apply: curl's precision reads .6708 where its edges from active lines read .9008
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect c -scip … -tool-oracle <preproc.json>` (cmd/indexbench/langoracle.go, the file-edge block after ScoreFileEdges), curl 8.22.0 and libuv v1.53.0, fathom 32afe369 plus wave cx item cinc; a scratch re-read that drops each edge whose caller definition starts on a line the preprocessor discards (the oracle's active_lines)
  - **Expected:** a call in an inactive `#if` branch (curl's win32, VMS, gssapi, ntlm, smb code with SSL off) is outside the one configuration the index holds, as it is for L1 and L2
  - **Actual:** curl file_edge_precision .6708 (1,724 of 2,570), libuv .9456 (747 of 790), pooled .7354; scoped to active callers curl .9008 (1,680 of 1,865), libuv .9787 (735 of 751), pooled .9232 with recall .3773. 49 curl files are compiled to nothing by the configuration (the index holds an empty document for each) and draw 533 of the 846 edges the index does not attest
  - **Repro:** the re-measure of docs/bench/readings/lang/c.json with the scratch hunk below
- **Root cause:** langoracle.go scopes L1's definitions and L2's callers to files the index holds and lines the preprocessor keeps (`scoped`) but passes every node to fusion.ResolveFileEdges and scores all its edges
- **Fix:** none here (the file is item calls'); the hunk, in the SCIP file-edge block (`activeLinesOf(opts.tools)` is read inside the clang-index branch above it and would be hoisted): after `edges = edgesFromIndexed(edges, sr.Docs, name, &res.notes)` drop the edges whose FromSymbol's node starts on a line `lineActive(active[n.FilePath], n.Line)` rejects, count them in a note ("N file-resolved edges from definitions on lines the build's own preprocessor discards are out of the file-edge scope"), and keep the targets whole
- **Status:** open
- **Impact:** with it C's L3 reads good at the pooled level (precision .9232 against .90, recall .3773 against .25); without it L3 stays unmet on precision although libuv alone reads good (.9456 and .3509)
