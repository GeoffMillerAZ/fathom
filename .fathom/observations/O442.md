### O442 — scip-typescript cannot grade untyped JavaScript's calls: half of fathom's pairs sit where it writes no occurrence, and nearly all the rest have a caller it does not define

- **Symptom:** after the oracle's environment (O441), its call-site vocabulary (LB-F174) and the extractor's fixes (LB-F171..LB-F173), JavaScript L2 reads call_precision .6173 (629 of 1,019) against TypeScript's .9235 on the same oracle; express alone reads .2473 (92 of 372).
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect javascript -scip <index> -unmatched` on axios cdcfd214 and express df0abc93 at fathom 43c90bb4, and the O440 classifier.
  - **Expected:** an L2 oracle judges the pairs fathom draws: it resolves the callee written at a call site and has a definition for the function the call is written in.
  - **Actual:** of 812 fathom-only pairs with the oracle-blind rule off, 431 (53%: axios 183 of 290, express 248 of 522) sit only at sites where scip-typescript writes no occurrence at all (a member of a parameter, of `this` inside a function assigned to a prototype, of a `require`d module it types any). With LB-F175 leaving 422 such pairs out, 390 fathom-only pairs remain, and 375 of them (96%) have a caller the oracle does not define as a module or member symbol: 229 a member assignment (`res.status = function status(code) {...}`, `app.init = function init() {...}`, `exports.x = function`) for which it defines no symbol at all (express 206, axios 23), 146 a named function expression or a function inside a function it defines only as a `local` with no enclosing range (axios 81, express 65). The other 15: an import alias the index names by its declaration 3, a member with no occurrence at one of two sites 9, a class or local called in a caller the oracle attributes elsewhere 3. 77 of the 78 member-assignment callers are among L1's 187 D3-admitted definitions, the oracle's verified misses (the 78th a computed `[Symbol.iterator]` method).
  - **Repro:** calibration/oracles/scip-typescript/README.md, then the lang-oracle run above with `-unmatched`.
- **Root cause:** scip-typescript is a type checker's index: on untyped CommonJS it resolves few receivers and defines a function only where TypeScript's binder declares a module or member symbol, so for express's prototype-and-assignment style it has neither the callee's symbol nor the caller's definition.
- **Fix:** none in the extractor (no pair in the 375 is fathom's error by the oracle's own evidence); the reading states the counted ceiling (LB-Q-javascript-rest). Were the 375 callers judged, call_precision would read at most (629 + 375) / 1,019 = .985.
- **Status:** open by design (oracle validity), trigger: a typed JavaScript subject (checkJs/JSDoc) or a tier-B JavaScript call oracle; or the owner's enclosure decision (O443), which judges the 146 local callers (call_precision .7566).
- **Impact:** JavaScript L2 stays unmet on precision for a reason the reading now counts; TypeScript, on the same oracle, reads excellent.
