### O1328 — module_symbol cannot be combined with a captured package, so an Elixir import draws no module-to-module edge

- **Symptom:** the elixir dialect resolves `alias M`, `import M`, `require M` and `use M` to the defining file (import_resolution .9652 Phoenix, 1 Ecto) but draws a file edge only from a call the import binds (file_edge_recall .3598, .4462), not from the statement.
- **Evidence:**
  - **Tool:** `go run ./cmd/indexbench lang-probe -dialect elixir` with `module_symbol` set
  - **Expected:** K18's moduleImportEdges (an import is an edge to the target's module symbol) alongside namespace-dir's declared-package lookup
  - **Actual:** `module_symbol "file": needs package strategy "dir" or "file" (the file's own name keys it), not "capture"`
  - **Repro:** add `"module_symbol": "file"` to `internal/extractor/dialects/elixir/dialect.json` with `"package": {"strategy": "capture"}`
- **Root cause:** moduleImportEdges resolves a spec by the strategy's path rule alone (`resolveImport`), never by the declared-package lookup specTargets and scopeOf add, and the module symbol is keyed by the file's package.
- **Fix:** TODO, a foundation row (not this item's files): let a module symbol coexist with a captured package, and let moduleImportEdges fall back to `declaredFiles` for namespace-dir; the dotted-module + `case: snake` alternative resolves only the lib/foo/bar.ex convention (import_resolution .62 and .72 on `lib/`).
- **Status:** open
