### O894: the .env-pattern secret rule lives twice in internal/mcp, so a receipt anchor cannot reuse it

- **Symptom:** wave rf1 item evx1 (EVX-1) built the anchor's `withheld` state on ADR-065's classifier, moved to `internal/receipt` (SecretValuedKind, SecretFiles, which `internal/mcp/secret_withhold.go` now reads) plus the scope suppressions. The third secret rule, the `.env`-pattern basename refusal, is written out twice: `notIndexedReasonOpts` in `internal/mcp/readsource.go` and `isEnvPatternFile` in `internal/mcp/search_tool.go`. Neither is a leaf the anchor core can import, and copying it a third time would be a new list.
- **Expected:** one `.env`-pattern rule in a leaf (beside `receipt.SecretFiles`), read by read_source, search and AnchorAt, so a receipt never carries an excerpt digest of a `.env` line.
- **Impact today:** low. Wave 1's anchors cite plan rows, instruction files, intent docs and concern evidence; a SARIF result inside a `.env` file would carry an excerpt digest (a digest only, never the text).
- **Repro:** `grep -n 'strings.HasSuffix(base, ".env")' internal/mcp/*.go` (two hits); `internal/receipt/withheld.go` has no `.env` rule.
- **Status:** open
