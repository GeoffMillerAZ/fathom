### O1291 — 98 hand-spelled `.fathom` paths in 68 files, so a reader and its writer could name different files

- **Symptom:** the Config panel checked `.fathom/bindings.cue` while every writer and server used `.fathom/modules.cue` (FD-2). Nothing tied the two spellings together: each of cmd/ and internal/ joined `.fathom` by hand.
- **Evidence:**
  - **Tool:** `TestProjectDirIsTheOneSpelling` (internal/projectdir), run against the merge base with the package copied in
  - **Expected:** one spelling per project-scope file
  - **Actual:** 98 bare `.fathom` path literals in 68 non-test files at base (the design critic counted about 96 in 65); 0 after FD-1. `git grep '"\.fathom' -- cmd internal` (non-test) fell from 112 lines in 74 files to 18, all display text with whitespace or other names (`.fathomignore`, `.fathom-converge-*`). Four user-scope joins (`<home>/.fathom`) route through the new `fathomhome.At`, which ignores `FATHOM_HOME` as the old literal join did.
  - **Repro:** `go test ./internal/projectdir -run TestProjectDirIsTheOneSpelling` on origin/main with the package added
- **Root cause:** no resolver owned the project-scope names; `internal/fathomhome` covered only the user scope.
- **Fix:** FD-1. `projectdir.File` names each file once; `Path`, `Rel` and `Under` join it. The test refuses a new bare literal outside projectdir and fathomhome. Paths are byte-identical. The FD-1 commit message's "94" was the line-count delta, not the literal count.
- **Status:** fixed
