### O1445 — `thrift --gen json` gives no positions, hides typedef names and can write invalid JSON

- **Symptom:** The Thrift compiler's JSON writes no line for any declaration, writes a typedef's target type where a member names the typedef (`TS2 t` becomes `typeId: i64`), and writes invalid JSON for a file whose const is a map with non-string keys (apache/thrift test/DebugProtoTest.thrift, EnumTest.thrift, lib/rs/test/thrifts/Midlayer.thrift, test/v0.16/DebugProtoTest.thrift).
- **Fix:** calibration/oracles/thrift-json carries a declaration scanner for positions and typedef-name references, refuses a file unless the scanner equals the compiler's definitions and non-typedef references, and reads the invalid-JSON files without their constants section (constants then unattested). The oracle is tier A for the definition and reference sets and the scanner's for where they are written.
- **Status:** closed (harness shipped with the dialect)
- **Impact:** The reading's positions and typedef references rest on a harness scanner held to the compiler, not on the compiler alone.
