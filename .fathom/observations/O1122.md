### O1122 — the stale-section withhold reads only the obligations layer's coverage, so an adr-rules claim compiled from a stale `docs/design` section is still served

- **Symptom:** O1105's fix withholds a compiled rule whose section changed since the compile, but only when the obligations layer's coverage calls that section stale; an `adr-rules` claim compiled from a `docs/design/*.md` section that has since changed is served as current, and no test fails.
- **Evidence:**
  - **Tool:** MCP `obligations` (`renderObligationReceipt`, `internal/mcp/semantic_tools.go`)
  - **Expected:** no rule compiled from a section that changed since its compile is served as current, whichever layer compiled it (I38, O1105).
  - **Actual:** the receipt reads one coverage, `cb.ObligationsLayerCoverage(ctx, service)` (`internal/mcp/semantic_tools.go:342-344`), and withholds a rule only when `stale[r.Subject]` is true in it (`:349`). `Client.ObligationsLayerCoverage` loads the obligations layer alone (`pkg/client/semantic.go:417-418`, `semantic.LayerObligations`). The adr-rules corpus is `ADR.md` plus `docs/design/*.md` (`internal/semantic/layers/adr-rules/layer.cue:13`); the obligations corpus has `ADR.md` and no `docs/design` file (`internal/semantic/layers/obligations/layer.cue:16`). So a `docs/design` subject never appears in the stale set, and an `ADR.md` claim's staleness is judged against the obligations layer's compile of that section, not the adr-rules layer's. The one test, `TestObligationsTool_StaleSectionClaimWithheld` (`internal/mcp/stale_withheld_test.go:25`), uses a fake backend whose single coverage marks an `ADR.md` subject stale (`:21`, `:32`), so it covers neither case.
  - **Repro:** read from the code at exp0 HEAD (unchanged since fd091c4f); found while writing E3's reference answers (`docs/bench/readings/decide/exp-e3.md`, Q3).
- **Root cause:** O1105 tied rules to their subjects but kept the one coverage the receipt already read, the obligations layer's, as if every served rule came from that layer's corpus.
- **Fix (proposed shape):** test first: a served `adr-rules` rule whose subject is a `docs/design` section that the adr-rules layer's coverage marks stale, while the obligations coverage is silent, is withheld and counted in `stale_withheld`; and an `ADR.md` subject stale in adr-rules but fresh in obligations is withheld. Then read coverage per layer present in `obl.Rules` and withhold by (layer, subject); the raw fallback already restricts to subjects.
- **Status:** open
