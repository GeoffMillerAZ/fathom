### O1400 — RO-28 raises the readout hook's row p95 from 13 to 43 ms on a corpus of this repository's commands, all of it read-outline's outline

- **Symptom:** once the rules see past a leading `cd <clone> &&`, the hook runs stages and joins on calls it used to leave as no-rule, so its own time goes up. RO-M1's bar is an added p95 of at most 100 ms.
- **Evidence:**
  - **Tool:** a harness over 20 compound Bash calls run in this repository's clone (`cd <clone> && grep -rn ...`, `ls -la`, `git log`, `git show`, `git diff`, `sed -n`, `cat` of a source file, `go vet`, `go test ... | tail`, plus `;`, `make -v &&` and redirect cases). It fed each real output 5 times to `fathom readout-hook --event post-tool` in a scratch HOME with `[readouts] mode = "observe"`, the daemon URL pointed at a closed port. That gives 100 rows per binary, run twice, at a load average of about 14.
  - **Tool:** origin/main (ab4cab36b): every row no-rule; row `ms` p50 12, p95 13, max 15 to 38; process wall p50 30 ms, p95 109 ms.
  - **Tool:** ro4-quiet (5a23c20cd): 70 of 100 rows matched (grep-group, ls-long, git-log, go-test, read-outline, git-diff, git-grep-group). Row `ms` p50 12, p95 43, max 44 to 52; process wall p50 30 ms, p95 108 to 110 ms. Per rule, the row p95 is 12 to 14 ms for each one except read-outline@1, which is 44 ms.
- **Root cause:** the outline join parses the whole file a `cat` printed, on calls the hook now reaches. Process start and config load dominate the wall time, which did not move (109 against 110 ms at this load).
- **Fix:** none. The added row p95 is 30 ms over base, and 43 ms in all, under RO-M1's 100 ms bar.
- **Status:** closed (measured; within the bar)
