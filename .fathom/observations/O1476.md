### O1476 — A tags query cannot say "no binding encloses this one", so the Nix root-expression rule is a 73 KB generated query

- **Symptom:** the definitions of a Nix file are its root expression's own names (top-level let bindings and the keys at depth one of its attribute set; `config.x.y`, a function binding's inner let and a nested set are not). A tree-sitter query matches downward from a node and has no "not nested in a binding": `(binding ...)` alone would define every key of every nested set.
- **Evidence:** `internal/extractor/dialects/nix/gen_tags.py` enumerates the wrapper chains (function, let, with, up to three deep, 40 chains) and writes one pattern per chain and kind: 854 lines, 72,849 bytes of `tags.scm`. Extraction measured on home-manager: 3,254 files, 4.75 MB, 1,481 ms CPU (3.21 MB/s), peak 319 module pages, max file 18 ms.
- **Root cause:** the engine's predicates are text predicates (`#eq?`, `#match?`); nothing reads ancestry.
- **Fix (not made):** a chain longer than three (`{ a }: with a; let ... in let ... in { }`) loses its definitions. An engine capture such as `@scope.root` (a definition counts only when no other `@definition` encloses it) would replace the generator; it is an engine row, outside this item. Revisit when a measured Nix subject loses definitions to the cap.
- **Status:** open (revisit when a Nix subject's sym_recall falls below .98 for a chain deeper than three)
- **Impact:** none measured: both tuning subjects and three holdouts read sym_recall 1. The query is large to read and is generated, not edited.
