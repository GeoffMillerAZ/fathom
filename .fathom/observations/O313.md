### O313 — `fathom observe` cannot file a reserved observation id

- **Symptom:** a wave worker holding reserved ids (O312-O315) cannot file with `fathom observe`, which mints the next id over the clone (O305 here), the range another worker's reservation may hold
- **Evidence:**
  - **Tool:** `fathom observe`
  - **Expected:** a flag (for example `--id O312`) that files under a reserved id, refusing an id already taken in the legacy log or the directory
  - **Actual:** `fathom observe --help` offers symptom, expected, actual, repro, tool and root only; the worker hand-writes .fathom/observations/O312.md in the generated shape
  - **Repro:** in a clone whose newest observation is O304, `fathom observe --symptom x` writes O305.md
- **Root cause:** observe's id minting is next-free only (EW-1's exclusive create), and agent-waves.md reserves ranges per worker
- **Fix:** none yet
- **Status:** open
- **Impact:** hand-written entries can drift from the generated shape; a worker that runs observe anyway collides with a sibling's reservation at merge
