### O701 — a new interim pass cannot store rows under its own typed_edges key without editing typedgate.go, and every edge-count reader would count them as edges

- **Symptom:** TL-4 weighed typed_edges (routeref.go's interim divergence, lines 14 to 24) for log templates and could not take it within its files: a key is safe from the Go typed pass only when `isNamespacedTypedKey` (internal/fusion/typedgate.go) names it
- **Evidence:**
  - **Tool:** ingest (`EnrichTypedEdges`' reconcile, typedcalls.go: it deletes every stored typed-edge package it did not load unless the key is namespaced)
  - **Expected:** a pass that writes typed_edges under its own key keeps its rows until it replaces them
  - **Actual:** in a repository with Go inputs, the next Go-input change purges an unnamed key's rows (O335 was this class for doc-xref and route-ref); and the readers that count typed edges (internal/mcp/meta.go's totals, cmd/fathom/report_evidence.go's typed share, the console's per-language tally, internal/conserve/tiers.go, which reports a language's tier as SCIP on any edge kind other than empty, file-resolved and unresolved) read every row as a call edge
  - **Repro:** write rows under a new key in a mixed Go and Python repository, change a .go file, ingest
- **Root cause:** typed_edges is shared storage with no per-pass namespace contract: the Go pass's keep-list is a hand-maintained allowlist, and an edge's kind is the only signal readers have
- **Fix:** none in TL-4 (it stored templates as observations, ADR-064). A namespace registry the reconcile and the counting readers both read (a pass declares its key prefix and whether its rows are call edges), before the next interim pass needs one
- **Status:** open
- **Impact:** every future interim pass under the table freeze; Stage B's `telemetry-ref` (ADR-062 decision 3) is the next one and would hit both halves
