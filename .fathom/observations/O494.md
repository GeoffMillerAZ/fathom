### O494 — the queue schema admits worker_model sonnet or haiku only, so the cue entry cannot record the opus the wave intended

- **Symptom:** wave fx's brief set the cue queue entry's worker_model to opus; `schema/langqueue` refuses it.
- **Evidence:**
  - **Tool:** schema/langqueue/schema.cue `#QueueEntry.worker_model: "sonnet" | "haiku"`, vetted by `task cue-vet` and internal/langbench/queueschema_test.go.
  - **Expected:** the queue records the model a wave assigns.
  - **Actual:** the value would fail the gate; the entry says sonnet and its notes name the intent.
  - **Repro:** set `"worker_model": "opus"` in docs/plans/language-breadth.queue.json and run `task cue-vet`.
- **Root cause:** the schema's enum predates opus workers.
- **Fix:** none here (schema/langqueue is outside item cue's files); widening the enum is a one-line schema change with its invalid testdata.
- **Status:** open
- **Impact:** the queue misstates the model for an item that needed the larger one (the brief's own note: the entry said haiku).
