### O514 — Java L2's remaining pairs: a field initializer's calls (the truth's caller is the field) and an anonymous class's creation (scip-java writes a type reference)

- **Symptom:** Java L2 reads call_recall .9529 (1,537 truth pairs not found) and call_precision .9804 (621 fathom-only) after O268 and O458
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect java ... -unmatched`, guava v33.7.1 and retrofit 3.0.0, scip-java 0.12.3, fathom a9349f0e, classified by the caller's kind in the JavaParser dump and the source at the pair
  - **Actual:** 851 of the 1,537 (guava 568, retrofit 283) have a field as the truth's caller (`static final CharMatcher X = createConstant(..)`, `@Rule public final MockWebServer server = new MockWebServer();`): the dialect's fields are not callable, so a field initializer's calls attach to no definition; 533 of the 621 (guava 248, retrofit 285) are an anonymous class's creation `new X<..>() {..}`, which the dialect records as a call to X (O268) and scip-java writes as a reference to the type X, not a constructor
  - **Repro:** `unm2-java-{guava,retrofit}.json` in the run's scratch
- **Root cause:** a dialect convention (fields are no callers; Python's assignment attachment, LB-F65's @calls.from, is the precedent for giving them their initializer's calls) and an oracle convention (an anonymous class has no constructor of its own)
- **Fix:** none here; L2 is excellent with both. A field attachment would move recall; a harness rule reading `new X(..) {` at a type reference as a call would move precision
- **Status:** open
- **Impact:** none on the level (L2 excellent); who-calls of a factory used only in field initializers misses those sites
