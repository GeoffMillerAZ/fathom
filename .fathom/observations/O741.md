### O741 — a file's synthetic `<module>` symbol answered queries that never named it: find_symbol's fallback tiers, keyword ranking and risk ranking

- **Symptom:** K18 (lf2, epoch 56) mints one `<module>` symbol per file of a dialect with `module_symbol` (Python now; JS/TS, Ruby and Lua in lf3). Every one is named `<module>`, contains "module", sorts before every letter on a name tie-break, and is the target of every import of its file, so it surfaced in lookups and rankings that did not ask for it
- **Evidence:**

Before: the deployed binary, fathom v0.10.0 @ 70afc4a9. After: a build of 361e3113. Both over `fathom serve-mcp --store <store> --auto-refresh=false`, the same store and the same calls

  - **Portfolio** (`certify.ClassifyTests`, the console's tests view, measured with a throwaway harness on the flask store): 0 tests take a `<module>` as their top reach and the p20 orphan threshold is 0 with or without them; its critical gaps carried 22 `<module>` rows of 103, all from the risk rows above, so the risk fix removes them and portfolio.go is untouched
- **Root cause:** the module symbol is a real definition with real edges, and these readers ranked or matched every definition by name or stored score. Centrality is right to count its importers (the edges are real); the ranking was wrong to offer it as a risk target
- **Fix:** 361e3113, in the query layer only, excluded on read (no epoch bump, no re-ingest, nothing stored changes): `core.SymbolNode.IsModuleSymbol` (the name, never a kind list) and its key twin `core.IsModuleSymbolKey` for the key-only centrality rows; `caseFoldMatches`, `substringMatches` and `fuzzySuggestions` skip it; `Engine.Query` ranks it only when the concern is `<module>` exactly (keywords never qualify: find_symbol lowercases the name it missed); `RiskWeightedCoverage` reads past its rows. Rows SR-69..SR-73 (docs/plans/surface-reckoning.md); tests pin a JavaScriptModule and a RubyModule fixture beside PythonModule
- **Status:** fixed
- **Impact:** every agent looking a symbol up by an approximate name, every keyword query whose words include "module", and every risk ranking in a Python repository; lf3 would have multiplied all of it across JS/TS, Ruby and Lua
