### O985 — An Astro component's import of a TypeScript module draws no file edge

- **Symptom:** an `.astro` file that imports `../lib/format.ts` and calls `format()` in its frontmatter gets no file-resolved edge to `format.ts`; only its imports of other `.astro` files draw edges.
- **Evidence:** `TestIngest_AstroDialect` (internal/fusion/astro_ingest_test.go) at wave lf7: the page's edges reach `Card.astro` and nothing under `src/lib/`. `resolveLang` (internal/fusion/fileresolve.go) builds each language's universe from that language's files only (`langFiles[lang]`), so the astro pass resolves `../lib/format` against `.astro` files alone.
- **Root cause:** the file resolver is per language; a host (F2) whose ranges are another language's (TypeScript in Astro, Vue and Svelte) imports that language's modules, which are in no universe the host's pass sees.
- **Fix:** none in wave lf7 (fileresolve.go is shared; a cross-language universe for injection hosts, TypeScript and JavaScript files as targets of a host's pass, is a foundation change for Astro, Vue and Svelte alike).
- **Status:** open
- **Impact:** astro.json's L3 grades `.astro` -> `.astro` edges only (a `.ts` target is out of scope, counted); in the product, a page's call into a TypeScript helper reaches no definition. LB-Q-astro-rest names it.
