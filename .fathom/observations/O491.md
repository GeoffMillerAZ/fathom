### O491 — a native language's cross-file references are counted but never graded: L3 for a language is measured only through the file resolver, which has no CUE strategy

- **Symptom:** CUE's reading carries xref counts (precision 1, recall .7510, 359 of 478 cross-file references) and grades L3 not-attempted.
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect cue` with the cue oracle's `cross_references` and `imports`.
  - **Expected:** an L3 for a language whose imports and cross-file references the dialect resolves.
  - **Actual:** a language reading's L3 is import_resolution, file_edge_precision and file_edge_recall; `subjectImports.resolve` and `scoreImportFileEdges` read them through the file resolver only (`importLang`: the harness's `fileResolveLang` or a manifest naming an import strategy from `resolvestrategy.go`'s closed set, with a FileSpecExtractor). The doc engine's cross-file references (`scoreXrefOracle`) set the xref family, which `recompute` keeps only for a tooling reading. The note "import_resolution not measured: the dialect names no import strategy (design §6)" is the reading's.
  - **Repro:** the reading's notes in docs/bench/readings/lang/cue.json.
- **Root cause:** two resolvers exist (the file resolver for languages, the doc-xref pass for tool formats) and the harness grades each kind on one of them; CUE's module-path imports are resolved by the doc-xref strategies (cue-import, cue-package) item cue could add, not by a file-resolver strategy (resolvestrategy.go and langoracle.go are wave ld's files).
- **Fix:** none here; LB-Q-cue-rest's trigger names the strategy, the FileSpecExtractor and the harness entry. The oracle already writes the `imports` truth.
- **Status:** open
- **Impact:** CUE stays at L2 in the reading while its cross-file references already reach ingest.
