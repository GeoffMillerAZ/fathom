### O1013 — blast_radius answers "no symbols for service" when the call graph failed to load

- **Symptom:** in a scratch serve-http over a scratch store of this repository (53,381 symbols), 6 of 9 direct `blast_radius` probes (origin probe-hook, `changed_files` one file) failed in 1-2 ms with `blast_radius: no symbols for service fathom`, while 2 others answered the same arguments after 10.8 and 11.3 s.
- **Evidence:** the EW-75 controlled run (docs/bench/readings/efficiency-wave/hook-path-deadlines.md), the scratch daemon's own call log; its stderr read `tenancy: normal → shed` at 504 MiB against a 384 MiB shed mark before the failures.
- **Root cause:** `loadNavGraphs` (internal/mcp/resolved_nav.go) returns nil on any `loadNavGraphsErr` error, and `blastRadiusChangeAnswer` (internal/mcp/extra_tools.go) reads nil as "no symbols". A failed load reads as an empty index (I38's shape: a failure is never "none").
- **Fix:** answer from `loadNavGraphsErr` and name the load error (and the shed refusal when that is the cause); the same nil-means-empty read is in `safeDeleteCheckAnswer`.
- **Status:** open
- **Impact:** an agent or the pre-edit hook reads "this service has no symbols" for an indexed service under memory pressure.
