### O375 — CMake and Meson cross-file link edges are not import-bound: 52 of 54 CMake and 113 of 113 Meson tool-oracle edges run child to ancestor or between sibling directories, which no import-bound reference resolves

- **Symptom:** CMake xref_recall .037 (2 of 54) and Meson xref_recall 0 (0 of 113); xref_precision 1 where an edge is drawn at all
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect cmake|meson -tool-oracle <cmake File API | meson introspect>` (LB-F56) on fmtlib/fmt 12.2.0, nlohmann/json v3.12.0, bulletphysics/bullet3 3.25 (cmake) and harfbuzz 14.5.1, libxml2 v2.15.4 (meson), fathom 3bf25f55
  - **Expected:** `target_link_libraries(test-main PUBLIC fmt)` in test/CMakeLists.txt resolves to the file defining fmt (a link to a target is a link to a name that is global to the build)
  - **Actual:** shape of the oracle's cross-file dependencies: nlohmann/json 5 child-to-ancestor, fmt 2 parent-to-child and 1 child-to-ancestor, bullet3 46 sibling; harfbuzz 206 sibling and 5 parent-to-child (all through alias_target()), libxml2 16 child-to-ancestor. Only a parent-to-child edge is drawn (fmt's 2)
  - **Repro:** `calibration/oracles/cmake-file-api/README.md` and `calibration/oracles/meson-introspect/README.md`; the shapes are the dirname relation between `path` and `to_path` of each `cross_references` entry
- **Root cause:** add_subdirectory(dir) and subdir('dir') are imports, so a name resolves from the importing file to the imported one; CMake targets and Meson variables are one namespace across every file of a build, so the reference a child or a sibling writes has no import to bind it (`internal/fusion/resolvestrategy.go`: relative-path binds the imported file's top-level names only)
- **Fix:** none here (a new strategy is an Opus row, design §6): a build-namespace strategy resolving a name to the file that defines it anywhere in the repository, or among a file's ancestors and siblings. LB-F128
- **Status:** open
- **Impact:** cmake and meson stay below L3 and cmakeextract.go's retirement waits on it (O377 too)
