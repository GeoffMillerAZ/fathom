### O1279 — calibration/corpus.d/html.yaml does not parse, so every `task calibrate-clone` fails after cloning

- **Symptom:** `task calibrate-clone -- lua` clones its subjects, then exits 1 with `bad file 'calibration/corpus.d/html.yaml': yaml: line 40, column 15: mapping values are not allowed in this context`. Any item's clone step ends red while every shard is loaded.
- **Evidence:**
  - **Tool:** task calibrate-clone (origin/main 10a63138)
  - **Expected:** the named shard's subjects clone and the task exits 0
  - **Actual:** the clones are made, the loader then rejects the html shard and the task fails
  - **Repro:** `task calibrate-clone -- lua`; `sed -n 38,41p calibration/corpus.d/html.yaml`
- **Root cause:** an idiom list item (`script and stylesheet hrefs to sibling vendor/ trees (out of scope` / `for L3: design 1.8 counts ...`) is a plain scalar holding `: `, which YAML reads as a mapping value.
- **Fix:** TODO, not this item's file (the html item owns it): quote the item or fold it with `>`.
- **Status:** open
