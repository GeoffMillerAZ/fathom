### O978 — A component script's `let` is no definition in TypeScript and a constant in JavaScript

- **Symptom:** Svelte 5's `let count = $state(0)` and `let { data } = $props()` extract nothing in a `<script lang="ts">` and a `JSConst` in a plain `<script>`; a Svelte 4 `export let items` is a `JSConst`.
- **Evidence:** svelte.json (LB-F540): sveltejs/kit's JavaScript scripts give 266 `JSConst` definitions the compiler declares as `let`s (sym_precision .8395, L1 unmet), shadcn-svelte's TypeScript scripts 1,229 of 1,229 and 2,573 `let`s outside the kind intersection (`tool:variable`); `testdata/legacy.svelte`'s golden (`items` a `JSConst` at line 4).
- **Root cause:** the TypeScript dialect captures `const` declarators alone; the JavaScript dialect captures every lexical declaration as `JSConst` (canonical constant). Neither has a variable kind, so the W4 rule (design §1.8, K19) keeps `let` and `var` outside the intersection, and a JavaScript `let` is a definition no oracle kind matches.
- **Fix:** none in this wave: the kinds are the script dialects' (LB-Q-svelte-rest's trigger).
- **Status:** open
- **Impact:** Svelte's L1 is unmet; a Svelte 5 TypeScript component's reactive state and props are invisible to symbol queries.
