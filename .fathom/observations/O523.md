### O523 — a C++ member call on a variable receiver reaches the extractor and the resolver as its bare name, and binds any header class or function of that name

- **Symptom:** 18 of the 46 false C++ file edges are `x.name()` calls bound to include/fmt/chrono.h's class `day`, base.h's `count` and `value`, os.h's `c_str`, format.h's `locale` (and, for a function the include only declares, the file that defines it: test/util.cc for `get_locale`, format-inl.h for `report_error`; those two spellings are bare calls too).
- **Evidence:**
  - **Tool:** extracting test/perf-sanity.cc and test/util.h with the cpp dialect: `main` calls = ["count" "fmt.format_to" ...] for `duration.count()`, `operator<<` calls = ["value"] for `s.value()`; the cppextract.go incumbent, which ingest uses, keeps the same bare name. `-unmatched` fathom_only_by names each edge `call <text>`.
  - **Expected:** a call through a variable is a member call and binds no free name of a header (a `this->name()` or an unqualified call inside a class binds the class's own member first).
  - **Actual:** fileresolve.go's callEdges binds the bare name through `wild[bareBase]` (the include closure's top-level names) and `matchPrototype`.
  - **Repro:** `s.value()` in a function beside an included header that defines a `value` class template.
- **Root cause:** the receiver is dropped at extraction, so the resolver cannot tell `d.day()` from `day(1)`.
- **Fix:** open, two files outside this item's: internal/extractor/cppextract.go (and the dialect's tags.scm) should write a receiver-qualified call text (`d.day`, which the harness compares on its last segment) and fileresolve.go's callEdges should not bind a dotted call whose head is no import or namespace; an ExtractorEpoch bump follows for every C and C++ file.
