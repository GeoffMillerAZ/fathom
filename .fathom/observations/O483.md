### O483 — a computed-key method's bare name reads `iterator]` in diagnostics (`Widget.[Symbol.iterator]`), and no score depends on it

- **Symptom:** in `-unmatched` files and call-pair lists webpack's `[Symbol.iterator]()` and `get [Symbol.toStringTag]()` methods appear as `iterator]` and `toStringTag]`, a name no oracle has.
- **Evidence:** langbench.BareName cuts a qualified name at its last `.`, which is inside the brackets. A scratch fix (a computed key is one segment) changed no metric on axios, express or webpack (the same counts in both runs): the oracle defines no symbol for a computed-key method (L1 dialect-only either way), and truth attributes the calls inside to the enclosing class, so the pair cannot match under any name. Reverted.
- **Root cause:** harness vocabulary, not the dialect (its names are `Widget.[Symbol.iterator]`, golden-pinned).
- **Fix:** none (a change with no effect on a score is not made; it would move every dialect's name in diagnostics).
- **Status:** open (cosmetic)
- **Impact:** none on a reading; the diagnostics read oddly for webpack's 25 or so such methods.
