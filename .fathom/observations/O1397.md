### O1397 — A tags dialect dropped every call inside a top-level non-callable definition: SCSS lost the references in variable values and selector interpolations

- **Symptom:** with the W5 reference queries first written, bootstrap's call_recall read .34 (173 of 514 pairs) and primer's .37 (52 of 141), and part of it was references with no owner: `$theme-colors: map-merge(...)`, `.alert-#{$state}` and `$z: if($cond, $g, 2)` lost their references.
- **Evidence:** `attachTSCalls` gives a call only to a callable definition, and `mintTSModule` gives the module only the calls no definition's node owns (`tsOwnedSpans`: every definition, callable or not), so a call inside a variable or selector definition at the top level had no owner and was dropped; inside a mixin the mixin kept it. `internal/extractor/dialects/scss/testdata/refs.scss` and its golden pin the owner.
- **Root cause:** `tsOwnedSpans` treats every definition as an owner while only callables can hold a call.
- **Fix:** manifest `calls.owner "scope"` (schema, `checkCalls`, scss manifest): only callable nodes own a call, so it is the smallest enclosing callable's, else the module symbol's. Opt-in: other dialects are unchanged (`TestCallsOwnerOnlyWhereTheManifestNamesIt`); the Astro style golden gains the SCSS reference it embeds (`pad`).
- **Status:** fixed for scss; other tags dialects with a non-callable definition that encloses top-level calls (not checked) may drop the same calls
- **Impact:** SCSS (and the style blocks Astro and Vue embed) record the references inside top-level variables, selectors and keyframes.
