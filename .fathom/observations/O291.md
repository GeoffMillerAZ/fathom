### O291 — the header `fathom observe` wrote named fathom-only paths in every adopting repo

- **Symptom:** the header `fathom observe` wrote into a new repo's observations file cited `docs/plans/pack-taxonomy-adoption.md` and `docs/dogfood-observations.md`, which exist only in fathom's own checkout
- **Evidence:**
  - **Tool:** `fathom observe` in an empty temp repo, then reading the file it created
  - **Expected:** a header an adopter can read with no reference to another repo's files (ADR-011, org-agnostic)
  - **Actual:** two dead paths in the header, and a claim that ids are advisory under concurrency that the flock mint (IT-10) had already made false
  - **Repro:** `fathom observe --root "$(mktemp -d)" --symptom x`, read the header (the never-filed O179 candidate)
- **Root cause:** the header was written for this repo's own log and shipped as the template
- **Fix:** the header is now `.fathom/observations/README.md`, names no repo-specific path, and states the exclusive-create id rule
- **Status:** resolved (EW-32)
- **Impact:** an adopting repo's first observation no longer carries another repo's paths
