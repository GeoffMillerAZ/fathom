### O1249 — the request plan cannot narrow a CLI verb's ask to its site: certify suggest, assess and preflight ask with no site on the context

- **Symptom:** JF-21's request plan (internal/decide/requestplan.go) keeps only the request fields the asking site declares, reading the site from the ask's context (`decide.ScopeFrom`). `POST /route` (`decide.WithSite`) and the client's re-rank and pre-filter (`decide.AtSite`) set it; `fathom certify suggest`, `fathom assess` and `plans context --preflight --score` ask `ports.Decider` with a bare context, so the plan sees site `""` and applies the union of every site's declaration (still never images).
- **Evidence:** `grep -rn "decide.AtSite\|decide.WithSite"` over cmd/, internal/ and pkg/ (non-test) names only route.go and pkg/client/semantic.go. scope.go's header says it: "serve-mcp and the CLI verbs set nothing: the process is the session, and each verb asks one site." `siteDeclarationOf("")` in requestplan.go is the union fallback.
- **Root cause:** KS-14 needed the site only for disclosure keys, and a CLI verb's process is its session, so the CLI sites never set it. The brief's premise was also partly stale: `fathom assess` already redacts its state with llmsec's extended catalog (cmd/fathom/assess.go `assessRedactor`) before the port; the plan's second pass finds nothing there and counts 0.
- **Fix:** wrap each CLI site's decider with `decide.AtSite(ports.Decider, decide.Site<Name>)` (certify_suggest.go, assess.go, internal/console/preflightscore.go). Those files belonged to the other dmp2 item, so this wave left them alone. Exclusion, redaction, the security refusal and plan-only already apply to every ask whatever its site.
- **Status:** open
- **Impact:** an unscoped ask can carry any field some site declares (criteria, options, rubric, levels) rather than only its own; no current CLI site sends a field outside its own declaration, so nothing leaves today that would not under a scoped ask.
