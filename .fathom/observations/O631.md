### O631 — the doc engine cannot select a step that has no `id`, so a run step and its id step are two entities

- **Symptom:** a step with both `id:` and `run:` is two entities on one line (GHAStep named by the id, GHARunStep named by position)
- **Evidence:** `where` has `has_key` and no negation (`internal/extractor/docengine.go` DocWhere), and a `fmt:` template cannot be one alternative of a `|` list; the brief's "id-less steps (`fmt:` with `$index`)" is not expressible as written
- **Root cause:** an engine gap owned by item prom (docengine.go, doc.cue)
- **Fix:** wave c2, item engine (K20, LB-F337, LB-F339): `where.not_has_key`, the doc engine's key-absent selector (`lacksKeys`, schema/dialect #DocWhere); the github-actions dialect selects GHARunStep with `has_key: ["run"], not_has_key: ["id"]`, so an id'd run step is the GHAStep its id names alone, and `internal/fusion/gharun.go` starts that step's first-command edge at the GHAStep (TestGitHubActionsRunStepIsIdLess, TestIngest_GitHubActionsRunSteps); the oracle writes a positional step only for a run step without an id, and the reading holds every metric at 1 (71 id'd run steps fewer over the four subjects' owned files)
- **Status:** fixed (wave c2, item engine)
- **Impact:** symbol listings showed an id'd run step twice and its edges attached to the positional one; now one entity, edges on it
