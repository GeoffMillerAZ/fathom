### O631 — the doc engine cannot select a step that has no `id`, so a run step and its id step are two entities

- **Symptom:** a step with both `id:` and `run:` is two entities on one line (GHAStep named by the id, GHARunStep named by position)
- **Evidence:** `where` has `has_key` and no negation (`internal/extractor/docengine.go` DocWhere), and a `fmt:` template cannot be one alternative of a `|` list; the brief's "id-less steps (`fmt:` with `$index`)" is not expressible as written
- **Root cause:** an engine gap owned by item prom (docengine.go, doc.cue)
- **Fix:** none here; the positional entity is selected by `has_key: run` (the steps that start commands) and named `fmt:{$path}#{$index}`; a `not_has_key` in DocWhere would let it be id-less only
- **Status:** open (disclosed in the github-actions PROVENANCE.md; a ceiling, not a defect in a reading)
- **Impact:** symbol listings show an id'd run step twice; edges attach to the positional one
