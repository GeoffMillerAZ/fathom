### O1418 — Solidity call names are read by syntax, so calls through a function-pointer variable and builtin members are the residual

- **Symptom:** call_precision .9948 and call_recall .996 on three subjects (.9844 recall on the holdout). The pairs that differ are not queries a pattern can fix.
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -unmatched` on OpenZeppelin v5.6.1, forge-std v1.17.0, solmate a9e3ea26, solady v0.1.26
  - **Expected:** a pair per call solc's `referencedDeclaration` resolves to a function, modifier, event or error
  - **Actual:** dialect-only: a call through a local or parameter of function type (`hasher(...)`, `op(...)`, `fnHash(...)`), a builtin member the query does not list (`.transfer` on a payable address, `.encode` on a non-`abi` object); oracle-only: a member call on a cast expression (`AccessManager(x).execute(...)`)
  - **Repro:** `jq '.calls' <unmatched.json>`
- **Root cause:** whether `x.transfer(v)` is the builtin or a user function, and whether `f(a)` calls a function or a variable, is a type question; the tags engine reads names. A capitalised callee is read as a type conversion or struct constructor, never a call (Solidity's naming convention), so a function named with a capital is missed.
- **Fix:** none planned, a ceiling of the syntax level (L2); a typed edge would need solc as a producer (not pure Go, ADR-066).
- **Status:** wontfix
