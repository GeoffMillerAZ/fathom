### O1308 — Markdown joins the doc-xref pass: every .md is read when any .md changes

- **Symptom:** isDocCandidate was `docs/plans/*.md` only; it is now every .md and .mdx, so the pass re-reads and re-extracts all of a service's Markdown whenever one changes (the pass waits for a candidate to change, then reads every candidate).
- **Evidence:** rust-lang/book: 479 files, 4.1 MB extracted at 27 MB/s CPU, slowest file 60 ms (markdown.json tenancy); the cost scales with the Markdown a repository holds, not with the change. Cargo's `crates/empty/README.md` was read as the one doc file in a directory reference until byDir stopped indexing Markdown (fusion test TestIngest_CargoWorkspace caught it).
- **Root cause:** the pass is whole-corpus by design (a reference can land in any candidate).
- **Fix:** if a Markdown-heavy repository makes the pass visible in the ingest's pass times, key the Markdown half to changed Markdown plus its link targets. Epoch 66 (extractor_epoch.go) is this wave's markdown entry and needs folding with the other lang2 item's bump.
- **Status:** open
- **Impact:** none measured on fathom's own repository yet; heading names also changed (inline markup now kept, ctags' naming; a heading of only a code span was dropped before).
