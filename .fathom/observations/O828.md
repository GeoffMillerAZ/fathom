### O828 — TQ-26's "a report path the caller names" is a file-name convention in `[tests] results_dir`, not a configured path

- **Symptom:** the three risk-rank callers have no input to name a report (test_impact's input schema is frozen, the console has none), so `certify.CoverageSources` reads the files the repository names by placing them in `[tests] results_dir`: `coverage.meta.json` (the attested Go pair) and a report of a known name (`lcov.info`, `coverage-final.json`, `coverage.json`, `coverage.xml`, `cobertura.xml`, `cobertura-coverage.xml`, `jacoco.xml`, `jacocoTestReport.xml`, `llvm-cov.json`).
- **Evidence:**
  - **Tool:** `test_impact rank:"risk"`, the console's /tests and work hotspots, `certify.ClassifyTests`.
  - **Actual:** a report under another name, or outside results_dir, is not read; the answer then says no coverage source is named. The Go pair's profile must be repo-relative (an absolute `profile` is refused by name), where `fathom conserve` accepts an absolute one.
  - **Repro:** put `coverage/lcov.info` in a repo whose `.fathom/config.toml` sets `results_dir = "coverage"`, then `test_impact {"service": S, "rank": "risk"}`; rename the file and repeat.
- **Root cause:** no `[tests]` key names a coverage report and its format; adding one touches internal/config, both config CUE schemas and the scope table, outside wave h5's files.
- **Fix:** none here. If a repository needs another name, a `[tests] coverage = ["<format>=<path>"]` key (repo-path scoped, like results_dir) is the next step.
- **Status:** open
- **Impact:** coverage reaches the rank only for repositories that write a conventionally named report into results_dir.
