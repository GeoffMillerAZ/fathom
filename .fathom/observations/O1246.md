### O1246 — CLI verbs ask the decision port with no site on the context, so the per-site cap and the miss kill key them as the process

- **Symptom:** `fathom certify suggest`, `fathom assess` and `fathom plans context --preflight --score` ask through `ports.Decider` without `decide.WithSite`. The port's cap (KS-10) counts them under the site-less scope, and the miss kill (KS-12) cannot judge them: the site is unknown at the ask.
- **Evidence:** wave dmp1, rails worker, 2026-10-18. `grep -rn "decide.WithSite\|decide.AtSite"` finds only serve-http's `/route` and the client's re-rank and pre-filter. Their rows still name the site (`RecordError(site, ...)`), so their misses count toward the site's window. A process that asks from such a site is just never refused by it.
- **Root cause:** KS-14 made the scope a context value and set it where the daemon asks. The CLI verbs keep "the process is the session, and each verb asks one site", which needs no site for a `killed` line but does need one for a per-site verdict.
- **Fix:** each verb wraps its port with `decide.AtSite(ports.Decider, <site>)`. The certify code belongs to the disclosure item; assess and preflight are one line each.
- **Status:** resolved (wave dmp2, rails2): `certify suggest`, `assess` and `plans context --preflight --score` ask through `decide.AtSite(ports.Decider, <site>)` with `certify_suggest`, `assess` and `preflight` (`decide.AllSites`); `TestCLIVerbsAskFromTheirOwnSiteSoTheMissKillRefusesThem` shows each site's miss kill refusing its verb before any dial.
- **Impact:** a one-shot CLI process keeps asking a site whose log shows more than 10% misses. Its rows still feed the daemon's verdict at the next Open, so the daemon's long-lived sites are covered.
