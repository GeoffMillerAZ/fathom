### O763 — Scala's queued oracles do not exist as written: universal-ctags has no Scala parser, and the grammar's upstream tags.scm grades no member call

- **Symptom:** the queue entry and LB-Q-scala named "ctags (unverified: check --list-languages)" and scip-java for Scala; the wave brief named the grammar's upstream `@reference.call` (tier C) for L2
- **Evidence:** universal-ctags 6.2.1 `--list-languages` lists no Scala; scip-java reads Scala only through SemanticDB, which needs each subject compiled by its own sbt build (not installed); upstream `queries/tags.scm` at v0.26.2 has one call pattern, `(call_expression (identifier) @name)`, so run through `calibration/oracles/ts-tags` it reads the dialect at call_recall .9887 and call_precision .3896 on cats and http4s: a member call (`xs.map(f)`) is in none of its pairs
- **Root cause:** the queue was written before the oracles were checked; upstream tags queries are written for symbol navigation, not call graphs
- **Fix:** `calibration/oracles/scalameta` (scalameta 4.17.4, tier B) dumps definitions and call pairs (`Term.Apply` by its last name, innermost def); the queue entry's and LB-Q-scala's oracle text now name scalameta (tier B) and scip-java through SemanticDB for L3/L4; the ts-tags run is kept as a disclosed cross-check in the reading
- **Status:** closed
- **Impact:** without it, Scala L1 would have had no tier-B oracle and L2 would have read unmet on a correct dialect
