### O1329 — an Elixir alias binds its full name, and a definition's own head and a type expression are listed as calls

- **Symptom:** `alias Foo.Bar` then `Bar.fun()` binds nothing (only `Foo.Bar.fun()`, `as: B` and a group member `alias Foo.{Bar}` bind a qualified call), and `def f(x)` lists `f` among its own calls, `@spec g(t) :: map()` lists `g` for the module.
- **Evidence:**
  - **Tool:** `go run ./cmd/indexbench lang-probe -dialect elixir internal/extractor/dialects/elixir/testdata/calls.ex`
  - **Expected:** the alias's last segment is the local name; a head or a type is no call
  - **Actual:** the import spec's local is the module text; the head call `f(x)` and the type call match the call pattern
  - **Repro:** `alias App.Repo` then `Repo.all(q)` in `internal/fusion/elixirimport_test.go`'s shape
- **Root cause:** tree-sitter-elixir's `alias` is one token (`Foo.Bar` has no child for `Bar`) and a query cannot cut a capture; a pattern cannot say "not the first argument of a definer".
- **Fix:** TODO, engine rows: an `@import.alias` default of the module's last segment under a manifest switch, and an ancestor exclusion for call patterns. Measured cost: call_precision .9656 and .9673 against the grammar's own tags.scm (which lists the same head calls).
- **Status:** open
