### O762 — `.scala` and `.sc` dispatch to the scala tags dialect needs the wave's one ExtractorEpoch bump: every Scala file's extraction changes

- **Symptom:** a `.scala` or `.sc` file fingerprinted by the CGO scalaextract.go holds only ScalaClass, ScalaObject, ScalaTrait and ScalaDef symbols, unsigned, with whole-text callees attributed to the outermost def
- **Evidence:** `docs/bench/readings/lang/parity/scala.json` (MERGE): sym_recall .5859 to 1, signature_coverage 0 to 1, call_recall .808 to .9999; TestScalaDialectIsWhatFusionDispatches and TestIngest_ScalaDialect read the dialect's output. The SourceKind diff from parity: ScalaConstructor, ScalaType, ScalaVal and ScalaVar gained on the subjects (ScalaEnum, ScalaEnumCase and ScalaGiven also emitted, on Scala 3 sources), none lost; names change for a nested container (`Outer.Inner`, was `Inner`), a method of one (`Outer.Inner.m`, was `Inner.m`), a def in an anonymous class or a local def (bare, was `Owner.m` or absent), a backticked name (backticks dropped) and a secondary constructor (ScalaConstructor `C.this`, was ScalaDef); every def gains a Signature and an EndLine of its own; calls are named by the callee's last identifier and given to the innermost def
- **Root cause:** a switch of extractor changes extraction without a content change, so the stat gate would honor a stale fingerprint
- **Fix:** the integrator's bump of `internal/fusion/extractor_epoch.go` (not edited by this item)
- **Status:** open (reported to the integrator)
- **Impact:** until the bump, an already-ingested repository keeps its CGO-era Scala symbols
