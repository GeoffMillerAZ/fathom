### O410 — the centrality pass is the one ingest pass still above its subjects' sum on the LB-M5 set (1.42x CPU)

- **Symptom:** after EW-49 and EW-50 every pass of a whole-tree ingest of the LB-M5 polyglot set costs about what its 17 subjects cost ingested one at a time, except `centrality`: 1.46 s CPU whole against 1.03 s summed, 1.42x, on the quiet EW-49 runs, and 2.35 s against 1.55 s, 1.52x, on the loaded after runs (docs/bench/readings/efficiency-wave/ingest-linear.md, pass_times).
- **Evidence:**
  - **Tool:** `fathom ingest --json` `pass_times` (EW-48), whole tree against the sum of the subjects; an in-process CPU profile of the whole-tree ingest (`cmdIngest` under `go test -cpuprofile`, scratch only).
  - **Expected:** a pass linear in the service's symbols and edges.
  - **Actual:** in the EW-49 profile, of the pass's 1.11 s of samples, `callgraph.BuildBoth` is 0.45 s (a call name resolves against every same-named symbol in the service, so a whole tree resolves more candidates per call and keeps more edges: a different graph, not only a bigger one), the store read and write 0.46 s, and `TransitiveCallerCounts` 0.10 s, whose closure allocates and scans one dense bitset of components/64 words per SCC component (internal/analysis/callgraph/condense.go `closure`): O(components^2/64), 74,907 components here.
  - **Repro:** the reading's method; `go tool pprof -top -cum -focus recordCentrality` on the whole-tree profile.
- **Root cause:** the closure's dense bitset per component is quadratic in the component count by construction; at 75k components it is 0.2% of the ingest, so the 1.42x is mostly the name resolution's larger candidate sets, which change the graph and are not a performance defect.
- **Fix:** none in wave ic (under the 1.10x whole-versus-summed bar: the ingest reads 0.97x). The shape when it is needed: sparse sorted ancestor sets that switch to a dense bitset above components/32 members, and no set for a component with no predecessors; exact counts unchanged.
- **Status:** open (revisit when the centrality pass exceeds 10% of a whole-repository ingest's CPU in a reading, or a service passes about 300k symbols, where the closure's term is about 16 times today's)
- **Impact:** small today (3% of the whole-tree ingest's CPU); the only pass whose cost still grows faster than its input on this set.
