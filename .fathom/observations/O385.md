### O385 — lang-oracle cannot measure a content-claimed doc dialect: ContentDialect knows only CloudFormation and OpenAPI, so Kyverno and Gatekeeper files are owned by no rule

- **Symptom:** `indexbench lang-oracle -dialect kyverno` would measure no file: the dialect's manifest names no extension, basename or glob (a `.yaml` is Kubernetes's, and a second `.yaml` claimant makes every YAML ambiguous), and `ownedSourceRefs`' content path asks `Pipeline.ContentDialect`, which answers only `cloudformation` and `openapi`
- **Evidence:**
  - **Tool:** `indexbench lang-oracle` / `ownedSourceRefs` (cmd/indexbench/langoracle.go), `ContentDialect` (internal/fusion/classify.go)
  - **Expected:** a dialect ingest claims by content is measured on the files ingest gives it
  - **Actual:** "subject has no kyverno files fathom would extract"; the px wave's Envoy and Kong rows record the same gap for files their names miss (O348)
  - **Repro:** a manifest with an empty `match` and no `ToolKind` case in ContentDialect
- **Root cause:** ContentDialect is classify.go's switch over two ToolKinds; this wave's items may not edit classify.go (wave iac claims CRs there)
- **Fix:** `indexbench lang-policies` (LB-F137) owns a content-claimed policy dialect's files by the predicate ingest claims it with, `fusion.PolicyDialect`, naming each claimed path as a literal glob and saying so in the reading; ContentDialect asking every content-claim predicate (gateway, policy, the iac CRs) stays open for whoever owns classify.go
- **Status:** worked around (lang-policies); open for lang-oracle
- **Impact:** `lang-oracle -dialect kyverno|gatekeeper` measures nothing; only `lang-policies` does
