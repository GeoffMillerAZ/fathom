### O982 — A component host's injected ranges churn the six-module parser pool

- **Symptom:** a fresh ingest of sveltejs/kit 2.70.3 instantiates 37 grammar modules at HEAD against 6 at the base (element-plus 2.14.7: 24 against 8), and its extract pass takes 5.0 s against 2.7 s, while the same 943 `.svelte` files alone extract in 0.8 s with 4 instantiations.
- **Evidence:** an in-process probe (`fusion.New`, memory store, `tsengine.Instantiations()` and `PoolPeak()`, both peaking at 6) at base 2b8829a9 and HEAD b1e72a52; `fathom ingest` warm medians of three, kit 3.63 s to 5.83 s, element-plus 5.05 s to 9.74 s.
- **Root cause:** a host leases its injected dialects' parsers (TypeScript, JavaScript, CSS, SCSS) under its own extractor's owner key (`leaseFor`), apart from the `javascript` extractor's TypeScript and JavaScript parsers, so a repository mixing components with `.ts` and `.js` files keeps more live modules than the pool's cap of six and re-instantiates them (LB-F15's LRU).
- **Fix:** at wave lf7's integration (LB-F526, LB-F550): `fusion.New` links its extractors (`extractor.LinkHostedParsers`), and a host's hosted TypeScript, JavaScript and CSS ranges lease the pooled parser of the extractor that reads those files, when it compiles the same queries; output byte-identical. Cold, kit 5.79 s to 4.02 s (c39875f3 4.00 s), element-plus 7.47 s to 6.99 s (4.88 s; the rest the 1,008 `.vue` files' own extraction, K27), withastro/astro examples/ 4.82 s to 1.65 s (1.26 s); a mixed fixture instantiates 5 modules where it instantiated 146 (docs/bench/readings/lang/astro-cost.md).
- **Status:** fixed
- **Impact:** about 1.5 s per 1,000 component files on a mixed repository; a shared owner for hosted ranges, or a host leasing the group extractor's parsers, would remove the churn (the module pool's close-on-Close contract, RT-107, is the constraint).
