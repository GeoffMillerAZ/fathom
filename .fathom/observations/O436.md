### O436 — the Envoy content sniff misses a single-quoted `'@type'`, so a whole xDS resource file draws no route pair

- **Symptom:** supabase/supabase's `docker/volumes/api/envoy/cds.yaml` yields no route_ref edge and no unresolved reference, while the oracle joins 10 of its cluster addresses (`auth`, `rest`, `storage`, `functions`, `meta`) to the compose services declaring them
- **Evidence:**
  - **Tool:** `indexbench lang-routes -dialect envoy` on supabase/supabase v1.26.08 docker/ (`-only` the two Envoy files), envoy-oracle 1.39.1 (tier A): route_truth 10, route_fathom 0, route_truth_found 0
  - **Expected:** a file whose manifest basename (`cds.yaml`) claims it and whose body is an xDS resource list is dispatched as Envoy, and its `socket_address.address` values are route-host references
  - **Actual:** `fusion.gatewayDispatch` asks the dialect's `content_sniff` (`internal/extractor/dialects/envoy/doc.json`), `"?@type"?[ \t]*:[ \t]*"?type\.googleapis\.com/envoy\.`, which accepts a bare or double-quoted key and not the single-quoted `- '@type':` YAML writes; `routeFile` returns false for the file (`RouteFileForBench` ok=false, 0 nodes)
  - **Repro:** a probe of `RouteFileForBench` over docker/volumes/api/envoy/cds.yaml reads ok=false nodes=0; the same file with `"@type"` reads its clusters
- **Root cause:** the sniff's quote class omits `'`; a basename-claimed file with a failed sniff falls through to the plain-YAML path. The same gate leaves ext_authz/config/*/v3.yaml (names no manifest claims, O348) unread: 6 more oracle pairs
- **Fix:** none here (the dialect is wave ic's): add `'` to the sniff's quote class and a golden with a single-quoted `@type`
- **Status:** open
- **Impact:** an Envoy L3 route reading cannot reach supabase's xDS files (10 pairs); xref_recall .8298 would read .9362 with them (88 of 94)
