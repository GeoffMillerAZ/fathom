### O1283 — A GraphQL definition node includes its description: a described definition's Signature starts at the description

- **Symptom:** `"""A book on a shelf.""" type Book implements Node & Titled @auth` is the Signature of a described type, and a field whose arguments span lines reads `author(`
- **Evidence:** bkegley/tree-sitter-graphql makes `description` the first child of every definition, so the engine's Signature (definition start to its `@body`, design 3.3) begins there; a callable with no `@body` gets its first line; a query cannot capture a node minus its first child. octokit/graphql-schema describes every type, field and argument. `TestGraphQLDialectSignatureContract` pins the undescribed shapes; `schema.graphql.golden.json` pins the described one
- **Root cause:** engine contract (a definition is one node), not the query. The incumbent's Signature (`object`, `String!`) was never a source span either
- **Fix:** none taken; a Signature template or a `@signature.start` capture would fix it for every dialect whose grammar nests documentation (Swift, Kotlin, GraphQL)
- **Status:** open (disclosed in the dialect's PROVENANCE.md)
- **Impact:** an agent reading a described GraphQL symbol's Signature sees documentation before the keyword; names, lines, ranges and references are unaffected
