### O396 — a file an include brings in has no resolvable relative path: Terragrunt reads `config_path`, `terraform.source` and `find_in_parent_folders` from the including unit

- **Symptom:** a Terragrunt dependency or local module source written in `_envcommon/app.hcl` resolves to a different directory for every unit that includes it, so no edge from that file is right for all of them
- **Evidence:**
  - **Tool:** terragrunt 1.1.6 `render --json --with-metadata`: an item's `found_in_file` is the included file, its `config_path` and `source` are relative to the unit
  - **Expected:** an edge per including unit
  - **Actual:** one file's extraction cannot see its includers
  - **Repro:** `TestTerragruntUnresolvedByReason`: `a/common.hcl`'s dependency and source are `included-file` unresolved
- **Root cause:** the doc-xref pass resolves a file's references in the file's own directory; the includer is another file's fact
- **Fix:** the dialect resolves paths only in a file named terragrunt.hcl and counts the rest as `included-file`; an includer-aware resolution would be a doc-xref change
- **Status:** open
- **Impact:** the edges of an included file's dependency, source and inputs-to-variable are absent; the unit's own edges (include, dependency, source, inputs) are all drawn
