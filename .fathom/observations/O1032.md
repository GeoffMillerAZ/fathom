### O1032 — kubernetes.json's subpath subjects were measured on cone-mode clones, the root's YAML files included

- **Symptom:** re-creating kubernetes.json's subjects with a non-cone sparse checkout of each `subpath` read 88, 33 and 95 files for gateway-api, ingress-nginx and kube-prometheus; the committed reading says 95, 38 and 98.
- **Evidence:** at the pinned shas the root holds 7, 5 and 3 YAML files (git ls-tree); `calibration/clone.sh` checks a `subpath` out with `git sparse-checkout set <subpath>` (cone mode), which keeps every file of the root, and the reading measured the clone root. With cone checkouts the harness at 99aa205a reproduces every subject's counts, files and bytes exactly (wave lf8, item k8s).
- **Root cause:** a shard's `subpath` names the directory of interest, but cone mode also checks out the root's files, and the measurement reads the whole clone.
- **Fix:** none needed for the counts: the root files hold no Kubernetes object, so every count is the same either way. A future reading that wants the subpath alone measures `<clone>/<subpath>` and says so.
- **Status:** closed (disclosed; counts unaffected)
- **Impact:** files, bytes and throughput only.
