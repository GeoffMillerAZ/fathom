### O395 — `find_in_parent_folders` names the nearest ancestor that has the file, and `fusion.ResolveDocXrefs` cannot pick the nearest of several repo-path candidates

- **Symptom:** `xref_precision` .9876 on the Terragrunt subjects: 6 of 473 emitted edges name a farther ancestor's file than Terragrunt takes
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect terragrunt` against terragrunt 1.1.6 (`find --json --include`), gruntwork-io/terragrunt `test/fixtures` f7104ac
  - **Expected:** `include "root" { path = find_in_parent_folders() }` in `root-terragrunt-hcl-regression/foo/terragrunt.hcl` is one edge, to the nearest `terragrunt.hcl` above its directory
  - **Actual:** the dialect emits one repo-path candidate per ancestor directory (one file cannot see which ancestors have the file) and the resolver keeps every candidate that is a file, so a repository with the file at two ancestors gets both edges
  - **Repro:** `TestResolveDocXrefs_TerragruntNearestAncestor`: `a/b/terragrunt.hcl` resolves to both `a/root.hcl` and `root.hcl`
- **Root cause:** docxref.go's repo-path strategy has no "nearest of these" semantic, and this item may not change it
- **Fix:** none; LB-Q-terragrunt-rest carries it (L3 reads excellent regardless: precision .9876)
- **Status:** open
- **Impact:** an extra edge to a farther root.hcl in a repository that nests roots; none in a repository with one root
