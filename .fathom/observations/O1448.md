### O1448 — search hands `path` to ripgrep as an override glob: a directory path finds nothing, and a glob path searches gitignored trees

- **Symptom:** two opposite failures from one cause. (1) A `search` with `path` set to a directory (`src`, `packages/investigation`) answers `no hits` for text that is in that directory. (2) A `search` with a glob path (`packages/investigation/**`) returns hits from gitignored build caches ahead of the authored source, or instead of it. Adopters filed 5 reports between 2026-09-26 and 2026-10-18 (theme T03 in docs/bench/readings/feedback/adopter-triage-2026-10-20.md).
- **Evidence:**
  - **Reports:** app-kit O73 and adopter repository C O3 (a directory path returned no hits for a symbol the file defines; `find_symbol` and `read_source` had already found it). app-kit O40, O105, O127 (with a glob path, every one of the first 6 or 12 hits was a copy under app-kit's gitignored `packages/investigation/.cache/`, 159 MB of bundled chunks).
  - **Probe, 2026-10-20, deployed binary 909ea5c2e, app-kit:** `search {pattern: "includeContext"}` with `path: "packages/investigation"` and with `path: "packages/investigation/"` both returned `no hits`. With `path: "packages/investigation/**"` it returned `8 hits in 7 files; first: packages/investigation/.cache/arch177-complete/index.js:65`. `rg -l includeContext packages/investigation` finds `src/browser.js` and `renderer/src/index.js` and nothing under `.cache`. `WebGPURenderer` occurs only in the cache: it returned 222 hits, all under `.cache`, with `path: "packages/investigation/**"`, and none from the cache without a path. Direct `rg` gave the same split: 46 cache files with `-g 'packages/investigation/**'`, 0 without.
- **Root cause:** `searchRipgrep` (internal/mcp/search_tool.go) passes the caller's `path` as `-g <path>`. In ripgrep a `-g` glob is an override, and an override takes precedence over every ignore rule. A positive glob therefore makes gitignored files searchable. A glob with no wildcard (`src`) matches only a path that equals it, never the files under it, so a directory path excludes everything. The schema calls the field "Glob narrowing which files are searched", and agents read it as a path.
- **Fix:** proposed, not built (small). Split `path` into its literal leading directory and its remaining pattern. Pass the directory to ripgrep (and to `searchWalk`) as the search root, so ignore files keep applying under it. Apply the full glob to the returned paths in Go. Describe the field as "a directory or a glob under the service root". Pin both cases (a directory path finds a file under it, a glob path never returns a gitignored file) with tests beside search_bounds_test.go.
- **Status:** fixed (1f08d5875). Answers app-kit O40, O73, O105, O127 and adopter repository C O3.
- **Impact:** the scoped search agents are told to prefer either reports false absence or buries authored code under build output. The first misled two adopters into "the symbol is not there".
