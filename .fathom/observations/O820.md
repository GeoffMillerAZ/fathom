### O820 — a Bash write into a gitignored file got the root's rules: the relative target was resolved at the project root (G3)

- **Symptom:** a `sed -i` into gitignored `workspace/durable-2026-09-30/DECISIONS-2026-10-09-kits.md` still got six ADR rules and "33 more", although EW-55 skips gitignored targets on the Bash-write path (`edithook_bashwrite.go:91` calls `dropIgnoredWriteTargets`)
- **Root cause:** reproduced with a build of 7863e4c3 against a fake daemon. The sed ran from the file's own directory with a relative target; `bashWriteRepoFiles` treated a relative target as repo-relative text, so `NOTES.md` from `workspace/notes/` became the root-level `NOTES.md`, which git does not ignore, and its rules were served for a file nobody wrote (a tracked `a.go` written from `internal/x/` was likewise asked about as `a.go` at the root). By absolute path, through a symlink, after a `cd`, and from the root the skip held, but read `foreign-target`. The doubt branch (no parsed target) served "39 rule(s) govern workspace/durable" for an ignored directory. `--pre` never serves obligations for a command (command guards only), so it was not the path
- **Fix:** a relative target resolves against the command's cwd; the Edit and Bash paths share one predicate (`editTargetIgnored`); the doubt branch skips an ignored cwd; an ignored write reads `gitignored`, and no obligations request is made (GL-25)
- **Status:** fixed
