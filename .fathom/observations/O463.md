### O463 — scip-dotnet writes `new X(...)`, an attribute and a base initializer as references to a constructor named `.ctor`: 1,158 of the 1,689 C# oracle-only call pairs

- **Symptom:** C# call_recall reads .9448 (1,689 truth pairs not found) and 1,158 of them name callee `.ctor`
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect csharp ... -unmatched`, Polly 9ad5ae9b (387 `.ctor` of 662) and Newtonsoft.Json 4e13299d (771 of 1,027), scip-dotnet 0.2.14, fathom 5c891a06 plus wave ld
  - **Expected:** a constructor call is spelled as an extractor can write it
  - **Actual:** the harness's callee is the SCIP descriptor's leaf, `.ctor`, where scip.go renames Java's `<init>` and Kotlin or Dart's `<constructor>`; no C# call text can equal `.ctor`, so recording `new X()` as a call (`X`) would add a fathom-only pair for each and match none
  - **Repro:** `unm-cs-*-Polly.json` `calls.oracle_only`, bench/Polly.Benchmarks/Bulkhead.cs (`[Config(typeof(PollyConfig))]` on a class attributed to the class)
- **Root cause:** scip.go's constructor naming (L754-L760, `<constructor>` and `<init>`) has no `.ctor` case, and the dialect has no object-creation call by design (php and Roslyn treat `new X` as a type reference)
- **Fix:** open, not mine (internal/langbench/scip.go, wave le's LB-F175 neighbourhood): name `.ctor` as the type's constructor and record `new X(...)` as a call to `X` only with it; recall is already above .90, so nothing is lost meanwhile
- **Status:** open
- **Impact:** none on the L2 thresholds (call_recall .9448 clears .90); the 1,158 pairs are the whole gap to recall .98
