### O493 — the CUE manifest turns on ingest's dialect gate for .cue: a generated CUE file is now skipped where it was read and marked generated

- **Symptom:** after the cue dialect claimed `.cue` (LB-Q-cue), `cue.mod/gen/**` files (`// Code generated cue get go. DO NOT EDIT.`) leave the index at ingest.
- **Evidence:**
  - **Tool:** `TestIngest_CUEModuleReachesTheCUEDialect` (internal/fusion/cuexref_test.go): a corpus with `deploy/cue.mod/gen/example.org/gen/gen.cue` extracts nothing from it, and `g: gen.#Gen` draws no doc-xref edge; the harness reports NetMeta's 51 generated files as "skipped by ingest's gates (generated)".
  - **Expected:** the dialect gate's rule (every dialect's generated or minified file is skipped, `gateDialectFile`) applies to CUE as to the others.
  - **Actual:** as expected; before the manifest a .cue file was no dialect's, so `IsGenerated` only marked its observations.
  - **Repro:** the test above.
- **Root cause:** by design (ADR-048 §5's gate), newly applying to CUE.
- **Fix:** none; disclosed in the dialect's PROVENANCE.md. Vendored generated Kubernetes types (`cue get go`, `timoni mod vendor k8s`) are dependencies, as vendor/ is.
- **Status:** resolved (decided: the gate applies to CUE as to every dialect; the dialect's PROVENANCE.md discloses it)
- **Impact:** an import of a generated package resolves to no file at ingest (item timoni's modules vendor their k8s types this way); find_symbol no longer lists a generated `#Deployment`.
