### O748 — the TypeScript and JavaScript module symbol costs a third more store on nest and zod, against origin/main

- **Symptom:** K18's module symbol for TS/JS (LB-F381) is the change that lifts typed_recall .1374 to .7051 and file_edge_recall .3632 to .7968 on nest + zod, and it is also the step of wave lf3 that crosses K17's +20% store bar.
- **Evidence:**
  - **Tool:** scratch ingests of the subject checkout (`fathom ingest --store`), median of three, a binary of e186fbc3 against one of 318aaf22; `dbstat` on the stores.
  - **Store:** zod 5,595,136 to 7,454,720 bytes (+33.2%), nest 13,987,840 to 19,218,432 (+37.4%); wall within noise (zod 3.30 to 3.16 s, nest 5.77 to 5.52 s, median).
  - **What grows (nest):** typed edges 7,276 to 15,200, of which 7,924 are made from a module symbol and 4,925 are module-to-module import edges; call rows 10,984 to 18,200 (each module's top-level calls: a test file's `describe`/`it` callbacks hold most); observations +1,724 (one per file).
  - **The later steps, each against the previous commit:** constants +11.6% store, +7.1% wall (b25a3683); members +9.5%, +6.9% (b9d25f09); cumulative on zod against e186fbc3 5,595,136 to 9,113,600 bytes (+62.9%).
- **Root cause:** a file's top level becomes a definition that owns calls and references: the edges it draws are the module-level file pairs O275 and O505 counted as missing, and each import of a module is an edge of its own.
- **Fix:** none here: the module symbol was the wave's mandated step and K17's gate was applied to the steps after it. Levers if the owner wants the cost back: no module-to-module edge where the import already draws a symbol edge to the same file (4,925 rows on nest), no call rows from a test file's module symbol.
- **Status:** open (owner decision)
- **Impact:** a TS/JS-heavy store grows by a third, for L3 excellent on both dialects and the module-level edges agents asked for (O275).
