### O361 — a dispatched tags dialect is parsed twice per file: once to extract, once for the file-resolved pass

- **Symptom:** after the C dispatch switch (LB-F119) libuv's ingest costs 42.1 G instructions against 33.5 G before it (+26%), the only subject of the LB-M5 polyglot set that moves (docs/bench/readings/lang/footprint.md, 2026-10-01).
- **Evidence:**
  - **Tool:** `/usr/bin/time -l fathom ingest --json --store <fresh> --path <one subject, nested>` at 32afe369 (main) and 5556eb84 (head), fresh stores and caches.
  - **Expected:** serving `.c` from the tags dialect replaces the CGO parse; the wasm parse the file-resolved pass already ran is the only one left.
  - **Actual:** the pipeline extracts each `.c` file with `TSExtractor.Extract` (one wasm parse), then `enrichFileResolvedEdges` -> `resolveLang` -> `extractImports` calls `TSExtractor.ExtractFileSpecs` on the same file (internal/fusion/fileresolve.go `extractImports`, ~L1026), a second wasm parse; before the switch the first parse was the CGO walker's, faster than wasm.
  - **Repro:** the per-subject runs in the footprint section.
- **Root cause:** extraction and the file-resolved pass are separate stages that each parse; `fileResolveExtractor` (fileresolve.go ~L1135) already shares the dispatched `TSExtractor` instance, but not its tree.
- **Fix:** none in this item (fileresolve.go belongs to item cinc; the engine change is in internal/extractor/tsextract.go and tsrefs.go). The exact change: a `TSExtractor` method returning a file's nodes and its `FileSpecs` from one parse (tsextract.go's `extractLocked` already holds the tree; tsrefs.go's `ExtractFileSpecs` runs its queries over a tree of its own), called by the pipeline's extract stage for a file whose language is in `fileResolveLangs`, the specs kept per ingest keyed by path and content hash; `resolveLang` reads that map before calling `extractImports`, and parses only a file the extract stage did not see (an unchanged file the stat gate skipped). Every dispatched tags dialect the file-resolved pass covers, C among them, loses its second parse.
- **Status:** open
- **Impact:** LB-M5 (1.9% of the polyglot set's instructions from C alone; more for every language that switches under D1). Not the reason LB-M5 fails (O362 is).
