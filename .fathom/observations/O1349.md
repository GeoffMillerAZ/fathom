### O1349 — a tool format's L2 is graded on `references`, so a call oracle for the Tiltfile has to be written as references; the tier-C query is tree-sitter-python's, cut by one pattern

- **Symptom:** the first Tiltfile reading, with `tags_oracle.py` writing its pairs as `calls`, matched every pair (1,087 of 1,087) and still read `level_met L1`, L2 `not-attempted`.
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect tiltfile -tool-oracle <defs> -tool-oracle <calls>`
  - **Expected:** matched call pairs grade L2
  - **Actual:** design 1.2 grades a tool format's L2 on `ref_recall` and `ref_precision`; the `calls` family is the languages'
  - **Repro:** the same run with the pairs under `references` reads L2 good
- **Root cause:** two families, one pair shape. The Tiltfile has no SCIP producer and no ctags parser, so its only oracle is a third-party tags query on an independent runtime (tier C, the cap is good).
- **Fix:** `tags_oracle.py --as-references` writes the pairs under `references`. The query is `calibration/oracles/ts-tags/starlark-tags.scm`: tree-sitter-python `queries/tags.scm` at v0.25.0 (MIT) less its `class_definition` pattern, which the Starlark grammar has no node for. Starlark's grammar descends from Python's, so the other three patterns compile unchanged.
- **Status:** closed (disclosed)
