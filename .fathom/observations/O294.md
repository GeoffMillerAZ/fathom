### O294 — `fathom report used` cannot see an input a build script declares by path: app-kit's `.vendor-commit`, which `scripts/ui-css.sh --check-sources` requires

- **Symptom:** `fathom report used` cannot see an input a build script declares by path: app-kit's `.vendor-commit`, which `scripts/ui-css.sh --check-sources` requires
- **Evidence:**
  - **Tool:** `fathom report used third_party/app-kit --json` (SV-7) and docs/bench/readings/stewardship/used-closure.sh, wave cd branch cd-steward
  - **Expected:** a mirror pruned to its used closure passes `scripts/ui-css.sh --check-sources`
  - **Actual:** it passes only because prune-to-closure.py keeps `.vendor-commit` and `LICENSE.md` beside the closure; with `.vendor-commit` removed the check refuses ("required source is missing: third_party/app-kit/.vendor-commit")
  - **Repro:** used-closure.sh <fathom clone> <scratch> <fathom binary>, then remove third_party/app-kit/.vendor-commit in the pruned tree and run scripts/ui-css.sh --check-sources
- **Root cause:** the closure is computed from imports, go:embed patterns and CSS directives; a provenance stamp or licence file is named by no import, embed or directive, only by a build script's `require_file` list
- **Fix:** none in fathom (SV-X4: the copy stays a script); a sync script keeps provenance and licence files, and the SV-M3 reading names the gap
- **Status:** open
- **Impact:** a pruning script that trusts `used_files` alone produces a mirror the CSS build contract refuses, and drops the licence file a vendored copy must carry
