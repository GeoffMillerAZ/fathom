### O680 — the module symbol's key is unique only under the dir package rule and one extension per file name

- **Symptom:** a module symbol's key is `<service>::<dir>/<package>.<module>`; with `package.strategy` "dir" the package is the file's name without its extension, so two files of one directory that differ only by extension (`a.js` beside `a.mjs`, `a.ts` beside `a.tsx`) would share it.
- **Evidence:**
  - **Code:** core.SymbolKey, extractor.pkgFromPath; checkModuleSymbol and schema #Dialect require the dir rule; Python claims `.py` alone (the `.pyi` variant is not dispatched).
- **Root cause:** the key carries the file's directory and stem, not its extension.
- **Fix:** none needed for Python (lf2). Recorded as the K18 amendment's revisit trigger (ADR-048, 2026-10-10): JS/TS, which turn the module symbol on in lf3, must give the key the extension or refuse a shared stem.
- **Status:** open (lf3's design input)
- **Impact:** none today; a JS/TS module symbol turned on without it would merge two files' top levels.
