### O1473 — A lookup through re-exports walked a package once per path when every file re-exports it

- **Symptom:** `indexbench lang-oracle -dialect cue` on hofstadter-io/hof (327 files) ran past twenty minutes at full CPU in `fusion.(*exportIndex).lookupIn` (sampled), where the three tuning subjects take seconds.
- **Root cause:** each CUE file re-exports its own package (`.:name`, so a reference through an import of a package split across files reaches the file defining the name), so every target of a re-export re-exports the same files again; `lookupIn`'s cycle guard is per path, so a name no file defines walks up to N^8 paths (maxExportDepth 8) for a package of N files. rego-package has the same shape (each file re-exports `data.<pkg>`, LB-F132): latent for a wide Rego package.
- **Fix:** under cue-module a package's own re-export is flat (`exportEdge.flat`): its targets' top-level definitions, never their re-exports (`TestResolveFileEdges_CUEWidePackage`: a forty-file package in 0.01s). Rego's re-export is unchanged (another item's language); revisit if a Rego subject with a wide package is measured.
- **Status:** fixed for CUE; open for rego-package
- **Impact:** None at ingest (CUE is out of the file-resolved pass, O1474); the harness's L3 reading of a wide CUE package now finishes.
