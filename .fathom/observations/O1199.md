### O1199 — `tests select --safe --since origin/main` in a worker clone selects nothing

- **Symptom:** wave ro1c's brief asks a worker to run `fathom tests select --safe` before whole-package runs; in the clone, with a committed diff over cmd/fathom and internal/readout, it printed "0 test(s) selected ... 0 changed symbol(s)".
- **Evidence:** `fathom tests select --safe --since origin/main --service fathom` from the ro1c inputs worker clone after commit 18be1ad2 (2026-10-18).
- **Root cause:** the verb resolves changed symbols against the daemon's index of the service, which holds the owner checkout at origin/main, never the worker's branch (docs/guides/agent-waves.md says the read tools answer for origin/main).
- **Fix:** when the store's indexed commit for the service is not HEAD, `tests select` prints one line naming both commits and saying the selection reads that index, and `--json` carries `index` (`commit`, `head`, `holds_head`); docs/guides/agent-waves.md's worker step says the `--store` is the scratch ingest refreshed after the last commit
- **Status:** fixed (wave fix1, item tsel)
- **Impact:** workers fall back to package-wide runs or name patterns; the step costs a call and selects nothing.
