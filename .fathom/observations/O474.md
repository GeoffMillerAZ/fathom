### O474 — the Kotlin PSI dump writes no imports, so kotlin.json cannot be measured at L3

- **Symptom:** kotlin.json has no import_resolution: `calibration/oracles/kotlin-psi/KotlinPsiDump.java` writes definitions and references, and no import directive or package
- **Evidence:**
  - **Tool:** reading calibration/oracles/kotlin-psi (wave ox's; not edited here: no "kotlin-psi released" on the launch line)
  - **Expected:** a neutral `imports` truth naming, per import directive, the file of the subject it resolves to (LB-F57)
  - **Actual:** none; the harness's neutral shape (`imports: [{path, line, to_path}]`, as `../scip-clang/preproc` writes) has no Kotlin producer
  - **Repro:** run the dump on any Kotlin file with an `import`
- **Root cause:** the dump was written for L1 and L2 only
- **Fix:** open, the exact change: per file, in KotlinPsiDump.java, emit (a) the file's package (`KtFile.getPackageFqName`), (b) every import directive (`KtImportDirective`: its 1-based line, `getImportedFqName`, `getAliasName`, `isAllUnder`), and (c) the file's top-level declarations (name and kind of each `KtNamedDeclaration` directly under the file, with the package), and let a post-pass join each directive to the file that declares its last segment (or, for a star import, every file of the package) in the subject, writing `imports: [{path, line, to_path}]` for LB-F57 (one entry per target file, `to_path` empty when it resolves outside the subject)
- **Status:** open
- **Impact:** Kotlin stays at L2 on kotlin.json; LB-Q-kotlin-rest carries it
