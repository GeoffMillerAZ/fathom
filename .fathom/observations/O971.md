### O971 — S1's lever: what a bash reading counts and the index stores now differ, and a dropped top-level call waits for its script's next read

- **Symptom:** two limits of LB-F520 (a bash script's top-level call is stored only when its callee is a repository definition), disclosed with it. (1) bash.json's L2 (tier C, ts-tags with `--module-caller '<module>'`) scores the extractor's output, which still carries every top-level call, while the index no longer stores a top-level call to an external command (`<module>` -> `echo`). (2) The filter reads the definitions the service has when the script is read: a top-level call to a function no file defines yet, added later in another file, stays dropped until the calling script is read again.
- **Evidence:** `indexbench lang-oracle` extracts each subject with the dialect's extractor (`measureSubject`, cmd/indexbench/langoracle.go) and resolves file edges with fusion.ResolveFileEdges; neither runs the extract sink, where the lever sits (internal/fusion/scriptcalls.go). So the reading is identical with and without the lever by construction (LB-F525), and on nvm 801 of the 1,574 top-level call rows (bats-core 168 of 235) are counted by L2 but not stored. For (2): the sink looks a name up once, at the end of the stream that reads the script (TestIngest_BashModuleCallsBind covers the unchanged file defining it; nothing re-reads an unchanged script when a new definition appears elsewhere).
- **Root cause:** (1) the harness measures extraction, the lever is a storage rule; (2) an unchanged file is never re-read (the hash gate), so a storage decision made on what the repository defined then is not revisited.
- **Fix:** none here. (1) is a disclosure: a dropped pair names no definition of the repository, so no answer about one (its callers, its blast radius, file edges) changes; the L2 grade is tier C and its pairs' bare callee names are what the oracle writes. (2) is rare (a script calling a function that exists nowhere) and heals at the script's next edit or the next ExtractorEpoch.
- **Status:** open. Trigger: a reading that scores stored calls rather than extracted ones (a harness rule, K29), or a report of a missing top-level caller in a bash repository.
- **Impact:** find_callers of an external command (`echo`) no longer lists a bash script's top level; a function defined after its caller's script was read is missing that one caller until the script is read again.
