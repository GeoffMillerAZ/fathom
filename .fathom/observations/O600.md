### O600 — the C++ dialect's CPU per byte sits at the 1 MB/s tenancy floor: the cpp-macros pre-pass doubles it and the engine's error check runs a full query

- **Symptom:** the C++ reading's level_met reads `none` on a loaded machine (CPU throughput 0.78 to 0.96 MB/s at load averages 15 to 34, 1.15 to 1.38 at lighter load) where every level's metrics are met; before the pre-pass it read 2.17
- **Evidence:**
  - **Tool:** a scratch probe over fmt, json and spdlog (3.07 MB): parse 1.80 s, the engine's error query 0.79 s, the pre-pass's lexical rewrite 0.017 s, re-parse 1.30 s; 152 of 232 files do not parse as written, 138 are rewritten, 87 then parse clean (51 re-parses wasted, Catch2's `TEST_CASE("...", "[tags]") {` and other shapes the pre-pass does not read)
  - **Expected:** a pre-pass costs its re-parses, not a second full walk per file
  - **Actual:** tsextract.go's tsHasError runs `(ERROR) @e (MISSING) @m` and collects every match on every file
  - **Repro:** `go test ./internal/extractor -run TestZZProbeCppCost` (scratch) with PROBE_DIR on the three subjects
- **Root cause:** the engine checks for errors by query; tree-sitter's ts_node_has_error on the root answers in O(1)
- **Fix:** open, outside this item's files: an O(1) root error check in the tags engine (tsengine/tsextract.go); a pre-pass shape for Catch2 test macros would save the wasted re-parses
- **Status:** open
- **Impact:** a C++ reading claims a level only when the machine's load leaves the dialect at or above 1 MB per CPU second; LB-M5 (FAIL 1.92x) grows with it
