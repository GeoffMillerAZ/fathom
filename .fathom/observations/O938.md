### O938 — JUnit's dry run reports a parameterized-only class with no test case, so a dry-run oracle under-counts what Surefire collects

- **Symptom:** RF-M8's Java oracle (`mvn verify -Djunit.platform.execution.dryRun.enabled=true`, the set read from `<testcase>` class names in `TEST-*.xml`) left out classes Surefire ran: commons-text's `ReplacementsFinderTest`, three `Parameterized*Test` and `SimilarityCharacterInputTest`, jsoup's `StructuralEvaluatorTest` (all `@ParameterizedTest`), and jsoup's `ParserSettingsTest` (no test method). jsoup read 0.946 and commons-text 0.949 precision instead of 0.973 and 1.000.
- **Evidence:** docs/bench/readings/repository-facts/roles-r1.md (Java disagreements); Surefire's log prints "Running" and "Tests run: 0" for each and writes a `TEST-*.xml` whose `<testsuite name>` names the class with no `<testcase>`. The pre-registered header claimed the dry-run set equals a real run's; it does not, because a parameterized template's invocations come from its argument source, which the dry run never expands.
- **Root cause:** an oracle claim written before running it; the header ("every class named in a TEST-*.xml") and the scorer (`<testcase>` class names only) also disagree on exactly these classes.
- **Fix:** none in rf2 (the verdict does not turn on it: TypeScript and Python fail under both readings). A later Java oracle runs the suite for real, or reads `<testsuite name>` as well and states which.
- **Status:** open
- **Impact:** any later JUnit-based collection oracle.
