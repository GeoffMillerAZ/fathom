### O711 — `verify --since` compared a moved plan with an empty plan (renamedFrom)

- **Symptom:** after the 22 plans wave w2a archived moved from `docs/plans/` to `docs/plans/archive/`, `fathom verify --strict --since origin/main` read each moved plan as empty at the base ref, so every `skip_test` it carried looked newly added and 16 archived plans failed as self-skipped
- **Evidence:** commit 51aae511 (`git log -S renamedFrom`): `sinceRefPlanWith` read the base with `git show ref:rel` at the plan's new path and `priorSelfSkipPlanWith` read HEAD and HEAD~1 the same way; `TestCmdVerify_SinceFollowsAMovedPlan` (committed move, uncommitted `git mv`, skip gained in the move) fails its two move cases without the fix
- **Root cause:** both readers assumed a plan has the same path at the base ref as in the working tree; an archive move breaks that
- **Fix:** 51aae511 adds `renamedFrom`, which asks git's own rename detection (one bounded `git diff -M --diff-filter=R`, only when the path is absent at the ref) for the path the plan had; a waiver gained in the move is still self-declared
- **Status:** fixed (51aae511)
- **Impact:** any wave that archives plans and then runs the pre-push `verify --strict --since`
