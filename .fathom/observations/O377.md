### O377 — uyha/tree-sitter-cmake v0.7.5 parses at about 1.1 MB per CPU-second in the wasm engine, so the 1.0 floor leaves no room for a query: cmake reads level_met none at throughput .71

- **Symptom:** `docs/bench/readings/lang/cmake.json` grades L1 and L2 excellent and reads `level_met: none` because tenancy is always required and throughput is .71 MB per CPU-second against 1.0
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect cmake` on fmt, nlohmann/json and bullet3 (350 KB of CMake), plus a per-pattern timing of one 40 KB file (nlohmann/json cmake/ci.cmake) with `getrusage`
  - **Expected:** a tags dialect extracts above 1 MB per CPU-second (protobuf 8.4, makefile 3.1)
  - **Actual:** an empty query 1.0 to 1.3 MB per CPU-second (32.6 ms for the 40 KB file), the eight definition patterns .9 to 1.0 (39 to 41 ms), the five-pattern link attachment .7 (58 ms); a single pattern with four optional sibling steps is slower (70 ms), and a pattern pairing every target with every later link command is quadratic: a flat file of 300 targets and 300 links fails the engine's 10 s scan budget
  - **Repro:** `go test` timing harness over `ExtractorFor("cmake")` with the patterns removed one at a time (the numbers are in the dialect's PROVENANCE.md and tags.scm)
- **Root cause:** the grammar's lexer and external scanner under wazero, not the queries; each tags pattern adds about a tenth of the parse
- **Fix:** none; LB-F129 (a cheaper grammar or an engine-side attach by name)
- **Status:** open
- **Impact:** CMake cannot reach any level while the floor holds; cmakeextract.go stays dispatched
