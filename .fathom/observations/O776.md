### O776 — `go list` under CGO_ENABLED=0 hides a cgo dependency; MACOSX_DEPLOYMENT_TARGET sets minos, it silenced nothing

- **Symptom:** a cgo-free guard written as "with CGO_ENABLED=0, no non-stdlib package lists CgoFiles" passes vacuously: under CGO_ENABLED=0 the go command drops every cgo file from its package (`go list` reports go-tree-sitter with `CgoFiles=[]`, `GoFiles=[logger.go]`, no error), so a cgo dependency surfaces only as undefined symbols at link time. Separately, the Taskfile and every build doc justified `MACOSX_DEPLOYMENT_TARGET=14.0` as silencing ld warnings from the tree-sitter objects
- **Evidence:** wave h4 cgofree, 2026-10-10, Go 1.26.2 on macOS 27: `GOOS=linux CGO_ENABLED=0 go list -f '{{.CgoFiles}}' github.com/tree-sitter/go-tree-sitter` prints `[]`, with CGO_ENABLED=1 it prints 13 files. A cold `CGO_ENABLED=1` build of cmd/fathom (cgo only in host_darwin.go and rss_darwin.go) printed no ld warning with the variable unset; `otool -l` reads LC_BUILD_VERSION minos 27.0 unset, 14.0 with it, 12.0 for a pure-Go build
- **Fix:** `cmd/fathom/cgofree_test.go` (CS-9) reads C sources with cgo on and checks the CGO_ENABLED=0 load separately; a blank import of the old treesitter package fails both of its tests. `MACOSX_DEPLOYMENT_TARGET=14.0` stays, re-justified as the darwin binary's minimum macOS (ADR-066 decision 2)
- **Status:** fixed in wave h4 (ADR-066, CS-9)
- **Impact:** a later "is X cgo-free" check reads with cgo on; dropping the deployment target would have shipped darwin binaries that refuse every macOS older than the build host's
