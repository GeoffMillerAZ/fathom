### O988 — tree-sitter-astro reads the rest of a file as an attribute after an unclosed start tag

- **Symptom:** in a component whose markup leaves a start tag unclosed (`<div class="a"` then a newline and `<Inner />`), every component tag after it is lost: `broken.astro`'s `<Tail />` (line 9) is no call, where @astrojs/compiler recovers it as a component.
- **Evidence:** `indexbench lang-probe -dialect astro internal/extractor/dialects/astro/testdata/broken.astro`: an ERROR node at line 5 holds an `attribute_js_expr` spanning to the end of the file; the compiler's `parse` gives `div` the attributes `class` and `<Inner`, then `component "Tail"`. The golden records the grammar's recovery (calls `[Shell]`).
- **Root cause:** the grammar's error recovery, not a query.
- **Fix:** none (a file in error is counted in files_with_error; 0 of 172 calibration files have one).
- **Status:** open
- **Impact:** a broken component loses the calls after the error; rare on real code.
