### O1133 — `[decide] allow_repo_provider = true` opened only a repository's `llm` provider: a repository's `typesafe` or `openai` provider could never open

- **Symptom:** with `allow_repo_provider = true` in `~/.fathom/config.toml`, a repository's `provider = "typesafe"` (or `"openai"`) still failed to open: the transport's well-known variable is refused for a provider the user did not name (KS-4), and the key the refusal tells you to name in `~/.fathom/config.toml` was then refused as "named for no remote provider" (DP-39).
- **Evidence:**
  - **Tool:** `internal/decide` (`checkAmbientKey`, `checkKeyTransport`), `internal/config` (`mergeDecideFields`)
  - **Expected:** ADR-073 decision 5: a provider or transport only the repository names opens when the user's `allow_repo_provider` allows it, with `consent_layer` `project`; KS-4's consent rows name every provider.
  - **Actual:** key fields are user-only, and `config.Load` bound a key named in a layer with no remote provider to `KeyTransportNone`, because `EffectiveTransport` ignores a transport without a provider; so the only key a repository's remote provider could use was refused. The `llm` path has no key check, so it alone opened.
  - **Repro:** user layer `allow_repo_provider = true` plus `api_key_env = "MY_KEY"`, repository layer `provider = "typesafe"`: `decide.Open` errs "named for no remote provider".
- **Root cause:** DP-39's key binding had no way to bind a user's key to a transport without the user also naming the provider, which is the user-named path, not the consent path.
- **Fix:** a layer that names a key beside a `transport` and no remote provider binds the key to that transport (`mergeDecideFields`), so with `allow_repo_provider` the repository's provider speaking that transport opens, `consent_layer` `project`, and no well-known variable is read; a key named with no transport, or the repository moving to another transport, is still refused, and without `allow_repo_provider` the port stays `none` with nothing touched (revert-probed: the new subtests go red without the consent guard). Both refusals now name the binding that works. Tests: `TestRepoProviderWithoutUserConsentNeverReadsAmbientKey` (three providers plus the moved-transport refusal), `TestLoad_DecideKeyTransportIsTheNamingLayers`.
- **Status:** fixed (fx1)
