### O520 — a named import of a library type binds the import symbol a same-named subject directory's file declares for its own import (53 false file edges on okhttp)

- **Symptom:** 53 okhttp files reach okhttp-testing-support/src/main/kotlin/okhttp3/okio/LoggingFilesystem.kt through `import okio.Sink`, `Source`, `Path`, `FileSystem`, `ForwardingFileSystem`.
- **Evidence:**
  - **Tool:** `-unmatched` file_edges `fathom_only_via` on okhttp: the drawing pair is `<importer> -> okhttp3.okio.okio.Sink` (a KotlinImport symbol of LoggingFilesystem.kt, named `okio.Sink`).
  - **Expected:** a named import of a dependency's type that no file, top-level name, class or member of the subject settles binds nothing.
  - **Actual:** the namespace-dir split (memberImport) reads the parent `okio` as the subject directory `okhttp3/okio/` (suffix match), then finds `okio.Sink` in that file's `qualified` map, where the file's own import symbol sits.
  - **Repro:** internal/fusion/testdata/ktlibimport (a lib `app/okio/Logging.kt` importing `okio.Sink` and `app/Use.kt` importing it too); the failing test and the patch that fixes it are at /Volumes/m2ext/tmp/fathom-build/w-pkc/ts-needs/kotlin-namespace-dir.patch (it adds `importKeys` to resolveIndex and skips them in memberImport).
- **Root cause:** import symbols are indexed in `idx.qualified` like definitions, and memberImport's member lookup does not skip them.
- **Fix:** open, item ts's file (internal/fusion/fileresolve.go): the patch above; with it TestResolveFileEdges passes in full.
- **Status:** open (handed to item ts through the integrator; the failing test is not committed here because it would break the gate)
- **Impact:** 53 of okhttp's 1,017 fathom-only edges; precision .7993 would read .8045 without them, so it does not move L3 alone.
