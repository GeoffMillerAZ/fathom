### O700 — a LogTemplate node is the innermost symbol at exactly its logger call's line, so line-to-symbol readers other than localize name the template there

- **Symptom:** after TL-4 (ADR-064) every logger call in a Python, Java, JavaScript/TypeScript or PHP file is a `LogTemplate` node at its call's line (`EndLine` = `Line`); a reader that asks "which symbol encloses line N" for exactly that line gets the template, not the function around it
- **Evidence:**
  - **Tool:** `search` (its receipt names "the symbol it sits in" through `enclosingSymbol`, internal/mcp/search_tool.go), and any line-to-symbol mapping over a changed or cited line (review and blast-radius change sets)
  - **Expected:** a grep hit or a changed line on `logger.error("order %s failed", id)` sits in the function that logs
  - **Actual:** it sits in the node named `order %s failed` (kind LogTemplate); one line before or after it still sits in the function, since the extractors of these languages set end lines
  - **Repro:** ingest a Python file whose method logs on line 8, then `search` for a word on line 8
- **Root cause:** innermost-wins (latest start whose span holds the line) is the right rule for code symbols and the same class of answer a `PythonField` assignment line already gets; TL-4's files (internal/logtemplate, internal/fusion's pass, internal/mcp's localize) could exclude the kind only where localize reads, which it does (`withoutLogTemplates`)
- **Fix:** none in TL-4. The shared `enclosingSymbol` (internal/mcp/search_tool.go) and the other line-to-symbol readers skip `logtemplate.Kind`, one predicate, with a test per reader; or the storage moves to the system graph's tables when RT-M1 reads PASS (ADR-064's revisit trigger)
- **Status:** open
- **Impact:** only the exact line of a logger call, only in the four languages, from the wave's extractor epoch on; localize, the consumer TL-4 serves, is unaffected
