### O842 — A plan-row pattern with an odd count of `\"` is not parsed as a row, silently

- **Symptom:** three rows written from the roadmap's section 11b, `pattern: "\"L3\": \"(excellent|ceiling)"`, verified as `? [md-358]` (an unparsed row named by its line) instead of `LB-F456`; the roadmap's code-block spelling `"^### 1\\.8 Owner rulings ..."` parsed but matched nothing (`1\\.8` is a literal backslash for the plan grammar).
- **Evidence:**
  - **Tool:** `fathom verify --strict --plan docs/plans/language-breadth.md` on a scratch ingest (wave lf5, item html, 2ad46bd1); a scratch plan with four spellings: only a pattern with an even count of `\"` parsed.
  - **Actual:** `? [md-001] a {id: T-1, ... pattern: "\"L3\": \"excellent\"|\"L3 ceiling: "}` (5 escaped quotes); `✗ [T-3]` parsed with 4.
  - **Repro:** `fathom verify --plan <scratch>.md` over the four rows in this record's evidence.
- **Root cause:** not traced; the attribute scanner appears to pair `\"` before it reads a quoted value, so an odd count leaves the brace block unparsed, and lint says nothing about it.
- **Fix:** worked around in F.59 (patterns with an even count; LB-F455's dot escaped once). The scanner or lint should name a row whose `{...}` block does not parse.
- **Root cause (traced):** `trailingBraceBlock` and `splitPairs` (internal/verify/markdown.go) toggled their quote state on every `"`, the escaped ones too: an odd count of `\"` left the scanner inside a quote at the closing brace (no block, a positional id), and an even count could still split a value on a comma between two escaped quotes. The lint read only blocks it found, so a block never found said nothing.
- **Fixed:** `\"` is data in both scanners, inside a quoted span or in an unquoted value (as internal/specdialect writes one), and `\\` a backslash; the value reaches its reader as written. `ParseMarkdownPlan` records every `{id:` line read as no row (`Plan.UnparsedRows`: a checkbox row with no id, or a stray line outside fences and code spans) and `LintPlan` names each as `line N: error:` with the reason; `TestRepoPlans_EveryIDBlockParsesAsARow` holds the repository's plans to it. Strict verify over every plan, base and after: no verdict changed, no row newly parsed. Tests `TestPlanRowWithOddEscapedQuotesParses`, `TestPlanLintNamesAnUnparsedRowBlock`.
- **Status:** fixed (wave fix1, item proof)
- **Impact:** a row can be written that verify never evaluates under its id, so a claim on it cannot be proven or refused.
