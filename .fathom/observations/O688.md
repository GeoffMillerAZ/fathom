### O688 — a doc-engine extractor does not say which dialect it is

- **Symptom:** `fusion.DispatchTable` cannot name the dialect behind a `*extractor.DocExtractor` or `*TagsDocExtractor` from the extractor value (a `TSExtractor` has `Name()`, a `RegoExtractor` has `Name()`, these two have none)
- **Evidence:** `internal/extractor/docengine.go` (`DocExtractor` keeps its spec unexported, no id) and `tagsdoc.go` (`id` unexported); a first draft of the check loop also stopped at the table's `|---` separator line and passed vacuously, caught only by a negative test
- **Root cause:** `NewDocDialectExtractor(id)` consumes the id and keeps none
- **Fix:** the accessor recovers the id from the manifest that claims the key (`docDialectIDsByKey`), so a key two doc manifests claim would read as both ids; an `ID()` on the two types (internal/extractor, outside this item) would make it exact
- **Status:** open
- **Impact:** none today (no key is claimed by two doc dialects in the dump); a future overlap would read as a joined label rather than a wrong one
