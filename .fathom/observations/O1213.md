### O1213 — The fold's one predicate is the readouts mode, so an unwired readout entry silences the test-run tier

- **Symptom:** with `[readouts] mode` on, `session-hook --event test-run` and `--event failed-test-run` exit 0 silent and the readout hook runs the test-run tier (RO-21). A settings file that wires the old test-run entries but not the readout hook's (the mode was switched on and `fathom init` not re-run) then runs the tier nowhere.
- **Evidence:** cmd/fathom/testrunhook.go `testRunEntryHook`; cmd/fathom/readouthook.go `readoutsOn`, `readoutTestRunTier`.
- **Root cause:** the fold reads config only, never the client's hook settings, so it cannot see which entry is wired; reading settings in the hot path would still miss plugin and managed settings and could run the tier twice.
- **Fix:** none in this wave. Doctor's hooks_installed already names the readout entry missing while the mode is on, and `fathom init` or `fleet reconcile` adds it.
- **Status:** open
- **Impact:** bounded to the window between switching the mode on and the next init; doctor names it. The edit hook stays a second fathom process on PostToolUse(Bash), outside RO-21's pair. A settings file wired before the fold keeps its old test-run entries on a re-run of `fathom init` (init adds entries, never removes one), so each Bash call still spawns the silent old entry until it is removed by hand.
