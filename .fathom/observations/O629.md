### O629 — `otelcol validate` is host-dependent and layered configurations fail alone

- **Symptom:** opentelemetry-demo's base configuration fails validate on macOS, and its observability layer fails alone
- **Evidence:** otelcol-contrib 0.162.0: `receivers::host_metrics: root_path is supported on linux only`, `extensions::file_storage/...: directory must exist`, `pipeline "profiles": ... gated under the "service.profilesSupport" feature gate`; `otelcol-config-observability.yml` alone: `no receiver configuration specified in config`
- **Root cause:** validate runs each component's own Validate, some of which inspect the host; the demo runs `--config base --config layer`
- **Fix:** the otelcol oracle sets a placeholder for every referenced environment variable, tries a failing file as a layer over each sibling that validates alone, and discloses (never counts) the three host-only error kinds (calibration/oracles/otelcol/README.md)
- **Status:** fixed 2026-10-09 (wave c1, item mesh)
- **Impact:** 8 of 10 candidate files accepted; the two refusals are real (a profiling-distribution receiver, an OTTL function the collector no longer has)
