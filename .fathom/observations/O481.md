### O481 — a tier-B JavaScript call oracle was measured (js-callgraph) and cannot grade: it names callees by property name and its parser stops at ES2018

- **Symptom:** brief item (2)(ii): a parser-based, independent JavaScript call-graph oracle for the untyped subjects, taken beside scip-typescript's L1/L3/L4 (O264 refused a calls file beside -scip).
- **Evidence:**
  - **Tool:** `@persper/js-callgraph` 1.3.2 (EPL-2.0, Esprima 4, run unmodified through calibration/oracles/js-callgraph/run.sh), `indexbench lang-oracle -calls-from tool -tool-oracle` on axios cdcfd214 and express df0abc93.
  - **Actual:** 183 and 141 in-scope pairs; fathom call_recall .608 (197 of 324) and call_precision .2472 (197 of 797), tier B. The oracle-only pairs are the tool's: express `defaultConfiguration` calls `header`, `disable` calls `header` (a property name matched across every receiver); it has no pair for `Error`, `apply`, `new Map`; Esprima 4 fails on webpack's object spread (`lib/Compiler.js`: Unexpected token ...) and the tool then dies, so the typed subject gets no oracle.
  - **Repro:** calibration/oracles/js-callgraph/README.md.
- **Root cause:** a field-based call graph over-approximates by name and is blind to builtins and modern syntax; neither side of the comparison can be held as truth.
- **Fix:** O264 fixed: `lang-oracle -calls-from scip|tool` (LB-F204) takes L2 from a -tool-oracle's calls beside -scip, the index grading definitions, imports and typed edges, the tier recorded as the file's (B), with a test. The oracle stays measured and out of the reading.
- **Status:** fixed (the flag); open (no tier-B JavaScript tool that parses current syntax is known: trigger, one that does, e.g. a Jelly-class analyser run unmodified, BSD-3-Clause)
- **Impact:** a tier-C or tier-B calls file can finally sit beside -scip in one reading; the tier-C ts-tags run (LB-F68) can be folded into the reading when the owner wants it.
