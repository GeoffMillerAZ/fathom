### O1253 — the gate preflight resolves a relative `git -C` against the work tree's root, not the directory a leading cd reached

- **Symptom:** for `cd <subdir> && git -C <rel> push`, the gate preflight read `<root>/<rel>`, where the shell runs git in `<subdir>/<rel>`. A `<root>/<rel>` that does not exist silenced the preflight; one that does exist read the wrong repository.
- **Evidence:** wave cwd1's audit, finding F4; grounded by wave dmp2's rails2 worker, 2026-10-18. `cmdEditHookPreCommand` (cmd/fathom/edithook_pre.go:428) passes `hookCallRoot`'s answer, the cd target's work-tree root (or the project itself when the cd stays inside it), to `gatePreflightLine`, which joined the `-C` path onto that root (`resolveBashDir(projDir, at)`, cmd/fathom/gatepreflight.go:120 at 3ffb2d55). A relative `-C` with no cd resolved against the project, not the hook's `cwd`, the same way.
- **Root cause:** cwd1's resolver (`hookEffectiveDir`, cmd/fathom/hookdir.go) places the leading cd, but the preflight's `-C` join used the root it was handed instead of that directory.
- **Fix:** `hookGitDir(command, at, cwd)` resolves a relative `-C` against the leading cd's target from the hook's `cwd` (an absolute one stays as written), and `gatePreflightLine` takes `cwd` and uses it. `TestHookEffectiveDirFollowsALeadingCd` carries the three `-C` cases.
- **Status:** resolved (wave dmp2, rails2).
- **Impact:** a subagent that cd'd into a subdirectory of its clone and pushed with a relative `-C` got no preflight line or one from the wrong repository. The advisory is never a deny, so nothing was blocked.
