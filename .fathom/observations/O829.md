### O829 — receipt verify offline (EVX-6): `-mod=readonly` sets vendor/ aside, and the cache check is the whole build list for pre-1.17 modules

- **Symptom:** EVX-6's contract appends `GOFLAGS=-mod=readonly` after the operator's environment. Two consequences a stranger may meet.
- **Evidence:**
  - **Tool:** `fathom receipt verify` (internal/receiptverify `offlineGoEnv`, `requireCachedModules`).
  - **Actual:** (1) a checkout that vendors its dependencies is loaded from the module cache, not vendor/, so it exits 2 naming a module the vendor directory holds when the cache lacks it. (2) the cache check is `go mod download` with no arguments, which for a module whose go.mod says go < 1.17 covers the whole build list, so a module the load never needs can still be named.
  - **Repro:** a vendored module receipt with an empty GOMODCACHE; a go 1.16 module requiring an unused module.
- **Root cause:** the contract names `-mod=readonly` exactly; `-mod=vendor` would be the vendored repository's own mode.
- **Fix:** none here (contract kept exactly, docs/usage/receipt.md says so). A vendored checkout could run with `-mod=vendor` when vendor/modules.txt exists, still with GOPROXY=off.
- **Status:** open
- **Impact:** exit 2 with the module named, never a download and never a false verdict; only an extra refusal.
