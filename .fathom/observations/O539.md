### O539 — lang-parity refuses the Rust dispatch on one file edge: rust-analyzer names two test targets' `utils` module by one SCIP symbol, and the harness takes the first document as the definer

- **Symptom:** `indexbench lang-parity -dialect rust -incumbent rustextract` reads REFUSED — file_edge_precision: dialect .9797 < incumbent .9803; every other gated metric is level or ahead (sym_precision .9761 vs .9754, file_edge_recall .3548 vs .3449, import_resolution .9771 both, call_recall .9479 vs .8125)
- **Evidence:**
  - **Tool:** lang-parity over ripgrep 14.1.1 and clap v4.6.1 with `-scip-defs`, then `lang-oracle -unmatched` on each side (a scratch worktree with lh-pkc's 17e784b7 writer applied, never committed)
  - **Expected:** a file edge both extractors draw correctly counts for both; an edge only the dialect draws, to a file the source really uses, is a hit
  - **Actual:** 837 fathom edges, 17 wrong, on the dialect side (16 on the incumbent: 764 and 762 edges per extractor in parity's rows); the one wrong edge only the dialect draws is `tests/builder/command.rs -> tests/builder/utils.rs`, through `utils::FULL_TEMPLATE` (a `RustConst` the incumbent has no symbol for). The truth lacks it because `tests/builder/utils.rs` and `tests/derive/utils.rs` are two modules of two test targets of the clap package and rust-analyzer writes both as `rust-analyzer cargo clap 4.6.1 utils/FULL_TEMPLATE.`; `internal/langbench/scip.go` records `definedIn[symbol]` first-wins (tests/derive/utils.rs), so a reference in tests/builder/*.rs is an edge to the other twin. Both extractors draw the other 16 builder-to-utils edges, which are wrong the same way
  - **Repro:** the calibration README's commands; add `-unmatched` and read `file_edges.fathom_only`
- **Root cause:** `res.FileEdges` takes one defining document for a symbol more than one document defines; `defDoc` already marks such a symbol ambiguous for import references (`import_oracle_ambiguous`, 444 here) and the file-edge truth does not
- **Fix:** none here (internal/langbench/scip.go is outside this item): a file edge to every document that defines the symbol, for a non-module symbol (a module symbol, `crate/`, is the owner's file-module question: giving it every defining document drops file_edge_recall to .0566). Measured in a scratch worktree (never committed): lang-parity reads MERGE, file_edge_precision .9963 (incumbent) and .9964 (dialect), file_edge_recall .2741 and .2822, every other gated metric as before. The reading's own file_edge_recall would read .2822 (truth 2,311 -> 2,955 edges, 834 of the dialect's 837 edges agree), below its current .3548 and above the good bar .25; decide with the dispatch
- **Status:** open
- **Impact:** the dispatch is blocked by an oracle defect, not by the dialect; file_edge_precision is understated on both extractors (17 of 17 wrong edges on clap are twin-module or twin-type collisions or one facade pair)
