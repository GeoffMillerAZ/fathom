### O507 — the file-resolved pass re-runs on a TS/JS manifest edit only: Cargo.toml, composer.json, pubspec.yaml, Package.swift, compile_commands.json, buf.yaml and a tsconfig base named otherwise do not trigger it alone

- **Symptom:** RT-108 gates the file-resolved pass on a changed input (`fileResolveInput`): a file of a file-resolve language or a header. The strategies read repo manifests too (resolvestrategy.go: composer.json, pubspec.yaml, Cargo.toml, Package.swift, compile_commands.json, buf.yaml/buf.work.yaml, package.json), so an edit to one alone left the stored edges as they were until a source file changed.
- **Evidence:**
  - **Tool:** TestIngest_TSWorkspaceEdgesReResolveOnManifestEdit (wave lh): before LB-F228 an edit to packages/core/package.json or tsconfig.json alone skipped the pass with "no input changed since the last successful pass".
  - **Fixed for TS/JS:** `tsResolveManifest` (a tsconfig*.json, jsconfig*.json, package.json, pnpm-workspace.yaml or lerna.json) is an input since LB-F228.
  - **Still open:** the other strategies' manifests, and an `extends` base whose name is not tsconfig*.json or jsconfig*.json (configs/base.json, a shared package's preset.json), re-resolve with the next source change.
- **Root cause:** the gate predates manifest-reading strategies (LB-F11 added them after RT-108).
- **Fix:** TS/JS done (LB-F228); for the rest, each strategy's manifest names belong in `fileResolveInput` (the owner of each strategy's row), or the pass records the manifests a run read and gates on their fingerprints.
- **Status:** open (partly fixed)
- **Impact:** an edit to a Cargo.toml's [lib] path, a composer.json autoload map or a pubspec name leaves stale file edges until a source file of the language changes.
