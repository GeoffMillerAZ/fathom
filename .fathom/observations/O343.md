### O343 — an nginx or Caddyfile include stores no edge at ingest

- **Symptom:** an nginx or Caddyfile include stores no edge at ingest
- **Evidence:**
  - **Tool:** ingest's doc-xref pass (internal/fusion/docxref.go enrichDocXrefEdges, isDocCandidate)
  - **Expected:** the native proxy dialects' include and import references become file-tier doc-xref edges at ingest, as go.mod's do
  - **Actual:** `isDocCandidate` admits YAML/JSON/TOML/XML, MSBuild's extensions and go.mod/go.work by name only, so a `.conf`, `.cfg`, `Caddyfile` or `sites-enabled/*` file never reaches the pass; the edges exist only in lang-oracle's scoring
  - **Repro:** ingest a repository with `nginx/nginx.conf` including `h5bp/basic.conf`; `TypedEdges` holds no doc-xref edge between them
- **Root cause:** the candidate filter is a hand list, not manifest-driven
- **Fix:** none here (docxref.go is the tl item's); the integrator adds a manifest-driven line after tl lands (the wave px brief)
- **Status:** open — integration dependency of LB-Q-nginx and LB-Q-caddyfile
- **Impact:** a stored include graph waits for integration; extraction and route targets are unaffected
