### O341 — an include glob resolves to no file

- **Symptom:** an include glob resolves to no file
- **Evidence:**
  - **Tool:** `fusion.ResolveDocXrefs` (internal/fusion/docxref.go fileTargets), through lang-oracle's xref scoring
  - **Expected:** nginx `include conf.d/*.conf;` and a Caddyfile `import sites/*.caddy` reference every file the glob matches, as nginx and Caddy read them
  - **Actual:** a target with `*?[` is matched against the repository's directories (the one doc file directly in each), never against files, so the glob resolves nothing: 2 of 28 nginx includes measured (h5bp's `conf.d/*.conf`, NGINX-Demos' `/etc/nginx/conf.d/*.conf`) are misses
  - **Repro:** `TestResolveDocXrefs_NginxInclude` (internal/fusion/proxydialects_test.go): `include conf.d/*.conf` beside `conf.d/a.conf` resolves nothing
- **Root cause:** fileTargets' glob branch was written for kustomize-style directory globs
- **Fix:** none here (docxref.go is the tl item's); a file-glob branch (a glob whose last segment names files) would resolve both
- **Status:** open
- **Impact:** nginx xref_recall .9286 instead of 1; LB-Q-nginx-rest and LB-Q-caddyfile-rest name it
