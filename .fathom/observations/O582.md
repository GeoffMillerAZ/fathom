### O582 — two docs still describe the single observations log after EW-32

- **Symptom:** two docs still describe the single observations log after EW-32
- **Evidence:**
  - **Tool:** fathom observe (EW-32: one exclusive-create file per entry, .fathom/observations/O<n>.md)
  - **Expected:** docs/usage/observe.md says observe writes .fathom/observations/O<n>.md; docs/intent/scope.md's compatibility surface names the .fathom/observations/ directory beside the legacy observations.md
  - **Actual:** docs/usage/observe.md says "Appends a structured entry to <root>/.fathom/observations.md"; scope.md's ".fathom/ files an adopter commits" item lists observations.md only. The 0.10.0 changelog moves EW-32 to Breaking for that reason; both files belong to other items (docs/usage* is the docs item's)
  - **Repro:** grep -n 'observations' docs/usage/observe.md docs/intent/scope.md
- **Root cause:** EW-32 changed the write path and its tests, and no doc guard reads docs/usage/observe.md or the scope.md surface list
- **Fix:** docs/usage/observe.md names the per-entry file, the id minted over both, the exclusive create and the never-written legacy log; scope.md's adopter-committed list names `observations/` beside the legacy `observations.md`
- **Status:** fixed (wave rel integration)
- **Impact:** an adopter reading the usage page committed only observations.md and missed every new entry
