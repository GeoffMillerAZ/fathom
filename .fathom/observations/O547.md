### O547 — against a tier-A runtime require trace, Ruby L3 reads unmet: the resolver's source roots miss nested gems' lib/ and a test task's test/

- **Symptom:** the runtime require trace (LB-F256) attests 145 of 147 (sinatra) and 114 of 119 (jekyll) in-repo statements, tier A. Against it the dialect reads import_resolution .8031, file_edge_precision .9457 and file_edge_recall .4710. It reads .7513 on ruby-lsp and .5417 on spoom
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect ruby -tool-oracle <trace imports>` without -scip (wave lx, fathom cfa58b63)
  - **Expected:** every require Ruby resolves to a subject file under the program's own load path resolves to the same file
  - **Actual:** sinatra's 51 unresolved requires name rack-protection/lib (39) and sinatra-contrib/lib (12), which Bundler puts on the load path as path gems. ruby-lsp's 47 and spoom's 88 are `require "test_helper"` (and its siblings) from a nested test directory, resolved through the Rakefile's `t.libs << "test"`. Five of jekyll's six fathom-only file edges follow statements the trace did not execute
  - **Repro:** calibration/oracles/ruby-require-trace/README.md
- **Root cause:** the manifest's `imports.source_roots` are fixed directories (`lib`, the root). The file-symbol strategy reads no gemspec `require_paths` and no test task's libs
- **Fix:** none here (internal/fusion). Module roots in the manner of buf (LB-F77) would take each `*.gemspec`'s require_paths and each Rakefile test task's libs as source roots
- **Status:** open
