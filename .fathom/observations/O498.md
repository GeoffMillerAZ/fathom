### O498 — Timoni's L1 and L2 cap at good: the tool cannot name an entity or a line, so those families are tier C

- **Symptom:** L1 good (sym 1, 1) and L2 good (ref 1, 1) beside L3 excellent: "oracle tier C caps at good"
- **Evidence:**
  - **Tool:** `indexbench lang-tracker` row for Timoni, reading docs/bench/readings/lang/timoni.json
  - **Expected:** a tier-A definitions oracle, as the other T3 rows the owner cares about carry
  - **Actual:** the timoni CLI evidences which modules build, which kinds render and (by renaming a template) who uses it, never an entity's name or line; the definitions and references are the oracle's own walk of the CUE syntax tree (the parser library the dialect shares), gated by the tool
  - **Repro:** calibration/oracles/timoni/README.md
- **Root cause:** `timoni mod vet` and `timoni build` print rendered resources, not source positions
- **Fix:** none; the trigger is a CUE or Timoni command that prints a definition's position (cue's `--trace` and `cue def` do not), or an independent CUE parser
- **Status:** open
- **Impact:** the target (L3) is met; excellent on L1 and L2 needs a stronger oracle
