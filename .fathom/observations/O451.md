### O451 — fmt's file-resolved pass read every C++ header with the C grammar for one C file that includes none of them

- **Symptom:** footprint.md's LB-M5 profile: fmt (fmtlib/fmt 5da4e9a3) costs 5.01x its base, `file_resolved` 1.8 of 4.1 s.
- **Evidence:**
  - **Tool:** `fathom ingest --json --store <fresh> --service poly --path fmtlib_fmt` under `nice -n 10 /usr/bin/time -l`, 5f41217d; a timer around each stage of `resolveLang`.
  - **Expected:** a pass that resolves 3 C files costs about what 3 files cost.
  - **Actual:** the C resolver's "foreign" step (headers the router sent to C++, read for their includes and prototypes) took 3.9 s wall of a 4.7 s pass: fmt has 26 .h files, 24 read as C++, and `extractImports` parsed each with the C grammar though the one C file (test/c-test.c) reaches none of them but through fmt-c.h's own includes.
  - **Repro:** ingest fmt and read `pass_times` (`file_resolved` 2.2 s CPU in the first run).
- **Root cause:** `resolveLang` and `resolveFileEdgesWith` parsed every foreign header and admitted it to the include set (cproto.go).
- **Fix:** LB-F179: a foreign header is parsed and admitted only when an own file's import, or a reached header's text, names its base name (every include resolves to a path that ends in its operand, so no other header is an include's target). fmt: 70.1 G to 50.1 G instructions, `file_resolved` 2.2 to 1.07 s CPU, symbols, file_resolved, docs.units_written and docs.links_written identical (5,627, 1,686, 137, 149). TestOneParsePerDispatchedFile's wasm-parse counts fall by the one unreached header (7 to 6, 24 to 23).
- **Status:** fixed
- **Impact:** every C or C++ repository whose headers split across the two languages: the C resolver stops paying for the other language's headers.
