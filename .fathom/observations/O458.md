### O458 — Java's call truth gives a call inside an anonymous class to the enclosing named method, while its L1 oracle and the dialect make the anonymous class's method a definition

- **Symptom:** `indexbench lang-parity -dialect java -incumbent javaextract` refuses the Java tags dialect on call_recall 0.8019 < 0.8409 and call_precision 0.959 < 0.9779 (with sym_precision, O457, and file_edge_precision 0.9978 < 1)
- **Evidence:**
  - **Tool:** `indexbench lang-parity -dialect java -incumbent javaextract -subject google/guava=<guava v33.7.1>/guava -subject square/retrofit=<3.0.0> -tool-oracle <JavaParser 3.28.2 definitions, calls emptied, imports removed> -scip <scip-java 0.12.3 index>` (wave ld, 2026-10-02, `docs/bench/readings/lang/parity/java.json`), each side's call pairs both ways written through lang-oracle's `-unmatched` shape
  - **Expected:** a call is attributed to the same definition by the L2 truth and by the L1 oracle's definitions, so an extractor that defines what the L1 oracle defines is not penalized at L2 for it
  - **Actual:** of the 1,403 SCIP call pairs the dialect misses and the incumbent finds (guava 1,113, retrofit 290), 1,058 (779, 279) are a callee the dialect does record in the same file under another caller: a method of an anonymous class (`new AbstractIterator<T>() { protected T computeNext() {..} }`, `new InvocationHandler() { public Object invoke(..) {..} }`, `new Callback<T>() { public void onResponse(..) {..} }`), which the JavaParser dump and the dialect define and the truth does not (scip-java names an anonymous class's members `local N`, and the harness attributes a reference to its innermost mapped definition, the enclosing named method: `Retrofit.create` calls `getDeclaringClass`, where the dialect has `invoke`); 937 of the dialect's 1,031 extra fathom-only pairs are the same calls seen from its side. 137 are constructor calls (`new X(..)`), which the incumbent records and the dialect does not (O268). The incumbent defines no anonymous class's method, so its calls fall to the enclosing method as the truth's do
  - **Repro:** the parity run above; `Retrofit.java` `create`: `Proxy.newProxyInstance(.., new InvocationHandler() { @Override public Object invoke(..) { if (method.getDeclaringClass() == Object.class) ..` gives the truth pair (create, getDeclaringClass) and the dialect pair (invoke, getDeclaringClass)
- **Root cause:** the L2 truth's caller is the innermost definition fathom can map, and scip-java's anonymous-class members are locals the harness does not map; the L1 oracle (JavaParser) and the dialect count them as definitions
- **Fix:** none here (internal/langbench and the Java dialect query are not this item's): either the call-truth attribution maps scip-java's local definitions that carry an enclosing_range and a method name to fathom's same-named definition inside them (`internal/langbench/scip_java.go` beside `javaName`), so the truth names `invoke` as the dialect does; or, as an owner decision, the dialect stops treating an anonymous class's method as a caller. Then re-run lang-parity: the calls metrics move by up to the 1,058 pairs on each side
- **Status:** open
- **Impact:** with O457 and O268 this keeps Java on the CGO javaextract.go although the dialect reads sym_recall 1, sym_precision 1 (name-dated oracle), file_edge_recall 0.829 against 0.2922 and typed_recall 0.669 against 0.3634
