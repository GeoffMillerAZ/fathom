### O692 — the capability inventory read routes from a narrower file set than ingest did, until both read the route registry

- **Symptom:** `inventory.Extract`'s `routeLangFor` was a hand-kept suffix list (`.go`, `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.py`), while ingest's `serviceref.ExtractFile` reads every file `connector.LanguageForPath` tags `js` or `ts`, which adds `.cjs`, `.mts` and `.cts`
- **Evidence:** `internal/connector/connector.go` maps `.cjs` to js and `.mts`/`.cts` to ts; before the route seam (LB-F321), a route registered in `server.cjs` was a `service_ref` hop target but never a `route:` item for `conserve surface` or certify
- **Root cause:** two lists of "files a route reader reads", one per consumer, drifted
- **Fix:** both consumers now ask the registry (`routes.HasReader(connector.LanguageForPath(p))`), so a reader registered for a language reaches ingest, hops and the inventory at once; env: items keep their old suffix list (envkeys reads no Java or PHP), so no env item moved. Inventory now also yields route: items for `.cjs`, `.mts` and `.cts` files, and for every language a reader registers (java in wave c2)
- **Status:** fixed (wave c2, item java)
- **Impact:** a base-to-head `conserve surface` run compares two inventories built by the same rule, so no false loss; a repository with `.cjs`/`.mts`/`.cts` routes gains items it should always have had
