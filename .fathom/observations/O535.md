### O535 — a lower case name an import brings in, and a `show` name in an export, draw no Dart file edge: about 33 pairs

- **Symptom:** `boundaryCharacters` (a top-level const), `isProtocolException` (a top-level matcher), an inherited getter written bare (`state`), and the names of `export 'x.dart' show BrowserClient;` have scip-dart references and no fathom file edge
- **Evidence:**
  - **Tool:** the scratch classifier at fathom cd4c1e9e: bare-Variable 14 pairs, bare-Property 14, show-hide lines 8
  - **Expected:** an unprefixed reference to an imported top-level function, getter or constant is a file edge; an export statement's listed name is a reference to the exported file
  - **Actual:** the extractor keeps a reference only where its head names an import's local binding or, with a wildcard import, starts with an upper case letter (internal/extractor/tsrefs.go), so every lower case name is dropped before the resolver sees it; a name inside an import or export statement is never a reference
  - **Repro:** http/lib/src/multipart_request.dart:159 `boundaryCharacters[...]`
- **Root cause:** the upper case rule is the precision guard of a wildcard import (it keeps locals and parameters out); a Dart-only widening needs the dialect to say "the names a wildcard brings in are every top-level name"
- **Fix:** none this wave (tsrefs.go is shared, fusion is wave lh's): a manifest key `imports.wildcard_names: "any"` for dart that keeps a lower case reference only when the resolver finds a top-level definition of that name in a wildcard-imported file (the lookup the resolver already does, with the name as the key), plus a `@ref.name` capture on the identifiers of an export's `show` combinator
- **Status:** open
- **Impact:** about 33 of Dart's 133 missing pairs
