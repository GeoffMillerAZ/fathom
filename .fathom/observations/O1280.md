### O1280 — the generic import builder cannot bind an alias and the bare form without writing the statement twice

- **Symptom:** a Lua `local x = require "m"` could carry an alias (`x`) in one pattern and the bare `require "m"` in another, but a call like `local x = require "m"` matches both and the builder records two specs for the one statement. The lua dialect binds no alias as a result.
- **Evidence:**
  - **Tool:** `importSpecsWithSpans` (internal/extractor/tsimports.go), generic `@import.module` case
  - **Expected:** one spec per statement, or a way to say "alias when the call is assigned"
  - **Actual:** no dedupe by module node (only the JS-specific cases use `claimed`), so overlapping patterns double-count
  - **Repro:** two patterns that both capture the same `@import.module` node give two ImportSpecs
- **Root cause:** `claimed` dedupes by statement range for the JS cases only.
- **Fix:** none needed for L3 (file-symbol brings every top-level name of the target into scope, and the measured file-edge recall is 1). Revisit if a call through the alias (`util.trim()`) needs the prefix binding.
- **Status:** open
