### O682 — the Node route readings cannot be re-scored without a runtime: their oracle files were never committed

- **Symptom:** wave lf2's brief asked for every wave c2 route subject re-read against the committed oracle JSONs, with no runtime. Java, PHP and Python have them; the four Node frameworks do not, so `indexbench route-oracle` has nothing to score Nest, Fastify, Express or Next.js against without `npm install`, `tsc` or `next build` on each pinned subject
- **Evidence:** `calibration/oracles/{express,fastify,nest,nextjs}/` hold only the converters and READMEs (`dump_routes.*`, `to_route_oracle.mjs`); the fastify README says "outputs stay out of the repository"; `calibration/oracles/{spring,jaxrs,laravel,symfony,django,fastapi,flask}/` each commit the oracle file beside the converter. Wave lf2 re-read the 68 Node subjects by a differential instead: route-oracle from origin/main `784657b9` and from `284b658d`, the 25-entry miss cap lifted in scratch copies, against an empty oracle, so each extra list is fathom's whole bound route set; identical on every subject (`docs/bench/readings/routes/node.md`)
- **Root cause:** wave c2's item node wrote the oracle files to scratch and committed only the readings
- **Fix:** proposed, not built: on the next Node runtime pass, commit each subject's `to_route_oracle.mjs` output beside its converter (78 Nest, 26 Fastify, 76 Express and 21 Next.js routes, all MIT or Apache-2.0), as the other frameworks do; until then a Node re-read is a differential against a prior binary, which proves no regression but cannot score a reader change that adds or fixes a route
- **Status:** open
- **Impact:** a Node reader change cannot be scored without a runtime; a differential needs a scratch patch of `routeOracleMissCap` on both binaries
