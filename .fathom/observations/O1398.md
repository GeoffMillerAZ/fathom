### O1398 — A tags query `parent field: (child)` matches only the first child of a repeated field

- **Symptom:** `(variable_declaration value: (variable_name) @n)` captured `$pad` of `$inner: $pad + $gap` and never `$gap`; `margin: $a $b` and `@if $a == $b` lost their second operand.
- **Evidence:** `indexbench lang-probe -dialect scss` on `$inner: $pad + $gap; a: $pad * 2 - $gap;` lists one capture per declaration while the tree shows `value:` on every operand; the same operands match when the pattern names the parent without the field (`(property_declaration (variable_name) @n)`) and a leading sibling (`(variable_declaration name: (variable_name) (variable_name) @n)`).
- **Root cause:** not isolated (the engine's cursor or the grammar's repeated field); the behaviour is what the scss queries must work around.
- **Fix:** the scss queries name the parent and, where a name child must be excluded, a preceding sibling; the field form is used only for single-valued fields (`parameter value:`, `member_expression name:`).
- **Status:** open: a dialect author reading `field:` as "every child with that field" is wrong in this engine
- **Impact:** any tags query built on a repeated field misses all but its first child, silently.
