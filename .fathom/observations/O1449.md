### O1449 — After an edit the index lags, and fathom tells the agent only where the agent cannot see it: the edit-time timeout opens the breaker the post-commit refresh needs, and the shed notice rides outside the tool result

- **Symptom:** after edits or a commit, `find_symbol` and `symbol_context` miss a function the working tree defines, `verify` fails a row a fresh store proves, and a claim-moment hook rejects a proven row. None of these answers says it came from an index behind the tree. Adopters filed 18 reports between 2026-08-12 and 2026-10-19 (theme T05 in docs/bench/readings/feedback/adopter-triage-2026-10-20.md).
- **Evidence:**
  - **Reports:** adopter repository C O2, O4, O5, O7 and app-kit O102 (the edit hook's refresh: `Post …/refresh-file: net/http: request canceled while awaiting headers`). Adopter repository C O6 (the post-commit refresh "was refused because the breaker remained open after earlier refresh-file timeouts; index stayed at the prior commit"). Adopter repository C O8 (post-commit refresh reported success, new files absent). app-kit O20, O58, O65, O70, O71, O77 (current or dirty definitions missing). Adopter repository C O13 and app-kit O120 (verify and the claim hook judged an index behind the tree). app-kit O35 and O38, plus adopter repository B O4 (shell-written files stayed invisible).
  - **Code:** the edit hook's `ensureFileFresh` (cmd/fathom/edithook_pre.go) has a 400 ms budget (`refreshTimeout`). hookguard counts a client timeout as a failure that opens the shared breaker (`TestClientTimeoutCountsAsFailure`, internal/hookguard). The post-commit hook says "the kill switch and the shared breaker still apply" (cmd/fathom/postcommithook.go). When the tenancy ladder sheds, a read's refresh is deferred and disclosed as `deferred (shed) — served from the index as it stands; freshness not checked` (internal/tenancy/refreshgate.go). `dispatch` puts that note in an envelope key, `refresh`, beside `content` and `structuredContent` (internal/mcp/dispatch.go). `budget` and `suppressed` go there too.
  - **Probe, 2026-10-20, deployed binary 909ea5c2e:** `find_symbol {service: agentic-kit, name: main}` answered with `refresh: {agentic-kit: "deferred (shed) — served from the index as it stands; freshness not checked …"}` outside `content`. The text block the agent reads carried no freshness word.
- **Root cause:** two faults. (1) The breaker is shared. A 400 ms edit-time refresh times out whenever the daemon is busy, and each timeout opens the breaker that the post-commit refresh then honours. The one refresh that would bring the index up to the commit is the one skipped. (2) The disclosure is out of reach. MCP defines a tool result as `content` and `structuredContent`, and a client shows the model those. The shed and refresh notice is in neither, so the agent reads a stale definition as current. Edits that no hook sees (a shell redirect, an `apply_patch` in a harness without fathom's edit hook) leave a file stale until the next ingest, with the same silence.
- **Fix:** proposed, not built. (1) Exempt the post-commit `/refresh-request` from the edit-time breaker, or open the breaker per class (`BusyScopeClass` exists for refusals). The request is queued (202) and nothing waits on it. (2) Carry the refresh disclosure inside the result object: a `freshness` field in the JSON text and structuredContent, naming the index commit and, when it is cheap, the dirty files the answer touches. Move `budget` and `suppressed` there too.
- **Status:** open
- **Impact:** agents that trust a stale answer miss code that exists, or fail a proven row. The fathom answer is wrong, and nothing in it says so.
