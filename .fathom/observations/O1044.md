### O1044 — A merged reading keeps a harness note after its premise changes: "xref not measured" outlived Jenkins L3

- **Symptom:** the first jenkinsfile.json run of wave lf8, merged into the committed reading, carried both "xref not measured: the dialect is no doc engine and names no import strategy" and the new Jenkins xref unit note, beside measured xref metrics.
- **Evidence:** `mergeNotes` (cmd/indexbench/langoracle.go) appends and never removes; the old note was the harness's own (fileXrefs.resolve), so no re-run can retract it. helm.json likewise keeps the 2026-10-02 note "L3 stays tier C, the ceiling" beside the new `L3 ceiling: ` note.
- **Root cause:** a reading's notes are the union of every run's, so a note whose condition no longer holds is never dropped.
- **Fix:** jenkinsfile.json was written into a fresh file by a second run of the identical code and data (every count equal to the first, 9576662a). The durable fix is the harness's: drop the notes a run's own code would write but did not (the subject-prefixed and rule notes it owns), the integrator's file (langoracle.go).
- **Status:** open (LB-F563)
- **Impact:** a stale note can contradict a reading's metrics; helm.json's older ceiling note is redundant, not wrong.
