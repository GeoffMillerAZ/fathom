### O655 — doctor read Claude Code's agents-md setting under the plugin's old id only: a claude-md setting under cc-plugin-agents-md@builtin read as unset

- **Symptom:** none reported by doctor; found by the owner's K12 reading (2026-10-09): `effectiveInstructionFilesMode` read `pluginConfigs["agents-md@builtin"].options.instructionFiles` only, so a user or managed settings file setting `instructionFiles = "claude-md"` under the id Claude Code uses since 2.1.285 passed `stanza_present` as `native (no CLAUDE file, default mode)` while Claude Code did not load AGENTS.md
- **Evidence:** Claude Code 2.1.277 through 2.1.284 named the plugin `agents-md@builtin`; 2.1.285 renamed it `cc-plugin-agents-md@builtin`. The descriptor note (internal/harness/descriptors.go L55), doctor's reason and remedy, docs/design/agents-md.md, docs/adoption/claude-code.md and docs/usage/doctor.md named the old id alone
- **Root cause:** the plugin id was a literal in cmd/fathom/doctor_claudeload.go with no version boundary; the rename changed the key, not the contract, and nothing pinned the key against a current release
- **Fix:** doctor reads both ids, the new one first, names the id it read, and names a settings file whose two ids disagree; every reason, remedy, comment and doc names both ids with the 2.1.285 boundary; ADR-059 note 2026-10-09 (AG-27, commit 89fbe434)
- **Status:** fixed (wave w2a)
- **Impact:** any operator who turned AGENTS.md loading off under the new id got a false PASS from `fathom doctor`; the ADR-059 trigger "Claude Code changes the agents-md contract" fired on the id alone
