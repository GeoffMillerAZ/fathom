### O1136 — `fathom intent audit` U4 reports tests as missing when the daemon's index is stale: 181 of 229 unproven claims were the index, not the tests

- **Symptom:** U4 lists invariants and `Done needs` whose named tests "do not exist". In the intent-practice-v2 review (`wf_a6ee03dd-707`), 181 of the 229 unproven claims it listed named tests that exist in the working tree; the daemon's index was behind HEAD.
- **Evidence:**
  - **Tool:** `fathom intent audit` (`auditInvariants`, `internal/intent/audit.go`; the `SymbolOracle` from `newIndexOracle`, `cmd/fathom/intentoracle.go`)
  - **Expected:** a test named by an invariant is checked against the repository the audit reads (its test files at HEAD); an index that cannot answer is named as such (I38), never reported as a missing test.
  - **Actual:** the U4 index half asks the daemon's index whether the name is known; a stale index answers "unknown", and the audit counts that as an unproven claim.
  - **Repro:** run `fathom intent audit` against a daemon whose fathom ingest is behind HEAD by commits that added tests named in `docs/intent/`; compare the U4 list with `grep -rn "^func TestX" --include=*_test.go`.
- **Root cause:** the oracle's source is the index, which can lag; the repository itself is the authority for whether a test function exists.
- **Fix (proposed shape):** test first: with a stale oracle and the test present in the tree, U4 reports no missing test. `docs/plans/intent-v2.md` IV-8, ADR-074 decision 7.
- **Status:** open
