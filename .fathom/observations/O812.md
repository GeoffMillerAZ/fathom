### O812 — the re-landed nested-module typed pass halted at refuse on a cold build cache, so stranger-check never confirmed its index

- **Symptom:** `task validate` on the h5 reland branch failed `stranger-check`: `fathom init` waited 30 min and exited 2, "service "stranger" did not confirm as indexed"
- **Evidence:** the throwaway daemon's log (FATHOM_TENANCY_BUDGET=4GiB): `tenancy: shed → refuse: footprint+children 4.2 GiB ≥ refuse mark 4 GiB (children 3.4 GiB)`, then `typed-edge pass "stranger" ... halted after 293 package(s): over budget`; the refuse diagnostics counted 3 child processes at 3.68 GB; the largest was `compile -p github.com/aws/aws-sdk-go-v2/service/ec2` at up to 2.1 GB RSS, a dependency of fathom's own `calibration/oracles/prometheus` module (its path is the repository's, so EW-59 loads it). A second ingest on the same daemon halted the same way 47 s in: the halt killed `go list` before it cached the compile, so no retry progressed. The compile itself outlived the halt (ppid 1, 1+ min). On the shared warm cache (the lever's ingests) the same tree ingests cleanly
- **Root cause:** a nested module's `go list -export` compiles its whole third-party graph on a cold cache, at the pass's parallelism (-p=2, GOMAXPROCS 2): two big compiles beside `go list` cross a managed-sized budget that the root module alone never reached
- **Fix:** a nested module's load runs at toolchain parallelism 1 (GOFLAGS -p=1, GOMAXPROCS=1; `nestedModuleEnv`, wave h5); the root load keeps the ceiling; FATHOM_TOOLCHAIN_PROCS=off still lifts every cap. A warm cache compiles nothing either way
- **Status:** fixed for the stranger-check budget (see the h5 reland report for the re-run); the orphaned compile after a halt is not addressed here (the go command's runner kills `go list`, not its compile children)
- **Impact:** without it, a first ingest of fathom (or any repository whose own nested module pulls a very large dependency) by a managed daemon on a cold cache halts at refuse on every attempt; with the epoch 5 re-run (EW-63) that includes the first ingest after deploy
