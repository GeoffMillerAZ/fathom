### O632 — a remote action pin's SHA-or-tag classification is not expressible in a doc spec; the pin nodes come from a fusion-side wrapper

- **Symptom:** `uses: o/r@<40 hex>` and `uses: o/r@v4` are told apart by no entity selection: the engine has no regular expression in `where`
- **Evidence:** DocWhere has `equals` (exact) and key predicates only; DocRef.Pattern reads values into references, not entities
- **Root cause:** an engine gap owned by item prom
- **Fix:** `extractor.GHADialectExtractor` (ghaextract.go) wraps the dialect and appends a GHAPinSHA or GHAPinRef node per remote `GHAAction`; fusion registers the wrapper. `lang-oracle` and `lang-parity` measure the unwrapped dialect, so the pins are covered by tests (TestGHAPinKind, TestGHADialectExtractorPins, TestIngest_GitHubActionsDialect), not by a reading
- **Status:** fixed for the step-level pins; a job-level `uses:` (a reusable workflow call) is not a pin node
- **Impact:** a `where.matches` (RE2) on a selected scalar would let the dialect carry the classification and the wrapper go
