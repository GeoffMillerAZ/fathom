### O297 — one section's per-call deadline aborts the whole compile and drops every compiled section

- **Symptom:** a compile ran 37 minutes, one claude-cli call hit its own 5 minute subprocess deadline, and the run returned an error with every compiled section's claims discarded.
- **Evidence:**
  - **Tool:** compile_layer / `fathom compile` (claude-cli lane)
  - **Expected:** the one section counts failed and the loop continues; compiled sections are stored.
  - **Actual:** `errors.Is(err, context.DeadlineExceeded)` was read as caller cancellation (internal/semantic/compile.go) and the run returned before PutClaims.
  - **Repro:** a fake LLMClient whose second of four calls returns a wrapped DeadlineExceeded under a live ctx (TestCompilePerCallDeadlineCountsSectionFailedAndContinues).
- **Root cause:** the abort test matched the error value, not the caller's context; the early return sat before the store flush.
- **Fix:** EW-33 (callerAborted: only ctx.Err() aborts; an abort flushes claims and records the run), EW-34 (claude-cli `timeout` key).
- **Status:** fixed — EW-33, EW-34
- **Impact:** a 37-minute compile's work was lost to one slow section.
