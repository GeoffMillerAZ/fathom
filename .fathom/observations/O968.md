### O968 — files sharing a stem in one directory share one module-symbol key across dialects (O915's cross-dialect form)

- **Symptom:** every dialect that mints a module symbol (K18) under package strategy "dir" keys it by the file's stem, so a stem two files share in one directory is one key, whichever dialects read them: `foo.component.ts` (typescript), `foo.component.html` (html) and `foo.component.css` (css) are all `svc::app/foo.component.<module>`; `index.ts`, `index.js` and `index.html` are all `svc::app/index.<module>`; a C++ `foo.hpp` and `foo.cpp` are both `svc::src/foo.<module>`. Live on main (c39875f3).
- **Evidence:** a scratch ingest at c39875f3 + the shell branch (wave lf7) of a probe tree holding those eight files: `select package, group_concat(source_ref) from observations where symbol = '<module>' group by package` reads `foo.component` for three files, `index` for three and `foo` for two (`foo.h` reads as C, which mints none). An edge naming the key (an import, a re-export, an `#include`) maps to any of them, as O915's did for PowerShell's `X.psd1` beside `X.psm1`; find_symbol `<module>` scoped to one file and blast_radius from a module symbol read the merged set.
- **Root cause:** the module symbol's key carries the file's directory and its package, and package strategy "dir" is the stem; `core.ModuleSymbolName`'s contract assumed a dialect claims one extension per name, and nothing assumed two dialects never share a stem (Angular's component triplet, a web root's index files, C++'s header beside its source).
- **Fix:** the foundation exists (LB-F519, wave lf7: package strategy "file", the base name with its extension, which PowerShell's held change opts into for O915). No existing dialect is re-keyed here: re-keying moves every module key (and, for "file", every definition key) of the dialect, so every reading that scores keys re-reads (K29), and each ingested service changes its keys at the next ExtractorEpoch.
- **Status:** open. Trigger: an owner ruling on re-keying existing dialects (which dialects, "file" for all definitions or for the module symbol alone, and the K29 re-reads it costs).
- **Impact:** a file-level question (who imports this component's template, what includes this header) can name the sibling; the definitions inside each file keep keys of their own only where their names differ.
