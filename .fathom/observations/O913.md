### O913 — a bash `.` call has an empty bare name, so its oracle pairs are never found

- **Symptom:** bash's L2 call_recall reads .9268 on bats-core 713504bc and nvm 1889911f once the calls oracle pairs top-level calls with the module symbol (K18, wave lf6, branch `lf6-shell-l3`), down from .9799.
- **Evidence:** `indexbench lang-oracle -unmatched` at 2d009537: 298 of the 314 oracle-only pairs have an empty callee (bats-core 20, nvm 278; before the module caller, all 50 misses were the same). The ts-tags oracle writes the `.` command's text, `.` or `\.`; `langbench.BareName` keeps the text after the last `.`, which is empty for both, and `callPairs` drops a fathom call whose bare name is empty while the oracle's pair stays in the truth.
- **Root cause:** an asymmetry in the harness's pair rule: an empty bare callee is skipped on fathom's side only.
- **Fix:** none here (a harness rule, K29: every reading with such a pair would be re-read). The 16 other misses are `cd` and `pwd` in an `export NAME="$(cd … && pwd)"`, which the dialect gives to the exported variable and the oracle to the module.
- **Status:** open. Trigger: the harness drops (or keys by the full text) a callee whose bare name is empty, on both sides, with a K29 re-read.
- **Impact:** bash's L2 recall is understated by about 7 points; the grade (good, tier C) does not move.
