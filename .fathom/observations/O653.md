### O653 — a repository's config chose paths and hosts outside it: a store the session hook wrote, a key host, files read anywhere

- **Symptom:** none seen; found by the SEC-2 audit (2026-10-09), grouped (four paths of one class)
- **Evidence:** (1) the SessionStart/SubagentStart outbox sync (`syncFindingsOutbox`) loaded the project layer alone, accepted an absolute or `..` `[findings] outbox` and exec'd `fathom findings import --store <the repository's [daemon] store>`, a write anywhere on disk (`TestSEC2_FindingsOutboxNeverWritesOutsideTheRepo`); (2) `[daemon] store`, `addr` and `call_log` from a repository set where a daemon started inside it writes, listens (`0.0.0.0` exposes it) and logs; (3) `[profiles.*] endpoint` from a repository received the user's `OPENAI_API_KEY` (the openai lane's default key variable); (4) `[tests] results_dir` (plain ingest and conserve's coverage meta), `[[work.ci_summaries]] path` (the console's /work) and `[connector] include` accepted absolute, `..` and symlinked-out paths, so a repository made fathom read files outside it (`TestSEC2_IngestRefusesResultsDirOutsideTheRepo`, `TestLoadConfiguredCoverage_ResultsDirOutsideTheRepoIsRefused`, `TestWorkCIRunsRefusesPathsOutsideTheRepo`, `TestLoadConnectorConfig_RefusesIncludeEntriesOutsideTheCorpus` each fail with the fix reverted)
- **Root cause:** the loader had no scope rule: every field merged project over user, and each use site joined a configured path to the root without confining it
- **Fix:** `daemon.store`, `daemon.addr`, `daemon.call_log`, `daemon.auto_refresh`, `daemon.memory_limit` and `profiles.*.endpoint` are user-only (dropped and named at Load); the outbox sync reads `[daemon] store` from the user config; one helper, `config.RepoPath`, refuses an absolute value, a `..` escape and a symlink escape by name at every repo-path use site, and `config.RefusedRepoPaths` names them in `fathom config` and doctor (CF-15..CF-17)
- **Status:** fixed by the SEC-2 commits
- **Impact:** every repository fathom opens; `configuredCallLogPathAt` (J5) no longer finds a repository-configured call log and falls back to the state-dir log, which is where a daemon writes one
