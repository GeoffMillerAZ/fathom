### O1284 — Retiring graphqlextract.go: what the dialect beats, what it changes, the epoch need

- **Symptom:** `.graphql` and `.gql` were read by gqlparser's schema parser, which returns nothing for a file holding an operation, a fragment or an extension (types and fields included), emits no directive definition or enum value, and no reference
- **Evidence:** `docs/bench/readings/lang/parity/graphql.json` (MERGE at L2 against graphql-js 16.14.2 on octokit/graphql-schema and gqlgen): sym_recall .8725 to 1, sym_precision 1 to 1, ref_recall 0 to 1; GraphQLDirective, GraphQLEnumValue, GraphQLExtension, GraphQLFragment, GraphQLOperation gained. No definition of the oracle is lost. Changed, not lost: a type's Signature (`object`, `input_object`, `enum`) is now its header as written (`type Query`), a field's (`String!`) the field as written (`name: String!`), and a described definition's starts at its description (O1283); a symbol's Line is its name's line
- **Root cause:** the incumbent was a schema-only walker over a parser that fails the whole file on the first non-schema definition
- **Fix (done, wave lang1):** the hand lines for `.graphql` and `.gql` are gone, the manifest loop claims both, graphqlextract.go and its tests are deleted, with lang-parity's incumbent entry and the tracker's registered-format entry; `TestGraphQLDialectKeepsIncumbentContracts` carries the incumbent's contracts. Epoch need for the integrator: every `.graphql` and `.gql` file re-reads (`fusion.ExtractorEpoch` bump, not taken here so parallel items do not collide); `gqlparser` stays in go.mod only if another package imports it (integrator's `go mod tidy`)
- **Status:** fixed (wave lang1), epoch bump pending
- **Impact:** GraphQL operation documents and extension files now index; schema files gain end lines, enum values, directives and type references
