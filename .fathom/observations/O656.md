### O656 — doctor's machine-side remedies prescribed a root CLAUDE.md with an @AGENTS.md import where AGENTS.md exists

- **Symptom:** `fathom doctor`'s `stanza_present` and `stanza_loaded` remedies for an ancestor CLAUDE file, the `instructionFiles` setting at `claude-md`/`managed-only`, and a Claude Code before 2.1.277 each ended "or add/import @AGENTS.md from a root CLAUDE.md", against the owner's K12 decision (2026-10-09): content lives only in AGENTS.md
- **Evidence:** cmd/fathom/doctor_claudeload.go `claudeLoad.warnings()` (L276-297 at 9e66f323); TestNoMachineRemedyPrescribesAClaudeImport fails on the three cases at the base commit
- **Root cause:** the remedies were written for ADR-059's first layout, where a CLAUDE import was the universal fallback; K12 retired creating CLAUDE files and the remedies were not revisited
- **Fix:** the three remedies name only the native path (move or merge the ancestor CLAUDE file into an AGENTS.md beside it, set `instructionFiles` under both ids, upgrade Claude Code); AG-3's import region for a CLAUDE file that already exists is unchanged, as are this repository's five `@AGENTS.md` files until one cloud session proves native loading (AG-28, commit 89fbe434)
- **Status:** fixed (wave w2a)
- **Impact:** every adopter whose machine warns; following the remedy recreated the CLAUDE files K12 removes
