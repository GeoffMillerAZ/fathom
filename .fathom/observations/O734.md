### O734 — the Next.js route reader reads a Vite app's `src/pages/*.tsx` as Next pages

- **Symptom:** react-router's lazy-loading example (a Vite app, no Next) stores `GET /About AboutPage` and, through its dashboard mount, `GET /dashboard/Dashboard Dashboard`, routes React Router never serves
- **Evidence:** `docs/bench/readings/routes/react-router.json`, subject remix-run/react-router/examples/lazy-loading: route precision .75, 2 of its 3 extra routes; `readNext` gates a `pages/` file on a default export plus JSX or a react import, all of which a React Router page component has
- **Root cause:** a per-file reader cannot see the project: whether `next` is a dependency or a `next.config.*` exists
- **Fix:** proposed (the route seam's owner, nextjs.go): a project-level gate, e.g. ingest tells a reader the service's framework dependencies from its package.json; until then a React Router file (one importing react-router) could veto a Next reading of the same app
- **Status:** open
- **Impact:** route precision for every Vite or CRA app with a `src/pages/` folder, a common layout
