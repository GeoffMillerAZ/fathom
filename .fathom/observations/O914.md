### O914 — a shell library with no extension and no shebang is read by no dialect, so sourcing it draws no edge

- **Symptom:** the bash holdout (kward/shunit2 v2.1.8, kward/shflags v1.3.0, wave lf6, branch `lf6-shell-l3`) has 23 literal `.` statements that resolve to a file of the subject, and only 8 count: 15 name a file fathom never reads.
- **Evidence:** calibration/oracles/bash-source on the holdout: targets `shunit2_test_helpers` (6), `shflags_test_helpers` (5), `shflags` (3) and `examples/math.inc` (1), each without an extension the bash manifest claims and with no `#!` line (`# vim:et:ft=sh:...`); lang-oracle counts them `import_oracle_out_of_scope`.
- **Root cause:** a file's dialect is decided by its name or its first line (D4); being sourced by a bash script is no signal ingest reads.
- **Fix:** none (disclosed in docs/languages.md's Bash row on the L3 branch).
- **Status:** open. Trigger: a measured need (a calibration subject whose sourced libraries carry neither), then a rule that reads a resolved `source` target as its importer's dialect (a fusion change: the file resolver would hand the target to extraction).
- **Impact:** a test helper or library sourced this way has no symbols, and the scripts sourcing it no file edge to it.
