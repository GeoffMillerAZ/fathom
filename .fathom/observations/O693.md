### O693 — a route's served path can depend on configuration no source reader sees, and the seam has no mount target for "the whole module"

- **Symptom:** quarkus-realworld-api serves `GET /api/articles`; its source declares `@Path("/articles")`. fathom's `route:GET /articles` would not join a client calling `/api/articles`
- **Evidence:** the subject's `application.properties` sets `quarkus.rest.path=/api`; the running app's OpenAPI (`docs/bench/readings/routes/java.md`) prefixes all 19 routes; the JAX-RS oracle strips it (`-strip-prefix /api`) and the reading counts 19 of 19 as this ceiling. The same shape: Spring's `server.servlet.context-path`, a JAX-RS `@ApplicationPath` class, a servlet mapping in `web.xml`
- **Root cause:** the route seam's mounts name files (`./x`, `../x`, `/x`, a dotted module, a directory's direct files); a deployment root applies to every file of a module, which no target form names
- **Fix:** proposed, not built: a reader for the configuration (`application.properties`/`.yml`, an `@ApplicationPath` type) that reports a mount, plus a contract amendment for a module-wide target (for example a directory target that names every file under it, recursively). That amendment changes Compose for items node and phppy too, so it waits for a decision. JAX-RS sub-resource locators (12 locators, 340 sub-resource HTTP methods unread on keycloak's resources) need no amendment: a locator's mount target is its return type's dotted name, which the dotted-module form resolves
- **Status:** open (ceiling counted in LB-F325)
- **Impact:** for a deployment with a configured root, a route key and a client URL differ by that root; a service_ref hop from a client that writes the full path is missed
