### O717 — symbol_context's snippet window serves the lines beside a definition, a Secret's data included (2026-10-10)

- **Symptom:** the snippet reads `symbolContextSnippetMaxLines` lines from a definition's line whatever its end line, so an Alertmanager route's snippet served the receivers' webhook URLs and keys below it, and a Kubernetes Secret object's (`K8sWorkload Secret/<ns>/<name>`) serves its `stringData`
- **Evidence:** TestIngest_AlertmanagerSecretsNeverStored found the sentinel in symbol_context answers about receivers, a datasource and a contact point before the fix; no store table held it
- **Root cause:** the snippet is a bounded read of the file, not of the definition's span (most Go definitions carry no end line, T5-6)
- **Fix:** LB-F367 / ADR-065: a dialect marks an entity `sensitive` and symbol_context withholds its snippet (`snippet_withheld`); every Alertmanager entity and Grafana provisioning entity is sensitive. A Kubernetes Secret object is not covered (k8sextract's `K8sWorkload` kind is shared by every object)
- **Status:** fixed (2026-10-10, wave h3, SR-76, O767): the answering layer withholds the snippet of every definition in a file holding a sensitive entity or a core Kubernetes Secret (`snippetWithheld`, internal/mcp/secret_withhold.go), the Secret object's own included, ahead of the kubernetes dialect's dispatch
- **Impact:** an agent asking symbol_context about a Secret object receives its data
