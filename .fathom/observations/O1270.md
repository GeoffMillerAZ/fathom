### O1270 — the certificate sweep costs a full call-graph build, about 8 to 13 s on fathom, on every repeat ingest at the same commit

- **Symptom:** TC-8 wired `certify.SweepCertifications` into `fathom ingest`: when the certifications layer is already compiled at the current commit, the skipped compile hands over to the sweep. On fathom the sweep re-reads every symbol and typed edge and rebuilds the call graph, the same cost a compile pays. Before TC-8 that repeat ingest paid only the hash gate's count reads.
- **Evidence:**
  - **Tool:** `fathom ingest` (scratch store of 10a63138 plus this change, 22 declared certificates, 22 compiled), then `certify.SweepCertifications` timed three times against a copy of that store
  - **Expected:** a sweep of 22 certificates in well under a second
  - **Actual:** 12,599, 10,749 and 8,922 ms. Split: claims 0 ms, symbols 800 ms (56,793), typed edges 1,564 ms (183,135), `callgraph.Build` plus `AddTypedEdges` 6,786 ms. No git read ran (the scratch store holds no attested run). The whole ingest took 671 s.
  - **Repro:** `fathom ingest --store <scratch> --service fathom --path .` twice at one commit; the second ingest runs the sweep
- **Root cause:** the sweep rebuilds the call graph from the store for its reach checks, like the compile. Holding the graph across ingests would be a cache, which the table freeze rules out.
- **Residual gaps of the hash gate (`certifyNextStep`):** it compares the claim count with the marker-declaration count only. A test renamed at the same commit leaves the old certificate `contradicted` but compiles none for the new name until the next commit. Once a suite-level `#Certifies` entry compiles, the service holds more claims than marker declarations, so it always compiles and never sweeps; the compile re-derives every certificate, so nothing is missed, but nothing is saved either.
- **Fix:** the sweep runs only when the ingest read a file (`Extracted + Skipped - StatSkipped`), found a stored file gone (`Report.Deleted`) or picked up a new run (a changed newest run per test). A no-op ingest of fathom: 9.0 and 9.9 s before, 1.41 s twice after, stat-skipped 6,022. A changed ingest still sweeps in full (`TestNoOpIngestSkipsTheCertificateSweep`). The call-graph memo below still serves a changed ingest and O1260, after RT-M1.
