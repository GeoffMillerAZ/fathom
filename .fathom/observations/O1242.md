### O1242 — On macOS 27, `codesign -dv` prints no Authority, so the signing row read a fathom-dev binary as "no authority named"

- **Symptom:** `fathom daemon status` printed `signing: signed, no authority named (identifier fathom)` for `~/.local/libexec/fathom/fathom`, which `task deploy` had just signed with fathom-dev.
- **Evidence:** 2026-10-19 on macOS 27.0.1, the binary installed from 1606ee4a. `codesign -dv` prints Identifier, CodeDirectory, `Signature size=1779` and Signed Time, but no `Authority` line. `codesign -dvv` on the same file prints `Authority=fathom-dev`.
- **Root cause:** `binarySigningIdentity` (cmd/fathom/daemon_signing.go) ran `codesign -dv` and read the leaf from the first `Authority=` line, which on this macOS only appears at `-dvv`. The ad-hoc and unsigned readings were unaffected (`Signature=adhoc` and "not signed at all" still print at one `-v`).
- **Fix:** run `codesign -dvv`. `TestSigningIdentityAsksCodesignForTheAuthority` pins it: the one-v output alone must not decide the reading.
- **Status:** resolved
- **Impact:** a correctly signed daemon read as unverified in status and in doctor's signing line. That hid the one fact an EPERM or launch triage needs first: is this the fathom-dev identity.
