### O1326 — The pipeline's extension lookup is exact, so `.R` needs its own manifest key

- **Symptom:** an ingest of `R/model.R` produced no R symbols while `R/util.r` did, with the manifest listing `.r` only.
- **Evidence:** `Pipeline.resolveExtractor` looks `filepath.Ext` up in `p.exts` unchanged; `sniffedExtractor` (register.go) folds a case variant only to the dialects `p.sniffExts` holds (a sniff or glob dialect), so a `.R` falls through unread, as a `.PY` does. The connector's `extClassMap` is exact the same way. dplyr's 195 R files are all `.R`.
- **Root cause:** extensions are case-sensitive keys by design (a `.PY` stays unread); R's common spelling is the upper-case one.
- **Fix:** the r manifest lists `.r` and `.R`, and `extClassMap` carries both (internal/connector/connector.go); TestIngest_PerlAndRReachTheirDialects reads both.
- **Status:** fixed
- **Impact:** a language with two spellings needs both as keys; `.Rmd` and `.rd` are other files and stay unread.
