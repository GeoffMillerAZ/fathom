### O730 — a one-file refresh of a run step's script left the doc-xref pass marked done: the edge to a function the edit removed outlived it

- **Symptom:** `passKeysFor` cleared the doc-xref pass's success record only for a doc candidate, while the pass's own gate (`isDocXrefInput`) also re-runs for an image-build source (a Makefile, a `.sh` script, a Dockerfile) and, from wave c3, a Jenkins file
- **Evidence:** `TestReingestFile_RunStepTargetInvalidatesThePass` (internal/fusion): after an ingest, a `ReingestFile` of the Makefile or of `scripts/ci.sh` (each on a fresh ingest) left `passStateOK(doc-xref)` true, so the next ingest, seeing the script's new fingerprint as unchanged, skipped the pass
- **Root cause:** two predicates for one pass: the gate read `isDocXrefInput`, the invalidator `isDocCandidate`
- **Fix:** `passKeysFor` asks `isDocXrefInput` (wave c3, item jenkins); the same one-line fix was found independently as O723 (wave c3, item cw) and merged once
- **Status:** closed
- **Impact:** a GitHub Actions or Jenkins run step's edge to a script function or a Makefile target could outlive an edit made through the edit hook's one-file refresh until another doc-xref input changed
