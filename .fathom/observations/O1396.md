- **Symptom:** scss.json read L1 good and L3 excellent with L2 not attempted (O851): no ruling defined Sass's L2, so LB-Q-scss stayed open at level_met L1.
- **Evidence:** owner ruling W5 (design 1.8, 2026-10-20) defines it: name references (`@include`, user function calls, `$v` reads, `@extend %p`) resolved within the referring file's `@use`/`@forward`/`@import` closure, built-ins and undefined names excluded and counted. The dart-sass oracle's `w5_refs.cjs` walks sass-parser 0.4.57's tree under those rules (tier A for the tree, the binding the harness's own walk). Before the engine fix (O1397) and the repeated-field queries (O1398) the same pairs read call_recall .34 on bootstrap (173 of 514) and .37 on primer (52 of 141).
  - **Precision loss (17 pairs on bootstrap, 1 on primer):** the pair is name-level, so a parameter read (`$map`, no definition, excluded) and a local variable of the same name in another function of the file (a definition, scored) cannot be told apart by the dialect: `map`, `color`, `values`, `mode`. The ruling's scoping is the oracle's, the dialect has no scope model (never pre-built).
  - **Exclusions are the ruling's:** names the referring file's own closure does not define leave both sides (bootstrap's partials read `$btn-*` and `$theme-colors` defined by the entry file that `@import`s them: 1,154 fathom pairs on bootstrap, 153 on primer, 1,521 on angular components).
