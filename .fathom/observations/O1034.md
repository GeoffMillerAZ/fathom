### O1034 — A manifest that repeats a key was skipped whole by K8sExtractor, though kubectl reads it

- **Symptom:** LB-F451's first parity run read 323 of 329 typed facts on kubernetes/examples: the six missing were three documents (`_archived/openshift-origin/etcd-controller.yaml`, `etcd-discovery-controller.yaml`, `openshift-controller.yaml`) with no workload, image or fact node at all.
- **Evidence:** each Deployment writes `spec.selector` twice; kubectl v1.36.1 accepts the files (the kubernetes.json oracle's accepted list) and k8s.io/api's typed decode reads them, the last value winning (sigs.k8s.io/yaml); yaml.v3's struct decode refuses a repeated mapping key, and `rawNode.Decode(&doc)` failing skipped the document.
- **Root cause:** K8sExtractor read its fields through a struct decode stricter than Kubernetes' own.
- **Fix:** on a failed struct decode the same fields are read from the node, each key's last value winning (`k8sDocFromNode`), and the facts walk reads last-wins too (`k8sYEntry`); TestK8sContainerFactsDuplicateKeyLastWins. Parity then reads 329 of 329.
- **Status:** closed
- **Impact:** three kubernetes/examples workloads and their images and facts were missing from the store; any repository with a duplicate-key manifest gains its workload on the next ExtractorEpoch.
