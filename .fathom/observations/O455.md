### O455 — C++ dispatch waits on a lexical macro pre-pass: the 0.0002 range_agreement gap is decorator and try/catch macros the grammar misparses

- **Symptom:** `indexbench lang-parity -dialect cpp -incumbent cppextract` refuses the C++ tags dialect on range_agreement alone, 0.9921 < 0.9923, every other gated metric ahead (sym_recall 0.5359 to 0.9449, sym_precision 0.9057 to 0.968, call_precision 0.5267 to 0.9517; `docs/bench/readings/lang/parity/cpp.json`, 2026-10-01). Wave ld (2026-10-02) did not re-run it: neither `internal/extractor/dialects/cpp/tags.scm` nor `cppextract.go`'s symbol path changed since 5556eb84 (only the EW-53 file specs, which no gated metric reads), so the reading stands
- **Evidence:**
  - **Tool:** the committed parity run over fmtlib/fmt 12.2.0, nlohmann/json v3.12.0 (include/) and gabime/spdlog v1.17.0 with the cpp.json reading's scope and oracles (universal-ctags 6.2.1 for L1, scip-clang 0.4.0 and clang-calls for L2)
  - **Expected:** a definition decorated by an export, inline or exception macro ends where the compiler's AST ends it, as an undecorated one does
  - **Actual:** the 45 range misses are definitions whose tree tree-sitter-cpp breaks on a macro it reads as a type or a statement: `class SPDLOG_API logger`, `SPDLOG_INLINE` before an out-of-line definition, `SPDLOG_NOEXCEPT` after a parameter list, fmt's `FMT_TRY { .. } FMT_CATCH(..) { .. }`, a decorator before a constructor; the same misparses hold spdlog's sym_recall to 0.9131 (L1 good, not excellent)
  - **Repro:** cpp PROVENANCE.md's measured upper bound: blanking lines that hold only an all-capitals identifier (same length) on a scratch copy of fmt and json lifted sym_recall .9523 to .9692 and sym_precision .9674 to .9857
- **Root cause:** a C++ macro is opaque to a syntactic parser; universal-ctags is lexical and unaffected, the CGO walker's older grammar errs differently, and the 0.0002 gap is which side's misparse the oracle's ranges favour
- **Fix:** none here (the tags engine is wave le's, `dialects/cpp/dialect.json` items calls' and xfile's). The exact change: a `cpp-macros` entry in `internal/extractor/tsextract.go`'s `tsPreprocessors` (the hook `csharp-conditionals` uses; `tsPreprocessed` re-parses its texts when the tree holds an ERROR node and keeps the first that parses clean), returning one text in which, at equal byte length so every offset, line and range maps back unchanged: (1) `\b[A-Z][A-Z0-9]*_TRY\b` becomes `try` padded with spaces and `\b[A-Z][A-Z0-9]*_CATCH\b` becomes `catch` padded; (2) an all-capitals identifier containing `_` is blanked where it decorates: between `class`/`struct`/`union` and the name (`class SPDLOG_API logger`), first on a declaration line before a type or a qualified name (`SPDLOG_INLINE void logger::log(`), and between a parameter list's `)` and `{`, `;`, `:` or `=` (`) SPDLOG_NOEXCEPT {`); (3) a line holding only an all-capitals identifier, with or without a parenthesised argument (`FMT_BEGIN_EXPORT`, `JSON_HEDLEY_NON_NULL(3)`), is blanked. `dialects/cpp/dialect.json` then names `"preprocess": "cpp-macros"`, with goldens for each shape. Then re-run lang-parity on the cpp.json reading's scope: a MERGE switches `.cc .cpp .cxx .hpp .hh .hxx` and NewCHeaderRouter's C++ branch to `NewTSExtractor("cpp")`, bumps ExtractorEpoch (namespaces become containers, every namespaced symbol renamed) and lets LB-F117 flip
- **Status:** fixed (wave lf1, item ccpp, e7069235: the `cpp-macros` pre-pass, LB-F295; lang-parity then read MERGE at L3 and C++ is dispatched, LB-F117)
- **Impact:** C++ stays on the CGO cppextract.go (sym_recall 0.5359, call_precision 0.5267) for a 0.0002 range delta; LB-F117's C++ half and LB-Q-cpp's L1 excellent both wait on it
