### O697 — two route-seam tests assert the pre-item behaviour the PHP and Python readers change by design

- **Symptom:** on branch c2-phppy, `go test ./internal/analysis/routes` fails two seam tests: `TestHasReader` (`registry_internal_test.go`) wants `HasReader("yaml") = false`, and `TestExtractPython` (`routes_test.go`) wants the row `GET,POST:/users` from a Flask file
- **Evidence:** the Symfony reader registers lang `yaml` (the brief's "yaml-lang reader gated by path" for `config/routes.yaml`), so `HasReader("yaml")` is true. The Flask reader reads `@app.route('/users', methods=['GET', 'POST'])` as two routes, `GET /users` and `POST /users`, bound to `users`; the python-regex reader, which now yields on a file the Flask or FastAPI reader reads, spelled it as one comma-joined `GET,POST` row with no handler. Kept beside the Flask reader, the regex rows would put CTFd's bound precision at .645 instead of .9954 (`docs/bench/readings/routes/python.md`)
- **Root cause:** the seam's tests pinned the seam-time output (no YAML reader existed, the regex reader was the only Python reader); both files are the seam owner's and outside item phppy's file list, so the item cannot amend them
- **Fix:** proposed for the integrator, one line each: `TestHasReader`'s `"yaml": false` becomes `true`; `TestExtractPython`'s check `"GET,POST:/users"` becomes `"GET:/users"` and `"POST:/users"`. `TestLegacyReadersRegistered` still passes: python-regex stays registered as the fallback for Python files the new readers do not read
- **Status:** open (both assertions fail on c2-phppy until amended at integration)
- **Impact:** the merged wave's gate fails on these two tests until they are amended; no product behaviour depends on the old assertions
