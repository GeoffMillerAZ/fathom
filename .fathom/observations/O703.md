### O703 — TL-5's serverless identities regressed the serverless reading, unmeasured (L2 excellent to good)

- **Symptom:** a Serverless function's `name:` became a TelemetryIdentity (canonical `key`, inside the serverless reading's kind intersection) that no oracle names, and an identity written with variables (`${self:custom.stack_name}-list`) hid the function's own `self:custom` reference
- **Evidence:** the serverless reading measured at 6280cfd4 against the 2026-10-09 oracle run: sym_precision .9932 (8 identities no oracle named) and ref_recall .9489 (7 references hidden), L2 good; the committed reading (2026-10-02) predates TL-5 and still read 1 and 1; a pattern reference never walks into another entity's node (`matchValues`), so an entity at the name took the name's strings from its function
- **Root cause:** TL-5 added an entity to a dialect whose reading puts its canonical kind in the L1 intersection, and the reading was not re-measured
- **Fix:** wave c2, item engine (K20, LB-F340): the identity refuses a template at extraction (`refuse_templates`), which gives the 7 references back, and the serverless oracle names a function's literal name where `serverless print` resolves it to the same literal (1 on serverless/examples); re-measured: every metric 1, L2 excellent
- **Status:** fixed (wave c2, item engine)
- **Impact:** between wave c1 and wave c2 the serverless reading on main overstated what fathom extracted; no product answer was wrong beyond the 7 missing references
