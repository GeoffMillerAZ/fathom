### O336 — lang-oracle refuses a tool oracle that carries route_references: its decode allows no unknown field

- **Symptom:** lang-oracle refuses a tool oracle that carries route_references: its decode allows no unknown field
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -tool-oracle <file with route_references>` (cmd/indexbench/langoracle.go scoreToolOracle, DisallowUnknownFields)
  - **Expected:** the wave px contract: "lang-oracle ignores both fields" (route_references, route_unresolved)
  - **Actual:** the decode fails on the first unknown field, so an oracle file carrying the route fields cannot be passed to lang-oracle
  - **Repro:** run lang-oracle on any reading with an oracle JSON that has `"route_references": []`
- **Root cause:** scoreToolOracle decodes strictly by design (a misspelt field is an error)
- **Fix:** `indexbench lang-routes` strips route_references, route_unresolved and route_crosscheck before the shared measurement (LB-F98); lang-oracle unchanged (lc owns langoracle*.go)
- **Status:** worked around — measure a file with route fields through lang-routes
- **Impact:** the nginx and gateway items' oracles must be run through lang-routes, not lang-oracle
