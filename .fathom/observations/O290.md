### O290 — the append-heavy hotspots split into per-entry and per-verb files (EW-32), and JP-3 still pins the legacy log

- **Symptom:** four append-heavy files took most of a wave's merge conflicts: `.fathom/observations.md` (605,907 B, 70 conflicts), `docs/usage.md` (248,523 B, 65), `docs/mcp-tools.md` (169,237 B, 32) and the `## Scenario runs` block of `docs/bench/README.md` (354,718 B of its 416,239 B)
- **Evidence:**
  - **Tool:** the per-file conflict counts the integrator reported for the wave merges (conflict diet 2, wave cd); byte sizes from `wc -c`
  - **Expected:** a parallel wave adds a file instead of editing one shared file
  - **Actual:** every wave appended to the same four files, so the integrator resolved adjacent-append hunks by hand
  - **Repro:** merge two wave branches that each file an observation or add a verb section
- **Root cause:** one file per append-only record, so every writer touched the same hunk
- **Fix:** `fathom observe` writes `.fathom/observations/O<n>.md` with an exclusive create; `docs/usage.md` and `docs/mcp-tools.md` are indexes over `docs/usage/` and `docs/mcp-tools/`; the scenario block moved to `docs/bench/scenario-runs.md`. The legacy log is untouched and still read. Plan row JP-3 (`docs/plans/judged-predicates.md`) still pins `.fathom/observations.md` for its J0-screen entry: whoever files J0 repoints JP-3's path to the per-entry file the J0 observation lands in
- **Status:** open until JP-3 is repointed; the split itself is EW-32
- **Impact:** bytes per full read and the per-entry and per-verb medians are in `docs/bench/readings/efficiency-wave/conflict-diet-2.md`
