### O383 — import-dump file edges cap a language whose import names a package split across files: Rego's file_edge_recall .3858

- **Symptom:** Rego's L3 reads good, not excellent: file_edge_recall .3858 (581 of 1,506 pairs) at precision .9949
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect rego` with opa-parse's `imports` as the file-edge truth (LB-F57)
  - **Expected:** an import's file pairs are reached by the edges of what the importer uses
  - **Actual:** `import data.regal.ast` names six files (160 importers), `data.regal.config` two; an edge reaches only the file defining the rule called or referenced, so the other pairs stay out
  - **Repro:** the MISS-TO tally per target file: bundle/regal/ast/*.rego and config/exclusion.rego carry 915 of regal's 918 misses
- **Root cause:** the truth is what import statements name, fathom's file edges are what references reach (the design's own note, LB-F57)
- **Fix:** none here; LB-Q-rego-rest's trigger (the file resolver drawing an import statement's own file edges, for every language)
- **Status:** open
- **Impact:** Rego L3 good; the same ceiling meets any language whose module spans files (a Go-like package)
