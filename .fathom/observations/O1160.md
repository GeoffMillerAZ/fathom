### O1160 — the fx2 six are exactly the plans with a claimed `gone` row, and a dirty tree or a commit after the ingest fails all six with exit 1

- **Symptom:** the six plans fx2's integrator saw exit 1 (O1159) are the only six of 76 that carry a claimed `gone:` row (efficiency-wave 1, language-breadth 10, observatory-console 3, portable-receipts 1, retire-unused-analyzers 18, surface-reckoning 13). A gone row is proven only when the plan's tree is at the ingested commit with no uncommitted state (`goneev.Evidence.IndexAtHead`, I44), so the tree's state at verify time, not load, decides all 46 of them at once.
- **Evidence:**
  - **Tool:** `fathom verify --strict` (store mode), the O1159 store and binary.
  - **Expected:** a precondition the environment fails (an untracked file, a HEAD moved since the ingest) reads as one operational cause, not as 46 failing claims across six plans.
  - **Actual:** one untracked file at the repo root, all 76 plans in one call: exit 1, exactly those six plans unproven, 46 rows, each `gone: not proven — the working tree has uncommitted changes since the index was ingested` (failing ids include LB-F19, LB-F338g..LB-F400, EW-53, OC-H3g, OC-H4d, OC-H4g, EVX-4, SR-10..SR-29, all 18 retire-*-gone). An empty commit after the ingest: portable-receipts exits 1 on `the index was ingested at commit 02673c142163, HEAD is now 5c2211dab9f1 — re-ingest`. Clean again: all exit 0. The summary line counts them as `failing` and names no shared cause; the reason appears only per row. fx2's history (two changelog fix commits after the merges, one removing stray conflict markers) fits a verify run on a tree that was dirty or one commit past its ingest; no fx2 verify log survives to confirm it, and fx2's notes name (op) and LB-Q rows, which did not fail here.
  - **Repro:** `echo x > stray.txt; fathom verify --strict --store <fresh ingest of HEAD> --service fathom --plan docs/plans/retire-unused-analyzers.md` (18 of 18 claimed failing; exit 1).
- **Root cause:** the gone precondition is evaluated per row and rendered as Unknown, which `--strict` counts as a failing claim; nothing aggregates the one environmental cause. O478 saw the same reading over a dirty tree on 2026-10-02.
- **Fix:** proposed, not made (the brief changes no code on a negative O1159): (1) one aggregate line when the gone precondition fails, naming the reason and the first dirty path; (2) an owner decision on whether a precondition-only strict shortfall exits 2 (operational, like a stale index) when no row really fails, since that fails open; (3) the integrator recipe ingests after its last commit and checks `git status --porcelain` is empty before verifying.
- **Status:** fixed (wave fx4, vexit, 2026-10-17): owner decision -- a strict shortfall whose every unproven claimed row is a gone: row held back only by the index-at-HEAD precondition exits 2; one `index-stale:` aggregate line (human, `--json` `index_stale`, daemon verify_plan `index_stale`); other unproven rows keep exit 1; rows stay Unknown (I44).
- **Impact:** an integrator who verifies between a merge and its fix-up commit, or with a stray file in the tree, sees six plans fail and may read it as flakiness.
