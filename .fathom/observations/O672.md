### O672 — the automatic typed pass honoured a repository's go.mod toolchain line (fixed: GOTOOLCHAIN=local)

- **Symptom:** under an inherited `GOTOOLCHAIN=auto`, the typed pass's go invocations ran in the repository, so a go.mod `toolchain go1.X` line (or a `go 1.X` line newer than the local toolchain) made the go command switch to, and when absent download, the toolchain the repository named (O654 point 3)
- **Evidence:** `TestTypedPassNeverSwitchesToolchain` (internal/fusion): a stand-in `go1.99.0` on PATH ran for `go list` (packages.Load) on both fixtures; `go env GOPATH` run in a repository directory switches too (a CLI ingest's environment repair, `goEnvValue`, runs in the process's directory, which is the repository); go1.26.3's `go env GOWORK` alone does not switch, but is pinned anyway
- **Root cause:** `TypedEdgeEnv`, `goEnvValue`, `detectWorkspaceOverride` and the background toolchain shim inherited the process's `GOTOOLCHAIN`
- **Fix:** `GOTOOLCHAIN=local` appended last to each (K22, LB-F341). A go line the local toolchain cannot satisfy is the pass's named failure on the service and in the ingest report (`go: go.mod requires go >= 1.99.0 (running go 1.26.3; GOTOOLCHAIN=local)`), syntax edges stand; a newer toolchain line alone type-checks locally. cgo flag safety stays the go command's own allowlist (no `CGO_ENABLED=0`). Explicit user verbs keep the user's environment, by design: `fathom doctor --stranger` (the repository's scripts/stranger-check.sh), `fathom receipt verify --run-tests` (go test) and a `fathom rules gen-test` test the user's own go test runs (layerrules.BuildIndex)
- **Status:** fixed (wave lf2, item go)
- **Impact:** a cloned repository can no longer choose the toolchain an automatic ingest, the typed pass or the daemon's auto-refresh fetches or runs
