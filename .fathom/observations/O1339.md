### O1339 — the stranger check's first index grew with the whole tree and outlasted init's wait under load

- **Symptom:** `task stranger-check` (RP-23, in every `task validate`) ran `fathom init` on a copy of this whole repository, so the scratch daemon's first index was a from-scratch ingest of every tracked file. On a loaded host it outlasted init's 30-minute wait and init exited 2 ("service \"stranger\" did not confirm as indexed"), failing the gate with nothing wrong; when it passed it cost 7 to 19 minutes, nearly all of it init.
- **Evidence:**
  - **Tool:** `scripts/stranger-check.sh` step 4 (`fathom init --path "${tree}"`), the gate's `stranger-check` dep
  - **Expected:** the check proves a fresh copy builds, init wires a stranger's repository, and its first index confirms, in a bounded time at any load
  - **Actual:** gate logs `gate-ext/fix2-1.log` (2026-10-19 18:12Z) and `lang2-3.log` failed at init's wait at host load 40-90; passing runs: total 498 s (init 405 s), 841 s (init 750 s), 1132 s (init 931 s)
  - **Repro:** run `task stranger-check` while other gate steps load the host; the init step's time grows with the tree, the wait does not
- **Root cause:** the check's index target was the whole repository. Its first index is work that grows with every commit (56k symbols, nested modules, the kit mirrors), while init's wait is wall-clock, so load times tree size could always exceed it. None of RP-23's claims needs that work: a stranger wires their own repository, which has no `.fathom/` yet; init's long-wait paths are Go tests (`init_ingestrun_test.go`, `init_slowingest_test.go`); a whole-tree ingest of HEAD is the pre-push verify step's; this tree's own concerns are `task config-audit`'s.
- **Fix:** the copy still builds standalone with `GOWORK=off`. Init now wires the fauxtown fixture fleet out of the copy (27 files, ten services in Go, TypeScript, JavaScript, Python, Ruby, Java, proto, Terraform, CUE and YAML, with an agent worktree to exclude), made its own git repository, so the first index is fixed work bounded by the fleet, not the clock, inside init's unchanged budget. Doctor's full row set reads that repository. `binary_fresh` SKIPs outside a fathom source tree, so a second doctor reads it against the copy and the check fails unless it is PASS (O5's class). Stronger than before: the first `find_symbol` call must name the stranger's `checkout-service/checkout.go` (the old `grep '"result"'` also matched an empty answer). `FATHOM_STRANGER_WIRE=tree` keeps the whole-tree path as the instrument EW-71's cold-ingest reading names; no gate sets it. `scripts/stranger-check_test.sh` (stubbed go and fathom, run first by the `stranger-check` task) was red at base, where init wired 308 tracked files and the stub's index confirmed none. No product change: init's wait is untouched.
- **Measured (this host, 2026-10-19):** before (origin/main 6c9c8ff6): 392 s wall (build 61 s, init 320 s), load 6.3 at start and 9.4 at end. After: 95 s wall (build 82 s, init 4.8 s), load 7.9 at start and 32.8 at end, then 49 s through `task stranger-check` with its test (build 36 s, init 1.0 s) at load 12.7. What is left is the build: each run copies the tree into a fresh directory, and without `-trimpath` the directory is part of every package's build-cache key, so fathom's own packages compile from scratch every time.
- **Lost, named:** the whole-tree daemon ingest under the check's 4 GiB budget was also an incidental canary for the typed pass's memory (EW wave h5 caught a refuse there). That is not an RP-23 claim. It now lives only in `FATHOM_STRANGER_WIRE=tree` and the cold-cost readings.
- **Status:** fixed (wave fix3, item strg)
- **Impact:** every gate saves about 5 to 17 minutes and no longer fails on host load in this step.
