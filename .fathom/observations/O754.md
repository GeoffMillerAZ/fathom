### O754 — K18's Rust half also takes the references made at a module's top level out of typed_recall, beyond Go's LB-F344 shape, and internal/scip still joins a whole-file module definition by position

- **Symptom:** Go's namespace rule (LB-F344) moves only the references TO a package; a Rust file module's definition spans its whole file, so every reference outside an item (a `use` line, an impl header, which rust-analyzer gives no definition) is made FROM the module
- **Evidence:**
  - **Tool:** `internal/langbench/scip_rust.go` `rustWithoutNamespaces` and `rustRecount`, `TestScoreSCIPRustNamespaceL4`; the reading's counts
  - **Expected:** a target-only rule, as Go's
  - **Actual:** 6,259 references to a module and 4,167 made at a module's top level leave typed_recall (`scip_edges_namespace_target`, `scip_edges_namespace_from`), 483 module definitions leave def_mapping; typed edges 55,196 -> 53,291: `internal/scip` joins a whole-file module definition (line 0) to whatever the file defines on line 1, by position (O527's shape for Python), so 1,905 typed edges had a module endpoint, mis-joined or an inline mod's RustMod
  - **Repro:** the test; or the reading's lang-oracle command with `SCIPOptions.RustNamespaces` off
- **Root cause:** rust-analyzer's module definition is the whole file; `buildDocDefs` maps a definition by its range's start line
- **Fix:** harness side done (LB-F389, counted and disclosed). Product side not here (`internal/scip` is outside this item): `fathom ingest --scip` with a rust-analyzer index still makes typed edges from a file's line-1 definition for its top-level references; `scip.ModuleDefinition` learning rust-analyzer's whole-file `x/` form (K18's revisit trigger names a producer other than scip-python) would leave them unmapped, as the harness now reads them
- **Status:** open (the product half, for the integrator)
- **Impact:** an ingest with `--scip` of a Rust index carries mis-joined typed edges from a file's first definition; ingest without an index is unaffected
