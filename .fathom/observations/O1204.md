### O1204 — Claude Code 2.1.302 reads the core plugin's server as plugin:fathom:fathom and wants a marketplace description

- **Symptom:** the design held three Claude Code facts open for the mods plan's install reading: the plugin-scoped server and tool names, whether `settings.json` passes `claude plugin validate --strict`, and the marketplace's own requirements.
- **Evidence:** `scripts/plugin-install-check.sh` on claude 2.1.302 (2026-10-18), scratch HOME: `claude --plugin-dir <plugin> mcp list` printed `plugin:fathom:fathom: http://localhost:7575/rpc/agent (HTTP)`; `plugin list --json` printed `fathom@inline` (scope session); `plugin details fathom` listed `Agents (1) fathom-scout`; `validate --strict` passed the plugin with `agents/fathom-scout.md` (`omitClaudeMd`, `effort`) and `settings.json` (`subagentStatusLine`) present. On the repository root, `validate --strict` failed until the marketplace carried a top-level `description` ("No marketplace description provided"), and advised a README install line until the README held `/plugin install fathom@fathom-plugins`. `claude plugin marketplace add <checkout>` and `claude plugin install fathom@fathom-plugins` installed 0.3.14, read from the folder.
- **Root cause:** none; these are platform facts the design marked unverified.
- **Fix:** render writes the marketplace description; the tool prefix `mcp__plugin_fathom_fathom__` (`pluginScopedToolPrefix`) is inferred from the server name, not yet seen in a live session, so the live owner session in the mods plan still records it. Validate passing does not show that Claude Code applies `subagentStatusLine` from a plugin's settings.
- **Status:** open (the tool prefix and the applied status line wait on the live session)
- **Impact:** a wrong prefix leaves the scout with no usable tools; the live session is the check.
