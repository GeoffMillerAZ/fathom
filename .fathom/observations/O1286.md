### O1286 — `init --dry-run` derives two wiring side files from the plan, not from the engine

- **Symptom:** the dry run lists `.fathom/owned.json` and the receipts log from the wiring plan's apply items, because `wiring.ApplyWiring` decides both inside its own apply and has no dry mode.
- **Evidence:**
  - **Tool:** `cmd/fathom/init_dryrun.go` (`initWrites.applyWiring`), `cmd/fathom/skillsinstall.go` (`installSkillsReport`'s ledger record)
  - **Expected:** every listed file decided by the same code that writes it
  - **Actual:** the ledger is listed when an owned key, file or link is applied, or a skill file is created or updated; a re-run over skill files current on disk but missing their baseline in the ledger would rewrite the ledger without the dry run listing it
  - **Repro:** a repository wired before FA-23 (skill baselines unrecorded): `fathom init --skills --dry-run` omits `.fathom/owned.json`, the real run writes it
- **Root cause:** internal/wiring exposes PlanWiring but no dry apply, and `ledgerRelPath` is unexported (cmd/fathom keeps `initLedgerFile` beside it).
- **Fix:** a `DryRun` option on `wiring.ApplyOptions` returning the files the apply and the ledger flush would write; `TestInitDryRunListsExactlyTheRealRunsTouchedSet` already fails on any drift for the three states it builds.
- **Status:** open
