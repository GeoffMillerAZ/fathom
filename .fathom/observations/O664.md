### O664 — custodian blind spots: pointers_hold passes sibling-repo and gitignored targets, and nothing budgets a nested guide

- **Symptom:** root AGENTS.md routed to `agentic-kit/docs/project-intent/changes.md` (a sibling repository a fresh or cloud clone cannot follow) and to the gitignored `tmp/design_inspiration/files/`, and `pointers_hold` held; docs/AGENTS.md grew to 89 lines restating docs/plans/README.md with no budget
- **Evidence:** `scanPointers` (internal/custodian/audit.go) skips a backticked path whose first segment is not a directory of this repo (the sibling-repo case) and skips the runtime directories workspace, tmp, ref and bin (the gitignored case); `router_thin` was the only max_lines concern
- **Root cause:** both skips were written to avoid false violations on foreign names and not-yet-created artifacts; no rule distinguishes "a pointer an agent is told to follow" from "a name that happens to contain a slash"
- **Fix:** budgets: max_lines concerns for docs/, internal/, cmd/fathom/ and schema/AGENTS.md and the intent router (w2a2 routers, AG-33); the two pointers were repointed or dropped by hand. Open: a pointers check that flags a routed sibling-repo or gitignored target (a row's pointer, not a prose mention) without flooding foreign names
- **Status:** open (budgets fixed; the pointer blind spot filed)
- **Impact:** a cloud session or a fresh clone follows a route that does not exist and the audit says it holds
