### O721 — a Lambda handler exported through a wrapper call or `module.exports.x = () =>` is no JSFunc, so its function binds nothing

- **Symptom:** on the recorded serverless-patterns subset 25 of the oracle's 376 handler bindings are missed (handler recall .9335, precision 1.0); every miss is a node handler
- **Evidence:** `exports.handler = metricScope(m => async (e) => ...)` (apigw-lambda-observability/src/app.js), `export const handler = withDurableExecution(...)` (the lambda-durable-* patterns), `module.exports.handler = async (event) => {...}` (apigw-lambda-sfn-transcribe-translate-polly-sam/src/speech.js), `awslambda.streamifyResponse(...)` (the streaming patterns); a probe of `module.exports.lambdaHandler = async function (event) {}` yields no node at all
- **Root cause:** the javascript/typescript dialect captures a function declaration, an arrow function or function expression bound by `export const`/`exports.x =`, but not one wrapped in a call (a middleware, a durable or streaming wrapper) and not `module.exports.x = ...`
- **Fix:** the javascript dialect's owner (tsextract*.go, outside wave c3 item cw) captures an export whose value is a call, and `module.exports.x =`, as the export's symbol; the binding (`fusion.ResolveLambdaHandlers`) then takes it unchanged
- **Fixed:** the javascript dialect names `module.exports.x =` and `exports.x =` of a function, or of a call wrapping one, as JSFunc x, and a node handler binds a module-level const of its name (LB-F382) when no function has it. On serverless-patterns a6cb0af2's 49 lambda-durable, streaming and apigw patterns (a sparse checkout), bound handlers 41 to 68 of 83 functions, `no-symbol` 27 to 0, no binding lost; the cloudformation reading's xref_recall is not re-measured here.
- **Status:** fixed (wave lf3, item tsjs, 0f4244a8, LB-F384)
- **Impact:** an agent asking what code a streaming, durable or middy-wrapped Lambda runs gets no edge; the handler's file is still named by the template
