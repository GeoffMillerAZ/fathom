### O1470 — Edits no hook sees leave the index stale with no freshness notice, and `budget` and `suppressed` still ride outside the result

- **Symptom:** a file written by a shell redirect, or by an `apply_patch` in a harness without fathom's edit hook, stays stale in the index until the next ingest. The answer carries `freshness` only when a refresh was deferred or queued (O1449), so a read that found no drift to refresh says nothing about files the tree changed since the last ingest.
- **Evidence:** app-kit O35 and O38, adopter repository B O4 (shell-written files stayed invisible). O1449's fix puts the refresh note in the result; `budget` and `suppressed` remain envelope keys beside `content`.
- **Root cause:** the refresh note is raised only on the auto-refresh path. Nothing compares the working tree to the index for the files an answer touches, and the O1449 fix moved only the refresh note in-band to keep the envelope change small.
- **Fix:** proposed, not built. Name the index commit and, when cheap, the dirty files an answer touches in `freshness`; move `budget` and `suppressed` in-band the same additive way.
- **Status:** open
- **Impact:** an agent trusts a stale definition after a shell-written change.
