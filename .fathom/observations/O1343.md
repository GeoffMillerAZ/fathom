### O1343 — `fathom observe` cannot take a reserved observation id

- **Symptom:** A wave brief reserves observation ids per worker (this one O1342..O1344) so parallel lines never add the same `.fathom/observations/O<n>.md`, but `fathom observe` always takes the next free id, so a worker that uses it can collide with a sibling's reservation and one that honors the reservation writes the file by hand.
- **Evidence:**
  - **Tool:** `fathom observe --help` (flags: actual, expected, repro, root, symptom, tool; no id)
  - **Expected:** a way to file under a reserved id, or an id no sibling line can take
  - **Actual:** the next id after the highest present in the clone (O1336 here), which a sibling's reservation may already hold
  - **Repro:** two clones of one base, `fathom observe --symptom x` in each, merge: both add `O1336.md`
- **Root cause:** the id is a shared counter read from the clone, not from the reservation.
- **Fix:** an `--id` flag that refuses an id already present, for briefs that reserve ranges. Reservations stay the cheapest id scheme (`docs/design/append-points.md` section 7).
- **Status:** open
