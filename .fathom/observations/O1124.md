### O1124 — `find_callers` shows a call inside a package-level function-literal variable as every `init()` of the package: 116 direct callers of `openDecisionPorts`, 6 of them real

- **Symptom:** asked for the callers of `main.openDecisionPorts`, `find_callers` answers 116 direct callers. Six are the real non-test call sites; more than a hundred are `init` rows at unrelated files (`cmd/fathom/gc.go:472`, `cmd/fathom/appkit_styleguide.go:229`, ...). The real seventh caller, the variable `preflightOpenPorts` (`cmd/fathom/planspreflight.go:287`, a function literal kept in a var so a test can swap it), is never named.
- **Evidence:**
  - **Tool:** `find_callers` (served through `bin/fathom serve-mcp --store` on a scratch ingest of fd091c4f)
  - **Expected:** a caller row names the code that makes the call: the variable and its file and line, or at least the one file whose initializer calls.
  - **Actual:** the typed pass gives every package-level variable initializer the caller key `<pkg>.init` (`internal/fusion/typedcalls.go:1263-1290`, TypedEdgeEpoch 3), and every `init()` function of a package shares that key (`:1299-1301`). The caller list expands the key to every node that carries it, so one edge from `planspreflight.go` prints as each `init()` declaration in `cmd/fathom`. In E3's Q1 the reference path through that variable reached the judge step only as an unrelated `init` span, and Jev labelled it false (`docs/bench/readings/decide/exp-e3.md`).
  - **Repro:** `printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"find_callers","arguments":{"service":"fathom","symbol":"main.openDecisionPorts","depth":1}}}' | fathom serve-mcp --store <scratch store> --auto-refresh=false`: "116 direct callers"; `grep -n 'openDecisionPorts(' cmd/fathom/*.go` outside tests finds 6 calls plus the definition.
- **Root cause:** the edge knows its file (`FromFile`), but the caller view resolves the caller by key, and the package-init key names no single declaration.
- **Fix (proposed shape):** test first: in a fixture package with two `init()` functions and a `var seam = func() { target() }`, `find_callers(target)` returns one row at the variable's file and line, named for the variable, and no `init()` row. Then key a variable initializer's edges by the variable (a GoVar symbol, when one is indexed), or else resolve a `<pkg>.init` caller by the edge's `FromFile` and line instead of expanding the key. Same E3 run, not filed separately: `blast_radius` `kind: "delete"` on a Go type lists call-shaped uses only, missing functions that take the type in a signature, and its referents carry no symbol key.
- **Status:** open
