### O1170 — Configured findings producer lists did not restrict decoded imports

- **Symptom:** Configured findings producer lists did not restrict decoded imports
- **Evidence:**
  - **Tool:** fathom findings import
  - **Expected:** An explicit empty producers list admits no event, flags only narrow policy, and hook subprocesses read the indexed project policy
  - **Actual:** At 0.15.6 the CLI accepted all three native criteria producers under producers=[]; an explicit --producer could also bypass the declared list
  - **Repro:** go test -race ./cmd/fathom -run TestFindingsImportConfiguredProducers with the new regression installed before the policy fix on the 1762acbe-based branch; retained red and green logs under workspace/logs/producers-boundary-*
- **Root cause:** The CLI loaded configuration only for subject defaults and never passed the producer list into the shared decoded-event importer. Automatic sync also inherited the harness working directory.
- **Fix:** Pass an optional producer boundary through ImportFindingsRequest into the shared importer, load policy even with explicit subject flags, and run automatic import in the indexed project. Refuse disallowed events before cursor reads or writes.
- **Status:** fixed locally, unreleased; targeted race regressions and CLI/client contract fixtures pass. Full upstream publication remains subject to the mandatory gate.
- **Impact:** A declared project trust boundary could admit an undesired catalogued producer; trusted catalog caps and subject binding still applied. Empty and malformed policy now refuse without broadening admission.
