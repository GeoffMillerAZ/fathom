### O718 — the doc-xref pass reads a Kubernetes manifest twice to find its embedded documents (2026-10-10)

- **Symptom:** when the doc-xref pass runs, its hook (`Pipeline.obsXrefs`, alertroute.go) fetches every `.yaml`/`.yml` file that is no doc file (a Kubernetes manifest, an unclassified YAML) a second time, to read the documents a ConfigMap, Secret or GrafanaDashboard embeds
- **Evidence:** `enrichDocXrefEdges` keeps only DocResulter results; the embed wrapper (k8sembed.go) is deliberately no DocResulter so the route and policy passes keep the Kubernetes object, and docxref.go takes one append line per wave item, so the loop that already read the content cannot hand it over
- **Root cause:** the doc-xref loop discards the content of a file whose extractor is no DocResulter
- **Fix:** none yet: the k8sEmbedCandidate byte check makes the second read cheap after the fetch; ADR-065's revisit (the kubernetes dialect at dispatch) removes it
- **Status:** open
- **Impact:** a doc-xref pass in a repository of many Kubernetes manifests reads them twice (page-cached; the pass took 1.06 s on fathom itself)
