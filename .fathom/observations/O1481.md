### O1481 — TQ-27 made non-Go tests test entries, but `tests select`, `related_tests` and the reach walks still read only `Test*`

- **Symptom:** on a TypeScript fixture with jest `describe`/`it`/`test` blocks calling a changed function, `fathom tests select --since HEAD --safe` reported `0 test(s) ranked` and "no test reaches it", though the stored call graph held the `it` and `test` blocks as callers.
- **Evidence:** `callgraph.TestImpactDetail`, the reach walks in graph.go, `RankedTestImpact` (testrank.go), `impact.TestGapSeedsOn`, `symbolnav` (`related_tests`), `bodyChangedSymbols` and `selectCertifyingFirstOn` each tested `strings.HasPrefix(name, "Test")`. TQ-27 changed only `impact.BlastRadius` and the bounded walk. Reproduced on a scratch ingest of a two-file TS fixture.
- **Root cause:** six readers kept the Go-only name test after TQ-27 gave non-Go entries a computed fact.
- **Fix:** `callgraph.IsTestNode` (the `Test` prefix or `repofacts.IsTestEntry`) replaces the prefix test in those six readers; `go test` invocation lines list Go tests only. The join (`testevidence.JoinCasesToSymbols`) takes non-Go entries by file and name (TQ-28). Verified on the same fixture: both TS tests selected.
- **Status:** fixed
- **Impact:** a TypeScript, Python or Java repo got an empty selection and an all-gap review while its tests were indexed.
