### O780 — a degraded ingest makes the pre-push verify gate fail open

- **Symptom:** while measuring EW-59, fathom's own scratch ingest exited 1 (`error: ingest degraded: typed-edge pass failed: 1/531 package(s) failed typed loading (calibration/oracles/argo/go.mod: ... go.mod requires go >= 1.26.5 (running go 1.26.3; GOTOOLCHAIN=local))`)
- **Evidence:** `lefthook.yml` pre-push `fathom verify` runs `bin/fathom ingest --store workspace/tmp/gate-verify.sqlite` and, on any non-zero exit, prints "scratch ingest of HEAD failed — allowing push (fail-open ...)" and exits 0. `fathom ingest` exits 1 for a degraded ingest, and one package that fails typed loading is enough to degrade it. So one package the local toolchain cannot type-check skips the whole plan gate, the same as a daemon outage
- **Root cause:** the gate treats exit 1 (degraded: the index is usable, a pass is partial) like exit 2 (operational: nothing to verify against)
- **Fix:** not built (lefthook.yml is not this item's file). Candidate: fail open only when the ingest refused or produced no store; verify against a degraded store and say it is degraded
- **Status:** open. The EW-59 narrowing (only the repository's own nested modules) keeps the argo oracle (module path `fathom.bench/oracles/argo`) out of fathom's typed pass, so fathom's ingest is not degraded at HEAD of h4-reach
- **Impact:** a push can skip plan verification without anyone noticing, whenever the pushing machine's Go is older than one package needs
