### O1416 — tree-sitter-solidity v1.2.9 does not parse a file-level `using X for T global;`, so the whole library after it is lost

- **Symptom:** Vectorized/solady `src/utils/g/LibTransient.sol` yields 11 symbols instead of 107: its `library LibTransient` (96 definitions) is inside an ERROR node. It is the one file of 107 on the holdout with a definition loss (sym_recall .9745).
- **Evidence:**
  - **Tool:** `indexbench lang-probe -dialect solidity src/utils/g/LibTransient.sol` (solady v0.1.26, grammar v1.2.9 bf268722)
  - **Expected:** `library LibTransient` and its members extracted, as solc's AST has them
  - **Actual:** `(ERROR L47 ...)` from the first `using LibTransient for TUint256 global;` (line 47) to the end of the library
  - **Repro:** a file of `struct S { uint256 x; }` then `using L for S global;` then `library L { function f() internal {} }`
- **Root cause:** the pinned grammar has no `global` after a file-level `using ... for T`, a Solidity 0.8.13 form; upstream HEAD (048fe686) is the next pin to try.
- **Fix:** TODO, a grammar bump with a re-measure (the lock row, the blob, the goldens); not done in this item, the pin stays at the tag the queue allows.
- **Status:** open
