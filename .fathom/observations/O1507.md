### O1507 — the CUE typed pass is not hermetic: it builds the default module registry, so ingesting a CUE module that declares external dependencies can contact the public CUE registry (an I14 egress gap no test caught)

- **Symptom:** the CUE typed pass is not hermetic: it builds the default module registry, so ingesting a CUE module that declares external dependencies can contact the public CUE registry (an I14 egress gap no test caught)
- **Evidence:**
  - **Tool:** fathom ingest (CUE typed pass)
  - **Expected:** the typed pass never reaches the network: an external CUE dependency reads as an unresolved import, counted and named
  - **Actual:** internal/fusion/typedcue.go comments the pass as hermetic, but with CUE_REGISTRY unset or inline:{} modconfig.NewResolver still names the public default host (cuelang v0.16.1 cue/load/config.go:402, internal/mod/modresolve/resolve.go:229); a scratch probe on main printed that host. Found by the triage of an adopter's patch series, whose large unit carried a registry refusal
  - **Repro:** modconfig.NewResolver with CUE_REGISTRY=inline:{} prints the default registry host; ingest a CUE module whose cue.mod/module.cue declares an external dependency
- **Root cause:** the typed pass's load.Config set no Registry, so cue/load built the default resolver from the environment, and an empty or inline registry setting still named the default public host. No test ran the typed pass on a module that declares an external dependency
- **Fix:** internal/cuerefuse supplies a registry that refuses every fetch, used by the typed pass (cueTypedLoadConfig, Env empty) and the schema loader; tests prove zero network requests with CUE_REGISTRY unset, empty, inline:{} and naming a reachable host, and a source test requires every load.Config to set a Registry
- **Status:** fixed
- **Impact:** an adopter indexing a CUE module with external dependencies could contact the public CUE registry during ingest. After the fix, one external import fails that module's typed pass (counted and named); reading a local module cache offline is a possible follow-up
