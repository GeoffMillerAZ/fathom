### O1472 — A CUE import reaches every file of its package, but file_edge_recall scores one per directory

- **Symptom:** CUE's L3 reading (LB-Q-cue, wave lang8) has import_resolution 1 (21 of 21) and import edges precision and recall 1 (49 of 49), yet file_edge_recall .4898 (24 of 49) on the tuning subjects and .3009 (247 of 821) on the holdout hofstadter-io/hof: just under the .50 bar, so L3 reads good, not excellent.
- **Root cause:** the cue-module strategy draws an import's edge to each loaded file's package entity (`package/<name>`), but the files of one package in one directory share that entity's key (`core.SymbolNode.Key`: directory, package, name), and `langbench.ScoreFileEdges` reads an edge's target key as one file (the last node bearing it). A package of several files in a directory therefore scores one reached file, plus those a name through the import binds; every miss in `-unmatched` is such a file (ci_tool.cue to github/*.cue, defs.cue to dashboards/*.cue), none a wrong or absent resolution.
- **Fix (not made):** a target of each file's own for an import edge (CUE has no per-file entity; K18's module symbol needs a file-named package), or an owner ruling that file_edge_recall reads a key one package's files share as each of them. Either changes a shared contract, outside this item.
- **Status:** open (LB-Q-cue-rest's trigger)
- **Impact:** CUE's L3 grade is good though every import resolves to exactly the files the cue binary loads.
