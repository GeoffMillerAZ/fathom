### O339 — a worker's scratch ingest of fathom degraded repeatedly: the typed pass's go list and the doc walk hit "operation not permitted" mid-run

- **Symptom:** a worker's scratch ingest of fathom degraded repeatedly: the typed pass's go list and the doc walk hit "operation not permitted" mid-run
- **Evidence:**
  - **Tool:** `fathom ingest --store $FATHOM_CACHE_ROOT/verify.sqlite --service fathom --path .` (wave px, 2026-10-01, six parallel waves running their own scratch ingests)
  - **Expected:** a scratch ingest of the committed HEAD that `verify --strict` can read
  - **Actual:** "go/packages returned 0 packages for ./... although 2809 Go file(s) were discovered", "IngestDocUnits: corpus walk: … operation not permitted", up to 447 EPERM lines per run; a run started right after `tccutil reset` still degraded
  - **Repro:** run several workers' scratch ingests at once on the external build volume; each `source genv-wave.sh` runs `tccutil reset SystemPolicyRemovableVolumes com.mitchellh.ghostty`
- **Root cause:** not isolated: the volume's TCC wedge recurs under heavy file work, and every worker's environment script resets the verdict on each shell, which may itself revoke a grant another worker's long process holds
- **Fix:** none; workaround: retry the ingest until a run has no EPERM line and a typed pass
- **Status:** open
- **Impact:** proving rows on a fresh scratch ingest costs several attempts per worker
