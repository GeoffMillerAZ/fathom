### O761 — the tags engine's EndLine runs to the next token for a grammar whose indentation nodes end at an outdent: Scala's range_agreement .8042, .9511 with the trailing whitespace trimmed

- **Symptom:** a Scala definition whose body sits on the lines after `=` (`def member(xs: List[Int]): List[Int] =` / `  xs.map(f)`), or a Scala 3 brace-less template, gets an `EndLine` on the next definition's line (or a blank line) instead of its body's last line, in 5,134 of 26,218 matched definitions on typelevel/cats and http4s/http4s
- **Evidence:** `docs/bench/readings/lang/scala.json` range_agreement .8042 (21,084 of 26,218) against the scalameta 4.17.4 dump; the dialect's goldens (`internal/extractor/dialects/scala/testdata`) carry nine such end lines where the hand-typed golden and the oracle say otherwise; with `tsEndLine` trimming trailing whitespace before it counts newlines (the patch below) the same subjects and oracle read .9511 (24,937 of 26,218) and L1 excellent. The walker read the same node end (CGO `EndPosition`): its range_agreement is .7183
- **Root cause:** tree-sitter-scala's external scanner emits a zero-width outdent token at the next token's position, after the newlines and indentation that follow the block, so `indented_block` (and the definition around it) ends there (`function_definition [8:2-11:2]` for a body on line 9); `tsEndLine` (internal/extractor/tsextract.go) counts the node to its last byte, whitespace included
- **Fix:** proposed for the engine's owner (item tsjs; this item may not edit tsextract*.go): in `tsEndLine`, step `end` back over trailing ` `, `\t`, `\r`, `\n` before counting, `return d.defLine + bytes.Count(src[d.start:end], []byte{'\n'})`. Tried in the worker's tree (wave lf3, item scala) and reverted: it also moves end lines in the html (2 fixtures) and makefile (6 fixtures) dialect goldens, which their owners would re-read, and the scala goldens' nine outdent end lines would then read as typed by hand. The patch, whole:
  ```
  -	return d.defLine + bytes.Count(src[d.start:d.end-1], []byte{'\n'})
  +	end := d.end
  +	for end > d.start+1 && (src[end-1] == ' ' || src[end-1] == '\t' || src[end-1] == '\n' || src[end-1] == '\r') {
  +		end--
  +	}
  +	return d.defLine + bytes.Count(src[d.start:end], []byte{'\n'})
  ```
- **Status:** open (engine need, reported to the integrator)
- **Impact:** Scala reads L1 good, not excellent; `EndLine` (blast radius, symbol context ranges) overstates such a definition by its trailing blank lines and the next definition's first line
