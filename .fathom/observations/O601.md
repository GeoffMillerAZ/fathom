### O601 — mapping macros, enumerators, fields and variables puts the calls written in them into L2's truth: the dialects attribute none

- **Symptom:** C call_recall .9883 -> .9626 and C++ .9407 -> .9292 when only definitions were added and the harness learned to map macros
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -unmatched` before and after, wave lf1 item ccpp
  - **Expected:** L2's call truth is the call sites inside a mapped definition
  - **Actual:** 468 new C truth pairs: callers INIT, POST, UV_LOOP_WATCHER_DEFINE (a function-like macro's body), CURLFORM_ARRAY (an enumerator written `CURLFORM_ARRAY CURL_DEPRECATED(...)`), uv__signal_tree (`RB_INITIALIZER(...)` in a variable's initializer), pad (`offsetof` in a field's bound); 43 in C++ (EXPECT_READ, NLOHMANN_DEFINE_DERIVED_TYPE_INTRUSIVE, SPDLOG_LOGGER_CALL bodies)
  - **Repro:** diff the `calls.oracle_only` of two -unmatched dumps
- **Root cause:** the tags engine attaches a call to the smallest enclosing callable; a macro body is preproc_arg text, never parsed, and a variable, field or enumerator is no callable
- **Fix:** open: attach a call in an initializer to its variable, and read a function-like macro's body as code
- **Status:** open
- **Impact:** L2 stays excellent on both (.90); the drop is a recall gap the unmapped callers hid
