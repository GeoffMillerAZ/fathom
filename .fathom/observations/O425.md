### O425 — a plan row's quoted pattern with an odd number of escaped quotes drops the whole annotation

- **Symptom:** two new rows of docs/plans/language-breadth.md (LB-F159, LB-F160) verified as positional `md-171` and `md-211` with no contract, so `fathom verify --strict` failed them, though their `{id: …, oracle: lexical, path: …, pattern: "…"}` blocks were well formed.
- **Evidence:**
  - **Tool:** `fathom verify --strict --store <scratch> --service fathom --plan docs/plans/language-breadth.md` (wave ox, branch ox-ci, 2026-10-02).
  - **Expected:** a double-quoted value may carry an escaped quote (`\"`), as LB-F95's pattern does (`"\"tool\": \"gradle .help. init-script model.\""`), and the trailing block is the annotation.
  - **Actual:** `pattern: "\"tool\": \"gitlab-ci-local --preview ablation"` (three escaped quotes inside the value) left the closing `}` inside a quoted span, so no brace pair was found and the row fell back to a positional id; LB-F95 works only because its value carries four.
  - **Repro:** a checkbox row ending `{id: X-1, oracle: lexical, path: README.md, pattern: "\"a\": \"b"}`, then `fathom verify --plan <it>`: the row reads `md-NNN`, not `X-1`.
- **Root cause:** internal/verify/markdown.go `trailingBraceBlock` toggles its quote state on every `"` byte, never skipping one escaped with a backslash, so quote pairing is by parity of all quote bytes; `splitPairs` does the same, so a comma after an odd number of escaped quotes splits the value (the first fix, four escaped quotes and a comma, then failed as a truncated pattern that matched nothing).
- **Fix:** worked around in the plan (each pattern carries four escaped quotes and no comma). Product side, open: skip a backslash-escaped quote in `trailingBraceBlock` (and in `splitPairs`, which shares the convention), and have LintPlan name a row whose trailing text carries `{id:` but parsed no block.
- **Status:** open (product side)
- **Impact:** any plan row whose quoted regexp matches a JSON string silently loses its contract unless its escaped quotes happen to pair; `--strict` catches it as failing, without saying why.
