### O1210 — The test-run hook's rows carry no tool-use id, so a failing run is located by session, runner, scope and time

- **Symptom:** `logTestRunRow` writes `session`, `invocation`, `scope`, `failing` and the head/tree keys, but no `tool_use_id`, though the hook input has `ToolUseID` (readout rows carry it).
- **Evidence:** cmd/fathom/testrunhook.go `logTestRunRow` and `testRunRowKeys`; internal/harness/codec.go `HookInput.ToolUseID`.
- **Root cause:** RO-35's keys were chosen for the test delta, which joins rows to each other, not to transcripts.
- **Fix:** `readout report --baseline` matches a row without an id to the one call in its session's transcript that ran the row's invocation and scope, nearest the row's time within 30 s, and counts an ambiguous or absent match as `tool-use id absent`, never untouched. Adding `tool_use_id` to the row (one additive key) makes the match exact for RO-M4's enriched rows; it is outside this wave's files.
- **Status:** fixed (wave fx1, item fold)
- **Impact:** the baseline's located share depends on the time match; rows whose transcript holds two equally near runs of the same scope are lost to `tool-use id absent`.
