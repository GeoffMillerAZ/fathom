### O1039 — actionlint's own local-uses resolution attests 225 of the 245 GitHub Actions L3 edges, at tier C

- **Symptom:** LB-F457 asked whether actionlint v1.7.12's own resolution (a Linter's Project, LocalActionsCache, LocalReusableWorkflowCache) attests the file a local `uses:` reaches, so github-actions.json's L3 could leave tier C.
- **Evidence:** `calibration/oracles/github-actions` `main.go -resolve-out` (resolve.go, wave lf8) asks both caches over a Project rooted at each subject. On the reading's scope (pytorch v2.8.0 `.github`, 245 edges: 170 reusable workflows, 75 step actions) they attest 225, every one equal to the reading's truth: all 170 reusable workflows, 55 of the 75 step actions. The other 20 reach `filter-test-configs`, `chown-workspace` and `upload-utilization-stats`, whose metadata actionlint refuses ("unexpected key \"type\" for definition of input") and GitHub's `parseAction` accepts. actionlint reads `action.yaml` before `action.yml`, the runner's reverse (TestActionlintResolution; no subject directory holds both). It lints workflows only, so a composite action's steps are not its parse.
- **Root cause:** actionlint is an independent parser library (owner decision D4, tier C), not GitHub's evaluation, and no offline GitHub tool resolves a step's `uses: ./dir`; a run step's first command (LB-F310) is a second family nothing evaluates.
- **Fix:** the ceiling is written: workflow_parser_oracle.mjs `-xref-out` discloses a note beginning `L3 ceiling: ` for every subject with a local-uses edge (e3c03ed7), and github-actions.json carries it (9c8f9156); LB-Q-github-actions-rest holds the trigger.
- **Status:** closed (the ceiling written)
- **Impact:** GitHub Actions L3 stays good at tier C with every metric 1; the reading now says why in its own notes.
