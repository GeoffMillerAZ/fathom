### O799 — HTML's L2 has no meaning under §1.2: a disclosed ceiling, the decision is the owner's

- **Symptom:** the tracker reads HTML "L2 not met: call_recall not measured", as if a call oracle were missing; LB-Q-html keeps an L3 target that needs L2 met first
- **Evidence:** design §1.2 defines L2 as call_recall and call_precision over (enclosing symbol, callee name) pairs. The html dialect's own kinds (HTMLId, HTMLCustomElement, HTMLForm, HTMLFormField; `internal/extractor/dialects/html/dialect.json`) carry no call, and markup has none to carry. The calls in a file are the injected languages': html.json's bootstrap subject holds 5 JSFunc definitions from inline `<script>` (excluded_by_kind `fathom:JSFunc`), and their calls are JavaScript's, measured by the javascript dialect's L2; an inline handler (`onclick="go()"`) is JavaScript too. universal-ctags 6.2.1's HTML parser reports no calls, and no HTML oracle here does
- **Root cause:** the queue entry targets L3 for a language whose L2 measure is empty by definition, so the level ladder cannot reach L3 without a rule for L2 on markup
- **Fix:** none invented. LB-Q-html-rest now states the ceiling: L1 capped at good (ctags writes no HTML end line), L2 undefined for markup, L3 needing a tier-A link-checker oracle (resolved src/href pairs) the entry does not name
- **Status:** open for the owner: waive L2 for a language without calls (the harness would then read L3 on import_resolution and file edges alone) or lower HTML's target to L1. The same shape holds for CSS (LB-Q-css-rest) and any stylesheet or markup dialect after it
- **Impact:** HTML stays at L1 good; no level rule is changed in this wave
