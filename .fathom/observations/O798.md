### O798 — CSS L1's misses are universal-ctags' CSS tokenizer, not the dialect: the miss table by cause

- **Symptom:** css.json read below L1 (sym_recall .1423, sym_precision .354, fathom 06815345); LB-Q-css-rest and the tracker blamed BareName's separator set, per-selector lines in multi-line comma lists, and tree-sitter-css v0.25.0 misparsing `:not(A, B)`
- **Evidence:** `indexbench lang-oracle -dialect css -unmatched` at fb7d9f3f on normalize.css dafaf9ee and pico 1039a478 (`css/`, 119 files), universal-ctags 6.2.1, each miss classified by replaying ctags' own tokenizer (parsers/css.c at v6.2.1, 9463f1c6) over the dialect's selector text. At HEAD the harness already reads recall .1593, precision .3964 (normalize 66 of 70; pico 30,955 matched of 78,191 dialect and 194,677 ctags definitions):

  | cause | dialect-only | ctags-only |
  |---|---|---|
  | BareName's separator set | 0 | 0 (css compares names whole, `name_match: identity`) |
  | per-selector physical lines (\|Δline\| > 2) | 0 | 0 (the dialect takes each selector's own `@name` row) |
  | tree-sitter-css v0.25.0 misparsing `:not(A, B)` | 0 | 0 (the grammar parses Selectors 4 lists; pico's one ERROR per file is `@-moz-document url-prefix()`, 118 of 119 files) |
  | ctags' spacing: tokens rejoined with one space (`a[x] ::before`, `:not([x] )`) | 12,165 | 12,165 |
  | ctags drops a leading attribute selector's brackets (`[hidden]` is `hidden`) | 301 | 301 |
  | ctags ends a tag at any comma, also inside `:not()`, `:is()`, `:where()`, `:has()`, and splits a leading `[a=b]` into `a` and `b` | 34,124 | 151,260 |
  | ctags' sort removes an identical tag on one line (`[type=checkbox]:checked:active, [type=checkbox]:checked:focus` share `type`, `checkbox`) | 60 | (inside the row above) |
  | ctags skips every at-rule block but `@media` and `@supports` (`@-moz-document`) | 590 | 0 |
  | rest | 0 | 0 |

- **Root cause:** universal-ctags' CSS parser does not parse selectors. It reads tokens (a run of letters, digits and `_-+>~|().:*#`, a string, or one other byte), writes one tag per run of selector tokens joined by spaces with a following `[...]` glued on, and a comma ends a tag wherever it stands. Its tags are a rendition of the selector text, so modern CSS (pico's Selectors 4 lists, unquoted attribute values) breaks into fragments: 117,016 of pico's 194,677 ctags tags are fragments of another selector. None of the three named causes is real at HEAD
- **Fix (K19, LB-F423):** a CSS-scoped matching rule. Against ctags, a CSS selector is compared in the tags ctags writes for it (`cssCtagsRendition`, internal/langbench/ctags.go): the first tag is the match key at its own line, and a matched selector's further tags are the same definition, consumed and tallied `ctags:selector-fragment`; the css manifest runs ctags with `--sort=no`, so a tag two selectors share on a line is written twice, as the parser makes it. BareName, oracleMatchName and every other language are untouched. On the calibration subjects: recall .9532, precision .9467 with the rendition alone; recall 1, precision .9925 with `--sort=no`; the 590 left are `@-moz-document` selectors ctags skips (a D3 candidate, not taken). To be held out on subjects chosen before the rule runs on them (calibration/corpus.d/css-holdout.yaml), read once
- **Status:** miss table filed first; the rule and its holdout shard are committed next, alone, before any holdout reading; the dialect does not change, so CSS has no ExtractorEpoch need
- **Impact:** CSS reads L1 (good: ctags writes no CSS end line), which satisfies SCSS's dependency under D6
