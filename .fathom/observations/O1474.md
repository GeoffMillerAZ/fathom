### O1474 — CUE's doc-xref pass stores every edge the file resolver draws, so running both stored each twice

- **Symptom:** with the cue-module strategy wired into ingest's file-resolved pass, `TestIngest_CUEModuleReachesTheCUEDialect` read each import edge and each reference through an import twice: both passes store `EdgeFileResolved` under their own typed-edge keys, and `typed_edges` has no uniqueness.
- **Root cause:** the doc-xref pass's cue-import strategy already draws an import's edge to each loaded file's package entity and binds a name below an import to every declaration of it; the file resolver binds a unique top-level name only. Measured on LB-Q-cue's subjects: the file resolver finds 61 of the 478 true cross-file references, all of them among the doc-xref pass's 359 (precision 1 both), and on the holdout 1,210 of its 1,441; it finds no true reference the doc-xref pass misses.
- **Fix:** the doc-xref pass supersedes it: ingest leaves CUE out of the file-resolved pass (`fusion.docXrefSupersedes`), and the doc-xref cue-import strategy loads an import's files by the cue-module strategy's own index, so the two never disagree on a package's files. The file resolver still grades CUE's L3 (ResolveFileEdges, ResolveImportSpecs); ingest cost unchanged (NetMeta: store 29,468 KiB both, wall 2.21 s base vs 2.16 s median of six).
- **Status:** fixed
- **Impact:** CUE's stored cross-file edges are the doc-xref pass's, once each.
