### O1382 — call_direction globs match package names, not directories, because call edges carry no target file

- **Symptom:** FD-30 asks for package globs over call edges; every other layer_rules kind matches package directories ("internal/store").
- **Evidence:** core.Edge holds FromFile but no ToFile (internal/core/model.go Edge); archconformance.Check keys edges by the declaring-package name (pkgOf of the symbol key), so a directory glob cannot be tested on the target side.
- **Root cause:** the arch_conformance engine, review and the archconformance.cue pack share one name-keyed edge form.
- **Fix:** call_direction globs match the package name an edge carries ("connector"), compiled to archconformance.Rule.FromGlobs/ToGlobs so both forms share Check. An allowing rule overrides a forbidding one across the set (the legacy rule), not in EvaluateLayerRule's per-rule view. gen-test and rulereplay skip the kind like cross_service_direction.
- **Status:** fixed in FD-30
- **Impact:** two packages with one name in different directories collide in either form, as they already did in the pack.
