### O443 — O265's enclosure rule measured both ways, for the tier-C JavaScript truth and for scip-typescript's local definitions: numbers for the owner's decision, no decision taken

- **Symptom:** the oracles and the dialects disagree on which function a call is written in wherever a definition sits inside a function. Tier C (upstream tags.scm) pairs a call with its innermost upstream definition, which includes function-local bindings, named function expressions and object-literal members the dialect does not define (O265); scip-typescript defines a class declared in a function, its methods, a nested function declaration and a named function expression only as a `local` with no enclosing range, so its truth pairs the call with the module or member definition around it while the dialect, which defines them, pairs it with the inner one (O440's g1: TypeScript 726 of the reading's 834 fathom-only pairs, JavaScript 146 of 390).
- **Evidence:**
  - **Tool:** at fathom 43c90bb4: (1) tier C: calibration/oracles/ts-tags/tags_oracle.py's pairing, run in a scratch copy that also emits each call's chain of enclosing upstream definitions (py-tree-sitter 0.25.2, tree-sitter-javascript 0.25.0, a private venv), scored against the dialect's pairs on the files it measures; (2) scip: a scratch build of `ScoreSCIPWith` (`go build -overlay`, never committed) that names a scip-typescript `local` definition by what is written at it and gives it the enclosing lines of the fathom definition it maps to (same name, |Δline| ≤ 2, D5), on the readings' indexes, oracle-blind rule on.
  - **Expected:** one enclosure rule, chosen by the owner, under which both oracles and the dialects agree.
  - **Actual:**
    - Tier C, JavaScript (axios + express): innermost upstream definition (today's rule, `lang-oracle -tool-oracle` on tags_oracle.py's own output): call_recall .7245 (1,173 of 1,619), call_precision .8151 (1,173 of 1,439); innermost upstream definition the dialect also defines (same name, |Δline| ≤ 2): recall 1 (1,301 of 1,301), precision .9041 (1,301 of 1,439). At 99c3c7d3 the committed note read .7245 / .8767: precision fell because the dialect now records `new X(...)` as a call (LB-F171), which upstream's query tags `@reference.class`, never a call. Under the second rule the oracle only checks callee names inside the dialect's own callers, so its recall of 1 is close to circular.
    - scip-typescript, TypeScript (zod + nest): today's rule (locals enclose nothing) call_precision .9235 (10,064 of 10,898), call_recall .9836 (10,064 of 10,232); a local definition the dialect also defines (a function, method or class of the same name within two lines) encloses its calls: .9516 (10,371 of 10,898) and .9849 (10,371 of 10,530). Mapped to any dialect definition instead, a test's `const a = z.string()` maps to its `type a = z.infer<typeof a>` and the truth gains 196 pairs no function encloses; the scratch rule keeps to callables and classes.
    - scip-typescript, JavaScript (axios + express): today's rule .6173 (629 of 1,019) and .8897 (629 of 707); locals enclosing: .7566 (771 of 1,019) and .9507 (771 of 811).
  - **Repro:** the commands above; the reading's own numbers come from `lang-oracle` under today's rule.
- **Root cause:** L1 pulls the dialects' definitions to module and member scope (scip-typescript's), and keeps a function declaration and a class at any depth because the oracle reports each as a definition, if only a local one; L2's truth then encloses calls by module and member definitions alone.
- **Fix:** none: an owner decision (O265). Options: (a) today's rule, disclosed; (b) a local function, method or class the dialect also defines encloses its calls, for scip-typescript (the D5 extent rule extended to locals, which scip-dart's PrivateMembers already names by what is written); (c) for tier C, the innermost upstream definition the dialect defines.
- **Status:** open (needs owner decision)
- **Impact:** TypeScript L2 is excellent under (a) and (b); JavaScript's is unmet under both (O442); the tier-C JavaScript L2 is unmet on recall under (a) and meets tier C's cap, good, under (c).
