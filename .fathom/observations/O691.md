### O691 — syslink's route source never reads java or php: the dialect map gained them, the registry that dispatches does not list them, and nothing in the product calls that registry

- **Symptom:** wave c2's brief asked `internal/syslink/route.go` routesLang to gain java and php so Spring, JAX-RS and PHP routes become `route:` provides rows. The map now names them, yet `DefaultRegistry().Keys(file, src, "java")` still returns no route row
- **Evidence:** `internal/syslink/defaults.go` registers `routeSource{}` only for `go`, `javascript`, `typescript`, `tsx` and `python`; `DefaultRegistry` is called only from tests (`fleet_test.go`, `route_test.go`, `proto_test.go`), and the product's `route:` keys come from `serviceref` (hops) and `inventory` (items), which the route seam does feed (LB-F321, `TestServiceRefs_NoMountRowLeaks`)
- **Root cause:** syslink's per-file contract sources are the SG-2 design's future and are not wired; a language added to routesLang does nothing until `defaults.go` registers the source for that dialect id
- **Fix:** none in wave c2 (`defaults.go` was outside item java's files). When SG-2 wires the registry, register `routeSource{}` for `java` and `php` beside the others; syslink's rows are also per file, so a mount another file applies is not composed there (Compose needs the service)
- **Status:** open
- **Impact:** none today (the registry has no product caller); a later SG-2 change that trusts routesLang alone would miss every Java and PHP route
