### O1513 — a gate host with an older local Go learns it ten minutes into validate, from an unrelated test first

- **Symptom:** a gate host whose local Go is older than go.mod's toolchain line fails the pre-push gate late and misleadingly instead of at the start with a remedy
- **Evidence:**
  - **Tool:** task validate (scripts/gate-log.sh)
  - **Expected:** gate-log.sh pins GOTOOLCHAIN=local on purpose (no toolchain download from a gate), and since 7c441a027 the local gate assumes go.mod's toolchain is installed; a host whose `go version` is older (go1.26.3 against `toolchain go1.27.3`) should be refused in the first second, naming the remedy (install go.mod's toolchain locally)
  - **Actual:** the gate prints `go version go1.26.3` and runs. The first failure seen was an unrelated test from #81 that fails only on 1.26.3 (TestReadSimulinkModelHeapBound, two pushes, about 23 minutes each), and only a later run reached the real guard, TestToolchainMatchesGoMod ("built with go1.26.3, older than go.mod's toolchain go1.27.3"), about ten minutes into validate
  - **Repro:** on a host with local go1.26.3: `GOTOOLCHAIN=local go test -count=1 -run '^TestToolchainMatchesGoMod$' ./internal/fusion` (FAIL); then `task push` and see how long the gate runs before failing
- **Root cause:** the toolchain contract is enforced by a test inside the suite, not by a preflight in gate-log.sh
- **Fix:** TODO: a gate-log.sh preflight that compares `go version` with go.mod's toolchain line and exits before any step, with the install remedy
- **Status:** open
- **Impact:** about 90 minutes of gate time on one host across four pushes, and a misdiagnosed test failure
