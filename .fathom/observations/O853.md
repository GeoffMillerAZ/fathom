### O853 — With SCSS registered, the generated unsupported table drops `.sass`, which no dialect reads

- **Symptom:** after LB-Q-scss-rest stopped being refused (the scss dialect is dispatched, LB-F465), `indexbench lang-disclosure` no longer lists `.sass` in `internal/connector/unsupported_language_gen.go`, though `.sass` (Sass's indented syntax) is neither classified nor dispatched: an indented-syntax file is now skipped without a disclosure.
- **Evidence:** the queue entry `scss` is named "SCSS / Sass (.scss .sass)"; `langbench.DisclosureTable` lists a queued language's extensions only while the language has no registration, and drops every extension of it once one registers. Regenerated at the plan of this wave: `.scss` left the table with the dialect (correct), `.sass` with it (not).
- **Root cause:** the table is per language; the queue entry joins two syntaxes, of which the dialect reads one. P233/tree-sitter-scss parses SCSS only (its README: "Indented Sass (.sass) is not supported"), and no measured grammar parses the indented syntax.
- **Fix:** the queue owner's: name the entry "SCSS (.scss)" and give the indented syntax its own entry ("Sass, indented syntax (.sass)"), which the table then discloses; or the generator keeps a registered language's extensions the connector does not classify. Neither file is this item's (the queue is html's in wave lf5; disclosure.go is the harness's).
- **Status:** closed (wave lf6, owner ruling M5): the queue entry is "SCSS (.scss)" and the indented syntax has its own entry `sass` ("Sass (indented syntax) (.sass)", LB-Q-sass, LB-Q-sass-rest); the regenerated table lists `.sass` as sass (LB-F508, O926).
- **Impact:** a repository with `.sass` files reads them as neither indexed nor disclosed until the queue splits the entry; `.scss` is indexed.
