### O606 — Go struct fields have no symbol: 4,236 of cli/cli's 4,967 unmapped definitions and 28,084 of its 42,232 unmapped typed_recall endpoints

- **Symptom:** go.json's L4 def_mapping .5494 and typed_recall .5805 against .85 good
- **Evidence:**
  - **Tool:** the scip-go notes of `indexbench lang-oracle` (scip_go_defs_unmapped_field, scip_go_unmapped_to_field; wave lf1)
  - **Expected:** a definition scip-go defines maps to a fathom symbol
  - **Actual:** a struct field (and an interface method, which scip-go writes as a term of its interface) has no `goextract` node; def_mapping would read .8837 without the class, typed_recall .7931 (arithmetic, not graded)
  - **Repro:** as O603
- **Root cause:** `goextract` emits functions, methods, types, interfaces, package variables and constants, never a member; neither ADR-048 nor design §1.4 makes fields-as-symbols a cross-language rule (Rust LB-F82, Python LB-F241/LB-F242, Java and C# added members per language)
- **Fix:** none. `goextract` is unchanged and no `ExtractorEpoch` need is reported; the decision is the owner's (a member pass, `Owner.name`, a `field` kind outside `oracle_kinds` as for Python)
- **Status:** open; trigger: owner decision on Go field symbols
- **Impact:** Go stays below L4
