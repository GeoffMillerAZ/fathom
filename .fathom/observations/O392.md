### O392 — a Cloud Custodian filter or action cannot be an entity: the doc engine names an entity from its own node and a symbol key is `service::package.Name`, so a file's second `value` filter collides with its first

- **Symptom:** the queue asks for "filters/actions by type" as entities; the dialect carries them as the policy's references (`Calls`) instead
- **Evidence:**
  - **Tool:** `ExtractDoc` on a file with two policies that each carry `type: value` filters (testdata/basic.yaml has the type in three places)
  - **Expected:** one entity per filter, named by its type and its policy
  - **Actual:** the entity's name can be `.type` only (no ancestor value, `$parent` is one step up and a sequence item adds no key), and two entities named `value` in one file are one symbol key
  - **Repro:** a `CustodianPolicy`-style entity rule on `$.policies[*].filters[*]` with name `.type`
- **Root cause:** docengine.go's entity name is a value expression on its own node; no ancestor accessor, and this item may change the engine only where a level is otherwise unreachable (L2 is reached without it)
- **Fix:** none; LB-Q-cloud-custodian-rest carries it, trigger an ancestor value in the entity name (a `$policy`-style accessor) or a per-file unique name
- **Status:** open
- **Impact:** a filter or action is a reference from its policy, not a symbol a caller can navigate to
