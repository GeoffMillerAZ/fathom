### O677 — scip-python 0.6.6 writes no reference for a relative import's module: 26 of Python's 41 fathom-only file edges

- **Symptom:** with K18's module symbol, Python's file_edge_precision moved from .9918 to .9875 (fastapi + flask, LB-F349): fathom-only file edges 15 to 41 (fastapi 15 to 32, flask 0 to 9), while file_edge_recall rose from .5119 to .9191.
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -unmatched` before (784657b9) and after (wave lf2) on fastapi 864b569 + flask 22d9247, scip-python 0.6.6 in run.sh's environment; `file_edges.fathom_only_via` names each new pair's endpoints.
  - **The new pairs:** all 26 are file-resolved edges to a module symbol (fusion.moduleImportEdges) from a relative import: to the package its leading dots name (`from . import cli` in src/flask/app.py to src/flask/__init__.py, `from . import a, b` in tests/test_modules_same_name_body/app/main.py), or to the module it reads names from (`from .requests import Request` in fastapi/__init__.py to fastapi/requests.py, `from ._compat.v2 import ...` inside a method of fastapi/datastructures.py).
- **Root cause:** scip-python writes an occurrence for each name a relative import reads, and none for the module path itself; Python executes that package's `__init__.py` and that module before binding the names, so the edge is the import's and the oracle is blind to it (an absolute import's module path is referenced, and agrees).
- **Fix:** none; disclosed in python.json's L3 note. A relative-import package edge could be left out of file_edge_precision as an oracle-blind rule (the LB-F175 shape) if a later reading needs the margin.
- **Status:** open (disclosed oracle deficiency)
- **Impact:** file_edge_precision .9875 instead of about .995; L3 stays excellent.
