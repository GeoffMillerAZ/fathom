### O1132 — a `serve-http` daemon started while killed kept its decision port closed after the kill lifted, until a restart, and nothing said so

- **Symptom:** with `~/.fathom/decide.off` present (or the user-only `[decide] enabled = false`) when `serve-http` starts, `decide.Open` returned `decision.None`; removing the file (or setting `enabled = true`) left every site on its deterministic path until the daemon restarted. `fathom doctor`'s remedy ("rm ~/.fathom/decide.off to reopen the port") and ADR-073 decision 5 (the file and `enabled` are live kills, re-checked before each ask) read as if it reopened.
- **Evidence:**
  - **Tool:** `internal/decide.Open`, `cmd/fathom/openDecisionPorts`
  - **Expected:** a live kill is re-checked before each ask, so lifting it reopens the port on the next ask with no restart, the way a port killed after start already does (KS-2).
  - **Actual:** a closed gate at Open built no `liveGate` and returned `decision.None`, so nothing re-checked the kill afterwards; for provider `llm`, `openDecisionPorts` returned `decision.None` before resolving the profile.
  - **Repro:** `touch ~/.fathom/decide.off`, start `serve-http` with a configured provider, `rm ~/.fathom/decide.off`, then ask: before this fix the obligations re-rank and `/route` still answered on the deterministic path.
- **Root cause:** Open treated every closing source as settled for the process; only the environment and a refused consent are.
- **Fix:** a port only a live kill closed at Open is a reopening port (`internal/decide/reopen.go`): it re-checks the kill before each ask like any open port, and the first ask after the kill lifts finishes Open once (the llm lane and its model through `WithLaneModel`, or the remote adapter and its key source, inside the degrade fallback), applying the daemon's gates (`Ports.Gated`) to the adapter then. While killed it reads no key, execs nothing, builds no lane and dials nothing (the KS fakes count zero), and there is no background job. A failure to open after the lift is disclosed once and the sites stay deterministic. The startup line and doctor's live-kill remedies say the port reopens with no restart. Tests: `TestPortKilledAtOpenReopensOnTheNextAskAfterTheKillLifts` (`internal/decide`), `TestDaemonStartedKilledReopensOnTheNextAskAfterTheKillLifts` (`cmd/fathom`).
- **Status:** fixed (fx1)
