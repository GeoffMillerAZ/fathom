### O1273 — a test-run row's absent `scope` means both "no pattern or filter" and "not computed"

- **Symptom:** RO-35 writes no `scope` key when `testRunScope` returns "", which it does both for a readable command with no package pattern or filter (a plain `task test`, the commonest declared command) and for an unreadable one (RO-4). RO-23's rule "a row missing a key reads `not compared`" would then read every plain `task test` delta as not compared.
- **Evidence:**
  - **Tool:** test-run hook row (`cmd/fathom/testrunhook.go` testRunRowKeys, testRunScope)
  - **Expected:** an absent key means a miss, as RO-35's row says
  - **Actual:** `task test` with no arguments logs no `scope`, the same as a command the lexer could not read
  - **Repro:** run `task test` through the test-run hook; the row carries `head` and `tree` but no `scope`
- **Root cause:** `testRunRowKeys` drops any empty value, and an empty scope is a value.
- **Fix:** RO-23 applies `not compared` to a missing `head` or `tree` only and reads an absent `scope` as empty; it compares rows by invocation and scope together and re-lexes the current command for its filters, so an unreadable command is never read as unfiltered. A later row could log `scope` as an explicit empty marker if another reader needs the distinction.
- **Status:** open
