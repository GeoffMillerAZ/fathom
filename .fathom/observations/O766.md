### O766 — every code edit re-ran the whole doc-xref pass in a repository with no Lambda function (C3's handler-source input)

- **Symptom:** after C3 (LB-F370), a one-line Python edit to zulip 12.3, a repository with no Lambda function, re-ran the doc-xref pass on every ingest (1.06 to 1.20 s), and the edit hook's one-file refresh invalidated the pass, so the ingest after it paid the pass too (0.86 to 1.20 s). fathom's own tree paid 0.61 to 0.63 s per code edit. 70afc4a9, before C3, skipped the pass on both
- **Evidence:**
  - **Tool:** `fathom ingest --json` pass_times (`doc_xref`), `POST /refresh-file` (ReingestFile), on zulip 12.3 (b3198225) and fathom c68b5097; readings in `docs/bench/readings/efficiency-wave/docxref-lambda-gate.md`
  - **Expected:** a code file a Lambda handler binding may name is an input of the pass only where some function can name it
  - **Actual:** `isDocXrefInput` OR-ed `isLambdaHandlerSource` (`.py`, `.js`, `.mjs`, `.cjs`, `.ts`, `.mts`, `.cts`, `.java`, `.rb`) for every service, and `passKeysFor` used it for the one-file refresh's invalidation (O723, O730)
  - **Repro:** ingest zulip 12.3 with c68b5097, append a line to `zerver/lib/utils.py`, ingest again: `doc_xref` 1.16 s
- **Root cause:** the input rule was the file's extension alone; whether the service declares a function was not asked
- **Fix:** EW-57 (wave h3). The rule is now service-aware. `isLambdaDeclaration` (shared with `ResolveLambdaHandlers`) reads a declaration from the stored symbols with one `ObservationsOfKinds` read, memoized per ingest or refresh. The read runs only while the pass's record still stands, and is timed as the `lambda_gate` span (66 to 73 ms on zulip, 18 ms on fathom). The gate covers both the ingest's gate (`docXrefPassNeeded`) and the refresh's invalidation (`passInvalidator.keysFor`). Stored output is identical on both subjects (no epoch bump). fathom declares no Lambda function in what it ingests (its Lambda fixtures sit under `testdata/`, which discovery skips), so it pays nothing either
- **Status:** fixed (EW-57). Open residual, as before C3: a GitHub Actions run step or a Jenkins shell step can name a `.py`, `.js` or `.rb` script that defines functions (LB-F310, LB-F374). In a service with no Lambda function, an edit of that script re-runs the pass only when a document changes. C3's blanket input had covered it by accident. A precise rule needs to know which scripts a step names without reading the workflows, so it waits for stored run-step targets. The gate's read scans the service's rows (no kind index, table freeze): 30 to 40 ms warm, up to 0.9 s on a cold page cache on zulip
- **Impact:** about one second of every code-edit ingest in a repository without Lambda functions (most of them), and the same after every edit-hook refresh
