### O764 — a tree-sitter query child pattern under a repeated field name reads only the first such child: a case class's second parameter list was lost

- **Symptom:** `(class_definition "case" class_parameters: (class_parameters (class_parameter ...)))` captured `fa` and `index` but not `R` in `final case class RepresentableStore[F[_], S, A](fa: F[A], index: S)(implicit R: Representable.Aux[F, S])`
- **Evidence:** `indexbench lang-probe -dialect scala` on the shape; dropping the `class_parameters:` field name from the pattern captures all three; the scalameta reading's oracle-only definitions fell by two (cats' RepresentableStore and RepresentableStoreT)
- **Root cause:** with a field-constrained child pattern the query matched the first child carrying that field, not each of them (tree-sitter 0.26.11 core, the blob's runtime)
- **Fix:** the scala dialect's case-class and enum-case patterns match `(class_parameters ...)` without the field name (dialects/scala/tags.scm, its comment says why)
- **Status:** closed for scala; a note for any dialect that matches a repeated field
- **Impact:** a field-name child pattern under a node with a repeated field silently reads its first occurrence only
