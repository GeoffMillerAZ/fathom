### O1475 — `nix-instantiate --parse` is a tier-C oracle for Nix: it prints no positions, so the lines are the writer's

- **Symptom:** the brief names `nix-instantiate --parse` as the reference parse. It prints the expression back as Nix text, fully parenthesised, attribute sets merged and sorted (`a.b = 1; a.c = 2;` is one `a = { b = 1; c = 2; }`), every path absolute, an operator on numbers as `__sub`, `__mul` and a `<nixpkgs>` as `__findFile`, and no line or column anywhere. It also refuses a file with an unbound variable (`error: undefined variable 'x'`), which is a scope error, not a syntax error. The harness matches a definition by (path, name, line within 2).
- **Evidence:** `calibration/oracles/nix-parse` (README, `main_test.go`); the reading `docs/bench/readings/lang/nix.json`: home-manager 3,254 of 3,254 files accepted, 15,139 definitions, sym_recall 1 and sym_precision 1, tier C on every family.
- **Root cause:** the printer is for reading back, not for tooling. Lines come from a second reader of the source (`lex.go`, `src.go`) that peels the root expression the way the dialect does, and the parse attests each name (a name the parse does not list is dropped and counted, `sites_unattested`, 0 on every subject read). The oracle therefore encodes the same definition rule as the dialect: it is independent in how it reads Nix (a parser and a lexer, not tree-sitter) and not in what a definition is. Tier C caps every level at good (design §1.3).
- **Fix:** none needed for the row (L3 good is met). Excellent would need an oracle that reports positions for a binding without evaluating: none ships with nix 2.34 (`builtins.unsafeGetAttrPos` evaluates).
- **Status:** closed (disclosed in the reading and the oracle README)
- **Impact:** the Nix row reads L3 good; a reader should take 1.0 recall and precision as agreement on one rule, not as a proof the rule is the right one.
