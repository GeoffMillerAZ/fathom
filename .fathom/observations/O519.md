### O519 — Kotlin L3 first reading: file_edge_precision .7993 because 96.8% of the fathom-only edges join two files of one package, which an import-statement truth cannot hold

- **Symptom:** Kotlin L3 reads import_resolution .9649 (excellent) and file_edge_recall .5671, but file_edge_precision .7993 (6,555 of 8,201 fathom edges), under the .90 bar, so L3 is unmet.
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect kotlin -tool-oracle out/kotlin-<subject>.json -unmatched <file>` (LB-F57; the dump is calibration/oracles/kotlin-psi KotlinPsiDump.java with the O474 imports) on square/okhttp parent-5.4.0 and JetBrains/Exposed 1.3.0, fathom 1f8b8faa plus wave lh item pkc.
  - **Actual:** 1,646 fathom-only file edges (Exposed 629, okhttp 1,017); the unmatched file's `file_edges.fathom_only` joined to each file's `package` line: 1,593 are same-package (Exposed 629 of 629, okhttp 964 of 1,017), 53 cross-package (O520). Counting the same-package edges out of both sides reads .992 (6,555 of 6,608): a counterfactual, not a reading.
  - **Repro:** the commands in calibration/oracles/kotlin-psi/README.md, then `-unmatched` on each subject.
- **Root cause:** a Kotlin file reaches every top-level name of its own package with no import statement, so the import dump (the LB-F57 truth: what each file's imports name) holds none of those edges and the resolver's same-package edges, real references, count against precision. The oracle is blind to them; the resolver is not wrong.
- **Fix:** none to the dialect (imports.scm captures every directive: 0 oracle imports on no statement). A same-package-aware truth (a PSI name-reference join, a separate tier-B family) or a Kotlin SCIP index with ranges would grade it; neither exists here.
- **Status:** open (measurement limit; Kotlin stays at L2 with L3 graded unmet)
- **Impact:** Kotlin L3 cannot read met on an import-statement truth however good the resolver, the same property LB-F57 states for every language.
