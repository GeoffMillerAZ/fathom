### O340 — lang-oracle refuses an oracle file that carries route_references

- **Symptom:** lang-oracle refuses an oracle file that carries route_references
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -tool-oracle` (cmd/indexbench/langoracle.go scoreToolOracle)
  - **Expected:** the wave px route contract's `route_references`/`route_unresolved` fields ride in the tool-oracle JSON and lang-oracle ignores them until LB-F98 reads them
  - **Actual:** `toolOracleFile` is decoded with `DisallowUnknownFields`, so an oracle file with either field is refused ("json: unknown field")
  - **Repro:** add `"route_references": []` to any tool-oracle JSON and run `go run ./cmd/indexbench lang-oracle -dialect haproxy -subject <dir> -tool-oracle <file> -out <reading>`
- **Root cause:** the decoder is strict by design (an unknown field is a typo in an oracle); the route fields were specified as additions it would ignore
- **Fix:** the nginx, haproxy and caddyfile oracles write them to a file of their own (`-routes-out`, same keys); LB-F98 reads that file, or adds the fields to `toolOracleFile`
- **Status:** open — LB-F98 decides where lang-routes reads them
- **Impact:** none measured: the routes are written beside the oracle file, not lost
