### O366 — a function written as `NAME(arg) { … }` (libuv's TEST_IMPL, BENCHMARK_IMPL) is no symbol, so its calls bind to nothing: about 880 of libuv's 1,382 undrawn file edges

- **Symptom:** a function written as `NAME(arg) { … }` (libuv's TEST_IMPL, BENCHMARK_IMPL) is no symbol, so its calls bind to nothing: about 880 of libuv's 1,382 undrawn file edges leave such a body
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect c -scip libuv.scip -scip-defs` (file edges, tier A) and `indexbench lang-probe -dialect c test/test-udp-multicast-ttl.c`, libuv v1.53.0, fathom 32afe369 plus wave cx item cinc
  - **Expected:** test-udp-multicast-ttl.c's `TEST_IMPL(udp_multicast_ttl) {` body calls uv_ip4_addr, uv_udp_bind and uv_udp_set_multicast_ttl, so the file has an edge to src/uv-common.c and src/unix/udp.c
  - **Actual:** tree-sitter-c parses the head as `(function_definition type: (type_identifier "TEST_IMPL") declarator: (parenthesized_declarator (identifier "udp_multicast_ttl")) body: …)`, which no pattern of dialects/c/tags.scm matches: no definition, and the body's calls have no enclosing symbol. Of libuv's 1,382 truth edges the resolver does not draw, the test/ directory holds 1,087 of the 1,127 that end in a .c file (a further 202 leave test-list.h's TEST_DECLARE lines)
  - **Repro:** the probe above (the captures list `uv_ip4_addr` at L65 and no @definition for L56)
- **Root cause:** the C dialect's function query needs a function_declarator; a macro-headed definition has a parenthesized_declarator
- **Fix:** none here (the dialect is item calls'). The pattern, probe-verified to capture `TEST_IMPL` as @name with its @body on that file (a scratch dialect build; its effect on the reading was not isolated, the build that carried it also changed L1's denominators), would be added to dialects/c/tags.scm and dialects/cpp/tags.scm:

  ```
  (function_definition
    type: (type_identifier) @name
    declarator: (parenthesized_declarator (identifier))
    body: (compound_statement) @body) @definition.function
  ```

  It names the symbol by the macro (TEST_IMPL), so every such body of a directory shares one key; the edges are scored by file, which that does not change. An L1 adjudication of the macro-generated definitions (LB-F80) stays as it is
- **Status:** open
- **Impact:** up to 880 more of libuv's 2,129 truth edges (libuv's file_edge_recall reads .351 with none of them); C pooled recall is capped near .38 by this and O369 together
