### O1436 — `TestTestsToRunLineNamesReachingTestsAndARecipe` flaked `not checked (deadline)` under load

- **Symptom:** Wave ro6's first gate run failed the test with `not checked (deadline)` though nothing was wrong. Its success-path subtests ran under the production `testsToRunWait` (300 ms, one `context.WithTimeout` spanning the identity lookup, the blast_radius call and the run-record lookup) while doing real git work in a temp repo, so a loaded machine overran it.
- **Fix:** Tests only. The test sets `testsToRunWait` to one minute for every success path (restored with defer); the deadline case alone shrinks it to 50 ms against the blocking fake daemon, so the miss is proven by the fake's block. Audit: `TestPromptDefinitionsLineNamesResolvedIdentifiersOnly` ran under the 8 s `promptHookDeadlineBudget` and now sets one minute. `TestDaemonJoinMissNamesTheDeadline` already sets `daemonJoinCap` to a minute on its success path and `TestDaemonJoinPlacesNoneOfSeveralDefinitions` runs under `context.Background()`, so neither changed. Proof: all four tests green under `-race -count=20 -cpu=1`.
- **Status:** closed
- **Impact:** A gate run failed on machine speed alone and the failure read as a product defect.
