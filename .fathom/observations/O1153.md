### O1153 — bench fixtures pin ADR.md line numbers, so every insertion above a pin fails the gate with a mismatch that does not say where the text went

- **Symptom:** a five-line insertion under ADR-018 (ADR-074's records pass, 2026-10-17) failed gate run iv2r-1 in two fixture tests at once; the fix (`d035164a`) re-derived both pins by hand. The same hand repin had already landed three times (`7d15957e`, `d00cf6e4`, `10c0decf`).
- **Evidence:**
  - **Tool:** `TestHomeCorpusTruthAtHead` (`internal/contextbench/truth_at_head_test.go`, `checkAnchor` for a `kind: line` anchor) and `TestGuardsCorpusDetectorsExist` (`internal/scenariobench/guards_test.go`, the rule-source check)
  - **Expected:** an ADR.md edit above a pin either leaves the fixture green or fails it with a message naming the pin, where its text now begins, and the command that rewrites it.
  - **Actual:** 29 `ADR.md#L` occurrences in `testdata/contextbench/tasks-home.json` (14), `testdata/scenariobench/guards-adr.json` (9) and `testdata/scenariobench/lookups-vs.json` (6). Two are live pins checked against the working tree: H1-T07's ground truth `ADR.md#L728` (a `kind: line` anchor with needle "Backend selection") and guards-adr-014's `rule.source` `ADR.md#L581` (the line after `## Amendment to ADR-014`, no needle). The line anchor's failure said "the ground truth is false at HEAD" with no remedy; the guards check said only "line N is neither a row nor inside the ADR-014 section", since nothing recorded which text the pin cites. The other 27 are prose (`source`, `notes`, `why`, `derivation`), heading-form sources (`ADR.md#ADR-006` and six more, already insertion-proof) or lookups-vs answers scored at `base_commit` 1b8765d (immutable: a HEAD edit never reaches them).
  - **Repro:** insert a line above ADR.md:581 and run `go test ./internal/contextbench ./internal/scenariobench -run 'TestHomeCorpusTruthAtHead|TestGuardsCorpusDetectorsExist'`.
- **Root cause:** both consumers need the literal line. H1-T07's token is the scored ground truth (an agent at HEAD must cite the line the text is on), and guards `rule.source` is the guards gold-source token, so neither can be resolved at test time without changing what the bench measures. The pin is correct by construction only until the file grows; the guards rule carried no record of the text it cites, so drift could not be named.
- **Fix:** the drift test names each stale pin and where its text moved, and `task fixtures:repin` rewrites it. `rule.needle` (new, optional, `internal/scenariobench.Rule`) records the cited line's text; a `path#Lnn` rule source into ADR.md must carry one. Both tests report `pin X is stale: its text ("…") now begins at FILE:N — run task fixtures:repin`, and `-repin` (the task target) rewrites every stale pin's literal in the fixture (the quoted JSON string only, refusing when another task holds the same literal), then re-checks. The line-anchor check now compares the cited line number exactly (it was a suffix test: `ADR.md#L728` passed for a needle at line 28).
- **Status:** fixed (wave fx2): `TestCheckAnchor_LineStaleNamesWhereTextMoved`, `TestCheckRuleSourcePin_StaleNamesWhereTextMoved` and the two refusal tests pin the behavior; guards-adr-014 now carries `rule.needle` "The daemon's 8-day call log". End to end: three lines inserted at ADR.md:5 failed both gates naming `ADR.md#L728` -> 731 and `ADR.md#L581` -> 584, `task fixtures:repin` rewrote exactly those two literals (prose untouched) and both gates passed; restoring ADR.md and repinning returned the fixtures byte-identical. Not covered: the 12 line pins into other files in guards-fathom.json (docs/intent/invariants.md) and guards-m1.json carry no needle yet, so they still fail the section check unexplained (needle optional outside ADR.md).
