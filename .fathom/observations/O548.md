### O548 — universal-ctags 6.2.1 tags Ruby source inside heredoc strings as definitions: 1,544 and 1,922 false oracle definitions on ruby-lsp and spoom

- **Symptom:** L1 sym_recall .6752 (ruby-lsp v0.26.11) and .551 (spoom v1.8.10) against universal-ctags, with sym_precision .9942 and 1
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect ruby -unmatched` (wave lx), each oracle-only definition's line checked against tree-sitter-ruby's `heredoc_body` ranges
  - **Expected:** a definition is code, not text in a string
  - **Actual:** 1,544 of 1,574 (ruby-lsp) and 1,922 of 1,940 (spoom) oracle-only definitions sit inside a heredoc body: the tests embed sample Ruby (`index(<<~RUBY) class A ... RUBY`)
  - **Repro:** the -unmatched output of the command above, then the heredoc check
- **Root cause:** ctags' Ruby parser is line-based and reads a heredoc's lines as code
- **Fix:** none (an oracle defect, disclosed). A Ruby subject whose tests embed source in heredocs needs `-only` outside them, or a tier-A L1 oracle (`-scip-defs` once the manifest maps scip-ruby's kinds)
- **Status:** open
- **Impact:** without the heredoc definitions both read above .99 sym_recall; the typed gems are not graded (F.26)
