### O597 — a C++ member call on a variable named like a top-level header class bound that class's method through the wildcard-member matcher

- **Symptom:** fmt's test/gtest-extra.cc `read()` (`std::string buffer(...); buffer.resize(offset);`) drew a file edge to include/fmt/base.h's class `buffer`; O523's receiver-qualified call text (`buffer.resize`) did not stop it
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect cpp ... -unmatched` (fathom_only_via `test/gtest-extra.read -> include/fmt/base.buffer`), wave lf1 item ccpp
  - **Expected:** `x.m()` is a member call on x's type; it binds no class named x
  - **Actual:** callEdges' matchWildMember binds a dotted call whose head names a top-level type of a reached file and whose member that type defines
  - **Repro:** `TestResolveFileEdges_CppMemberCallKeepsReceiver` (`int shrink(text &widget) { widget.resize(1); }` beside a header's top-level `class widget`)
- **Root cause:** the dialect writes `obj.m()` and `Type::m()` alike (`.`), and only the scope-operator form names a class
- **Fix:** LB-F294: for a C++ caller, a dotted call the file's references do not write with `::` binds nothing through any matcher (this->m() exempt)
- **Status:** fixed (wave lf1, item ccpp)
- **Impact:** C++ file_edge_precision .8761 -> .9754 together with LB-F296 (the veto removed 5 coincidentally true pairs too, recall .4401 -> .4355)
