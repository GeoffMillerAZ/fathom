### O400 — lang-oracle's ownedSourceRefs skips a file it cannot read without a note, so a TCC-wedged run measures fewer files and still writes a reading

- **Symptom:** a Bicep reading on Azure/azure-quickstart-templates came back with fewer files than the oracle accepted and level_met unchanged; nothing in the reading's notes said files were dropped
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect bicep -tool-oracle <oracle.json>` during a macOS TCC wedge on /Volumes/m2ext (reads fail with "operation not permitted")
  - **Expected:** an unreadable owned file is a fault or a note, or the run refuses
  - **Actual:** the walk drops it and the subject's `files` shrinks; the merged reading keeps the failed run's notes
  - **Repro:** measure while `cat` of a subject file fails with EPERM; compare `subjects[].files` to the oracle's accepted count
- **Root cause:** ownedSourceRefs (cmd/indexbench/langoracle.go) treats a read error as "not this dialect's file"
- **Fix:** none here; wave iac measured with a min-files check in its runner and re-measured from an empty reading
- **Status:** open
- **Impact:** a reading can silently cover a subset of its subject
