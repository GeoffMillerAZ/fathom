### O676 — re-measuring a language reading keeps the previous run's per-subject notes beside the new ones

- **Symptom:** `indexbench lang-oracle -out <existing reading>` merges the subject (counts replaced by name) but unions the notes, so every generated per-subject note whose numbers moved appears twice, the old figure beside the new one (Go, wave lf2: 15 stale cli/cli and cobra notes, "scip-go's 10521 named definitions ..." beside "... 10569 ...")
- **Evidence:** `mergeNotes` (cmd/indexbench/langoracle.go) appends what is new and keeps everything else; `MergeSubject` (internal/langbench/merge.go) replaces only the subject entry
- **Root cause:** a generated note carries no marker of the subject run that wrote it, so the merge cannot tell a stale generated note from a hand-written one
- **Fix:** none (outside this item's files); worked around by hand: a from-scratch run (`-out` a new file) gives the current generated notes, and the merged reading keeps only those of each subject plus the hand-written ones
- **Status:** open
- **Impact:** every worker re-measuring a reading; a stale note contradicts the reading's own metrics until someone curates it
