### O720 — two alerting rules of one name in one file are one symbol key, so their routing edges merge (2026-10-10)

- **Symptom:** kube-prometheus writes one alert at two severities (`KubeAPIErrorBudgetBurn`, critical and warning) in one rule file; the prometheus dialect stores two symbols at their own lines but one key, so their `routes_to` edges (Critical for one, Default for the other) land on one key and read as one rule reaching both receivers
- **Evidence:** the alertmanager oracle scores routing per rule name and file (125 names for 139 rules) to match; fathom's routeAlert routes each occurrence by its own labels, and the stored edges merge on the key
- **Root cause:** a symbol key is service, package and name; a rule's identity in Prometheus is its group and position, not its name
- **Fix:** none (the prometheus dialect's naming, LB-Q-prometheus); a disambiguated name (`<alert>@<severity>`) would break the alertname join, which names rules by alert name
- **Status:** open
- **Impact:** blast_radius from such a rule shows every receiver either occurrence reaches
