- **Symptom:** the queue row names "a reference validator's $ref resolution"; the reading's oracle is `@apidevtools/json-schema-ref-parser`, a resolver (the library swagger-parser and most validators bundle), and the dialect claims a `.json` by two rules the row text does not spell out.
- **Evidence:**
  - **Tool:** `internal/fusion/jsonschemadispatch.go` (`jsonSchemaJSON`), `docs/bench/readings/lang/json-schema.json`
  - **Expected:** the row prose matches the reading
  - **Actual:** a `.json` is a schema when it decodes to a root mapping and its root `$schema` names `http(s)://json-schema.org/` or its base name ends `.schema.json`; a schema with neither (19 of SchemaStore's 1,001 files, `plain.json`) and a `tsconfig.json` pointing `$schema` at schemastore.org stay generic JSON; a basename claim (`package.json`) and an earlier content claim (OpenAPI, CloudFormation, Grafana, ARM) win. The Azure ARM schema document, which ARM's own test kept JSON, is now a JSON Schema
  - **Repro:** `go test ./internal/fusion -run 'JSONSchema|AppFramework|ARM'`
- **Root cause:** n/a (a design choice the row left to the worker).
- **Fix:** the row prose names the resolver; `ExtractorEpoch` is not bumped here (ADR-048 D2: the wave integrator owns one bump): every `.json` the dispatch now claims was read as generic JSON before, so the integrator's bump must cover it.
