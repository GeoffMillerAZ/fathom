### O476 — the served Go graph answered a typed file's dependency call by bare name and listed a type's consumers as its callers

- **Symptom:** `symbol_context` and `blast_radius` (include_heuristic) named `Same` a caller of the service's `Store.Equal` because `Same` calls `bytes.Equal`, and named `Build` a caller of the type `Config` because it declares `var d svc.Config`; design §1.6 counted the two classes at 1,706 and 1,533 of the 3,921 served pairs scip-go lacks on cobra and cli/cli
- **Evidence:**
  - **Tool:** `go test ./internal/analysis/callgraph -run TestServedCalls_Golden` over a real ingest of `internal/analysis/callgraph/testdata/servedcalls` (goextract plus the typed pass), golden `testdata/servedcalls.golden.json` ("before" recorded at 90f0a01f); `go test ./internal/mcp -run 'TestSymbolContextServesCallsNotGuessesOrTypeRefs|TestBlastRadiusHeuristicKeepsTypeConsumersAsReferences'`, which fail on 90f0a01f
  - **Expected:** a call the typed pass answered (or dropped, its callee outside the service) is not re-answered by name; a type reference is not a call, and is not lost either
  - **Actual (before):** `BuildBoth` kept every syntax edge: `Same -> Store.Equal`, `Same -> Store.Lock` (syntax), `Build -> Config` (syntax); `TestImpact(Store.Equal)` named `TestSame` through the guess. `ProductReach.walk` alone discounted the first class (EW-15)
  - **Repro:** the tests above
- **Root cause:** `callgraph.resolve`'s unambiguous bare-name rule binds a dependency's selector call to the one in-service method of that name, and goextract records a type written in a declaration, literal or assertion as a `Calls` entry, which `Build` resolves to the type node; `BuildBoth` added the typed edges on top and never let them supersede either
- **Fix:** wave lg. E (LB-F199): `AddTypedEdges` ends with `dropTypedFileGuesses`, removing a syntax-only edge into a `GoMethod` from a caller whose file is in `typedFiles` (the file stands for the call site: `core.Edge` carries none); `ReplacePackage` applies it to the re-derived edges too. D (LB-F200): `edgeLabel` labels a syntax-only edge whose callee is a `GoType` or `GoInterface` as `core.EdgeTypeRef` (heuristic, in memory, never stored); `CallersDetail`/`CalleesDetail` leave it out, `ReferrersDetail`/`ReferencesDetail`/`DependentsDetail`/`DependenciesDetail` return it; reach walkers walk it unchanged. Consumers moved to the dependents views so a type's consumers stay: `impact.BlastRadiusBounded` (new `References`), MCP by_depth (`edge_kind`), `review.ChangedSymbolReviews`, the review layer diff, findings neighborhoods, the console neighborhood and the preflight blast radius. Left on the calls-only views (a type reference was never their question, or they read resolved edges only): find_callers' depth annotation, localize's neighbors, refactor_plan, refactor status migration, verify's gone-evidence, conserve's resolved caller count, the indexbench L0 oracle and the SCIP oracle's syntax fallback, the console's most-called suggestions
- **Status:** closed 2026-10-02 (LB-F199, LB-F200). Closes the consumers side O448 left open: the reference channel needed no table
- **Impact:** Go L2 C .7794 / .9292 to .9573 / .9219 (excellent). Residue: a compiled file that yields no typed edge at all is not in `typedFiles` and keeps its guesses; a symbol key two files define keeps the surviving node's file (cli/cli `TestNormalizeReference`, one pair; O479)
