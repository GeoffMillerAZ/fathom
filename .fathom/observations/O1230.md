### O1230 — A hook's cwd is the session's directory, so hooks inside a subagent's scratch clone read the parent's repository

- **Symptom:** a Claude Code hook's input `cwd` is the session's working directory; inside a workflow or Agent subagent that works in a scratch clone it is the parent session's project directory, never the clone. Every hook that keyed on it read the wrong repository: the readout hook's `[readouts] roots` scope and its joins (roots naming the wave clones never matched, so RO-M1's observe window would record nothing from the sessions Q-RO-2 approved), the gate preflight (`cd <clone> && git push` was checked against the parent's repo), the SubagentStop claim check (a worker's claims checked against the parent's HEAD and tree), and the test-run rows those two read (their HEAD and tree keys were the parent's too).
- **Evidence:** found 2026-10-18 by the main thread: every `cwd` field in the four subagent transcripts of workflow wf_2f65bdc2-fc2 reads the owner's checkout (41 to 123 entries each) while their Bash commands ran `cd <scratch clone> && ...` (the harness resets a shell cwd outside the project). Code: `readoutHookDir` returned `in.Cwd`; `cmdEditHookPreCommand` passed `resolveProjDirFor(cwd)` to `gatePreflightLine`; `cmdSubagentStopHook` used `stopHookProjDir` (CLAUDE_PROJECT_DIR first); `cmdTestRunHook` keyed rows at `eventProjectDir`.
- **Root cause:** the hooks read where the session is, not where the call acts.
- **Fix:** one resolver, `hookEffectiveDir` (cmd/fathom/hookdir.go): a Bash command acts in the target of its first `cd <dir>` or `pushd <dir>` after RO-28's quiet prefixes (an assignment alone, export, set, source, ., tccutil reset, sleep N, mkdir -p), lexed by `shellcmd.ParseCommand` and resolved by `resolveBashDir`; a file tool acts in its file's directory; an unreadable command, a computed target or one that is not a directory reads the hook's cwd. `hookCallRoot` maps it to a work tree other than the session's, else the session's. Wired: the readout hook's roots and joins; the Read outline hint's config; the gate preflight (which also follows `git -C <dir>` on the commit or push); the test-run hook's row keys; the SubagentStop claim check, from the last Bash or file tool call in the agent's own transcript (`agent_transcript_path`, now decoded by the Claude Code codec). The command guards' deny keeps the session's project: guard scoping is ADR-038's and out of scope. The main session's Stop is unchanged: its verify gate, ledger and retro are the session project's, and one Stop reading two repositories would split them.
- **Status:** resolved
- **Impact:** only while the opt-in hooks are on (`[readouts] mode`, `[hooks] gate_preflight`, `[hooks] claim_check`, `[hooks] test_run`, `[hooks] read_outline_hint`); a session that never leaves its project reads exactly what it read before.
