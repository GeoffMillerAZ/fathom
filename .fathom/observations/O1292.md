### O1292 — a whole-file digest anchor in the findings-loop corpus breaks on any mechanical edit to its file

- **Symptom:** FD-1 changed one join line and one import in `cmd/fathom/purgecmd.go`. `TestFindingsLoopCorpusParses` then failed: the RK-PURGE-ERRWRAP-1 anchor stores the sha256 of the whole file, so a change far from the anchored range (recordPurge) fails the corpus.
- **Evidence:**
  - **Tool:** `go test -race ./internal/scenariobench -run TestFindingsLoop`
  - **Expected:** a refactor that leaves the anchored lines unchanged needs no corpus edit
  - **Actual:** `anchor cmd/fathom/purgecmd.go digest = 5317…3970, want 3604…32bb`. This is the fourth re-anchor of this one finding (SR-13, PE-26, EW-45, FD-1). Each one moves every task's `base_commit`, and this one points at a branch commit (8c6250b6) that only exists on main if the integrator merges rather than rebases.
  - **Repro:** edit any line of purgecmd.go and run the test
- **Root cause:** the anchor follows the import contract (a file digest for `anchor_current`), so the bench fixture is coupled to every byte of the file.
