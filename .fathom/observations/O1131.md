### O1131 — the `killed` line prints once per process per closing source, not once per session and site as KS-2 states: no session or site reaches the decision port

- **Symptom:** KS-2 (`docs/plans/decision-port.md`, `[x]`) promises that under a live kill every site stays on its deterministic path "with one `killed` line per session and site". A `serve-http` daemon prints one `warn: decision port killed` line for all of its sessions and sites until the port reopens, so a second session, or a second site in the same session, gets no line.
- **Evidence:**
  - **Tool:** `internal/decide` (`liveGate.check`), read against KS-2 and ADR-073 decision 6 ("a miss is disclosed once per session, site and class")
  - **Expected:** at most one `killed` line per (session, site) while the kill holds, reset when the port reopens.
  - **Actual:** `liveGate.disclosed` is a `map[string]bool` keyed by the closing source (`internal/decide/consent.go`, `liveGate.check`), cleared only when the port opens again. Nothing the port sees names a session or a site: `decision.Request` carries `State`, `Questions` and `Images` only (`third_party/agentic-kit/foundations/decision/types.go:86`).
  - **What a session is on each path:** `serve-http` `/rpc` (MCP tool calls and hook calls such as the obligations re-rank): the `X-Fathom-Caller` header's `session=`, parsed by `rpcContext` (`cmd/fathom/admission_http.go:39`) into `mcp.CallerInfo.Session`, which only `internal/mcp` can read (`callerFrom` is unexported). `/route` (the prompt hook): `routeHandler` uses `r.Context()` without `rpcContext`, and `routeRequest` carries only the prompt (`cmd/fathom/route.go:82`), so no session at all. `serve-mcp` (stdio): one client per process, `WithCaller` without a session (`cmd/fathom/servemcp.go:127`): the process is the session. CLI verbs (`fathom compile`, `certify suggest`, `assess`, `plans context --preflight --score`): the process is the session, and each asks one site, so today's line already matches the contract there.
  - **Repro:** under `~/.fathom/decide.off`, two hook sessions edit files in a repository whose `[decide] rank_within_tier = true`: the daemon log carries one `killed` line, not one per session.
- **Root cause:** the per-(session, site) clause was written into KS-2 without a carrier for either value; the disclosure was keyed on what the gate knows, the source.
- **Fix (proposed shape):** test first: under the kill file, two sessions times two sites asking twice each through the daemon's gated ports write four `killed` lines, and a third ask writes none. Then a decide-owned context scope (site, session) read by `killable` and `reopening`, the disclosure keyed by it and cleared on reopen; set by `rpcContext` from `CallerInfo.Session`, by `route.go` (site `route`, session from `X-Fathom-Caller`) and by the client's re-rank and pre-filter (their site). It crosses `cmd/fathom/admission_http.go`, `cmd/fathom/route.go`, `pkg/client` and `internal/semantic`, outside the fx1-decide range, so this wave fixed O1132 and O1133 only.
- **Status:** fixed (fx2): `internal/decide/scope.go` carries the (session, site) scope on the ask's context; `liveGate.check` keys the disclosure by (source, session, site) and clears it on reopen; `rpcContext` and `/route` set the session from `X-Fathom-Caller`, `/route` its site, and the client's re-rank and pre-filter theirs (`decide.AtSite`). Proven by `TestKilledLineOncePerSessionAndSite` (KS-14).
