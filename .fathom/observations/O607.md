### O607 — Go's per-file package symbol is Python's module question: 728 definitions and 14,101 references with no fathom symbol on cli/cli

- **Symptom:** after fields, the other L4 remainder: 728 of 4,967 unmapped definitions and 14,101 of 42,232 unmapped typed_recall endpoints are scip-go package symbols
- **Evidence:**
  - **Tool:** the scip-go notes of `indexbench lang-oracle` (scip_go_defs_unmapped_package, scip_go_unmapped_to_package; wave lf1)
  - **Expected:** a definition scip-go defines maps to a fathom symbol
  - **Actual:** each file's package clause defines the package symbol and every `pkg.Name` references it; fathom mints no per-file or per-package symbol. Without fields and packages def_mapping would read .9995 and typed_recall .9991
  - **Repro:** as O603
- **Root cause:** a package is a namespace spanning files; whether it is a minted symbol or a file-granularity reference is the question Python's module definitions left open (O527), shared with Rust
- **Fix:** none; counted, not excluded, as for Python's modules
- **Status:** closed 2026-10-10: the trigger fired (K18, owner-architect, 2026-10-09); a Go package is a namespace, never a fathom symbol, its definitions and the references to it out of def_mapping and typed_recall as a counted harness rule (`scip_defs_namespace`, `scip_edges_namespace_target`; wave lf2, LB-F344, O675)
- **Impact:** Go stays below L4 even with fields
