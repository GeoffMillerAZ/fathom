### O506 — scip-typescript reads one root config for every file; fathom reads each importer's own project, and they agree on all but one import

- **Symptom:** the oracle recipe (calibration/oracles/scip-typescript/run.sh) indexes a subject under one tsconfig.json that extends the root one and includes every file, so the root's `paths`, `baseUrl` and `customConditions` apply to files whose own project sets none; fathom's resolver (LB-F223) reads the project that holds each importer, as the compiler and tsserver do.
- **Evidence:**
  - **Tool:** the scratch classifier of O505 on nest 9ff83d54 and zod 1fb56a5c.
  - **nest:** 524 imports in sample/ (and 7 in tools/) name `@nestjs/*`; each sample's tsconfig.json has no `paths`, so the compiler resolves them through node_modules. They resolve to packages/* through lerna.json's `packages` (packages/*), read as a workspace declaration beside npm/yarn `workspaces` and pnpm-workspace.yaml (LB-F225): the oracle's targets, 524 of 524. packages/<x>/tsconfig.json is a solution config (`files: []`, `include: []`); its reference tsconfig.build.json holds the sources and maps `@nestjs/*` to ../<pkg> (LB-F223's reference rule), the same files the root's `paths` name.
  - **zod:** packages/tsc, packages/integration (customConditions []) and packages/resolution (bundler, none) do not carry `@zod/source`; `zod` resolves there through exports' `types`/`import` targets, which are build outputs named back to packages/zod/src through tsconfig.build.json's outDir "." and rootDir "src" (LB-F227): the oracle's targets. One CommonJS importer (a .cts) has no source for its `require` target: unresolved, the oracle's root condition resolves it (O505).
- **Root cause:** the oracle trades per-project fidelity for one index covering every file (O441's fix).
- **Fix:** none needed for the reading; a per-project oracle run (scip-typescript --pnpm-workspaces or one run per tsconfig) would grade the per-project rule exactly.
- **Status:** open (a measurement-method note)
- **Impact:** 1 of 7,067 imports reads unresolved where the per-project rule and the oracle's root config differ; lerna.json is honoured as a workspace declaration, which the brief did not name.
