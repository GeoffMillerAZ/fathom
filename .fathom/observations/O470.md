### O470 — a template parameter named like a class binds that class through the include graph; a function-local alias named `T` bound the header's first `T`

- **Symptom:** C++ references bound `template <typename Shape> struct Wrapper { Shape inner; };` to the class `Shape` a reached header defines; before the fix, a use of `T` bound a typedef named `T` that sits inside a function of include/fmt/chrono.h (35 false pairs in fmt)
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect cpp` before and after, fmtlib/fmt 12.2.0; a scratch fixture for the template parameter
  - **Expected:** a template parameter is a local name, never a reference to a header's class; a definition inside a function body is no header name
  - **Actual:** the function-local alias is excluded (`insideCallable`, internal/fusion/crefs.go); the template-parameter case binds, because the resolver sees a reference's text only and the references query cannot mark a parameter's uses
  - **Repro:** a header with `template <typename Shape> struct Wrapper { Shape inner; };` beside an included header defining `class Shape`
- **Root cause:** shadowing by a template parameter needs the enclosing `template <...>` parameter list per reference, which RefSpec does not carry
- **Fix:** open: carry the template parameters in scope in the reference's @ref.not captures or a per-reference scope list
- **Status:** open
- **Impact:** a false edge from a template to a same-named class; not counted on the three subjects (a scratch fixture shows it)
