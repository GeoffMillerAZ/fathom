### O437 — a plan row written with no space after its box is skipped without a word, and `verify --since` passes over the loss

- **Symptom:** wave ox's proxy branch wrote its six `-rest` rows as `- [-]Text {id: LB-Q-…-rest, …}`; the plan parser dropped all six, and `fathom verify --strict --since origin/main --plan docs/plans/language-breadth.md` printed `deleted since origin/main (docs/plans/language-breadth.md): LB-Q-caddyfile-rest, LB-Q-envoy-rest, LB-Q-haproxy-rest, LB-Q-kong-rest, LB-Q-nginx-rest, LB-Q-traefik-rest` and exited 0
- **Evidence:**
  - **Tool:** `fathom verify --strict --since origin/main` on the wave ox integration branch at 6f3b0986 (merge of ox-proxy), 2026-10-02
  - **Expected:** a line that carries a `{id: …}` annotation but does not parse as a task is reported (a parse warning, or a failing row), so a malformed row cannot leave the plan unnoticed
  - **Actual:** `internal/verify/markdown.go` `taskLineRe` (`^\s*[-*]\s+\[([ xX~\-])\]\s+(.*\S)\s*$`) needs whitespace after `]`; a line without it is not a task and is skipped with no diagnostic. `--since` lists the row as deleted (CV-14) and, per I45, a deleted row is reported, never a gate failure
  - **Repro:** in any plan, change `- [-] X {id: P-1, disposition: deferred, reason: "r"}` to `- [-]X {id: P-1, …}`; with the edit uncommitted, `fathom verify --since HEAD --plan <plan>` reports P-1 deleted and exits 0
- **Root cause:** the task grammar is strict about the space and silent about near-misses; a deleted row is report-only by design (I45), so the two together let a typo remove rows from the gate
- **Fix:** open: warn (or fail under `--strict`) on a line that carries `{id:` and is not a task; the integration fix restored the spaces (8293d599)
- **Status:** open
- **Impact:** a typo can drop a deferred row's disposition, or a claimed `[x]` row's proof, from every verify run; only a reader of the `deleted since` line notices
