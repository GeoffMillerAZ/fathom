### O1347 — `bazel query` is not offline: loading a workspace fetches its module dependencies, and `//...` reaches fewer BUILD files than the checkout holds

- **Symptom:** the LB-Q-bazel row says the oracle is `bazel query --output=streamed_jsonproto (tier A, offline)`. On `bazelbuild/examples` and `grpc/grpc` Bazel downloaded its own binary (bazelisk, 9.3.0 and the 8.7.0 grpc pins) and the modules the workspaces name (`rules_cc`, `bazel_skylib`, `platforms`, ...) from the Bazel Central Registry before the query ran; and grpc's `//...` listed 2,466 call sites while its checkout holds 278 BUILD files in directories `//...` never loads.
- **Evidence:**
  - **Tool:** `calibration/oracles/bazel-query/bazel_oracle.py` (`bazel --output_user_root=<scratch> query //... --output=streamed_jsonproto --proto:instantiation_stack --proto:definition_stack --noimplicit_deps`)
  - **Expected:** a query that needs no network
  - **Actual:** first run per workspace fetches modules (the cache lives under the scratch `--output_user_root`); `.bazelignore` (grpc: `third_party/upb`, `third_party/abseil-cpp`, `test/distrib/bazel/*`, ...) and nested repositories (a directory with its own MODULE.bazel, WORKSPACE or REPO.bazel) are outside `//...`
  - **Repro:** `bazel_oracle.py -subject <grpc> -output-user-root <scratch>`, then `-scope-globs` for the reachable files
- **Root cause:** Bazel resolves bzlmod dependencies before it loads a package; `//...` is the package universe of one repository.
- **Fix:** the row's oracle prose now reads "tier A; the module fetch needs the network, the query does not", `-scope-globs` prints the reachable files and the readings pass them to `lang-oracle -only`, so the oracle's silence about an ignored directory is not read as a miss.
- **Status:** closed (disclosed)
