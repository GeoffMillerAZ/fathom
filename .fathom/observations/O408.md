### O408 — a subject's own `testdata/` is skipped by ingest, so a calibration subject made of testdata measures one file

- **Symptom:** fluxcd/flux2's `cmd/flux/testdata` (142 files, every Flux kind) read as 1 file in the first flux reading (oracle: 62 entries "on files fathom does not read")
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect flux` on fluxcd/flux2 at v2.9.6 with sparse `cmd/flux/testdata/**`
  - **Expected:** the queue's second flux subject (fluxcd/flux2) supplies the breadth
  - **Actual:** connector.skipDir prunes `testdata` (and vendor, generated, node_modules) from every Discover walk, so the harness reads what ingest reads: nothing
  - **Repro:** corpus shard with `sparse: ["cmd/flux/testdata/**/*.yaml"]`
- **Root cause:** none: the exclusion is ingest's rule and the harness is right to share it
- **Fix:** the flux shard uses flux2-multi-tenancy, flux2-monitoring-example and bjw-s-labs/home-ops instead; the shard's comment names the rule
- **Status:** fixed (shard)
- **Impact:** a queue entry's named subject can be unmeasurable by design; check the subject's paths against `connector.skipDir` before pinning it
