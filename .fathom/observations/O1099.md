### O1099 — `plans status` advertised `archivable:` for plans `plans archive` then refused

- **Symptom:** status printed 22 lines `archivable: <plan> (0 open, 0 claimed-unproven) — fathom plans archive ...`; archive refused every one on its absorption guard (row ids not named in CHANGELOG, ADR, docs/changelog or a commit body, e.g. IO-28, IA-6/IA-7, LC-10..LC-12).
- **Evidence:**
  - **Tool:** fathom plans status / plans archive
  - **Expected:** a status line that names a command means the command accepts it
  - **Actual:** status judged only open/claimed-unproven counts; archive also checked absorption
  - **Repro:** `fathom plans status --service fathom`, then run any printed archive command
- **Root cause:** the absorption criterion lived only inside runPlansArchive; status never ran it.
- **Fix:** one shared `absorptionCorpus` (files + commit log, loaded once per run) used by both verbs. Status prints `archive blocked: <plan> — <n> row ids not absorbed (first: ...)` and `--json` carries `archive_blocked` + `unabsorbed_ids`. The guard is unchanged; no ids were absorbed.
- **Status:** fixed
