### O821 — a write inside a worker's clone was served the owner checkout's rules

- **Symptom:** in this session (project the owner's checkout, cwd a worker clone under the external volume's scratch tree), `printf … > cmd/fathom/zz_shim_test.go` got the owner checkout's obligations for `cmd/fathom/zz_shim_test.go`
- **Root cause:** O820's resolution: the relative target was read as relative to the project root, so a file in the clone was named as the same path in the owner's checkout. The rules happened to fit (the clone is of the same repository), which is XM-37's fold done by accident and for the wrong reason: a clone at another commit would get rules for a file that is not the one written
- **Fix:** the target now resolves to the clone's own path, classed `clone` on the beat (XM-36) and silent `foreign-target` until XM-37 folds clone and worktree targets on purpose
- **Status:** fixed (the accident); the fold is XM-37
