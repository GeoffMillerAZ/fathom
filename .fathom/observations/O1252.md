### O1252 — doctor and status tell the operator to reload the daemon by hand after a reconcile that already reloaded it

- **Symptom:** the `daemon_posture` remedy that doctor and `fathom daemon status` print read `fathom daemon install --reconcile --label <label>, then from your terminal: launchctl bootout gui/<uid>/<label> && launchctl bootstrap gui/<uid> <plist>`. Run from the operator's own terminal, reconcile reloads the agent itself, so the launchctl lines were a second, redundant reload.
- **Evidence:** wave dmp2, rails2 worker, 2026-10-18. `postureRemedy` (cmd/fathom/daemon_signing.go:156-162 at 3ffb2d55) builds the line; `runDaemonReconcile` (cmd/fathom/daemon_lifecycle.go:536-550) prints the reload lines only when `ops.AgentShell()` and otherwise runs `launchctl bootout` and `launchctl bootstrap` itself, then prints `reloaded <label>`. Doctor (`checkDaemonPosture`) and status (cmd/fathom/daemon.go:482) share the one function.
- **Root cause:** the remedy was written for the agent-shell path, where reconcile cannot reload, and named that path's manual step as the only one.
- **Fix:** the remedy names reconcile run from the operator's own terminal and says it reloads the agent; the launchctl lines appear only as what an agent shell prints instead. `TestDoctorDaemonPostureNamesReconcile` pins the wording.
- **Status:** resolved (wave dmp2, rails2): `postureRemedy` reads `from your own terminal: <reconcile>, which reloads the agent (from an agent shell it reloads nothing and prints the lines to run instead: launchctl bootout ... && launchctl bootstrap ...)`.
- **Impact:** an operator who followed the old remedy bounced the daemon twice; harmless, but it taught that reconcile does not reload.
