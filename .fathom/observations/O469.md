### O469 — C++ file_edge_recall .2325: 396 of the 639 undrawn edges end in a file the referring file's include graph never reaches

- **Symptom:** after C++ references and qualified calls bind through the include graph (LB-F196, LB-F198), fmt, nlohmann/json and spdlog pooled file_edge_recall reads .2325 (196 of 843 truth edges) at precision .8305
- **Evidence:**
  - **Tool:** `indexbench lang-oracle -dialect cpp -scip -tool-oracle <preproc>` on fmtlib/fmt 12.2.0 (-only include/**, src/**, test/*.cc, test/*.h, test/fuzzing/**), nlohmann/json v3.12.0 (-only include/**) and gabime/spdlog v1.17.0 (-only as in the reading), scip-clang 0.4.0; each undrawn truth edge checked against the preprocessor oracle's `imports` closure from the referring file
  - **Expected:** an undrawn edge is one fathom could draw from the file's own includes
  - **Actual:** of 647 undrawn edges, 396 end in a file the referring file's transitive includes do not contain (a partial specialization or an overload a later header supplies, seen in `formatter<T>` specializations across fmt/std.h, ranges.h and chrono.h, and defined only in the translation unit that includes both); 251 end in a reachable file
  - **Repro:** the commands in calibration/oracles/scip-clang/README.md; nlohmann/json contributes 0 truth edges under -only include/** (the amalgamated headers are included by tests/, outside the restriction)
- **Root cause:** the compiler resolves a name through every header the translation unit has already read and through template instantiation; a header's own include graph is a smaller set, and no resolver that follows includes alone can draw the 396
- **Fix:** none for the 396; the 251 reachable are definitions the C++ incumbent emits no symbol for (using-aliases, enumerators, variables, macros) and calls through a member of a template-dependent receiver
- **Status:** open
- **Impact:** C++ file_edge_recall is bounded by about .53 at the include graph (447 of 843); L3 stays below good (.25) only narrowly
