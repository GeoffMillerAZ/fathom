### O1478 — tree-sitter-css rejects what Tailwind CSS v4 and CSS Nesting write most, and drags the next rule into an ERROR node

- **Symptom:** the first read of the shadcn/ui holdout (apps/v4) left 11 of 12 files with an ERROR or MISSING node (level none), and 26 of 111 calibration files before the variant's rewrite grew: `@custom-variant dark (&:is(.dark *));` turns the rule after it into an ERROR with a garbage selector, `.parent &` loses its descendant combinator and `&`, `@import "x" layer(base)`, `@theme default inline reference`, `@reference`, `(width >= 48rem)`, `url(@scope/pkg/file)`, `@apply p-4!` and `@apply [&_img]:size-4 **:p-2` do not parse, nor does a last `@apply` without its `;`.
- **Evidence:** docs/bench/readings/lang/holdout/tailwind-shadcn.json (8 of 12 files in error after the first rewrite, throughput 0.87 MB/s, level none); `indexbench lang-probe -dialect css` on internal/extractor/dialects/css/testdata/tailwind.css; calibration after the fix: 0 of 117 files in error, holdout 2: 1 of 18.
- **Root cause:** tree-sitter/tree-sitter-css v0.25.0 knows neither Tailwind's at-rules and candidate syntax nor a nesting selector after a descendant combinator, a layer() option on @import, or media range syntax.
- **Fix:** the css dialect's Tailwind variant blanks each spelling at equal byte length before the parse (tsextract_tailwind.go) and cuts every name from the file as written. A plain stylesheet never takes the rewrite, so `.a &`, `@import ... layer()` and `(width >= 48rem)` in a file without a v4 at-rule still read with an ERROR node (heroui's index.css is one). The holdout that found this is spent (tailwind-holdout.yaml); tailwind-holdout-2.yaml holds the next.
- **Status:** open for plain CSS (the css dialect), fixed for v4 files.
- **Impact:** the variant's files read clean; the css reading is unchanged, byte for byte.
