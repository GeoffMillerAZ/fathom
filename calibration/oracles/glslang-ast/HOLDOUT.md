# GLSL G-r3 independent holdout

`holdout-selection-pin.json` records the selected `g-truc/ogl-samples` source and archive and the SHA-256 of the original workspace selection receipt. Its timestamp is historical workspace evidence, not a claim established by commit ancestry. `holdout-pin.json` is the separate post-acceptance binding record: its final catalog digests were added after the catalog audit. The archive and detailed file receipts stay under `workspace/`. This corpus is not a canonical language-reading shard. Do not tune exclusions against its results.

After a CPU lease and independent acceptance of the extension catalog, run `holdout.py` from the repository root with `--archive workspace/holdouts/glsl-g-r3/ogl-samples-38cada7a9458864265e25415ae61586d500ff5fc.tar.gz --product-source . --product-commit <clean final commit> --compiler workspace/tools/glslang-16.6.0/bin/glslang --baseline-catalog calibration/oracles/glslang-ast/glsl460-baseline-functions.json --core-catalog calibration/oracles/glslang-ast/glsl460-functions.json --extension-catalog <reviewed complete registry JSON> --out workspace/holdouts/glsl-g-r3/run-1`. The committed `holdout-pin.json` is the default pin. Its extension digest and accepted source list bind the accepted catalog; those later-bound fields are not part of the original selection record. The driver refuses a different catalog.

The driver verifies source and archive pins, builds one product binary, and measures the same shader population and AST calls three times: baseline core functions, core functions plus types, and full registry. This is an L2 calls-only comparison; it disables ctags and makes no L1 claim. It keeps every GLSL-recognized extension in the denominator, including `.fs` files accepted by the dialect sniff, and checks the product's exact measured path list against that manifest. Its generic `glslang -i -S` stage inference is reconstructed input, tier B at best; it does not claim native CMake flags. Unknown stages and compile failures are recorded as gaps. Below 95% oracle scope there is no grade. The private receipts contain exact file lists and diagnostics; the summary contains counts and hashes.

The baseline preserves the original 197 core function exclusions and 44 scalar, vector and matrix constructor identifiers. Their catalog and generated identifier-set digests are pinned separately. Core-plus-types adds the complete core type tables before the registered-extension mode, so the comparison does not credit existing G2 exclusions as improvements.

The default run refuses coverage below 95%. After such a refusal, `--diagnostic-below-coverage` can record paired counts using exactly the same compiler inputs and population. This option removes grades from the private mode readings and marks the summary as diagnostic only, with `validation_claimable: false`. It does not authorize a holdout validation claim, lower the coverage gate, or change the catalog, inputs or rejected-file tenancy.

After the run, write a private comparison configuration under `workspace/` with `before_reading`, `after_reading`, `catalog`, and `pairs`. Each pair names `subject`, `before_unmatched` and `after_unmatched`. For the holdout use subject `g-truc/ogl-samples holdout` and add `evidence: {"kind": "holdout", "summary": "<run>/summary.json", "oracle_receipt": "<run>/oracle-receipt.json"}`. For canonical subjects add `evidence: {"kind": "canonical", "before": "<baseline scratch>/evidence.json", "after": "<full scratch>/evidence.json"}`. The canonical driver prints each scratch path. The default comparison is `baseline-core` against `full-registry`; set `before_mode` or `after_mode` explicitly for the intermediate control.

Run `python3 -I -B calibration/oracles/glslang-ast/catalog_deltas.py workspace/<comparison>.json workspace/<deltas>.json`. The reporter checks accepted catalog fingerprints, hashes of readings and unmatched receipts, fixed product/source identity, exact truth, and population evidence before computing precision and overlapping declaring-spec family counts. A spelling present as both a function and a type keeps its ambiguity. Detailed input paths remain private; the output contains counts and evidence hashes.
