# Route oracles: what a running framework says it serves

`indexbench route-oracle` (LB-F324) scores fathom's framework routes against the route dump of the
running application. Each subject is ingested into a scratch store exactly as a product ingest stores it,
and its routes are read back through `serviceref.RoutesFromRows`, the composition `BuildFromStore` joins
on. A route that ingest drops, or a mount that composition would not apply, is never scored as found.

## The oracle shape

One JSON file per subject, written by a converter under `calibration/oracles/<framework>/` from the
framework's own dump:

```json
{
  "tool": "spring-boot-actuator-mappings",
  "tool_version": "spring-boot 4.1.0",
  "subject": "spring-projects/spring-petclinic",
  "sha": "<the commit the dump ran>",
  "licence": "Apache-2.0",
  "routes": [{"method": "GET", "path": "/owners/{ownerId}", "handler": "OwnerController.showOwner"}]
}
```

- `method` is upper-case, or `ANY` when the framework matches every method.
- `path` is written as the framework renders it. Scoring normalizes both sides with
  `serviceref.NormalizeTemplate`, so `{ownerId}`, `:id` and a trailing slash compare alike.
- `handler` uses fathom's naming: `Class.method` (`Outer.Inner.method` for a nested class), or the
  function's name. It is `""` when there is none.
- `licence` is the subject's licence, verified at the pinned commit.

Only routes declared by the application's own source belong in the file. Routes the framework or a
library contributes, such as an error controller, actuator endpoints or static resources, are left
out by the converter.

## The metrics

| Metric | Counts |
|---|---|
| `route_recall`, `route_precision` | (method, normalized path) pairs |
| `bound_recall`, `bound_precision` | (method, normalized path, handler) triples |

The reading reports each subject and the pool. Each subject's missed and extra lists are capped at
25 entries, with the remainder counted. A subject reads PASS when both bound metrics are at least
.90; the reading reads PASS when every subject does. `-only GLOB` restricts the files fathom's routes
may come from, for example `src/main/**` to leave out controllers that exist only in tests.

## Converters

| Directory | Framework | Dump | Tier |
|---|---|---|---|
| `calibration/oracles/spring/` | Spring MVC | `GET /actuator/mappings` of the running application | A |
| `calibration/oracles/jaxrs/` | JAX-RS | the runtime's OpenAPI document (`GET /q/openapi` on Quarkus), operation ids generated by SmallRye's `CLASS_METHOD` strategy | A |

Each converter is its own Go module, so it is never a dependency of the main module. Its README
gives the exact build, run and dump commands for each subject.
