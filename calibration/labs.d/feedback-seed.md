# Adopter-feedback seed map (LAB-17, draft for review)

Maps each of the 25 themes of `docs/bench/readings/feedback/adopter-triage-2026-10-20.md` to exactly one disposition
(docs/design/feature-labs.md section 4, step 6):

- **lab case**: the card id under `calibration/labs.d`, a case sketch and the grader of the asserted defect. A card's firing grader
  checks that a tool or hook fired, not the defect, so it is not borrowed. The row names a predicate from `#PredicateKind`
  (`contains`, `regex`) where one expresses the defect, and says `grader: not built` only for what no predicate can express
  (a call-log outcome, a negation). No case file is written here; LAB-18 writes them for the lab-case rows only (T01, T13, T15, T16). The fixed themes are not cases here: their proof is the named Go test, and LAB-18 does not duplicate them.
- **fixed**: the fix commit and the test it added that proves it, found with `git log -S'func Test…'` or
  `git log --grep=<id>`, or named by the observation's own record. Not fathom's say-so: every test named here exists at
  this commit.
- **no case possible**: one line why.

Each status comes from the observation's own committed record (the per-entry file wins over the legacy log), never
from the 10-20 triage. Where a theme is partly fixed and partly open, the open part decides the disposition, and the
fixed part's commit is named beside it. Where no fix commit was found, the row says so. Rows are in theme-id order.
