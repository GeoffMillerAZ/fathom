# Product

## Register

product

## Users

Developers operating indexed repositories and the coding agents working in them.
The Observatory helps a human inspect whether Fathom is wired, being used, and
producing defensible results, then follow evidence or an exact repair command.
Source: [product vision](docs/design/product-vision.md) and the page framing in
`cmd/fathom/observatory_render.go`.

## Product Purpose

Make governed code evidence useful at a decision moment. The dashboard explains
the existing instruments; it is not another store of truth. Wiring, traffic,
verification and impact are distinct questions. A number is useful only when its
source, denominator, freshness and limits remain visible.

## Brand Personality

Precise, candid, practical. This distills the adopted principles: deterministic
before model, never silent, minimal theater, and measured rather than argued.
The interface earns trust through explanation and working evidence links, not
claims of savings the instruments cannot support. Preserve the current kit-token
identity and both themes; this context does not introduce a new palette.

## Anti-references

Hand-built look-alike components where app-kit already supplies them; attractive
tiles with invented zeroes; implied savings without a counterfactual; narrative
presented as evidence; unexplained grades; a dashboard that hides a degraded read.
These are the project's own named failure modes, not a new external brand brief.
Sources: [principles](docs/intent/principles.md),
[UI doctrine](cmd/fathom/AGENTS.md).

## Design Principles

1. Separate configuration, observed invocation, static proof and runtime outcomes.
2. Keep absent, unreadable, partial and stale states visible alongside the result.
3. Present the next evidence link or repair command without silently applying it.
4. Compose existing app-kit primitives and tokens; return reusable improvements.
5. Keep the CLI and web projections on the same state and policy boundaries.

## Accessibility & Inclusion

Use the kit's native keyboard-operable controls, navigation and responsive shell;
preserve text explanations rather than encoding truth only through color. Both
light and dark themes require actual browser inspection under the UI doctrine.
No formal WCAG conformance level is recorded or claimed. A screenshot is not a
keyboard, assistive-technology or complete accessibility certification.

## Authority

[Project intent](docs/intent/README.md) and accepted decisions govern. This is a
compact routing context, not a replacement roadmap, new measurement standard,
deployment approval or claim that entry-conditioned futures have shipped.
