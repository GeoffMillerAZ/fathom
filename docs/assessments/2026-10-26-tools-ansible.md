# Ansible: current evidence and stale-trigger audit

The existing L3 good reading stays unchanged: 694/694 definitions, 9/9 local
references and 60/60 cross-file edges, all C. This is a read-only candidate and
trigger audit; no new extraction, oracle measurement or L3 grade is claimed.

The newly checked official Ansible language server 26.6.0 does not offer the
same families as CircleCI's server. Its checksum-verified published source
advertises module-code definitions, no document-symbol/reference provider;
its implementation resolves module keys to Python implementation locations.
That supplies no complete play/task/variable or handler-notify population.
The runnable source audit, archive/source identities and the named/versioned
native/ctags/parser candidate list live in calibration/oracles/ansible/README.md.
A server would have A authority for its own relevant evaluated family under
P-T1; no family is promoted merely because a vendor server exists.

The old raw triggers are qualified: the current INI decoder reads Conan option
lines, not Ansible inventory syntax; `not_has_key` now exists, but does not add
native truth or dynamic module naming. The ten disclosed INI inventories need
inventory semantics, not a declaration that all INI is now supported. T-R2
holds the shared decoder/strategy work. The absence claim for negative key
selection is removed. No product patch, epoch or generated surface is changed.

The native CLI's earlier partial acceptance/name cross-check is preserved and
explicitly bounded; it is not a full native semantic-loader or installed-role
experiment. A future full-population native instrument is a valid reopening
route at L1/L2 now. New L3 work remains held for D19. No claim that every possible
native API has been exhausted is made by this audit.

Decision models: none; this is source-contract and evidence-scope reporting.
