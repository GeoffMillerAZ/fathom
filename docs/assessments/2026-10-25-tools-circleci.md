# CircleCI: preregistered input union and remaining oracle ceiling

T-R3's input protocol was committed at f6e47f021 before compilation or grading.
It fixes three fresh subject identities and all cases: the default plus false
and true `cron` for cimg-python and cimg-node, and the default for scikit-learn.
The corpus shard retains the five earlier subjects. No original configuration
was edited, no source declaration dropped, and no orb replaced by a stand-in.

The adapter checks checkout identity, rejects unregistered or missing configs,
fails on a failed registered case, and unions native compiler jobs, workflows
and requirement sets deterministically. Parameters go through a temporary JSON
file to `circleci config process --pipeline-parameters`; pipeline jobs never run.
The 1.7.0 Darwin ARM64 release archive was verified against its published SHA256.
The parameter protocol and README record pins and licence declarations.

The separate committed holdout reads L2 (L1 excellent, L2 good): symbol precision
and recall 1 (11/11), reference precision and recall 1 (8/8), zero faulting files.
The timing instrument records the median of three identity-checked runs and
all run values in the reading. This is a different, small scope from the canonical
reading's 48/49 definitions and 74/75 references; those old values are preserved
and this is not a same-subject extractor improvement.

The ceiling is the full reference family's tier C. Compiler workflow/job pairs
are native, while command/executor pairs still come from an independent YAML
walk after inlining. Native ablation must attest those pairs before a tier can
rise, on fresh preregistered subjects exercising both families. A perfect small
holdout is not a reason to relabel the mixed oracle. No product extraction,
shared engine, epoch, generated board or plan checkbox changed.

Decision models: none. Matrix identity, input union and evidence tiers are
computed facts; no model is invoked.
