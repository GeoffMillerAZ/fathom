# Jinja2 coverage routes: X-R4 source audit

Checked 2026-10-25. This source inspection changes no corpus, grade or routing.
The explicit extensions are measured at L3. The remaining `.html` constraint is
HTML-first product dispatch and resolution, not absence of a parser or oracle.
Search misses below are bounded to the named sources and queries.


1. **Own runtime dump or introspection.** Query checked: `Jinja Environment.parse meta.find_referenced_templates lexer`. [Jinja 3.1 API](https://jinja.palletsprojects.com/en/stable/api/) documents `Environment.parse()` AST, `meta.find_referenced_templates()` for literal extends/include/imports and `None` for dynamic template names. This is the already measured 3.1.6 oracle. It accepts HTML-named templates; extension routing belongs to fathom.
2. **SCIP and LSIF lists plus GitHub search.** Queries checked: Sourcegraph [SCIP recommended indexer table](https://sourcegraph.com/docs/code-navigation/writing-an-indexer), Sourcegraph-maintained archived [LSIF.dev indexer table](https://lsif.dev/), and GitHub connector `search_repositories({query:"scip-jinja",per_page:10})`. Neither table lists Jinja and the repository query returned `[]`. This scoped negative does not prove nonexistence.
3. **Language servers.** Queries checked: `jinja-lsp language server html`, PyPI `jinja-lsp 0.4.2`. [`alex-oleshkevich/jinja-lsp` 0.4.2](https://pypi.org/project/jinja-lsp/0.4.2/) is a Rust binary with diagnostics, definitions/references, document and call hierarchy, macro/template navigation; default scanned extensions include `html`, `jinja`, `jinja2`, `j2`. PyPI provenance pins publishing commit [`521c857a`](https://github.com/alex-oleshkevich/jinja-lsp/tree/521c857a). Also inspected [`uros-5/jinja-lsp` `d25952b2`](https://github.com/uros-5/jinja-lsp/tree/d25952b2e5e0121cd0fcc1bf992d7c3e0e8d824c), which advertises MiniJinja-oriented navigation. **Neither run on the 520-file corpus or tested as fathom product parser.** The first is a concrete new HTML-named template oracle candidate.
4. **Package registry parser/typechecker/AST dumper.** Queries checked: PyPI `Jinja2`, `tree-sitter-jinja2`, `types-for-jinja`. [Jinja2 on PyPI](https://pypi.org/project/Jinja2/) supplies the already working Jinja 3.1.6 AST oracle; [`tree-sitter-jinja2` 0.1.0a1](https://pypi.org/project/tree-sitter-jinja2/) is an older grammar binding, not newly graded; [`types-for-jinja` 1.1.4](https://pypi.org/project/types-for-jinja/1.1.4/) advertises Jinja-owned syntax, template globs including `*.html`, and Python-LSP-assisted type completion. These do not alter existing product dispatch. `types-for-jinja` unrun.
5. **Runtime call/require tracing.** Queries checked: `Jinja get_template join_path loader trace`. [Jinja API](https://jinja.palletsprojects.com/en/stable/api/) documents `Environment.get_template`, `join_path`, and `BaseLoader.get_source` override points, usable to observe loaded template names during rendering. This covers executed dynamic loads, while static `meta.find_referenced_templates` returns `None` for unresolved dynamic names. No runtime tracer was run and observed execution is not a complete static edge oracle.

**Jinja action:** retain the `.html` *product-routing* ceiling only. Do not call it a parser or oracle ceiling. Implement an explicit opt-in Jinja HTML dispatch/resolution route, preserve plain HTML routing, then regrade HTML files against Jinja 3.1.6; optionally compare `jinja-lsp` 0.4.2 as an independent navigation oracle. This is a viable engineering route, not an absent-tool refusal.
