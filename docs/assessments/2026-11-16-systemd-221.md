## Real RED before implementation

Two new lane-only tests exercised the existing decoder with authored witnesses:

- `TestSystemdExistingINIDecodeContinuation221`: a Requires assignment continued
  over two physical lines must be one logical assignment at source line 2, with
  both dependency tokens. Actual: logical assignment count 2, want 1.
- `TestSystemdExistingINIDecodeMalformedWholeUnit221`: valid prefix followed by a
  malformed section header must give named incomplete/refusal and withhold the
  whole unit. Actual: malformed selected unit silently accepted, roots 1.

Command: `go test -race ./internal/extractor -run '^TestSystemdExistingINI.*221$' -count=1`.
Both FAIL lines and complete output are retained in
`workspace/artifacts/lang-systemd/capability-red.log`; the exact new-file witness
is `workspace/artifacts/lang-systemd/capability-red.patch`. The witness was
removed from the package after the experiment, not converted into a false passing
test or a production implementation. Existing decoder source was never edited.
These are capability witnesses, not independent native calibration or a population
estimate. They award no level. The second assertion is the required whole-unit
honesty boundary, not a claim that systemd's native parser rejects every warning.

The documented syntax independently specifies backslash continuation (including
intervening comment blocks). The existing decoder processes physical lines with
`strings.Split` and appends one item per non-comment line, returns no error on any
bytes, drops content before a section, and treats a malformed header as an ordinary
line. Reference regexes can split whitespace-separated units within a scalar, but
cannot recover the continuation's directive or its complete range after decode.
Changing doc selectors alone does not provide a faithful systemd decoder.

Retry when a validated existing decoder can pass both preserved witnesses and
