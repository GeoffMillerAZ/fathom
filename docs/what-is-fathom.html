What is Fathom?

A local, always-fresh index of everything your repos mean — code, call graphs, design docs, schemas — served to Claude Code as query tools. Read this first; then the tokenomics explainer.

The 10-second version

Fathom reads your repositories once, extracts every symbol, call edge, design-doc section, and schema definition into a single local database, and serves it to Claude Code as a set of query tools. Instead of agents re-reading your codebase to find things, they ask the index.

It indexes concepts, not just code

The detail that makes it different: design docs, schemas, and templates live in the same ranked index as the code. Ask about “element coverage” and the answer is the governing design-doc section plus the exact functions that implement it — one query, one ranked list.

Always fresh, nearly free

The six tools agents actually use

ToolQuestion it answers
find_symbolWhere is CloseCase defined, and what's its exact signature?
query_symbolsEverything about “outcome recording” — ranked, docs + code together
find_callersWho calls FormatCents? (works across language boundaries)
outlineWhat's in this file, without reading it?
repo_mapThe most-connected symbols in a repo, budget-bounded
pack_contextThe best evidence for a topic, packed into N tokens

A typical answer is ~600 tokens and includes file paths, line numbers, signatures, and evidence tiers. ~74 more tools exist (complexity, dead code, security scans, cross-repo callers, spec coverage…) — discoverable when needed, costless when not (Claude Code defers tool schemas).

Fleet-wide, local-first, honest

Fleet: sibling repos that co-evolve get indexed into one store — cross-repo impact becomes one tool call. Local: nothing leaves your machine; a .fathomignore file keeps sensitive directories (user data, case files) out of the index entirely. Honest: results carry evidence tiers, queries that match nothing return nothing (no fabricated relevance), and staleness is reported, not hidden.

Where it came from

Fathom was built as the code-intelligence layer for an evidence-governance platform — which is why honesty semantics (tiers, provenance, no silent truncation) are load-bearing design, not bolt-ons. It dogfoods itself: fathom is indexed by fathom, and the team that builds with it files fixes against it the same day they're found.
