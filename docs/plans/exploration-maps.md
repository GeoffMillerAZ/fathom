# Exploration maps: the plan (vision 40, ADR-056)

Grammar v2 (`docs/plans/README.md`). A row flips to `[x]` only when
`fathom verify --service fathom --plan docs/plans/exploration-maps.md` proves it. Design:
`docs/design/exploration-maps.md` (section numbers below are its). Goal G30. Futures F44 (set algebra over maps), F50 (durable live maps) and F52 (concern scopes as live-map queries); the incident rows moved to `docs/plans/incident-maps.md` (ADR-058, F56).

Measurement first. Wave 1 is a transcript-scan reading over 14 days; the wave 2 build rows all carry
`needs: XM-M1` and start only if re-derivation is at least 15 percent of sub-agent reads. The design is
binding for how a map is built (composable by reference, live maps beside semantic layers, maps that
arrive rather than being looked up); the reading decides whether it is built. No row here needs a
provider. Beside `docs/plans/receipts.md` (RC-28, the handoff) and the continuity-threads plan
(`docs/design/continuity-threads.md`).

Wave 3 (design section 3b, live maps as documentation for agents) is built only when live maps are promoted
(XM-D1). Its rows name XM-D1 in `needs:` as the owner asked, and add RT-M1, one of XM-D1's own trigger rows,
added while a deferred row satisfied a `needs:` edge by its disposition alone (before G2-6, when XM-D1 by itself
left them eligible). They do not name XM-M2: XM-D1's trigger is RT-M1 PASS and either XM-M2 PASS or a named consumer
of a non-handoff use case with its own bench metric (F50, amended 2026-09-29), because live maps' value (concern
scopes, incident maps, structural claims, saved questions) does not depend on sub-agent re-derivation, so an
XM-M1 KILL, after which XM-M2 never runs, must not close the route to them. Since G2-6 a deferred XM-D1 keeps
the edge unmet, so the graph and the gate agree: promoting XM-D1 (the F50 trigger) comes first, and nobody starts
wave 3 or wave 4 before it.
