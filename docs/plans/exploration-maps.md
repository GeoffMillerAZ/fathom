# Exploration maps: the plan (vision 40, ADR-056)

Grammar v2 (`docs/plans/README.md`). A row flips to `[x]` only when
`fathom verify --service fathom --plan docs/plans/exploration-maps.md` proves it. Design:
`docs/design/exploration-maps.md` (section numbers below are its). Goal G30. Futures F44 (set algebra over maps) and F50 (durable live maps).

Measurement first. Wave 1 is a transcript-scan reading over 14 days; the wave 2 build rows all carry
`needs: XM-M1` and start only if re-derivation is at least 15 percent of sub-agent reads. The design is
binding for how a map is built (composable by reference, live maps beside semantic layers, maps that
arrive rather than being looked up); the reading decides whether it is built. No row here needs a
provider. Beside `docs/plans/receipts.md` (RC-28, the handoff) and the continuity-threads plan
(`docs/design/continuity-threads.md`).

Wave 3 (design section 3b, live maps as documentation for agents) is built only when live maps are promoted
(XM-D1). Its rows name XM-D1 in `needs:` as the owner asked, and add XM-M2 and RT-M1, XM-D1's own trigger rows,
because a deferred row satisfies a `needs:` edge by its disposition alone, so XM-D1 by itself would leave them
eligible today.

## Deferred and refused (recorded so they are not re-proposed)

- [-] Live maps (stored queries recomputed on read) that compose the same way (by reference, as a DAG, with the same lifetime rule: permanent only when named and used, idle unnamed maps decay) {id: XM-D1, disposition: deferred, reason: "the designed extension; storage stays in existing thread fields until RT-M1 reads PASS (R5)", trigger: "XM-M2 reads PASS and responsible-tenant.md#RT-M1 reads PASS"}
- [-] Set algebra over maps (intersection, difference) {id: XM-D2, disposition: deferred, reason: "union covers the observed handoffs so far", trigger: "a real brief needs base minus what is already done (F44); dropped if union covers every observed handoff for 60 days"}
- [-] `map show --for '<task>'`: one noul per entry on a map over budget {id: XM-D3, disposition: deferred, reason: "the SubagentStart input likely does not carry the sub-agent's prompt, and the planner already decided what matters", trigger: "XM-V1 finds the prompt in the hook input and a map exceeds its budget in practice"}
- [-] Live maps query layers: a live map's selector may use layer claims and labels as predicates ("handlers where 'validates input' is no", "code governed by ADR-048 rules and touched by the language plan"), and an expensive judged column is computed only inside the maps that need it, not across the repository (design section 3, points 1 and 2) {id: XM-D4, disposition: deferred, reason: "needs live maps (XM-D1) and, for judged columns, a passed J0 and RT-M1 (R5)", trigger: "XM-D1's trigger fires; judged columns additionally need judged-predicates.md#JP-M1 to read PASS (F37)"}
- [-] Graduation: a live map reused by many agents or sessions becomes a named concern in a layer, and layer claims gain "used by map X" signals that feed rule effectiveness (design section 3, point 3) {id: XM-D5, disposition: deferred, reason: "needs live maps (XM-D1) and measured reuse before any map becomes a concern", trigger: "XM-D1 is built and one live map is mounted in at least 3 runs; see F50"}
- [-] A cheap typed model drafts a map's purpose line, committed by a human {id: XM-D6, disposition: deferred, reason: "optional convenience; the creator writes the purpose today and XM-7 refuses a named map without one", trigger: "XM-7 refusals show creators omit purpose lines and a calibrated text-shaped site exists (R2, R3)"}
- [-] Human docs rendered from maps: a deterministic console view first, model narration later {id: XM-D7, disposition: deferred, reason: "needs live maps to render from; a narrated view is a text-shaped site that needs calibration (R2, R3), and the deterministic view has to earn its readers first", trigger: "live maps promoted (XM-D1)"}
- [-] Undocumented-territory coverage: code covered by no map and no doc, reported as a computed complement {id: XM-D8, disposition: deferred, reason: "needs live maps to define what a map covers and a doc-to-code anchor to define what a doc covers; a coverage figure without both would be a guess", trigger: "live maps promoted (XM-D1)"}
- [-] A list of map ids in the brief instead of one composite id {id: XM-X1, disposition: refused, reason: "every sub-agent would re-implement merge, dedup and budgeting, and ids could not be handed down a level"}
- [-] Fathom spawning, scheduling or dispatching sub-agents from a map {id: XM-X2, disposition: refused, reason: "the dispatch non-goal: fathom stores and serves, never spawns"}
