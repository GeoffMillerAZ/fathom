# Readouts: a command's output as a compact, enriched or raw readout, with a receipt (RO-)

Design: `docs/design/readouts.md`. Decision: ADR-071 (amends ADR-042 by the opt-in site `readout_mode`); ADR-073 for its decision models (RJ-). Goal: G39.
Roadmap: `docs/vision/38-proof-layer-roadmap.md` §9.6, the next priority program after the RT-M1 reading; the Claude
Code mods program follows. Futures: F75 (the index hint, still future), F76, F77, F78. The interception seams
readouts owns (design §20, goal G41) close the plan. Readings live under `docs/bench/readings/readouts/`; each bar is
fixed here before any run (K19: never moved after the data); every reading before phase 4 is $0 in model spend and
prints aggregates only, never transcript text.

Every reading over the hook log reads both generations, `hooks.jsonl` and `hooks.jsonl.1`, asserts its window from its
first row's `at` and reads INCOMPLETE when the window is shorter than its bar asks: the log is user-global and rotates
at 64 MB keeping one prior generation (`cmd/fathom/beats.go:22-35`); on 2026-10-16 `hooks.jsonl.1` covered 2026-09-29
to 2026-10-16, about 17 days and 187k rows, and readout rows (about 6 MB a day at 4,860 Bash calls) cut one generation
to about 10 days. So a reading whose window is 14 days or longer (RO-M1, RO-M4) files a $0 interim aggregate every 7
days beside its reading (`fathom readout report --since 7d`, aggregates only), and its verdict sums the interims with
what the two generations still hold; a gap no interim covers reads INCOMPLETE, never a verdict.

Phase 0 is buildable now under the table freeze and the budget hold: no store table, no cache, no background job, no
model spend; evidence rides the existing hook log, and the corpus is read by an explicit verb. Rows inside a phase run
in value order from the corpus (design §1, §17): long source reads (10.6% of Bash bytes, ceiling 8.5%), then `ls`
(6.8%, unsized), grep (16.5%, grouping 0.6%, the cap unsized), git output (5.3%, unsized), test runs (ceiling 1.2%),
then the base stages (0.2%); RO-M0 sizes what is unsized and may reorder phase 1. Symbols are provisional until
grounded with `find_symbol` at row start. Owner questions Q-RO-1 to Q-RO-4 (ADR-071, `docs/intent/questions.md` Q35),
answered 2026-10-16 by the owner-architect under the owner's delegation: Q-RO-1 yes (a count- and byte-bounded file
the hook process writes under the state directory is outside the table freeze, which guards daemon memory; RO-22,
RO-36); Q-RO-2 yes for the owner-architect's wave sessions when phase 1's rows land, open for the owner's own
interactive sessions; Q-RO-3 yes; Q-RO-4 no for now (the only model budget is up to $10 on OpenRouter for Jev).
