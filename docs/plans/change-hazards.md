# Change hazards: contract and change hazards that never read a value

Status: Proposed 2026-11-12 (architect ruling, owner review pending). Grammar v2 (`docs/plans/README.md`). Prefix: HZ- (HZ-n work, HZ-Mn readings). Design: `docs/design/change-hazards.md` (codes H, V, E, D and M are its). Decision: ADR-099. Goal served: G49. Prerequisite rows live in `docs/plans/iac-facts.md` and are referenced by id, not duplicated: IF-13, IF-6, IF-11, IF-14, IF-17.

Rows HZ-0 to HZ-22 follow the design's phase order. The library roadmap (`docs/plans/library-roadmap.md`, programs LP-2 and LP-4) tracks the computation rows, and the differences from the policy review that it records are applied below: catalog-free hazards run first (HZ-10 beside IF-13, ahead of HZ-8), HZ-1 is the first lane of wave 1, and entries that wait on a trigger are register rows (`[-]`, deferred). Wave 1 on either roadmap starts with HZ-1, then HZ-0. The design's readings M1 to M7 are HZ-M1 to HZ-M7. HZ-1, HZ-15, HZ-16, HZ-17 and HZ-18 are themselves the readings HZ-M2, HZ-M3, HZ-M5, HZ-M4 and HZ-M6, so each opens its reading file with that verdict line. HZ-M1 and HZ-M7 are separate rows. M8 (agent outcome) is deferred in the design and has no row.

No store table, column, cache, memo file or background job. The product never reads a value (ADR-092 decision 7) and never evaluates a resource rule (ADR-063 O11). Readings live under `docs/bench/readings/change-hazards/`, one file per row, each opening with a verdict line. A row flips only through `fathom verify --service fathom --plan docs/plans/change-hazards.md`. Raw plans, exports and replay state stay under `workspace/`.

Owner gate: HZ-13, HZ-14, HZ-15, HZ-16 and HZ-18 start only on a yes to OQ3 (`docs/vision/46-proof-at-the-moment-of-change.md`, design D8), restated as a yes or no on building the check kernel in the library. The owner's earlier message was a hedged view on location and a delegation, not a request to build it, so the kernel is not built now: nothing would use it, and waiting costs no schedule because it sits after HZ-3, HZ-4 and HZ-6 in every ordering. The default is no on 2027-01-31, read with OQ2. It turns to yes if the owner says yes, or the policy tool's first design names evaluation through the library, or an outside adopter asks in writing. Until then these rows stay open and nothing in them is built. HZ-14 waits on HZ-13, and HZ-15, HZ-16 and HZ-18 wait on HZ-14, by `needs`. HZ-17 is not gated by OQ3: it is a scheduled reading lane that grades the reader, not the kernel, and needs only HZ-3. The product never evaluates a caller's rule (ADR-092 decision 7, ADR-063 O11): conditions and standards stay named kinds written in Go. A draft acceptance test (library row LIB-10) starts with the kernel.

Stop rules:

- If HZ-1 reads under its floor (the IF-CM3 floor of 0.85), fix that before any other row. Until it is fixed the live CloudFormation flag in `review_diff` (IF-C4) drops to advice wording. HZ-1 gates CloudFormation only.
- If HZ-9 precision (HZ-M1) reads under 0.9, no agent surface for Terraform hazards. The binary and the benchmark still state the reading. HZ-9 gates Terraform only.
- If HZ-17 shows Trivy decides far more at equal soundness, the kernel stays small and the design's R5 advice stands.
