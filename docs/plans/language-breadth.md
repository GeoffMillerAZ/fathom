# Language breadth and depth — the plan (vision 37, ADR-048)

Grammar v2 (`docs/plans/README.md`). A row flips to `[x]` only when
`fathom verify --service fathom --plan docs/plans/language-breadth.md` proves it.
Design: `docs/design/language-breadth.md` (section numbers below are its; §13 is the worker
recipe). Queue: `docs/plans/language-breadth.queue.json` — one `LB-Q-<id>` row per entry,
in the same order (`TestLanguageQueueMatchesPlan`, LB-F22, holds the two together).
Invariants I54 and I55 rise from `stated` as LB-F12, LB-F14, LB-F16 and LB-F17 land.

Rows name the contract they will be proven by: the function that will carry the behaviour
and the test that will reach it, or — for a language or tool format — a lexical oracle on
the committed reading whose `level_met` the harness computes (design §10). Nobody types a
level into a reading. Until the code and readings exist every row is open, and
`fathom verify` reports it open, never proven.

Row ids are stable. Foundation rows are `LB-F<n>` (Opus), measurements `LB-M<n>` (op), and
queue rows `LB-Q-<queue id>` (Sonnet workers, one per row, recipe §13). A queue row that
cannot reach its target keeps its contract and gains a `[-]` sibling
`LB-Q-<id>-rest` with a disposition (§14.2); the pattern is never loosened.
