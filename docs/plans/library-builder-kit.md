# Library builder kit: support around the existing understanding programs

Status: Proposed 2026-11-14 (architect ruling on owner direction). Design: `docs/design/library-builder-kit.md` (LK-D1 to LK-D7). Records: ADR-112 and ADR-113 drafts. Grammar v2. Every row is open. These rows add only builder support missing from LIB, RL, LP and HZ. They do not claim those programs complete.

All file paths below are proposed ownership assignments, not claims that files or commands already exist. Every row fits one lane of at most one working day. A row that exceeds that limit returns to the architect for a file split. Each implementation lane receives frozen interfaces and a failing proof before starting, as required by `docs/design/parallel-lanes.md`, PL-D1. Machine `any` means any supported development platform with the pinned local tools available. No row needs a managed daemon or paid model call.

The architect records the two ADRs and the OQ3 confirmation state before scheduling. Kernel-dependent rows require the owner's one-line confirmation and the existing kernel rows. This is an entry condition, not a new kernel deliverable. LIB-10's deferred disposition and older gate prose are reconciled by the architect. RL-9 is bound in `library-roadmap.md#RL-9` under the 2026-11-14 ruling, and remains gated on `realignment.md#CHG-10` passing. LBK-7 waits on that implementation and its frozen rule-data contract before dispatch.

Every reading below opens with `LBK-n verdict: pass` only when its stated bar holds. Otherwise it says fail or unknown and records why. Each reading names its commit, corpus or fixture digests, tool pins, commands, raw evidence under `workspace/`, numerator and denominator where applicable, and independent label provenance. A lexical verdict is the gate anchor, not a substitute for inspecting its evidence. Before any box changes, run `fathom verify --service fathom --plan docs/plans/library-builder-kit.md` against an index of the integrated tree. This lane performs no implementation or measurements.
