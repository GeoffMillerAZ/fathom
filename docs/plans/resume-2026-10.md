# Resume plan, 2026-10: the paused queue, readable from the repository alone (RES-)

The owner paused the local waves on 2026-10-11 (credits) and named cloud sessions (Claude Code on the web,
`claude --cloud`) as the continuation path. This plan is the paused queue, R1 to R6, so one cloud session can take
one item from the repository alone. A cloud VM has none of the owner's gitignored decision notes, local wave scripts
or scratch paths, the Mac daemon and fleet index, or `task deploy`; what a session needs is here or in the files
each row names.

How a session works. Set up per `docs/adoption/cloud-sessions.md` section 1.1 (the index finishes in the background
after the session starts). Take ONE item, in order: R6 first (the first cloud session's job), then R1 top to bottom,
then R2 to R5 as their gates allow. Test first; `command gofmt -l`; push through the Linux gate (`task validate`, the
lefthook pre-push); a conventional commit per reviewable unit with a `Verified:` line; never `--no-verify`, never
force-push `main`. A row here and the row it mirrors flip to `[x]` together, only when `fathom verify --strict
--service fathom --plan <plan>` proves both. Deploy catches up on the Mac later; never deploy from a VM.

## Rulings a cloud session follows

- **K19, pre-registered readings.** A reading's criterion and bars are committed before any data and never moved
  after a result. A failed reading stays failed. It reopens only through an independent oracle, or a new rule
  committed alone before re-measuring and read once on a holdout no tuning touched. A holdout read once is spent.
- **K26 to K30, the cost gate.** K26: a change over +20% store or +15% wall ships only with an owner ruling recorded
  beside its metric gain; without one, revert or hold it on a branch. K27: read against a baseline that did the work;
  a baseline whose pass was skipped is disclosed "previously skipped", never counted as a regression. K28: sum per
  wave and per language against the last ruled baseline. K29: a harness rule change re-reads every committed reading
  it touches in the same wave, or marks each stale with a row naming the rule. K30: read cold first-ingest wall as
  well as warm for any change to what an ingest loads.
- **X1, the role classifier is closed.** RF-M1 and RF-M8 both read CUT on one cause: a path convention cannot know
  what a runner collects. The durable answer is the runner's own collection list as an input (test-kit envelopes,
  `go list -test`). RF-6, RF-14 and RF-15 no longer need RF-1: a runs edge needs no role, and the passport shows
  `role: unknown`.
- **The evidence-plane boundaries (ADR-069).** Fathom stores concern facts as observations of their own file and
  computes joins at request time, with coverage. It never grades, sets severity, admits, tiers a change or holds the
  findings record (Review Kit, pe's `pdk/risk`, policy-kit do). It never executes, proposes or records a mitigation,
  never fetches (I56), stores no deploy state, carries no auth and binds no non-loopback address, and selects no
  literal env or arg value. No new table, cache or background job before RT-M1 reads PASS.
- **Resources.** The owner's Mac rules (the 15 GiB swap-volume floor, at most two waves at once) do not apply in a
  cloud VM. One scratch ingest at a time and one whole-package `go test` at a time still do (`fathom tests select
  --safe` first).
- **Standing rules.** No model spend (the spend hold of 2026-09-29). ADR-011: no organization-specific name, host or
  catalog anywhere. Done means proven and wired: anchor the function a product entry point runs. One
  `ExtractorEpoch` bump per wave that changes extraction. Kill only processes you started. The U1-gated edits
  (`docs/design/index-snapshots.md` section 16) are never landed by a session.
