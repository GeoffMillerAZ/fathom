# Language breadth, gap sweep gap1: the 2026-10-26 support-gap rows

Grammar v2 (`docs/plans/README.md`). A row flips to `[x]` only when
`fathom verify --service fathom --plan docs/plans/language-breadth.gap1.md` proves it. Nothing here is claimed: every row is
open, and the Swift parser decision is a typed deferral that waits on the owner. Rows here are the rows the 2026-10-26
support-gap sweep files (`docs/plans/language-breadth.md` is edited only for a worker's own rows, AP-14). Queue needs use
the cross-plan form `language-breadth.md#LB-F<n>`.

The sweep asked which shockers fathom's support is missing, ranked by how many real repositories contain the item times how
big the gap is (absent, refused, queued but unbuilt, disclosed but not at runtime, or weak). A completeness review corrected
the first ranking: Python `requirements*.txt` and Ruby `Gemfile` are top-reach gaps the board hid, the board named file kinds
nothing dispatches (W1 to W3), and several template engines had been dropped (A4). Row ids are `GAP1-<n>`; evidence tags in
parentheses (S0 to S22, A1 to A12, W1 to W6, N1 to N8) are the sweep's own item codes, defined with the method, the corrected
top 10 and the supported-well list in `docs/assessments/2026-10-26-support-gap-sweep.md`. Jinja2 (S2) is not a row: it
landed in wave B (dispatched, L1 to L3 excellent, 5.17 MB per CPU-second, 0.58% of files in error; LB-Q-jinja2), so the id
GAP1-15 is unused and the ids are not renumbered.

Lanes (low merge conflict): L1 owns the disclosure generator and the dispatch maps in `connector.go` (additive edits only);
L2 owns `internal/extractor/templatescan` and the template dialects; L3 owns the sql and python-packaging dialects. Only the
integrator edits `language-breadth.queue.json` and regenerates `unsupported_language_gen.go` and `docs/languages.md`.
