## Hygiene: product reach across nested Go modules (waves h4, h5; O779)

In platform-engineering (70d88ddb) none of its 22 nested modules had a typed edge, and four kits each declaring `internal/cmd.NewRoot` left the syntax call `cmd.NewRoot` bound to nothing: every kit main reached only itself, and env-kit read 22 plan rows library-only. The reading is `docs/bench/readings/efficiency-wave/nested-module-reach.md`. EW-59 and EW-60 verified at e0da3f75 (merge 03d4ff57) and were held for the K26 cost gate (fathom's warm ingest +17%, median of five interleaved pairs, against a 15% bar), so the h4 integration reverted the code before it shipped (0a72b3c2). **K26 ruling (owner-architect, 2026-10-10): ACCEPT at +17% fathom wall.** The excess is serial per-module load latency, not work (typed CPU +1.3 s against typed wall +7.5 s); store +0.26%, peak RSS flat, no verdict change over fathom's 66 plans. platform-engineering's 12.2 to 67.7 s is disclosed as previously skipped, never as a regression (K27: its baseline did no typed work for its nested modules). Wave h5 re-landed the pass by reverting the revert, under the ruling's conditions: this record (a), the own-module rule for the common shapes (b, EW-62), one wall lever (c, EW-64) and a TypedEdgeEpoch change that re-runs the pass (d, EW-63).
