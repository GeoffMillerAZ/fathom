# The decision port — plan (vision 32, ADR-042)

Design: `docs/vision/32-decision-port.md`. Decision: ADR-042 (owner-directed,
2026-09-22). Grammar: `docs/plans/README.md`. Rows are proven by `fathom verify`; the
A/B rows at the end are operator decisions (LLM spend) and are never claimed by this plan.

- [x] `[decide]` config block parsed with defaults (`provider = none`, `compile_threshold = 0.5`, `route_confidence = 0.9`, `rank_within_tier = true`); an unknown provider is refused by name at load {id: DP-1, symbol: Load, package: internal/config, reachable_from: TestConfig_DecideBlock}

## B. Compile pre-filter (ADR-042 decision 2; ADR-037 preserved)

- [x] `PrefilterSections` asks one batched `noul` per section ("does this section state a binding rule for code in this repository") in chunks of at most 20 sections and returns the sections at or above `compile_threshold`; with `none` it returns every section untouched and makes no call {id: DP-5, symbol: PrefilterSections, package: internal/semantic, reachable_from: TestCompile_PrefilterSkipsAndDiscloses}

- [x] When an active decision port (`RankWithinTier && Decider != nil`) has nothing eligible in scope to rerank, `RankedBy` still reads `none` (no rerank occurred) but `RankNote` now names why — distinct from "no provider configured at all", closing the gap a live probe could not resolve (zero decisions logged and `ranked_by:"none"` looked identical either way) {id: DP-20, symbol: noteNoEligibleRerank, package: internal/semantic, reachable_from: TestObligationsWire_NoEligibleClaimsNamesWhyOnWire}
- [x] `POST /route`'s own decider call is bounded by `[decide].route_timeout_ms` (default 3000ms, CUE-enforced 100-30000), not a fixed 3s constant {id: DP-21, symbol: routeHandler, package: cmd/fathom, reachable_from: TestRouteHandler_ConfigurableTimeout}
- [x] `rerankWithinTiers` splits its noul batch into chunks (`decisionBatchSize`: a Decider's own `MaxQuestions()` when it opts in, 20 for a Decider named `llm`, unbounded otherwise — the same rule `PrefilterSections` now reads too) and runs the chunks concurrently, bounded at 4; a chunk that hard-fails leaves its own rules at their exact pre-rerank position (never dropped, never reordered) and is reported as a `DecisionError` rather than poisoning the other chunks' answers — fixing O109's live finding that an unbounded ~160-claim batch against the `llm` adapter truncated before it parsed as JSON and nothing ranked {id: DP-22, symbol: rerankWithinTiers, package: internal/semantic, reachable_from: TestRerankWithinTiers_ChunksByDeciderName}
- [x] A decision-port call that hard-fails (no `decision.Response` at all) is still logged: `(*Recorder).RecordError` writes one `decisions.jsonl` row naming site/provider/model/questions/latency_ms/error, `applied:false`, at every site that can hard-fail (the obligations re-rank's own chunk failures, the compile pre-filter's aborted run, and `POST /route`'s decider error) — closing O109's "a failed decision left no trace in the log at all" gap {id: DP-23, symbol: RecordError, package: internal/decide, reachable_from: TestRecordError}
- [x] `rerankWithinTiers` asks the Decider only about claims in governing-scope tiers that intersect the served window `[0, max)` in the pre-rerank lexical order — a tier wholly inside the window is asked in full, a tier straddling the cut is asked in full (ranking decides who survives), a tier wholly below the cut is never asked (it cannot be served no matter how it ranks); `ranked_count`/`candidates_total` disclose how many claims were actually asked versus how many existed — closing O109's live finding that a 6-rule cap asked about ~160 candidates (8 chunks, 28-29s) when only the nearest tier(s) could ever be served {id: DP-24, symbol: rerankEligible, package: internal/semantic, reachable_from: TestRerankWithinTiers_ServedWindowNarrowsCandidates}
- [x] `[decide] rerank_timeout_ms` (default 1500ms, CUE-enforced 100-60000) bounds how long the WHOLE obligations re-rank (every chunk together, under one shared `context.WithTimeout`) may wait for the Decider; a chunk still in flight at the deadline is cancelled and treated as a hard-failed chunk (its rules keep their lexical position), `rank_note` names the budget explicitly, and the response returns promptly at the deadline rather than blocking on a slow or unresponsive decider — kept under the PostToolUse edit hook's own 2000ms obligations-RPC timeout with margin so a daemon-side rerank can never push that hook past its own budget {id: DP-25, symbol: rerankWithinTiers, package: internal/semantic, reachable_from: TestRerankWithinTiers_BudgetBoundsWallTime}
- [x] `decisionBatchPlan` chunks a decision-port batch by BOTH a question-count cap and a state-byte budget, never by count alone (llm: 20 questions/96KiB; typesafe and any unrecognized Decider: 64 questions/96KiB, previously fully unbounded; either overridable per-Decider via `MaxQuestions()`/`MaxStateBytes()`), and a single item whose own content alone exceeds the byte budget is never sent — skipped and recorded with a reason instead; both `PrefilterSections` and `rerankWithinTiers` route through it — fixing O110's live finding that an unbounded ~72-full-section compile pre-filter batch against the real `typesafe` (Jev) adapter was refused outright (`max_tokens_exceeded`) before answering a single question, re-measured live afterward with zero errors {id: DP-26, symbol: decisionBatchPlan, package: internal/semantic, reachable_from: TestDecisionBatchPlan_ByteBound}
