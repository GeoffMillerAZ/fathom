# Portable receipts: the plan (ADR-068)

Grammar v2 (`docs/plans/README.md`). A row flips to `[x]` only when
`fathom verify --service fathom --plan docs/plans/portable-receipts.md` proves it. Vision:
`docs/vision/43-portable-receipts.md` (section numbers below are its). Decision: ADR-068, accepted for waves 1 and 2.
Serves goal G25 (CX-M1, CX-M2). Not `docs/plans/receipts.md` (ADR-034's plan, which this one grows).

Every reading here is $0 (no provider or agent spend, no bench run). No row adds a table, a column, a cache or a
background job (ADR-049 decision 2). No row adds an MCP tool, a tool parameter or a wire field (P4). Fathom signs
nothing, verifies no signature, posts nothing and dials nothing (ADR-040, I56, QK1). Every code row is reached from
a product entry point (`reachable_from` names a `cmd*`), never from a test alone. A reading's pattern accepts either
verdict. The change that records a CUT also marks the rows it gated `[-]` with a refused disposition.

Gates: waves 1 and 2 run now as fillers (the owner-architect's ruling on D13, 2026-10-10). EVX-V1 names their
consumers and is an open owner input: it feeds EVX-K1 and EVX-G3 and gates no build row. Wave 3 needs EVX-G3 (a second
consumer, P20). Wave 4 needs EVX-M3 KEEP. Reopened at landing, outside this plan (done means proven, not an owner
call): VB-19 in `docs/plans/verbs.md` (no per-fact anchors on the wire) and CX-17 in
`docs/plans/change-and-compliance.md` (it recomputes from the current store and working tree,
`cmd/fathom/trace.go:296`).
