# Platform engineering: the fathom side of readiness readings, fleet fact inventories and investigations (PLT-)

Grammar v2 (`docs/plans/README.md`). A row flips to `[x]` only when
`fathom verify --service fathom --plan docs/plans/platform-engineering.md` proves it. Design:
`docs/design/platform-engineering.md` (section numbers below are its). Issue: GitHub #14. Extends
`docs/plans/well-architected-evidence.md` (WAE-, ADR-069, G37); measurement joins `docs/plans/bench-prep.md` (BX-) and
`docs/plans/feature-labs.md` (LAB-), which merge first. The consumers are an adopting platform team's review kit
(through its facts lane), readiness inventory and change-risk tierer; the rows here are only what those consumers
read and no fathom plan owns. Roadmap: `docs/vision/38-proof-layer-roadmap.md` section 9.15.

Gates. P0 starts now: no store, hook or daemon-path change; model spend only in PLT-M0's decision-port calls, within
the owner's decision-experiment allowance. P1 rides lf8 beside WAE wave 2 and needs WAE-10. P2 waits on an adopter's
consumer (PLT-M4) and on the owner's cap (PLT-M5). No row adds a table, column, cache, memo file or background job (the freeze
until RT-M1 PASS). No row fetches, posts or grades (I56, ADR-069 decisions 5 and 10). Every bar is fixed in
`docs/bench/prereg/platform.md` before its run (K19), every grader fails both stubs before its reading counts, and a
false clean has a bar of zero in every reading. Kill: G37's, widened (PLT-G): on 2027-01-31 a PLT-M4 that is unread or
CUT removes PLT-7's multi-kind mode and PLT-5's delta file. Org-specific consumer detail (catalog, cadence, teams) lives
in the operator's private pack, never in this repository (ADR-011). Symbols are provisional until grounded with
`find_symbol` at row start.

Lanes, named at the end of each row: `controller` (the owner-architect's session: intent records, ADR text, merges,
consumer-side asks), `owner` (the owner's own hours), `cloud` (a cloud session from the repository alone), `codex` (a helper
machine's Codex lane: build and test from a brief), `api` (an API-funded session: decision-port calls within the
owner's allowance, agent runs on an owner-named cap).
