# Upgrading to 0.17.0: hook output

Three hook-facing contracts changed in 0.17.0. Nothing needs to change for an agent session; scripts that parse hook or doctor output may.

## Edit-time context is not repeated on Claude Code

`edit-hook` (pre and post) and `session-hook --event cwd-changed` keep a small per-session record under the fathom home. Within one Claude Code session, an injection identical to one already delivered prints nothing. It is delivered again after compaction (SessionStart with source `compact` or `resume`, or any `pre-compact-hook` call), after 30 minutes, or after 10 skipped repeats. A subagent has its own key. Codex, Gemini CLI, Copilot and Cursor are unaffected: they receive every injection, because their hook payloads do not yet prove a fresh context.

To restore every injection, set this in `~/.fathom/config.toml` or the repository's `.fathom/config.toml` (a user's `false` wins over a repository's `true`):

```toml
[hooks]
dedupe = false
```

Any error reading or writing the record emits the full injection.

## Citation tags

When the file a rule or symbol citation points at no longer matches what was indexed, the hook line carries `[citation stale]`, `[citation refreshing]` or `[citation unknown]`, and MCP results carry a typed `citation_status` with a reason. A clean citation is unchanged. A file whose last full ingest saw it within two seconds of a write can read `unknown` until the next full ingest; run `fathom ingest` once after upgrading to clear that.

## `doctor --brief` and doctor's exit code

The Setup brief lists TIMEOUT and UNKNOWN rows with their own counts next to FAIL rows, at most 8 lines. `fathom doctor` exits 1 only for a definite failure. A row that timed out, or project wrapper wiring doctor cannot resolve by reading it (a dynamic script, a deep Task chain), reports `timeout` or `unknown`, counts under `summary.skipped` in `--json`, and exits 0 when nothing definite failed. A hung daemon, a missing hook script and a foreign command in a fathom hook slot stay FAIL.
