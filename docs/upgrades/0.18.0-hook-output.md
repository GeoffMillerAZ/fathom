# Upgrading to 0.18.0: hook output

Three hook-facing contracts changed in 0.18.0 (ADR-080). Nothing needs to change for an agent session; scripts that parse hook output may.

## Raw rules print only instructions

When a governing section has no compiled rule, `edit-hook` used to print the section's first lines whatever they said. It now prints at most two sentences that read as instructions (an imperative such as "Never run ..." or "Every doc must ...", or a line from an ADR Decision block), keeps a preceding condition with its instruction or prints neither, and prints nothing for a section with no instruction. Compiled rules are unchanged. To see what a file is governed by regardless, run `fathom obligations <file>`.

## Rules are not repeated within a context

0.17.0 dropped repeated injections on Claude Code only. Edit-time obligations are now deduplicated per rule and per context (session plus agent) on Claude Code and Codex: a rule already delivered unchanged is not printed again until its text, tags or staleness change, the context is compacted, or capacity evicts it. Set `[hooks] dedupe = false` in `~/.fathom/config.toml` or `.fathom/config.toml` to restore every injection.

## Silent when not ready, unknown when not provable

A hook whose prerequisites are missing (the root is not indexed, the harness has no matching registration) prints nothing and logs `skipped:not-ready:<reason>`; `fathom doctor` lists each channel's state in its `channels` table. `stop-hook` and the claim check report a criterion as unknown, with a freshness note, when its contract path has uncommitted files the index has not seen, instead of failing it. A proven failure still fails, and `--block` still blocks it.
