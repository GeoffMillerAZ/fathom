# 0.9.0 — discovery skips the default cache directories

**Breaking:** `LocalConnector` discovery now prunes eleven directory names on
top of the always-skipped set (RT-145, `docs/design/responsible-tenant.md`
§4.2): `.cache`, `.tools`, `target`, `dist`, `build`, `__pycache__`, `.venv`,
`.gradle`, `.next`, `.turbo`, `coverage`. They are build output, tool caches
and virtualenvs; on the 2026-09-26 incident machine app-kit's `.cache/` and
`compute/.tools` were 43% of a 5.3 GiB tree the daemon read whole.

| Before | From 0.9.0 |
|---|---|
| a directory with one of those names was walked, fetched and indexed like any other | it is pruned from discovery; the next ingest's orphan purge removes what it held; the ingest names it (`excluded: N default-ignored cache dir(s) (…)`, `default_ignored_dirs` in `--json`) |
| every file was read whole during an ingest | a file over 2 MiB is never read (RT-69); it is counted under `oversize` as before |

## What to do

- **Measure first:** `fathom ingest --service <id> --path <root> --dry-run --json`
  reads nothing and writes nothing; `default_ignored_dirs` lists every
  directory the default list prunes in that tree.
- **A repository that commits source under one of those names** (a Go package
  named `coverage`, a `dist/` of shipped assets) re-includes it in its own
  `.fathom/config.toml`, then re-ingests:

  ```toml
  [connector]
  include = ["coverage", "dist"]
  ```

  A bare name re-includes every directory with that name; an entry with a
  slash (`web/build`) re-includes just that path. `include` never re-includes
  `vendor`, `.git`, `testdata` or the other always-skipped names.

## Why

ADR-047 and invariant I48: a tenant's reads are bounded by what it is asked
about. Cache directories are never what an agent asks about, and reading them
is where the daemon's memory went.
