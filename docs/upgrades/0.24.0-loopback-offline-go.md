# Upgrading to 0.24.0: loopback-only daemon and offline Go

Two defaults changed in 0.24.0. Both are Breaking for the setups named below. (`--allow-non-loopback` never shipped, so its absence is not a change.)

## The daemon answers loopback peers only

**Symptom.** A client that reaches the daemon through a LAN address, a container or a VM gets 403, and a daemon configured with `--addr :7575` or a wide `[daemon].addr` listens on `127.0.0.1` instead. `fathom doctor` row `daemon_bind` FAILs on a wide plist.

**Why.** The daemon has no authentication, so a network peer could reach `/rpc`. Remote serving needs token auth, which fathom does not have yet.

**Fix.** Point clients at `127.0.0.1`. Rewrite an installed plist from your own terminal (not an agent's shell):

```sh
fathom daemon install --reconcile
```

## Fathom's own go commands run offline

**Symptom.** Ingest of a Go repository exits 1 with `ingest degraded: typed-edge pass failed`, naming a module missing from the module cache. The Go typed pass is degraded until the cache is filled.

**Why.** The typed pass, the daemon's toolchain shim, `ask` and `receipt verify` now run with `GOPROXY=off`, `GOSUMDB=off` and `GOTOOLCHAIN=local` (ADR-083), so ingesting a repository can no longer fetch code or reach a private dependency's version control.

**Fix.** Fill the module cache once, in each Go module of the repository:

```sh
go mod download
```

Or let the typed pass download as before, in `~/.fathom/config.toml` (user scope only; a repository cannot set it):

```toml
[ingest]
go_network = true
```
