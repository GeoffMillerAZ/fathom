# 0.8.0 — skills on the standard

**Breaking:** `fathom init --skills=codex` no longer writes
`~/.codex/prompts/<name>.md`. It writes `<repo>/.agents/skills/<name>/SKILL.md`
— the path Codex's own skills documentation lists (`$REPO_ROOT/.agents/skills`,
every directory from cwd up to the repo root, `$HOME/.agents/skills`), which
Gemini CLI, Cursor, Copilot and the rest of the surveyed harnesses also read
(`docs/vision/25-harness-port.md` §1). Codex marks custom prompts deprecated
("use skills").

| Before 0.8.0 | From 0.8.0 |
|---|---|
| `--skills=codex` → `~/.codex/prompts/*.md` (user-global) | `--skills=codex` → `.agents/skills/*/SKILL.md` (repo-scoped, spec-only frontmatter) |
| bare `--skills` / `--skills=all` → `.claude/skills` + `~/.codex/prompts` | bare `--skills` / `--skills=all` → `.agents/skills` + `.claude/skills` (both repo-scoped; no user-global write) |
| `--skills=agents` → `.agents/skills` | unchanged (same as `codex`) |
| — | `--skills=codex-prompts` → `~/.codex/prompts/*.md` — the deprecated twin, explicit only; the one user-global write `--skills` can make |

## What to do

- **If you invoked skills as `/prompts:fathom-<name>` in Codex:** run
  `fathom init --skills=codex` in each repo; invoke as `$fathom-<name>` (or
  `/skills`). The prompt files fathom wrote earlier stay where they are —
  delete them when you are done with them, or keep rendering them with
  `--skills=codex-prompts`.
- **If a script or hook ran `fathom init --skills` and expected
  `~/.codex/prompts`:** add `--skills=codex-prompts` (a second run is
  idempotent; every file fathom writes carries the `fathom:owned` marker and
  is only ever rewritten under it).
- **Fleets:** `fathom fleet reconcile --apply` now plans both repo-scoped
  shapes through the wiring engine — a missing or stale marker-owned skill is
  written and receipted (`fathom fleet undo` reverses it), a hand-authored
  file by a skill's name is BLOCKED by name and left alone.
- **Doctor:** `skills_installed` reads `.agents/skills` for every non-Claude
  `--harness` and names each missing skill.

## Why

The Agent Skills specification (agentskills.io) settled `SKILL.md` under
`.agents/skills` as the cross-client convention; 13 of 15 surveyed harnesses
honor it. A user-global prompt directory served one harness on one machine
and drifted from the shipped source with every release, invisibly.
Repo-scoped skills are reconciled like every other fathom-owned file, and
the shipped frontmatter is vetted against the vendored spec schema
(`schema/skills/schema.cue`) on every `task validate`.
