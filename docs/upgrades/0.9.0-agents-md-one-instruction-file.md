# 0.9.0 — AGENTS.md is the one instruction file

**Breaking** (ADR-059, `docs/plans/agents-md.md`): fathom writes its stanza into `AGENTS.md` only,
for every harness. Claude Code reads `AGENTS.md` natively since 2.1.277, and Codex always has. A
root `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` that already exists gets one
fathom-marked region holding the import `@AGENTS.md` (`@../AGENTS.md` from `.claude/`). fathom
never creates a CLAUDE file, and never deletes one.

| Before | From 0.9.0 |
|---|---|
| `fathom init`, `fleet reconcile --apply` and the console apply wrote the same stanza region into `CLAUDE.md` and `AGENTS.md`, creating both | the stanza region goes into `AGENTS.md` (created when absent); the first present root CLAUDE file gets a one-line import region; a repository with no CLAUDE file gets none |
| `init --harness=gemini-cli` wrote the stanza into `GEMINI.md` | it writes the stanza into `AGENTS.md` and sets `.gemini/settings.json` `context.fileName` to `["AGENTS.md", "GEMINI.md"]` through the wiring engine |
| `fathom init --skills` rendered two copies, `.claude/skills` and `.agents/skills` | `.claude/skills` holds the only copy; `.agents/skills` is a relative link to it, written for `--skills`, `--skills=codex` and `--skills=agents` |
| `fathom gen-claude-md` wrote `workspace/artifacts/CLAUDE.md` | `fathom gen-agents-md` writes `workspace/artifacts/AGENTS.md`; the old name still runs through 0.9.x and prints a deprecation line |

## What to do

- **Run the rewire once:** `fathom fleet reconcile --repo <root>` shows the move ("CLAUDE.md still
  carries the stanza — --apply moves it into AGENTS.md"); `--apply` rewrites the CLAUDE.md region
  in place to the import, writes the stanza into `AGENTS.md`, and records one receipt.
  `fathom fleet undo --repo <root> --last` puts the old layout back.
- **A hand-edited stanza region blocks** (law 15): reconcile names it and writes nothing to that
  file. Keep your text outside fathom's markers, or take fathom's, then re-run.
- **If you already import `@AGENTS.md` yourself**, fathom removes its own region from that CLAUDE
  file instead of adding a second import.
- **Check that Claude Code loads it:** `fathom doctor` `stanza_present` passes and names the load
  path ("native (no CLAUDE file, default mode)" or "imported by CLAUDE.md"). It warns, with the fix,
  when a CLAUDE file in a parent directory switches `AGENTS.md` off, when your user or managed
  settings set `pluginConfigs["agents-md@builtin"].options.instructionFiles` to `claude-md` or
  `managed-only`, or when `claude --version` is older than 2.1.277. fathom never writes that
  setting: it is user-global.
- **Skills:** re-run `fathom init --skills` (or `fleet reconcile --apply`). A real `.agents/skills`
  holding only fathom's own unedited files is replaced by the link, with each removed file in the
  receipt; one file fathom did not write there blocks the link and is named.
- **Scripts calling `gen-claude-md`:** switch to `gen-agents-md`.

## Why

Two copies of one stanza drifted, and under Claude Code's default mode a CLAUDE.md suppresses
`AGENTS.md` entirely. One file that every harness reads, with a one-line import where a CLAUDE file
already exists, keeps one contract.
