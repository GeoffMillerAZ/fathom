# Upgrading past 0.9.0 — the surface reckoning

The surface reckoning (docs/plans/surface-reckoning.md, docs/design/surface-reckoning.md,
ADR-053) deletes zero-call MCP tools, CLI verbs and canned prompts and merges several
others into a composed verb. This note is the tool/verb/prompt → replacement table,
appended one row per removal row as it lands (SR-36 is the row that completes this table
and its `### Breaking` block in `CHANGELOG.md`).

| Removed | Kind | Row | Replacement |
|---|---|---|---|
| `investigate_incident` | MCP prompt | SR-20 | Call `entrypoints`, `find_callers`, `community`, `staleness_report` directly |
| `review_change` | MCP prompt | SR-20 | Call `review_diff` directly |
| `onboard_service` | MCP prompt | SR-20 | Call `entrypoints`, `list_sources`, `god_object` directly |
| `plan_requirement` | MCP prompt | SR-20 | Call `entrypoints`, `complexity`, `dead_code` directly |
| `brief` | MCP tool | SR-15 | Call `find_symbol` + `query_symbols` (or `pack_context`) directly and assemble the context yourself; the console's `/brief` page covers the human-facing value brief |
| `fathom brief` | CLI verb | SR-14 | Open the console's `/brief` page (same `renderBriefMD` content); nothing replaces the `--json`/`--out` machine paths |
| `fathom narrate` | CLI verb | SR-14 | None — the story-mode capture feature (story rows, the narrate capability) is retired outright, not replaced |
| `dep_drift` | MCP tool | SR-10 | None — superseded by the system graph (ADR-050): `pkg:` contract-key reads plus `system_impact`/`contract_drift`, not a revived tool pair |
| `cross_repo_blast_radius` | MCP tool | SR-10 | Call `cross_repo_callers` for the symbol's cross-service callers, then `blast_radius`/`find_callers` in each caller's own service |
| `find_callees` | MCP tool | SR-21 | Call `symbol_context` — its `callees` field already answers this |
| `entrypoints` | MCP tool | SR-22 | Call `repo_map` — its response now carries an `entrypoints` header (same detector, capped at 10 with `entrypoints_more`) |
| `capabilities` | MCP tool | SR-23 | Call `status` with `section: "tools"` — byte-compatible with the retired tool's answer |
| `server_stats` | MCP tool | SR-23 | Call `status` with `section: "daemon"` (optional `service` for `typed_edges`) — byte-compatible with the retired tool's answer |
| `list_sources` | MCP tool | SR-23 | Call `status` with `section: "sources", service: "<id>"` — byte-compatible with the retired tool's answer; refused under hosted-modules mode, as before |
| `rename_impact` | MCP tool | SR-24 | Call `blast_radius` with `kind: "rename", symbol: "<name>"` — byte-compatible with the retired tool's answer |
| `safe_delete_check` | MCP tool | SR-24 | Call `blast_radius` with `kind: "delete", symbol: "<name>"` — byte-compatible with the retired tool's answer, including the proven-zero receipt (`symbol_id` alias not carried over) |
| `diff_impact` | MCP tool | SR-25 | Call `blast_radius` with `max_depth: 0, max_symbols: 0` for the same unbounded walk, or `review_diff` for the composed diff/PR verdict |
| `api_diff` | MCP tool | SR-26 | Call `review_diff` with `since` for its `conservation` dimension's `surface` plane, or `fathom conserve --since <ref>` store-direct (base→head on one service, not two independently-ingested snapshots) |
| `stale_docs` | MCP tool | SR-28 | Call `staleness_report` — its response now carries the same scan as an additive `doc_drift: [{file, line, ref}]` section |
| `discoveries` | MCP tool | SR-29 | The SubagentStart hook's push-form render (`subagentDiscoveries`) already covers the need; call `fathom discoveries` (the CLI verb, unaffected) for a pull-form read |
| `fathom routes` | CLI verb | SR-29 | Run `fathom prime --routes [package|concern]` — the identical `cmdRoutes` render |
| `arch_conformance` | MCP tool | SR-27 | Call `review_diff` over `changed_files` — its `arch_conformance` dimension runs the identical check in-process (project rule pack only; no inline `rules`) |
| `spec_coverage` | MCP tool | SR-27 | Call `review_diff` over `changed_files` — its `spec_coverage` dimension runs the identical check in-process |
| `spec_refs` | MCP tool | SR-27 | Call `obligations` with `file` — its `spec_refs` section carries the same `{spec_id: [{file, line}]}` map for the IDs that file cites |
| `http_client_calls` | MCP tool | SR-12 | None — 0 lifetime calls; `fathom report` still runs `security.HTTPClientCalls` directly |
| `fleet_drift` | MCP tool | SR-12 | None — 0 lifetime calls; no MCP replacement |
| `reachable` | MCP tool | SR-12 | None — 0 lifetime calls; use `find_callers`/`blast_radius` to see whether a path exists |
| `traverse` | MCP tool | SR-12 | None — 0 lifetime calls; use `find_callers`/`blast_radius`/`symbol_context` for call-graph walks |
| `history` | MCP tool | SR-12 | None — 0 lifetime calls; no MCP replacement (`fathom purge history`/`fathom plans history` are unrelated CLI verbs) |
