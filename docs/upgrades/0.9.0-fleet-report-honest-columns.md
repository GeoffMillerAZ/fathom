# 0.9.0 — `fleet report --json` stops writing zeros it did not measure

**Breaking:** two columns of `fathom fleet report --json` (and the `/fleet`
page's `fathom fleet report --json` section, the same function) change.

| Before | From 0.9.0 |
|---|---|
| `calls_total: 0`, `calls_agent: 0` on every service when the call log could not be read, beside `call_log_note: "… never zero"` | both keys are **omitted** for every service when `call_log_note` is set; present (a measured count, `0` included) whenever the log was read |
| `session_count`: session-ledger **rows** per repo label (the Stop hook writes one per turn — 346 for a repo with 2 sessions), read from `~/.fathom/session-ledger.jsonl` regardless of `FATHOM_SESSION_LEDGER` | distinct **sessions** per repo label (`console.DistinctSessionsByRepo`, the rule every console page uses), from the ledger `FATHOM_SESSION_LEDGER` names, else `~/.fathom/session-ledger.jsonl` |
| — | additive: `call_log` (`path`, `rule`, `note` — which rule chose the log) and a per-service `observations_error` when `.fathom/observations.md` exists and could not be read |

## What to do

- **A script that reads `calls_total`/`calls_agent`:** treat a missing key as
  "not measured" and read `call_log_note` for why. Never default it to 0.
- **A script that compared `session_count` across reports:** numbers from before
  this release counted rows; re-baseline against a fresh report.
- **A test that pointed the report at a ledger by writing `~/.fathom/…`:** set
  `FATHOM_SESSION_LEDGER` instead.

## Why

ADR-045 names "ledger rows were counted as sessions" as a contradiction the
console removes, and doctrine rule 6 (`cmd/fathom/AGENTS.md`) says an unread
source carries no zero in JSON. The fleet report is the `/fleet` page's verb
section (OC-8), so its columns had to meet the same rules.
