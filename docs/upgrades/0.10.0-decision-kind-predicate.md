# 0.10.0 — the yes/no decision kind is `predicate`

**Breaking** (JF-24; agentic-kit DP-12 and DP-14, pinned at 0c08348): the decision port's
yes/no kind takes the kit's generic name. fathom asks the same questions and every provider
sees the same wire; only the name fathom writes changes.

| Before | From 0.10.0 |
|---|---|
| `decisions.jsonl` rows at `schema_version: 1`, a yes/no answer with `"kind": "noul"` | `schema_version: 2`, `"kind": "predicate"` |
| the assess ledger (and `fathom assess --json`) at `schema_version: 1`, a yes/no verdict with `"kind": "noul"` | `schema_version: 2`, `"kind": "predicate"` |
| `fathom decide log` showed a yes/no row as `noul` | every yes/no row shows as `predicate`, including rows written before this release |

Unchanged: the `noul` field (the probability a statement is true) keeps its name, the
`question_set` digests of `fathom assess` keep their values, and the request each adapter
sends is byte-identical.

## What to do

- **A reader of `decisions.jsonl` or the assess ledger that matches `"kind": "noul"`:** also
  accept `"predicate"`, or decode the kind with agentic-kit's `decision.ParseKind`, which
  reads both. Rows at `schema_version` 1 keep saying `noul`; nothing rewrites them.
- **Go code built against the kit's `foundations/decision`:** `decision.KindNoul` is gone; write
  `decision.KindPredicate`. The `LLM` and `TypeSafe` adapters moved to
  `foundations/decision/llm` and `foundations/decision/typesafe` with their names unchanged
  (the kit's `docs/upgrades/decision-adapter-subpackages.md`).

## Why

The port is meant to stay provider-neutral: "noul" was one vendor's term for a yes/no question.
The kit renamed it and kept "noul" as a decode alias, so fathom writes the generic name and
reads both.
