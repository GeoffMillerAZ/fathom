## Shared tools (GroupShared)

These tools are visible on the full registry and under every group surface. One
exception: the `agent`/`companion` surface shows only its explicit allowlist (see above)
— other shared tools are still callable there, execute-and-flagged rather than hidden.

| `find_symbol` | `service` (req), `name` (req) | `{symbols: [SymbolNode], matched_via, truncated?, elided?, did_you_mean?, implementations?: [{name, file_path, line, via}]}` | Locate symbol definitions with tiered matching: exact/key-suffix → case-insensitive → substring (capped at 20, tightest first); a full miss returns up to 5 concern-ranked `did_you_mean` suggestions. **J3(b)** (app-kit O22): the case-insensitive tier (name match, then a package-name match) also caps at 20 rows, carrying `truncated:true` and the standard `elided` disclosure (`{count, of, ordering, how_to_get_more}`) when more matched — a query naming a whole package no longer floods the response with every exported symbol. `matched_via` = `exact` \| `case_insensitive` \| `substring` \| `none`. An exact hit on a single Go interface additionally carries `implementations` (SB-5, docs/plans/strengths-bench.md): the concrete types satisfying it, `via` = `"typed"` (a persisted interface-dispatch edge confirms a real call-site dispatch), `"assertion"` (a `var _ Iface = (*T)(nil)` in source), or `"method_set"` (structural name-only match over indexed `GoMethod` symbols) — in that preference order, deterministic and sorted by name. `displaced` is then the TOTAL repo+module count (a compatible superset of its pre-phase-O meaning), split by `displaced_repo`/`displaced_module`; a binding naming a module this daemon does NOT have mounted produces a `module_notes` entry (`{module, note}`) — never silence. **ADR-032 §4 / ADR-035 decision 2 (the serve-time fixes):** served rules are ordered **fresh before non-fresh**, then by layer **role**, then by **governing-scope proximity** — exact file, then package, then the nearest named ancestor directory, then root (VB-8's `rankByGoverningScope`; the byte-length "keyword score" this replaced now only breaks a tie INSIDE one proximity tier — with one narrow exception, wave O3's `crossTierCloser`, ADR-037 addendum: a farther-tier rule that STRONGLY names the file — a hit on its own package path, stem, or a resolved symbol/behaviour token — leapfrogs a nearer-tier rule that is a total lexical blank about the file; the cap is filled by `role:"governs"` layers (`obligations`, `adr-rules`) FIRST and `role:"claims"` layers (`spec-bindings`, `findings`) take only the slots left (D1), with `displaced` still counting both; and a claims-layer rule citing a gated plan row is scoped at serve time by that row's own `{package, symbol}` contract — a row naming no contract binds to nothing (D2, O23: six plan rows about C++, CUE and tree-sitter bound to one Go file by the word "extractor" in their prose and displaced 65 more). Each rule also carries `snippet`, its cited lines inlined and capped at 240 bytes with a named cut (D3, reusing `symbol_context`'s `read_source`-backed snippet path) — pass `include_snippets:false` for the smallest payload; the edit hook always does, so its decision-moment budget is unchanged. **O54 coverage disclosure (the same execute-and-flag doctrine ADR-014 applies elsewhere):** `layer_coverage` rides every response for which the obligations layer has ever been compiled (absent only when no `compile_runs` row exists yet), reporting the LIVE corpus's completeness — `sections_total`/`sections_compiled` are recomputed from the CURRENT corpus (a cheap split, no LLM) every call, never trusted stale off the latest `compile_runs` row, so a doc added after a full compile does not silently read back as "100% covered"; `corpus_grew` (present only when > 0) counts sections the CURRENT corpus has that NO compile run has ever even seen, distinct from a section that compiled once but has since changed (still not-compiled, but not "growth"). `uncompiled_scopes` names the governing-document paths that are either stale or never-seen. The compile order itself is THREE tiers, nearest-scope-first (`internal/semantic`'s `orderSectionsByGoverningScope`): every nested `CLAUDE.md`/`AGENTS.md` guide, then the repo ROOT's own `CLAUDE.md`/`AGENTS.md` (document order within both — never re-sorted by size, so a root Non-negotiables table an author put first is never buried behind smaller sections later in the file), then everything else root-scoped (`ADR.md`, `docs/plans/README.md`, smaller sections first) — so a budget stop always leaves every guide (nested and root) compiled and the root-OTHER tail uncompiled, never the reverse. When the queried `file`'s own nearest guide is among the uncompiled scopes, `note` names it and the resume command instead of silently omitting the rule that governs the file (e.g. `"internal/CLAUDE.md governs this path and was not compiled: budget stopped at 18/60 sections; run `fathom compile --layer obligations --continue`"`) — a NESTED guide wins when one governs the path; when none does, the repo's ROOT guide is the fallback (it governs every file by construction, so its own incompleteness is still worth naming); never fabricated for a root-scope call, a file whose own guide already compiled, or a plain root-OTHER document (`ADR.md` is never "the nearest guide" for anything) — mutually exclusive with the root-scope `note` above. **ADR-037 raw-section fallback:** whenever that same gap exists for a file-scoped call, `obligations` also serves the nearest uncompiled section(s) themselves — up to `RawFallbackReserve` (2), ranked by the identical governing-scope proximity ranker compiled rows use — as real rows tagged `tier:"raw"` with a `why` note naming the coverage defect (`budget_stopped`, `no compile_runs row`, or `uncompiled`), prepended ahead of any farther-tier compiled row; a raw row only ever adds (never displaces a compiled row, never consumes a `max_rules` slot) and never fires once a fresh compiled claim already covers that exact section. A raw row's citation (`src`) narrows to the lines around its own first relevance hit rather than always spanning the whole section (wave O2) — the inlined `snippet` truncates from the citation's first byte at its own 240-byte cap, so an unnarrowed long section previously showed only its opening lines. `fathom compile --layer <layer> --continue` (O54) resumes a budget-stopped compile from the first not-yet-compiled section (the same three-tier order) instead of re-estimating the WHOLE remaining corpus against the same per-run budget — the recorded `compile_runs` row's `resumed_from` names the section, and a `--continue` against an already-complete layer prints a one-line "nothing to resume" instead of refusing or re-spending. Also on the agent/companion surface, and (module-tagged, budget-capped) on the PreToolUse guard hook (docs/design/guarded-edits.md) for scopes named in `.fathom/guard.cue`. **`as_of`** (SU-19, ADR-041 decision 7) answers "what governed `file` AT this instant" instead of now — the claims whose bi-temporal validity window (`valid_from`/`valid_to`) contains it, REGARDLESS of their current status (a claim later superseded or refuted still answers if `as_of` falls before that event); the response echoes it back as `as_of`. Requires `file` (root-scope `as_of` is not supported). Each served rule also carries `asserted_by` when its underlying claim recorded one — the minting activity's `kind:id` identity (SU-22). **`ranked_by`** (DP-8, ADR-042 decision 2, `docs/plans/decision-port.md`) always names which decision-port `Decider` re-ranked the served rules WITHIN their governing-scope tier — `"none"` (the default: no provider configured, `rank_within_tier` off, or a configured provider's call itself failed, named in `rank_note`) or the provider's name (`"llm"` or `"typesafe"`); a rerank never crosses ADR-035's tier order and never drops a rule, so `displaced`/`displaced_by_tier` are unaffected. Each served rule then carries its own `relevance` (the noul probability the provider gave "does this rule govern this edit") whenever `ranked_by` names a real provider and that provider answered it; absent under `ranked_by:"none"`. **DP-24, O109 — rules below the served window are not ranked:** the Decider is asked only about claims in governing-scope tiers that intersect the served window `[0, max_rules)` in the pre-rerank lexical order — a tier wholly inside the window is asked in full (its own internal order still matters for reading), a tier straddling the cut is asked in full (ranking decides who survives), and a tier wholly below the cut (no member can reach a served slot regardless of how it ranks) is never asked at all, so a real, billed round trip is never spent on an answer the cap could never use. `ranked_count`/`candidates_total` (present only when a rerank ran) disclose the effect directly: `candidates_total` is how many scope-eligible claims existed before this filter, `ranked_count` is how many of them were actually asked about. **DP-25, O109 — the re-rank is time-boxed:** `[decide] rerank_timeout_ms` (default 1500ms, `docs/configuration.md`) bounds how long the WHOLE rerank call (every chunk together) may wait for the Decider; a chunk still in flight at the deadline is treated exactly like any other hard-failed chunk (its rules keep their lexical position, logged as a `DecisionError`), and `rank_note` names the budget explicitly (`"decision budget <N>ms exceeded: <k> of <m> chunks unanswered"`) rather than the ordinary per-chunk-failure text, so a slow or unresponsive decider can never hold the response hostage. |
