## Investigation tools (GroupInvestigation)

For cross-service investigation, incident response, and understanding code structure.

| `find_callers` | `service` (req), `symbol` (req), `depth` (opt, default 1; 0 = unbounded), `include_heuristic` (opt, default **false**), `with_signatures` (opt, default **false**) | `{summary, callers: [{loc: "file:line name", c: "r"\|"h", sig?}], edge_filter: "resolved"\|"all", caller_service?, caller_tier?, caller_depth?, caller_edge_confidence?, by_depth: [{depth, count, resolved, heuristic}], transitive_callers?: [{key, depth, edge_confidence}], typed_callers?: [{key, kind}], elision?, scope_required?, count?, top_packages?, message?, resolution: {typed,heuristic}, index_commit?}` | Find all symbols that call the named symbol within the service. **VB-19** (ADR-035 decision 4, docs/vision/29-verbs-not-lookups.md §3 wave E): `resolution` sums `by_depth`'s own `resolved`/`heuristic` counts (`callers`+`transitive_callers`); `index_commit` names the daemon's watermark for the service when it can name one — a receipt built from this answer reproduces (or refutes) independently via `fathom receipt verify` (VB-20). **RC-19**: `callers` is budgeted (`fitToolBudget`, 16000 chars); a truncated answer carries a one-line `elision`: `"elided: N more — refine with a package-qualified symbol (pkg.Name)"`. **RC-20**: a fan-in far too large to page through at all (a generic name's callers across a whole fleet) instead returns `scope_required: true` with the true `count`, the top ≤8 packages (`top_packages: [{package, count}]`, sorted by count descending then name ascending), and a `message` — `callers`/`by_depth` come back empty in that case. **By default only RESOLVED callers are returned** (BP-26): edges a typed pass confirmed — the Go pass (ADR-021 §3) or, since ADR-041 decision 5, the CUE pass (`EnrichCUEEdges`, SU-10). The TypeScript/JavaScript/Python per-file resolver's edges (kind `file-resolved`, SU-11) never count as resolved — no compiler or type checker confirmed them, only an import graph and module-scope name matching — so they stay heuristic tier (`c: "h"`) and surface only via `include_heuristic: true`, same as the syntax-only pass. The same holds for the reference and topology edges ingest stores at file tier (LB-F74..LB-F78, LB-F96, LB-F87, LB-F135): an import-bound type or identifier reference (a definition that only names a type draws an edge to the file defining it), a `route-ref` edge from a route, upstream or proxy target to the Kubernetes or compose Service its host names, an image-ref edge (a Dockerfile's `FROM`/`COPY --from`, a compose `image:`/`build:` or a container's `image:`) to the Dockerfile that builds the image, and a `policy-ref` edge from a policy to what it governs; each is heuristic-tier and feeds impact, never a verdict. The syntax-only pass measured precision 0.607 on this repository's own index (`docs/bench/README.md`), so its bare-name matches are opt-in via `include_heuristic: true` — which restores the pre-0.9 answer, still fully labeled. `edge_filter` names which evidence answered; a service with no typed edges (a non-Go corpus) falls back to the heuristic answer and reports `"all"` rather than returning an empty resolved one. **Since SB-47, each caller is rendered compact for the wire** (mirroring `references`' SB-1): `loc` combines file:line and name into one string, `c` collapses `edge_confidence` to a single character, and `sig` (the full signature) is carried only when `with_signatures: true` asks for it. `service`/`tier`/`depth`/`edge_confidence` are lifted to the envelope as `caller_service`/`caller_tier`/`caller_depth`/`caller_edge_confidence` whenever every listed caller shares one — which the direct, depth-1, single-service `callers` list almost always does; a row keeps only `loc`/`c`/`sig?` when a dimension disagrees. `by_depth` summarises the rows by depth and confidence; `depth` > 1 (or 0) adds `transitive_callers` — every deeper caller with the depth it was first reached at, in the full (uncompacted) `{key, depth, edge_confidence}` shape. `typed_callers` (ADR-021 §3, Go services only) lists callers reachable ONLY via a typed edge — e.g. an interface-dispatch caller across an ambiguous method name the syntax-only graph can never include — each labeled `kind: "direct"` or `"iface-dispatch"`. Omitted when the service has no typed edges. Also on the agent/companion surface. |

Widen with `max_depth` / `max_symbols` (0 = no bound) and `include_heuristic: true`. The response always reports `edge_filter`, `total_symbols` (the full count before the cap), `truncated`, `depth_capped` and the greatest `max_depth` reached, so a bounded answer never reads as a complete one. `by_depth` (BD-3) regroups the SAME listed symbols by distance from the change — depth 0 = the changed symbols, 1 = direct callers, … — each labeled `edge_confidence` `resolved` or `heuristic`, with per-bucket counts; the union of the buckets is exactly `symbols`. **Wave lg (LB-F200):** a symbol pulled in through a reference to a Go type rather than a call (a syntax-only edge to the type, `include_heuristic: true`) stays in the radius, its row labelled `edge_kind: "type-ref"` (heuristic) and its key listed in `references` (empty, never omitted, on the resolved default); a syntax-only edge into a Go method from a file the typed pass compiled is no longer walked (LB-F199). A change to a file also reaches, with `include_heuristic: true`, the files that name its types by reference and the `route-ref`, image-ref and `policy-ref` file-tier edges that end at it (a Service's file reaches every route in front of it, a Dockerfile the manifests that run its image, a declared target the policies that govern it): heuristic rows, `edge_confidence: "heuristic"`. `kind:"rename"`: every call site that needs updating if the symbol is renamed (direct callers); **`claims_anchored`/`claims_anchored_ids`** (SU-21, ADR-041 decision 7): claims bound to the renamed symbol via an `anchors` claim link — present only when at least one exists, so a rename is never silent for governance. `kind:"delete"`: "can this symbol go" — `referents` lists every remaining use, typed edges first, each labeled `tier` (`typed` = a confirmed call-graph edge, `heuristic` = a bare-name match); `test_referents` (present only when non-empty) lists test-function referents separately; `checked_edges` names the strongest evidence tier the verdict rests on; `referent_count: 0` alongside an empty `referents` array IS the proven-zero receipt (`fathom receipt verify`, VB-20); an interface (or a method only an interface declares) lists its concrete implementations as referents. A module symbol (`<module>`) answers `module_symbol: true` and its `file`, lists the file's importers at their tier and never reads proven zero (it lives as long as its file: ask `kind:"change"` on the file), and a symbol's file-resolved callers the resolved filter drops are listed as `heuristic` referents (SR-75, O742, O743). ADR-035 decision 1 (docs/vision/29-verbs-not-lookups.md §3 wave A): the answer grep cannot give for any of the three kinds — no text search walks a call graph or resolves identity across a shared name. Also on the agent/companion surface. **RT-89:** `service_ref_hops` join routes and client calls extracted at ingest (stored rows, never a per-call source read); `service_ref_unextracted` names services not re-ingested since. |
