### Shared: obligations-b

| Tool | Arguments | Returns | Purpose |
|---|---|---|---|
| `obligations` | `service` (req), `file` (opt; `path` accepted as an alias — O82, `file` wins when both are given), `layer` (opt: `rules`\|`claims`\|`all`, default **`rules`**), `max_rules` (opt, default 6), `include_snippets` (opt, default **true**) | `{service, file, layer, rules?, compiled_at_watermark?, index_stale?, index_unchecked?, displaced?, displaced_by_tier?, displaced_repo?, displaced_module?, module_notes?, root?, note?, layer_coverage?}` — `layer_coverage` is `{sections_total, sections_compiled, budget_stopped, uncompiled_scopes?, uncompiled_reasons?, corpus_grew?, prefilter_skipped?, unread_corpus?}` | Return compiled claims governing a file at decision time, across every compiled layer. Empty result with no `index_stale` field means a clean file (zero-output-on-clean contract). `index_unchecked` names a freshness check that did not read the file (over the 2 MiB hot-path cap, or not a regular file): its index freshness is unknown and it was not refreshed. `layer_coverage` reads only the layer's own guides, never the tree: their paths come from one names-only walk per ingest (a new guide is counted after the next ingest; an edit to a known one on the next call), and `unread_corpus` names any guide it could not read (over 2 MiB or unreadable), making the counts a lower bound; it is carried on the `status:"unknown"` placeholder too, and the raw-fallback rows' `why` names the same guides. **`layer` splits the question (VB-9, ADR-035 decision 2, `docs/plans/verbs.md`):** `"rules"` (default) serves ONLY human-authored governing rules (`role:"governs"` layers — CLAUDE.md/AGENTS.md, ADR invariants, docs/intent) — "what governs this file"; `"claims"` serves ONLY plan-row bindings bound STRICTLY by the row's own `{symbol, package}` contract (a row naming no contract binds to nothing, never by prose keyword) — "what plan rows claim this file", a different reader; `"all"` is the pre-VB-9 union of both, prose fallback included for a non-plan-row corpus (`findings/**`). The response's `layer` field echoes what was actually served — a backend older than VB-9 always reports `"all"`. **`file` omitted (and no `action`) answers "what governs this repository"** (RC-22/RC-23, docs/vision/28-receipts.md §3.5): the root-scope rules — the compiled layer's rules whose scope reaches the repo root / CLAUDE.md level — budgeted the same way, with `root:true` and a `note` pointing back at `file` for file-scoped rules; this was previously a bare "file required" error. Each rule carries its source citation, evidence tier, and a `layer` label naming which manifest layer compiled it (T5-2/O14 — `"obligations"`, `"adr-rules"`, `"spec-bindings"`, `"findings"`, …); drifted or contradicted rules are flagged. **J2** (app-kit O6/O16/O24/O26/O29/O30): a stale/contradicted rule's inlined `snippet` is its stored compile-time text (never a live re-read of the current file at the rule's now-possibly-unrelated citation range), and the response carries `stale_count`/`remedy` (a `fathom compile --layer <layer> --service <service>` line) whenever any served rule is non-fresh; every hook renderer moves such rules into a separate "not binding until recompiled" block instead of the governing list. `displaced` (present only when > 0) counts served-eligible rules a cap dropped this call — the 6-rule `max_rules` cap, plus (rarely) the shared 16KB tool-payload budget every list-returning tool obeys; a recompile blending a new layer in can evict a previously-served rule, and this makes the eviction visible instead of silent. `displaced_by_tier` (VB-10) breaks that same count out by governing-scope proximity — `"exact_file"`, `"package"`, `"parent_dir"`, `"root"` (`rankByGoverningScope`, VB-8) — so a dropped root-level catch-all reads differently from a dropped package rule; present only for a file-scoped call. Rules from non-obligation layers carry `kind` (e.g. `"finding"`); finding-kind rules whose scoped code changed since compile carry `code_drifted:true` (remediation-drift annotation, never a status flip). **Phase O (docs/design/platform-modules.md):** when the calling service's `.fathom/modules.cue` binds a mounted platform module, matching module rules are unioned in, each carrying `module:"<name>"` (module-tagged, absent for every repo-local rule); `displaced` is then the TOTAL repo+module count (a compatible superset of its pre-phase-O meaning), split by `displaced_repo`/`displaced_module`; a binding naming a module this daemon does NOT have mounted produces a `module_notes` entry (`{module, note}`) — never silence. **ADR-032 §4 / ADR-035 decision 2 (the serve-time fixes):** served rules are ordered **fresh before non-fresh**, then by layer **role**, then by **governing-scope proximity** — exact file, then package, then the nearest named ancestor directory, then root (VB-8's `rankByGoverningScope`; the byte-length "keyword score" this replaced now only breaks a tie INSIDE one proximity tier — with one narrow exception, wave O3's `crossTierCloser`, ADR-037 addendum: a farther-tier rule that STRONGLY names the file — a hit on its own package path, stem, or a resolved symbol/behaviour token — leapfrogs a nearer-tier rule that is a total lexical blank about the file; any hit on the nearer rule, however weak, keeps proximity's own order) — then, inside that same tier (wave O2, `.fathom/observations.md` O73/O75, ADR-037 addendum), a deterministic lexical **relevance score** (path-derived tokens plus optional resolved symbol/import names — and, wave O3, a small fixed table of behaviour signals scanned from the file's own source: writing output (`os.WriteFile`, `os.MkdirAll`, …) adds `"workspace"`, running the test/build gate or a shell command adds `"gate"`/`"validate"` — weighted stem > package > ancestor > extension, heading hits doubled, no length normalisation) so a nested guide's several same-tier sections are no longer served in mere document order — then rule text (D5 — both payloads in the stopped replicated run led with a stale rule, and a stale rule is demoted below the budget line by this same fresh-first ordering, never served first); the cap is filled by `role:"governs"` layers (`obligations`, `adr-rules`) FIRST and `role:"claims"` layers (`spec-bindings`, `findings`) take only the slots left (D1), with `displaced` still counting both; and a claims-layer rule citing a gated plan row is scoped at serve time by that row's own `{package, symbol}` contract — a row naming no contract binds to nothing (D2, O23: six plan rows about C++, CUE and tree-sitter bound to one Go file by the word "extractor" in their prose and displaced 65 more). Each rule also carries `snippet`, its cited lines inlined and capped at 240 bytes with a named cut (D3, reusing `symbol_context`'s `read_source`-backed snippet path) — pass `include_snippets:false` for the smallest payload; the edit hook always does, so its decision-moment budget is unchanged. **O54 coverage disclosure (the same execute-and-flag doctrine ADR-014 applies elsewhere):** `layer_coverage` rides every response for which the obligations layer has ever been compiled (absent only when no `compile_runs` row exists yet), reporting the LIVE corpus's completeness — `sections_total`/`sections_compiled` are recomputed from the CURRENT corpus (a cheap split, no LLM) every call, never trusted stale off the latest `compile_runs` row, so a doc added after a full compile does not silently read back as "100% covered"; `corpus_grew` (present only when > 0) counts sections the CURRENT corpus has that NO compile run has ever even seen, distinct from a section that compiled once but has since changed (still not-compiled, but not "growth"). `uncompiled_scopes` names the governing-document paths that are either stale or never-seen. The compile order itself is THREE tiers, nearest-scope-first (`internal/semantic`'s `orderSectionsByGoverningScope`): every nested `CLAUDE.md`/`AGENTS.md` guide, then the repo ROOT's own `CLAUDE.md`/`AGENTS.md` (document order within both — never re-sorted by size, so a root Non-negotiables table an author put first is never buried behind smaller sections later in the file), then everything else root-scoped (`ADR.md`, `docs/plans/README.md`, smaller sections first) — so a budget stop always leaves every guide (nested and root) compiled and the root-OTHER tail uncompiled, never the reverse. When the queried `file`'s own nearest guide is among the uncompiled scopes, `note` names it and the resume command instead of silently omitting the rule that governs the file (e.g. `"internal/CLAUDE.md governs this path and was not compiled: budget stopped at 18/60 sections; run `fathom compile --layer obligations --continue`"`) — a NESTED guide wins when one governs the path; when none does, the repo's ROOT guide is the fallback (it governs every file by construction, so its own incompleteness is still worth naming); never fabricated for a root-scope call, a file whose own guide already compiled, or a plain root-OTHER document (`ADR.md` is never "the nearest guide" for anything) — mutually exclusive with the root-scope `note` above. **ADR-037 raw-section fallback:** whenever that same gap exists for a file-scoped call, `obligations` also serves the nearest uncompiled section(s) themselves — up to `RawFallbackReserve` (2), ranked by the identical governing-scope proximity ranker compiled rows use — as real rows tagged `tier:"raw"` with a `why` note naming the coverage defect (`budget_stopped`, `no compile_runs row`, or `uncompiled`), prepended ahead of any farther-tier compiled row; a raw row only ever adds (never displaces a compiled row, never consumes a `max_rules` slot) and never fires once a fresh compiled claim already covers that exact section. A raw row's citation (`src`) narrows to the lines around its own first relevance hit rather than always spanning the whole section (wave O2) — the inlined `snippet` truncates from the citation's first byte at its own 240-byte cap, so an unnarrowed long section previously showed only its opening lines. `fathom compile --layer <layer> --continue` (O54) resumes a budget-stopped compile from the first not-yet-compiled section (the same three-tier order) instead of re-estimating the WHOLE remaining corpus against the same per-run budget — the recorded `compile_runs` row's `resumed_from` names the section, and a `--continue` against an already-complete layer prints a one-line "nothing to resume" instead of refusing or re-spending. Also on the agent/companion surface, and (module-tagged, budget-capped) on the PreToolUse guard hook (docs/design/guarded-edits.md) for scopes named in `.fathom/guard.cue`. |
