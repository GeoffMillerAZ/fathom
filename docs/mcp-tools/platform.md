## Platform tools (GroupPlatform)

Fleet-wide operations across all ingested services.

| Tool | Arguments | Returns | Purpose |
|---|---|---|---|
| `list_services` | — | `{services: [{service, symbol_count, languages, unsupported_languages?}], count}` | List all services in the fleet with detected languages and symbol counts. `unsupported_languages` (O69, present only when non-empty) is `[{language, files}]`: source files whose extension names a KNOWN programming language (e.g. `zig`) fathom has no registered extractor for — disclosure, never inference; see "Unsupported vs. unclassified languages" below. Kotlin closed this gap in wave P2 (O79) — `.kt`/`.kts` now extract via `internal/extractor.NewTSExtractor("kotlin")` and no longer appear here. |
| `list_services` | — | `{services: [{service, symbol_count, languages, path?, unsupported_languages?, typed_edges?, root_missing?, remedy?}], count}` | List all services in the fleet with detected languages and symbol counts, read from each service's `service_summary` row (RT-79): written in the ingest's final transaction, or derived by SQL from the stored rows at first use (on a read-only store, derived without being written) — never a symbol load or a tree walk. A count the store could not read (RT-41, I38), or a summary not yet derived (the ingest slot was busy, or an ingest of the service is in progress or was interrupted — in any process), omits `symbol_count` and carries `symbol_count_error` naming why — never `0`. `path` is the recorded corpus root (absolute), when the backend has one. `unsupported_languages` (O69, present only when non-empty) is `[{language, files}]`: source files whose extension names a KNOWN programming language (e.g. `kotlin`) fathom has no registered extractor for — disclosure, never inference; see "Unsupported vs. unclassified languages" below. `typed_edges` (O82, .fathom/observations.md) is `{packages_seen, packages_processed, edges, failed, error?, fallback?, discovery_gaps?, discovery_gap_files?}` — the SAME per-service typed-edge outcome `ingest`'s own response and `staleness_report`'s `typed_edges` block read; present only when this daemon process has a recorded outcome for the service (never a fabricated clean pass for one it has not touched). `discovery_gaps`/`discovery_gap_files` (diagnostics sweep DG-9, present only when nonzero) name a call target file that EXISTS on disk despite being excluded from the connector's allowed set during the typed pass — a likely wedged `Discover` pass, not a legitimate exclusion — the same fact `staleness_report`'s `typed_edges` block and `doctor`'s `typed_edges` row (WARN, naming the file(s)) read; `discovery_gap_files` lists the excluded files. `root_missing` (diagnostics sweep DG-18, present only when true) names a service whose recorded corpus root no longer exists on disk — reported structurally, never as a live re-walk turning into an error line — with `remedy` naming how to drop the stale record (`fathom fleet` / the `remove_service` MCP tool). `unsupported_languages` comes from the summary row (classified by file name at ingest, or from the fingerprinted paths when derived) and `root_missing` is one stat of the recorded root: nothing is walked to answer a read. |
| `cross_repo_callers` | `symbol` (req) | `{callers: [{service, symbol, file_path}], count}` | Find all callers of a symbol across every service via stored call edges (formerly aliased as `platform_callers`, deleted as zero-call structural redundancy — surfaces week-1, SW-1) |
