### Shared: registry

| Tool | Arguments | Returns | Purpose |
|---|---|---|---|
| `ingest` | `service` (req), `path` (opt, absolute corpus root — required only when onboarding a NEW service), `remap` (opt, bool — authorizes re-pointing an EXISTING service's recorded root at a different `path`), `remap_from` (opt, string — EW-19: the root being replaced; required with `remap` while that root is a live checkout of the same repository as `path`), `indexers` (opt, array of `scip-typescript` \| `scip-python` — SR-65, F-74: after the ingest, import the SCIP index each named producer left at `<root>/.fathom/scip/<name>.scip` as typed edges), `run` (opt, string — EW-66: the run a past-budget answer named; the call only reports that run and queues nothing) | `{service, ok, root?, unclassified_files?, oversize_files?, default_ignored_dirs?, typed_edges?, scip?, quarantine_cleared?, coalesced?}`, or, past the wait budget, `{service, completed:false, state, waited, run, note, coalesced?, follow_up?, paused?}`; with `run`, `{service, run, completed, state: "queued"\|"running"\|"done"\|"unknown", ok?, error?, superseded?, note}` | Re-ingest the named service to refresh the symbol store, or onboard a brand-new service into the index when `path` is given. **`indexers` (SR-65):** the producers are a closed set (any other name is a params error, since the name becomes a file name under the root); `fathom init` runs `scip-typescript` / `scip-python` when that toolchain is on PATH and never installs one, then names it here. The daemon imports each index after the syntax pass, holding tenancy's one ingest slot (RT-160) and declining an index over the admission budget (the tree class's per-call ceiling, 64 MiB with no gate) by name. `scip` is one row per named indexer — `{indexer, path, producer, edges, direct, unresolved, unmapped}` or `{indexer, path, error}` — and an index that cannot be imported never fails the ingest: the syntax index is already written. `root` names the corpus root the service is recorded at after the call (O22). A `path` that is a git worktree of an EXISTING service's recorded root — or any `.claude/worktrees/` path — is refused as a JSON-RPC error naming both paths, never `ok:true` (PC-33, I30); ingest from the main checkout, or register the worktree as its own service. **O82 (.fathom/observations.md):** a `path` that differs from an EXISTING service's recorded root at ALL (a plain `git clone` elsewhere included, not only a linked worktree) is likewise refused unless `remap:true` is passed — a hook must never re-point a service; `remap:true` (or the store-direct `fathom remap` verb) is the deliberate-move escape hatch. **Ingest honesty (O82):** for a Go service, `typed_edges` is `{packages_seen, packages_processed, edges, failed, error?, fallback?}` (`edges` counts the typed edges WRITTEN by that pass: a package whose content hash is unchanged keeps its stored edges and adds none, so `edges: 0` with `packages_processed > 0` means "nothing changed", not "no typed graph") — present whenever this daemon process has a recorded typed-edge outcome for the service (the same fact `staleness_report`'s `typed_edges` block and `list_services`' own per-service `typed_edges` row read); `failed:true` (packages seen but none processed, a package failed to type-check, or the load failed outright) flips the envelope's `ok` to **false** even though the syntax index was written and kept — never a silent `{"ok":true}` over a syntax-only graph, which is exactly what let a 2026-09-16 push refuse downstream with no earlier signal. `fallback` names `"GOWORK=off"` when an ambient Go workspace was discoverable and therefore overridden. The optional file counters are a before/after delta of this call's ingest-event stats (ADR-021 §2), present only when the backend supports them; `oversize_files` counts every file over the 2 MiB read cap this ingest met, changed or not (never read, never indexed). `default_ignored_dirs` names, repo-relative and sorted, each directory the default cache list (RT-145: `.cache`, `target`, `dist`, `build`, …) pruned from this ingest's discovery; re-include one with `[connector] include` in the corpus's own `.fathom/config.toml`. **Quarantine (RT-155):** a service quarantined at the governor's exit mark is lifted only by an explicit call that completes (`quarantine_cleared: true`); a call whose `X-Fathom-Origin` is a hook is refused with the quarantine named, and a failed or halted ingest leaves it. An ingest the ladder halts at refuse fails with `over budget: …` (RT-153), its prior watermark kept. **Live-root guard (O127, EW-19):** `remap:true` alone no longer re-points a service whose recorded root is a LIVE checkout of the same repository as `path` (the root exists, is a git checkout, and shares its root commit with `path`) — a worker's scratch clone once captured the owner's own service that way. The call is refused as a JSON-RPC error naming both paths until it also carries `remap_from` equal to the recorded root; a recorded root that is gone, is no git checkout, or belongs to another repository still needs only `remap:true` (the repair of a deleted root). **Long ingest (O128, EW-18):** the call waits at most 120 s on the queue for its run (`mcp.DefaultIngestWaitBudget`, under the daemon's 150 s per-route write deadline); a run that outlasts it answers `{service, completed:false, state: "queued"|"running", waited, note, …}` — the queue's state, as `POST /refresh-request` reports it, with no `ok` field — instead of an empty body from a dropped connection, and finishes on the queue under the daemon's lifetime (a quarantine it would have lifted is still lifted at that completion; requested `indexers` are not imported — call `ingest` again with them once the run finished). **Completion (EW-66, G4):** that answer names the `run` that serves it (the queued job, or the one follow-up of a running one), and `ingest` called with `{service, run}` reads it from the refresh queue's state and the service's last finished run without queuing anything: `completed:false` with `state` `queued` or `running` while it waits or runs; `completed:true, state: "done"` with `ok` and, for a failed run, `error` once it finished (`superseded: true` when a later run of the service has finished since: `ok` and `error` are then that later run's); `state: "unknown"` for a run this daemon has no record of (it restarted, its interrupted ingest resuming on the next start, or the id is another service's). `run` with `path`, `remap` or `indexers` is a params error. **Refresh queue (RT-97, RT-98):** on `serve-http` the ingest runs on the daemon's refresh queue — one ingest per service, one at a time machine-wide, under the daemon's lifetime (a disconnect never cancels it); a call for a service whose ingest is already running waits for the one follow-up and answers `coalesced: true`, and the counters are that run's. The queue refuses at refuse and in store distress; an explicit call passes safe mode and a quarantine. Also on the agent/companion surface. |
| `remove_service` | `service` (req) | `{service, removed}` | Registry surgery: delete EVERY stored row for a service (duplicate/malformed rows, e.g. a path-like twin). Idempotent — removing an unknown service returns `removed:false`. |
| `rename_service` | `from` (req), `to` (req) | `{from, to, ok}` | Registry surgery: atomically re-key every stored row from one service id to another. Refuses when the source has no rows or the target already exists. Claim ids keep their minted values (historical evidence); new compiles mint fresh ids. |
