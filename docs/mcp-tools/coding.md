## Coding tools (GroupCoding)

Symbol navigation, structural analysis, and impact analysis for active coding tasks.

### Core queries

| Tool | Arguments | Returns | Purpose |
|---|---|---|---|
| `query_symbols` | `service` (req), `concern` (req), `keywords` (opt), `top` (opt, default **10** — cut from 20 by SR-43) | `{summary, nodes: [SymbolNode], staleness, truncated, elided?}` | Concern-scoped symbol search. Returns ranked SymbolNodes. `concern` is mandatory (ADR-006). **SR-43** (F-24, design §5): the answer opens with a one-line `summary` (wave L1 — count for the concern, the top hit's name/kind/location) built from the exact rows `nodes` returns. The `staleness` block is constant-size: `{sources: [≤3 oldest stale], stale_sources, total_sources, fresh_sources, oldest_ingested_at, reingest_recommended}` — the full source list and commit drift live in `staleness_report`. |
| `symbol_context` | `service` (req), `symbol` (req), `snippet` (opt bool, default `true`) | `{def, callers, callees, related_tests, referenced_by?, references?, typed_edges?, snippet?, snippet_truncated?, elision?, resolution: {typed,heuristic}, index_commit?, file?: {path, role, basis?, role_unknown, unread?}} \| {ambiguous?, scope_required?, candidates, count, hint}` | Neighbourhood context: definition, direct callers, direct callees, related test functions. **A file path (RF-4, `docs/plans/repository-facts.md`, no new tool or parameter):** a `symbol` that resolves to no symbol but names a file of the service (one an indexed symbol is declared in, or a regular file under the corpus root that does not escape it) answers `file`: the file's role from the closed vocabulary (source, test, fixture, script, config, ci, build, iac, schema, migration, docs, generated, vendored, unknown), the `basis` that decided it (`attribute`: `.gitattributes` `linguist-*`, root and nested; `header`: Go's generated-code line or the ADR-063 O6 kit provenance header; `dialect`; `linguist`: Linguist's pinned vendor, documentation and generated data; `convention`), `role_unknown` (1 when no rule decided, always printed, I65) and `unread` (a `.gitattributes` on the chain that could not be read, I38); the neighbourhood fields are then empty. Computed on read by `repofacts.Role`, never stored. **Wave lg (LB-F199, LB-F200; ADR-048 amendment 2026-10-02):** `callers`, `callees` and `related_tests` read the served graph (`callgraph.BuildBoth`, as `blast_radius` with `include_heuristic` and verify do; before, the syntax graph alone), so a bare-name guess from a file the Go typed pass compiled (`bytes.Equal` bound to the service's one `Equal`) is gone and a typed dispatch or function-value edge appears; a Go type's consumers (a type written in a declaration, literal or assertion) are references, not calls: `referenced_by` lists them and `references` the types the symbol references, each present only when non-empty, budgeted and counted heuristic in `resolution`. **J3(a)** (app-kit O12): a bare `symbol` matching more than one definition returns `ambiguous:true`; one resolving to a single definition with more than 50 callers (a hub) returns `scope_required:true` instead — either way `candidates` (≤10 `{symbol_key, file, line}`), `count` (the match count, or the real caller count for a hub) and `hint` replace the whole neighbourhood, computed before any caller/callee/cross-service lookup ever runs. **RC-19**: `callers`/`callees` are each budgeted (`fitToolBudget`, half of 16000 chars); a truncated response carries a one-line `elision`: `"elided: N more — refine with find_callers (depth) for every caller"`. `typed_edges` (ADR-021 §3, Go services only) is `{callers: [{key, kind}], callees: [{key, kind}]}` — kind-labeled (`direct` / `iface-dispatch`) typed edges NOT already covered by the plain `callers`/`callees` lists, e.g. an interface-dispatch fan-out invisible to the syntax-only graph. Omitted when the service has no typed edges. `snippet` (T5-6, docs/plans/trust-and-tokenomics.md) is the definition's source, inline, line-numbered, capped at 40 lines — read via the same safe, bounded path as `read_source`, so a define-and-show answer completes in ONE turn; `snippet_truncated:true` marks a snippet that stopped at the cap with more file below it (a 100-line function must never LOOK 40 lines long — most defs carry `end_line` 0, so the flag is the only clipping signal). Pass `snippet:false` to omit the snippet entirely (smaller payload). Additive and honest: omitted (never faked) when the definition has no file/line or its source isn't retrievable (no `ServiceMeta` corpus root, file missing, binary, etc.) — `def`/`callers`/`callees` are unaffected either way. **VB-19** (ADR-035 decision 4, docs/vision/29-verbs-not-lookups.md §3 wave E): `resolution` tallies the typed/heuristic mix behind exactly the returned (post-budget) `callers`+`callees`; `index_commit` names the daemon's watermark for the service when it can name one — see `fathom receipt verify` (VB-20). |
| `outline` | `service` (req), `file` (req) | `{symbols: [SymbolNode], elision?}` | List all symbols defined in a specific file, ordered by line number. **RC-19**: `symbols` is budgeted (`fitToolBudget`, 16000 chars); a truncated file carries a one-line `elision`: `"elided: N more — refine with read_source with start_line/end_line"`. |
| `read_source` | `service` (req), `file` (req, repo-relative), `start_line` (opt), `end_line` (opt), `max_bytes` (opt, default **8000**, ceiling 16000) | `{file, lines: [{line, text}], start_line, end_line, total_lines, clamped_eof, note?, elided?}` | Bounded, read-only raw-text read from the service's INDEXED corpus (T5-4, docs/plans/trust-and-tokenomics.md) — the agent surface's `sed -n` equivalent, line-numbered so results are pinnable as citations. Not the first move after a `find_symbol` hit (already carries file+line) or `symbol_context` (already carries the body) — reach for it only for bytes neither carried. No `start_line`/`end_line`: a capped whole-file view from line 1. Capped at 200 lines / 8000 bytes per call by default (SB-3, docs/plans/strengths-bench.md; O31/O32 — half the old default, since `read_source` was the largest single per-tool payload contributor in the home bench), whichever is hit first; the byte cap bounds the `lines` array as sent — each row's `{line, text}` envelope and JSON escaping count, as `fitToBudget` counts every other budgeted tool's rows (BP-42, docs/plans/bench-pyramid.md: counting raw text let an 8000-byte read reach the model as 11,189 bytes); `max_bytes` raises the byte cap for one call, up to a 16000-byte ceiling; `end_line == total_lines` in the response means EOF was reached; a first line whose row alone does not fit the byte cap (a line longer than the cap, or one a little under it raw once its envelope and escaping count) comes back TRUNCATED (on a rune boundary) so its row fits, with the note set — never whole (minified JS cannot void the cap); the cut itself adds nothing to `elided` (no line was DROPPED, only that one line's content was cut), so a single-line range cut this way carries no `elided` block; a multi-line range the cap stopped short of its natural end carries `elided` (`{count, of, ordering, how_to_get_more}`) naming how many LINES were dropped. **Readable = what ingest walks, enforced:** refuses (RPC error) a `.fathomignore`'d path (the same compiled matcher `Discover` applies, file and ancestor dirs), the always-skipped directories (`vendor`, `.git`, `testdata`, `generated`, `node_modules`, `.idea`, `.vscode`, `.claude`), `.env`-pattern files (unconditional defense in depth — secrets-shaped files are never served even when a repo forgot to ignore them; other dot-paths like `.github/` stay readable since they ARE indexed), a file over the 2MB read ceiling (`os.Stat`-checked before any read; equals the indexer's own extraction cap, so such files aren't in the index either), a binary file (`connector.IsBinary`), an absolute `file`, path traversal, a symlink resolving outside the corpus root (`filepath.EvalSymlinks` containment on both the root and the candidate — a same-corpus symlink target reads fine), and an EXPLICIT range wider than the line cap (narrow it, or make repeated calls — never silently narrowed). An explicit `start_line`/`end_line` landing beyond EOF is clamped, not refused, and noted (`clamped_eof:true`); running past the line/byte cap is separately noted. An empty file reports `total_lines: 0`. The corpus root is resolved from `ServiceMeta` with the same absolute-path discipline as `review_diff`'s project-rule loader (O10/C4 class; SR-27 folded the standalone `arch_conformance` tool into `review_diff`'s in-process check): a service with no recorded root, or a pre-O10 relative one, is refused with a re-ingest pointer rather than resolved against the daemon's ambient CWD. Also on the agent/companion surface. |

### Impact / call-graph analysis

| Tool | Arguments | Returns | Purpose |
|---|---|---|---|
| `localize` | `service` (req), exactly one of `stack_trace`, `failing_test`, `error`, `concern` (checked at call time), `budget` (opt, default 12, max 40) | `{summary, candidates: [{file,symbol,score,tier,why:[string] (≤3 citations),graph_distance?}], candidates_total, elided?, hops: [{n,tool,arg,added}], budget: {allowed,used}, reformulated?, reformulated_terms?, log_template?: {lines,templates,note}, index_commit?}` | ADR-035 decision 1 (wave G, plan VB-26); graph expansion, reformulation and the payload cap are ADR-041 D4 (SU-14): "where does this bug live" as a verb, never a bare list — one bounded, budgeted, LOGGED walk of the index. Seeds from parsed stack frames (file:line, function names), quoted literals (the same grep engine `search` runs), or a concern's own significant terms; an `error` text's lines are first matched against the service's log templates (TL-4, ADR-064: each logger call's template, stored at ingest), and a line a template matches seeds that call (a `log_template` hop citing the template and its call site; the call's enclosing symbol scored above a literal hit, below a trace's throw site) and nothing else, so the line itself is never cited (`log_template` counts the matched lines and seeded templates); when seed extraction finds nothing at all, seeds are reformulated by identifier splitting (camelCase/snake_case), quoted literals and file basenames (`reformulated: true`, `reformulated_terms`, never a model call). Every resolved seed then expands through the typed/heuristic call graph (`expandSeedsByGraph`) to depth 2 — resolved edges first, heuristic only when a seed has no resolved edges of its own — ranked by seed evidence, graph distance (`graph_distance`: 1 or 2; absent/0 means the candidate is itself a seed), resolved-over-heuristic, then convergence (how many distinct seeds' walks reached it); open obligations rank a candidate already found by something else higher still (never a discovery path on its own), and recency is skipped with a note today (no churn analysis is wired in yet). Every hop is logged whether or not it added anything, including the graph-expansion and reformulation hops. `tier` is `typed` when a call-graph or index lookup confirmed a candidate, `heuristic` when only a text match did; `why` cites which hop(s) produced it, capped at 3 citations. `candidates` caps at 25 (`candidates_total` names the full count; `elided` appears when either cap cut the response). Deterministic: identical input against an unchanged index returns byte-identical results. Also on the agent/companion surface. |
