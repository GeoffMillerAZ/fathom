### Shared: context

| Tool | Arguments | Returns | Purpose |
|---|---|---|---|
| `repo_map` | `service` (req), `budget` (opt, default **1,200** tokens — cut by SR-41 from the original 2,500, project → user → built-in via `.fathom/capabilities.cue`'s `budgets.map`) | `{map: string, budget, label: "orientation-only", elided?, elision?, entrypoints?: [SymbolNode], entrypoints_more?}` | Build a budget-bounded symbol map ranked by outbound call-edge count (most-connected symbols first), suitable for LLM context assembly. **SR-41** (F-07, design §5): every answer carries `label: "orientation-only"` — the map is a landing view, not the comprehensive answer; a caller that wants more reaches for `query_symbols`/`pack_context`. **RC-19**: a truncated map carries the existing structured `elided` block (`{count, of, ordering, how_to_get_more}`) alongside a uniform one-line `elision`: `"elided: N more — refine with budget"`. **SR-22** (F-10, design §4): the header carries likely entrypoints — the same detector the retired `entrypoints` tool used (`main` functions, HTTP handlers, CLI root commands) — capped at 10, with `entrypoints_more` naming how many were cut; both fields omitted (never an empty list) when the service has none. Also on the agent/companion surface. |
| `pack_context` | `service` (req), `concern` (req), `budget` (opt, default 4000) | `{included: [{id,text,score}], tokens, dropped, budget}` | Pack ranked evidence items from a concern-scoped query into a token budget, returning the highest-scoring items that fit. **J3(d)** (app-kit O28): `concern` must be an identifier, never a sentence — a value containing whitespace is refused with a params error instead of silently running a futile query and returning an empty pack. Also on the agent/companion surface. |
