# Future directions: F86 to F91

Records of the futures router, `../futures.md` (the confidence and horizon key, and every id with its member).

## F86. Component corpora: per-component audit, plans, guard and review in a monorepo

- Confidence: plausible (ADR-074, 2026-10-17). Horizon: later. Evidence: the intent-practice-v2 monorepo research
  (research `wf_888f8f2d-57b`, review `wf_a6ee03dd-707`): fathom audits and plans only the repository root, so a
  component's own intent is invisible to `fathom intent audit` and `fathom plans`; platform-engineering's ids clash
  across its homes (F1 in 7, G1 in 5).
- Motivation: a monorepo whose components each carry their own intent gets the same audit, plan progress, generated
  guard entries and review per component that a single-scope repository gets at its root, with cross-scope citations in
  the kit's `<scope> <id>` form.
- Do not build: discovery of nested routers (a vendored kit's router would be read as a component).
- Preserve: components come only from the map rows of the monorepo's root repo.md (the kit's monorepo charter), never
  discovered; fathom's own repository stays single-scope.
- Promote when: the owner asks fathom to audit or plan a monorepo component, or a second monorepo adopter appears.
- Drop if: platform-engineering consolidates to one intent scope.

## F87. A dedupe view: a repeated result served as a pointer to the earlier one (readouts seam H7)

- Confidence: speculative (RO-M19, 2026-10-18). Horizon: later. Evidence: `docs/bench/readings/readouts/seam-dedupe-sizing.md`.
  Over 30 days, exact repeats of Bash and Read results and Read spans inside an earlier span of an unchanged file,
  since the last compaction, were 0.40% of Bash and Read bytes, against the 1% bar. RO-M0 had already read CUT on
  the lossy track.
- Motivation: an agent shown a result it already holds could be shown a pointer instead, if repeats ever become a
  real share of what agents read.
- Do not build: RO-47 (`dedupeView`) or the view channel it rides (RO-20, RO-M2) on this evidence.
- Promote when: a later `fathom readout replay` (its `dedupe` section) reads repeats at 1% or more of Bash and Read bytes over 30 days. The
  first step is then RO-M19's unrecorded half: one captured PostToolBatch input, showing what it carries and whether
  its output can replace a result.
- Drop if: Claude Code drops repeated results from context itself.

## F88. Collision-free append points

- Confidence: plausible (owner-architect decision, 2026-10-19). Horizon: later. Evidence: F82's Evidence 2026-10-19
  line. This repository's parallel waves collide at merge time on shared append points, never as live edits.
- Motivation: the cheaper fix for merge-time collisions is shared append points that parallel lines cannot conflict
  on: change-note fragments rolled at release (`.fathom/observations/` already works this way, one file per entry),
  per-dialect registration instead of one shared dispatch switch, generated boards regenerated rather than merged, and
  ids that need no shared counter. Prior art: towncrier, changesets.
- Placement: an agentic-kit practice first (`third_party/agentic-kit/docs/project-intent/changes.md`), fathom adopting
  it.
- Do not build: a lock or a reservation (F82 rejects them for now).
- Decision models: none applies (a deterministic file layout).
- Promote when: the F82 replay classes at least 4 append-point conflicts a month.
- Drop if: it classes fewer than 1 a month.

## F89. Responsibility clusters: split candidates for files agents keep growing

- Confidence: plausible (owner-architect decision on the owner's "concern density" idea, 2026-10-19). Horizon: later.
  Evidence: "concern" already has three meanings in fathom: the `Engine.Query` scope (ADR-006, I5), the custodian's
  config wants, and the evidence plane's concern facts (ADR-069). This record never adds a fourth.
- Motivation: per file, the connected components of its symbols over call edges and shared types (LCOM4 adapted to
  files), with size from L1 ranges, fan-out from `file_imports` and churn from `file_churn`. A split candidate is a
  churning, large file with at least 3 clusters (the hotspot-times-cohesion idea). Computed at request time from
  existing tables (ADR-051's join rule, so the table freeze holds), Go first (typed edges), and shown where a decision
  happens: `review_diff` when a diff adds a new cluster to a split candidate, and the console hotspots view (U13).
- Do not build: a new MCP tool (SR-19: the retired `god_object` and `complexity` tools had 0 lifetime calls; ADR-053's
  tool freeze); a grade (ADR-044); a per-person view (files, not people: the non-goals).
- Decision models: naming a cluster's responsibility is a decision-port Choice site. Provider `none` shows no label
  (the deterministic fallback); measured by label acceptance; opt-out per repository.
- Promote when: a precision reading on this repository and one other judges at least 70% of the top 20 split
  candidates real.
- Drop if: under 40% are real, or a shown line is switched off within 2 weeks.

## F90. Duplicate at birth: a new symbol that already exists

- Confidence: plausible (owner-architect decision on the owner's DRY idea, 2026-10-19). Horizon: later. Evidence: the
  agent-era DRY failure is agents re-implementing helpers they did not find.
- Motivation: when a new symbol lands (the post-edit hook inside I35's budget, or `review_diff`), compare it with
  existing symbols in the service and the fleet on keys the index already stores: signature shape, callee multiset and
  L1 size band. Deterministic candidates first.
- Do not build: a body fingerprint before RT-M1 reads PASS (it needs a new column). Rejected for now: a repo-wide clone
  audit, a commodity (dupl ships in golangci-lint; PMD CPD; jscpd) whose backlog of old clones is noise. Wins if: an
  adopter asks for a cross-repo clone report. Rejected: a general best-practice linter; per-language linters own it,
  and fathom's lane is cross-file and cross-repo evidence (deadcode, archconformance, risk). Wins if: never.
- Decision models: the decision port (ADR-073) is an optional "same concept?" Choice over the deterministic
  candidates (F23's same-concept question). Provider `none` shows the deterministic candidates only. A/B'd against the deterministic baseline and
  removed if it reads null (earlier port sites read null or negative).
- Promote when: a replay of 30 days of agent-written symbols here finds at least 2 true duplicates a month at 60%
  precision or better.
- Drop if: it finds fewer than 1 a month.
