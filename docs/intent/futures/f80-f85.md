# Future directions: F80 to F85

Records of the futures router, `../futures.md` (the confidence and horizon key, and every id with its member).

## F80. Template promotion: a free-form `ask` question that recurs becomes a committed template

- Confidence: speculative (DMP-20, rated Low, 2026-10-16, `docs/design/decision-models.md` section 5). Horizon:
  later. Evidence: none yet; `fathom ask` is not built (`docs/plans/agentic-decisions.md` AQ-2).
- Motivation: a free-form question agents ask again and again is a template nobody wrote; a committed template can be
  calibrated and earn a band, a free-form answer never can (I62).
- Do not build: a model that writes or promotes a template; a counter, table or background job before RT-M1 (R5); a
  promotion without a human commit.
- Preserve: `ask` never stores a question's text; a recurrence count, if one is ever kept, comes from a hash of the
  spec's shape in an existing log.
- Promote when: 30 days of `fathom ask` use show one free-form question shape asked in at least 5 sessions.
- Drop if: EXP-M5 reads CUT, or the verb is removed.

## F81. Evidence timing: when the mods show a fact

- Confidence: speculative (DMP-21, rated Low, 2026-10-16, `docs/design/decision-models.md` section 5). Horizon:
  later. Evidence: none; the mods refresh on turn completion and after edits (ADR-072).
- Motivation: a fact shown after the agent already acted, or long before it matters, is noise; a typed `choice` of
  when to show it (now, at turn end, at the next edit of that file) might time the band and the proof line better
  than fixed refresh points.
- Do not build: a timer, monitor or pushed event (the dispatch-loop non-goal); a model call on a display path before
  RT-M1 reads PASS and an events source exists.
- Preserve: the mods' refresh points stay one list in the render's registrations, so a timing rule would replace one
  list.
- Promote when: RT-M1 reads PASS, an events source exists, and MOD-M4 or MOD-M5 records a fact acted on late in at
  least 20% of its cases.
- Drop if: MOD-M4 and MOD-M5 read KEEP with the fixed refresh points.

## F82. Line overlap: two live lines of work that change the same file or the same symbol's callers

- Confidence: plausible (owner brainstorm 2026-10-17, `docs/assessments/2026-10-17-machine-situation.md`). Horizon:
  later. Evidence: parallel agents in worktrees collide today, and nothing tells them. This repository's own waves
  pre-assign record ids because parallel writers took the same ADR, F, I and O numbers. Integrators resolve CHANGELOG
  merge markers (904d3c6d). A sibling project commits to this tree (autonomy.md). Claude Code's Remote Control docs
  warn that same-directory sessions "can conflict if editing the same files". herdr, Conductor, claude-squad and
  container-use show which worktree an agent is in, but none says that two lines touch the same code.
- Motivation: worklines (`internal/worklines`) already classes every unlanded line (branch, linked worktree, stash)
  against the integration branch, and `blast_radius` already maps a diff to the symbols it reaches. Checking each pair
  of live lines for shared files, shared changed symbols and intersecting blast radii forecasts a semantic conflict
  before the merge, from git and the index alone. Only a code index can see "line A changes `Open`, line B adds a
  caller of `Open`".
- Do not build: a lock, a reservation or a claim on a file; a watcher, poll or pushed event (the dispatch-loop
  non-goal); a new table, cache or background job before RT-M1 reads PASS; a session registry. A session's identity
  (the hook's `session_id`, herdr's pane) is a label on a line, never the key. herdr's state is read, if ever, only by
  a hook running inside a herdr pane, never by the daemon. Rejected for now (owner-architect, 2026-10-19): file locks.
  Parallel workers here run in isolated clones, so collisions happen at merge time on shared append points, never as
  live concurrent edits; a lock serializes parallel work, TTL claims go stale, a multi-machine lock needs a server (a
  non-goal), and mcp_agent_mail already offers advisory file reservations to anyone who wants them. Wins if: the replay
  below finds live same-file concurrent edits at least 4 times a month.
- Evidence 2026-10-19: this repository's waves conflicted at merge on `CHANGELOG.md`, `docs/languages.md`, the shared
  dispatch in `internal/extractor/gomoddialect.go`, `ExtractorEpoch`, observation ids and plan boxes, and four BSD-sed
  backup files were committed while resolving them (three of `CHANGELOG.md`, one of `docs/plans/readouts.md`; removed
  by e73a46a9, 32194547, 3bfcc94b and e98ce79e). The cheaper fix for that class is F88. The replay's reading:
  `docs/bench/readings/readouts/f82-overlap-replay-2026-10-19.md`.
- Preserve: worklines stays a pure read of git, so a pairwise overlap is a function of two of its lines plus the
  index. A line's diff stays computable against its merge-base without a checkout.
- Promote when: a zero-cost replay of 30 days of local transcripts and worktrees finds at least 4 true overlaps a
  month (two lines that changed the same symbol or its callers, confirmed by a merge conflict or a red integration).
  The replay is the same method as the 2026-10-16 tool-bytes reading.
- Drop if: the replay finds fewer than 1 a month, or a shown overlap line is switched off within 2 weeks of use.

## F83. Declared resources: the ports, databases, sockets and directories a repository's code says it binds

- Confidence: plausible (owner brainstorm 2026-10-17, `docs/assessments/2026-10-17-machine-situation.md`). Horizon:
  later. Evidence: several projects on one machine collide on ports, and parallel worktrees all default to the same
  dev-server port (wtdev's README states the problem; portless, vercel-labs, 12.7k stars, allocates around it). The
  TL- rows already read telemetry identities that code declares (`docs/plans/language-breadth.md` TL-5, TL-9).
- Motivation: a collision starts as a declaration: a `PORT` default, a compose `ports:` line, a package script's
  `--port`, a literal in a listener, a database name or a socket path. Read as facts across the fleet they give three
  answers no allocator gives:
  - which indexed repositories or worktrees declare the same resource;
  - a repository's runtime contract (what it needs running), served at edit time through `obligations`, which gives
    the layer its consumer;
  - runtime impact in `review_diff` and `blast_radius`: this diff changes a port or an env key that another repository
    reads.
- Do not build: a port allocator or naming proxy (delegate to portless); a new MCP tool (the tool-growth non-goal); a
  live scan of the machine. This future is static facts only.
- Under portless (0.15.8, adopted by the owner 2026-10-17): portless injects `PORT` into each dev server it starts, so
  the port half of this future loses value, because the collision a `PORT` default or `--port` literal would cause no
  longer happens for a server portless launches. The non-port declarations (databases, sockets, debug ports, home
  directories) keep their value, since portless does not allocate them.
- Preserve: config extractors emit literal values with their key path and file:line, so a `binds` fact is an
  additive kind, not a reparse.
- Promote when: a hand-labelled reading of 30 declarations across the owner's fleet reads precision of at least 0.8,
  and the fleet holds at least 5 true cross-repository collisions. The reading counts port declarations and
  non-port declarations (databases, sockets, debug ports, home directories) separately, and the 5 collisions must
  include non-port ones: a fleet whose only collisions are ports portless already resolves does not promote it.
- Drop if: either bar fails, or portless (or a successor) becomes the norm and leaves no declared collision to find.

## F84. Listener provenance: which checkout and commit a running local server was started from

- Confidence: plausible (owner brainstorm 2026-10-17, `docs/assessments/2026-10-17-machine-situation.md`). Horizon:
  later. Evidence: an agent that verifies against a server on :3000 started from another worktree, or from a stale
  build, reads the wrong code as passing. `cmd/fathom/portholder.go` already names the holder of fathom's own port, and
  `checkDaemonFresh` (`cmd/fathom/doctor_provenance.go`) checks that the daemon serves HEAD. No tool joins a listening
  pid, its working directory, the checkout and the commit (prior-art sweep, 2026-10-17).
- Motivation: one read-only answer on request: ":3000 is served by pid P from worktree X at commit Y (dirty), not this
  checkout at Z". It extends the port-holder join beyond fathom's own port. This is staleness honesty (I38) applied to
  a running process.
- Do not build: a watcher or monitor; killing, restarting or reaping any process (P23 meters fathom's own footprint
  only); a new tool. The answer is informational tier, never attested.
- Preserve: the port-holder code keeps the pid-to-cwd join behind one function, so a second caller reuses it.
- Under portless (0.15.8, adopted by the owner 2026-10-17): the join reads `portless list` first (route to worktree,
  name and port) before any `lsof`, and delegates named routes to portless; only a listener portless does not know
  falls through to the pid-to-cwd join. `portless prune` owns orphaned dev servers, so the non-goal note stands:
  fathom reports provenance and never reaps.
- Promote when: F76 (witnessed runs) is promoted, and the owner's sessions show at least one wrong-checkout
  verification a month (a replay of transcripts that curl or test a local port).
- Drop if: F76 is dropped, or the replay finds none in 60 days.

## F85. The host cause behind an operational verdict

- Confidence: plausible (owner brainstorm 2026-10-17, `docs/assessments/2026-10-17-machine-situation.md`). Horizon:
  next. Evidence: the maintainer's hand-built bash guards against causes no doctor row names:
  - a wedged macOS file-access verdict on an external volume, where stat works and read fails with EPERM (the owner's
    global notes; `tcc-keeper.sh`);
  - the internal-disk floor under swap (`push-internal-disk.sh`, INC-23);
  - a held gate lease (`scripts/gate-lease.sh`);
  - an orphaned language server holding gigabytes.

  `checkHostPressure` (`cmd/fathom/doctor_tenancy.go`) already reads pressure, swap and swap-volume free.
- Motivation: when `fathom verify` exits 2, a gate dies or doctor fails, the verdict names the host cause it can
  observe (a stat and read split on the repository's volume, the disk floor, the lease holder and its queue, memory
  pressure) instead of a bare failure. This is P23's "stays visible when it cannot answer" and I38, read-only.
- Do not build: a keeper loop that re-runs the TCC reset, a reaper or any action on the host; a check that reads
  outside fathom's own repository, store and volume.
- Preserve: operational exits carry a reason class, so a host cause is a new class, not a new exit code.
- Promote when: the RT-M1 reading is in (2026-10-19) and the tenancy program's next wave is scoped. It then becomes
  responsible-tenant rows.
- Drop if: a 30-day reading of exit-2 and gate failures finds no host cause among them.
