# Future directions: F74 to F79

Records of the futures router, `../futures.md` (the confidence and horizon key, and every id with its member).

## F74. Environment daemon: a read-only fathom serving one lineup

- Confidence: likely (owner direction, 2026-10-11). Horizon: later. Evidence: ADR-069 decisions 7, 9 and 14;
  `docs/design/index-snapshots.md`; `docs/assessments/2026-10-11-index-snapshots.md`.
- Motivation: the CD gate's prod side and a live incident need answers about what an environment runs, not about
  main. A long-running `serve-http --read-only --lineup <env>.lineup.cue` (deployed as `fathom-<env>`) holds the
  index snapshot of every service the lineup names at its deployed commit, with each service's platform
  dependencies at theirs; a lineup change replaces the daemon with one on the new lineup (a rolling update).
- Do not build: a service fathom operates; any write path on the daemon (it writes only its own composed store, at
  start); a multi-tenant daemon; auth inside fathom or a non-loopback bind; query-time RPC between daemons before
  one of F3's amended triggers fires; a stored deploy record; a fetch; a control channel or a reload endpoint; a
  fathom-run deployment, a fathom-maintained cloud account, or any cloud SDK in fathom core.
- Preserve: index snapshots are immutable files; the answer basis; I56; the lineup is the operator's file; one
  daemon per lineup; the decision port at provider `none` on the daemon.
- Deployment recipes: the Kubernetes recipe first, on the operator's existing platform, in a shared-services
  cluster other than the one the daemon investigates. AWS Lambda (A1, index snapshots copied to local disk at init;
  A2, a precomposed lineup store baked into an arm64 image with SnapStart; a Function URL with IAM auth) is a
  measured option. Promote it when IXS-M8 passes against the Function URL path, the owner-architect accepts IAM at
  the Function URL as meeting the proxy contract, and an incident question's cold-start p95 is under 5 s over 20
  trials. Drop it if that p95 stays above 15 s with pre-warm, the composed lineup passes the 10 GB image limit, or no
  session recorded with a law 6 stamp file uses it within 60 days.
- Promote when: the owner answers U1 yes (a self-hosted, single-organization, read-only environment daemon), the
  read-only hostile sweep passes (IXS-M3 KEEP), `import snapshot` (IXS-7) is built, one named service has an
  on-call owner who will use it, and the owner rules a lineup change is not attach (ADR-069 decision 7).
- Drop if: no gate or incident session recorded with a law 6 stamp file within 60 days of its first deploy
  (IXS-M9); then the lineup mode and the environment-daemon recipe are deleted with a `gone:` row (the SR-17
  precedent).


## F75. Shell-read interception: a hint beside code-discovery shell commands

- Confidence: plausible (owner direction, 2026-10-16: record the idea only). Horizon: later. This is the shape the
  `No grep-blocking` non-goal (`../scope/non-goals.md`) already allows once its revisit condition fires, with
  `docs/design/production-tokenomics.md` §4 (instrument B, the discovery-share denominator, `cmd/fathom/discovery.go`)
  as its measurement and §5 (the A/B) as its causal proof. It adds no new mechanism; it records the evidence and the gap.
- Evidence (2026-10-16): 14 days of this repository's local agent transcripts: tool results 95 MB, Bash 92%; code
  read or searched through the shell (`sed -n`, `grep`, `cat`, `head`, `awk`, `git grep`) about 44% of Bash bytes
  over about 13.6k calls, against 0.6 MB over 350 calls through fathom's MCP tools (a throwaway script, not
  committed). `rtk discover --all --since 30` (every project on the owner's machine, 4755 sessions, 351,726 Bash
  commands) estimates 41.9M tokens saveable, 62% from code-reading shapes (`grep -n` 15.4M, `cat -n` 10.0M).
- Gap: instrument B counts `grep`/`rg`/`find`/`ag`/`ack` and the Read tool, but not shell reads (`sed -n`, `cat`,
  `head`, `tail`), the largest share above; and nothing yet classifies a counted grep as index-answerable, so the
  non-goal's 30% condition cannot be computed.
- Motivation: rtk (rtk-ai/rtk) compresses shell output lexically; for code-shaped commands fathom can answer the
  question behind the command (a definition, a capped caller list, a symbol's own lines) with a receipt.
- Do not build: generic command-output filters, a filter engine, an API proxy or a per-agent install matrix (rtk
  owns them; ADR-063); a block, a rewrite, or replaced output (the non-goal; I38); a hint on an unindexed or stale
  service that reads as fresh.
- Preserve: the observer stays counting-only until the condition fires; hooks fail open inside their ceilings; the
  hint names its source; rtk and fathom compose.
- Promote when: instrument B, extended to shell reads and to an index-answerable classification of each counted
  grep, shows the non-goal's condition (≥30% of greps in indexed repos index-answerable), and the §5 A/B (model
  spend: the owner's budget) shows the hint lowers tokens per task without lowering task success.
- Drop if: the classification reads under 10%, or the A/B shows no token saving or any loss of task success.
