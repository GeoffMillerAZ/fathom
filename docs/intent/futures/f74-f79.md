# Future directions: F74 to F79

Records of the futures router, `../futures.md` (the confidence and horizon key, and every id with its member).

## F74. Environment daemon: a read-only fathom serving one lineup

- Confidence: likely (owner direction, 2026-10-11). Horizon: later. Evidence: ADR-069 decisions 7, 9 and 14;
  `docs/design/index-snapshots.md`; `docs/assessments/2026-10-11-index-snapshots.md`.
- Motivation: the CD gate's prod side and a live incident need answers about what an environment runs, not about
  main. A long-running `serve-http --read-only --lineup <env>.lineup.cue` (deployed as `fathom-<env>`) holds the
  index snapshot of every service the lineup names at its deployed commit, with each service's platform
  dependencies at theirs; a lineup change replaces the daemon with one on the new lineup (a rolling update).
- Do not build: a service fathom operates; any write path on the daemon (it writes only its own composed store, at
  start); a multi-tenant daemon; auth inside fathom or a non-loopback bind; query-time RPC between daemons before
  one of F3's amended triggers fires; a stored deploy record; a fetch; a control channel or a reload endpoint; a
  fathom-run deployment, a fathom-maintained cloud account, or any cloud SDK in fathom core.
- Preserve: index snapshots are immutable files; the answer basis; I56; the lineup is the operator's file; one
  daemon per lineup; the decision port at provider `none` on the daemon.
- Deployment recipes: the Kubernetes recipe first, on the operator's existing platform, in a shared-services
  cluster other than the one the daemon investigates. AWS Lambda (A1, index snapshots copied to local disk at init;
  A2, a precomposed lineup store baked into an arm64 image with SnapStart; a Function URL with IAM auth) is a
  measured option. Promote it when IXS-M8 passes against the Function URL path, the owner-architect accepts IAM at
  the Function URL as meeting the proxy contract, and an incident question's cold-start p95 is under 5 s over 20
  trials. Drop it if that p95 stays above 15 s with pre-warm, the composed lineup passes the 10 GB image limit, or no
  session recorded with a law 6 stamp file uses it within 60 days.
- Promote when: the owner answers U1 yes (a self-hosted, single-organization, read-only environment daemon), the
  read-only hostile sweep passes (IXS-M3 KEEP), `import snapshot` (IXS-7) is built, one named service has an
  on-call owner who will use it, and the owner rules a lineup change is not attach (ADR-069 decision 7).
- Drop if: no gate or incident session recorded with a law 6 stamp file within 60 days of its first deploy
  (IXS-M9); then the lineup mode and the environment-daemon recipe are deleted with a `gone:` row (the SR-17
  precedent).


## F75. Shell-read hints: an index answer beside code-discovery shell commands

- Confidence: plausible (owner direction, 2026-10-16: record the idea only). Horizon: later. **Promoted in part
  2026-10-16 (ADR-071):** the view of a command's output became readouts (`docs/plans/readouts.md`, RO-), and
  counting shell reads in instrument B became RO-29. What stays future here is the index hint itself. This is the
  shape the `No grep-blocking` non-goal (`../scope/non-goals.md`) already allows once its revisit condition fires,
  with `docs/design/production-tokenomics.md` §4 (instrument B, the discovery-share denominator,
  `cmd/fathom/discovery.go`) as its measurement and §5 (the A/B) as its causal proof.
- Evidence (2026-10-16): 14 days of this repository's local agent transcripts: tool results 95 MB, Bash 92%; code
  read or searched through the shell (`sed -n`, `grep`, `cat`, `head`, `awk`, `git grep`) about 44% of Bash bytes
  over about 13.6k calls, against 0.6 MB over 350 calls through fathom's MCP tools (a throwaway script, not
  committed). Over 30 days of every project on the owner's machine, deduplicated by tool-use id, bare-identifier
  greps were 13.5% of 29,643 greps, an upper bound on the index-answerable share (`docs/design/readouts.md` §1).
  `rtk discover --all --since 30` estimates 41.9M tokens saveable from a static per-rule percentage over 351,726
  calls that include session copies: an estimate, not a saving (P12).
- Gap: instrument B counts `grep`/`rg`/`find`/`ag`/`ack` and the Read tool, but not shell reads (`sed -n`, `cat`,
  `head`, `tail`), the largest share above (RO-29 closes this); and nothing yet classifies a counted grep as
  index-answerable, so the non-goal's 30% condition cannot be computed.
- Motivation: for a code-shaped command fathom can answer the question behind it (a definition, a capped caller
  list, a symbol's own lines) with a receipt, beside the command's own output.
- Do not build: a block, a rewrite, or a hint in place of the hits (the non-goal; I38); a hint on an unindexed or
  stale service that reads as fresh; a daemon call on the hook path before EW-76 (`docs/plans/efficiency-wave.md`).
- Preserve: the observer stays counting-only until the condition fires; hooks fail open inside their ceilings; the
  hint names its source; readouts' contract (ADR-071 decision 3); fathom never reads, writes or ships rtk
  configuration (owner, 2026-10-16).
- Promote when: instrument B, extended to shell reads (RO-29) and to an index-answerable classification of each
  counted grep, shows the non-goal's condition (≥30% of greps in indexed repos index-answerable), and the §5 A/B
  (model spend: the owner's budget) shows the hint lowers tokens per task without lowering task success.
- Drop if: the classification reads under 10%, or the A/B shows no token saving or any loss of task success.
- Note (2026-10-16, ADR-072, Q5): the Claude Code mods program's read-routing hint (M10) is this future; it ships
  only as the recorded firing of the non-goal's condition, and `docs/plans/claude-code-mods.md` has no row for it.

## F76. Witnessed runs: an observed test or build result shown beside attested runs

- Confidence: plausible (ADR-071, 2026-10-16). Horizon: later. Evidence: the readout hook parses a declared test
  command's output (`internal/testrun` tier 0) and the test-run hook already logs a three-way result per run with no
  output text (`cmd/fathom/testrunhook.go`); `runtime_pass` reads only attested runs (I8, ADR-067), and a piped
  output is not an attested run (I43).
- Motivation: most test runs an agent makes carry no envelope. A witnessed run (the command, the commit pin, tree
  cleanliness, the result; never output text) could read "last witnessed: pass at a1b2c3d, 12 minutes ago" beside
  an attested result, informationally.
- Do not build: a witnessed run that proves, certifies or gates anything (ADR-043 decision 5: only attested runs
  do); fathom running a test; a store table before RT-M1 reads PASS.
- Preserve: an attested run outranks a witnessed one in every render; I8; I43.
- Promote when: RT-M1 reads PASS, a decision record amends ADR-043 and ADR-067 to name a witnessed provenance, and a
  plan row or a review consumer asks for it in writing.
- Drop if: over 30 days a witnessed result disagrees with an attested run at the same commit more than once in 50.

## F77. A session map from readouts: reads and greps become exploration-map anchors

- Confidence: plausible (ADR-071, 2026-10-16). Horizon: later. Evidence: a map entry is an anchor plus a `why`, of
  kind ephemeral or composite (`internal/explmap/model.go`), stored in existing thread fields and arriving by hook
  (`cmd/fathom/maphooks.go`, `docs/design/exploration-maps.md`); readouts classify every shell read and grep and
  extract `read_span` and `match` records (`docs/design/readouts.md` §7).
- Motivation: a sub-agent's reads become a map its parent or the next worker uses without re-reading the same spans.
- Do not build: a new table; a map that carries a command (ADR-071 decision 7); arrival in a session that did not
  opt in.
- Preserve: maps stay anchor maps; the session's map stays ephemeral unless composed by the user.
- Promote when: G30 (exploration maps cut sub-agent tokens without losing accuracy) reads KEEP.
- Drop if: G30 reads CUT.

## F78. Readouts as a Claude Code mod: the same engine behind `tool.call`

- Confidence: likely (owner sequence, 2026-10-16: the Claude Code mods program follows readouts). Horizon: next.
  Evidence: a mod's `tool.call` may return a replacement result validated against the tool's output schema, with a
  10 s budget per hook (Claude Code 2.1.301's plugin typings; unverified beyond them); one in-process vehicle saves a
  process start per Bash call, about 4,860 calls a day on the owner's machine (`docs/design/readouts.md` §19).
- Do not build: a second engine or rule format; anything that runs the command for the harness; a rule language in
  the mod's own language.
- Preserve: ADR-071's contract; the engine stays a pure function either vehicle calls; one rewriter per command.
- Note (2026-10-16, ADR-072): the mods program settles the `No Node toolchain` reading (one dependency-free TypeScript
  module, the non-goal's carve-out) and names this vehicle as the deferred row MOD-X5
  (`docs/plans/claude-code-mods.md`), because a result replacement is outside ADR-072's display-only decision and
  its allowlist; the future stays open.
- Promote when: RO-M2 reads PASS, RO-M1 reads the readout hook's added p95 at 30 ms or more, and a decision record
  amends ADR-072 decisions 1 and 4 for this vehicle (MOD-X5's trigger).
- Drop if: the mods program declines a readout vehicle, or RO-M1 reads the hook's added p95 under 30 ms.

## F79. Pinned docs beside a docs fetch: a fetch of a pinned package's docs pointed at its local pinned docs

- Confidence: speculative (seam H13, rated Low, 2026-10-16, `docs/design/readouts.md` §20). Horizon: later.
  Evidence: fathom's `search` with `kind: docs` and a `pkg: <eco>/<name>@<ver>` serves that pinned version's docs
  from the local cache and never fetches; a repository's manifests pin the version; no reading has counted agents'
  WebFetch calls to the docs of packages a repository pins.
- Motivation: an agent that fetches a library's current docs may read a version the repository does not pin. One
  line on PreToolUse(WebFetch) naming the pinned version and the local docs query could save the fetch or a
  version mismatch.
- Do not build: a block or a rewrite of the fetch; a fetch by fathom (I56); a docs registry or a download; a line for
  a package with no local docs cache entry.
- Preserve: the fetch runs as the agent asked; the line names its source and the pinned version.
- Promote when: a $0 reading over 30 days of local transcripts finds WebFetch calls to the docs of a package the
  repository pins, with a local docs cache entry, in at least 5% of sessions in indexed repositories.
- Drop if: that reading finds them in under 1% of sessions, or a docs server the user already runs answers pinned
  versions in the sessions that fetch.
