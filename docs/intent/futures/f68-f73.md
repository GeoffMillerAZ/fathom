# Future directions: F68 to F73

Records of the futures router, `../futures.md` (the confidence and horizon key, and every id with its member).

## F68. Reference maps: researched implementations linked to this project's specifications

- Confidence: plausible. Horizon: later. Evidence: owner note N6 (2026-10-10), ADR-067 decision 9, vision 42 D9,
  the hand-built README in the gitignored `ref/` directory, the calibration corpus shard schema (url, ref, sha,
  licence), ADR-056 (exploration maps), KR-6 and KR-7 (doc-to-code links with drift).
- Motivation: research into how another project solved a problem (a parser, a protocol, an algorithm) is paid for
  once and lost when its session ends. A map of kind `reference` anchors into a service ingested from a clone,
  pinned at its commit, carrying its licence and the spec IDs it bears on, so the next session that touches the spec
  finds the reference instead of searching again. The calibration corpus is the first candidate: pinned, licensed
  implementations the language program already researches wave after wave.
- Do not build: anything before the baseline below, a reference verb or tool, a `git:` contract key, any fetch or
  clone by fathom (I56), any gate on a reference link (advisory only), or a copy of non-OSI or copyleft code into
  the tree (the licence is served with every anchor, and such a source is marked "read, do not copy").
- Preserve: a map entry keeps its service for both anchor forms. Today a span anchor's `Entry.Path` is
  repository-relative with no service (`internal/explmap/model.go`), and a symbol anchor's dedup key passes through
  `NormalizeSymbol`, which drops `svc::` (`internal/explmap/anchor.go:92`), so a fork's identical code would collide
  on dedup and re-resolve into the wrong service. Also preserved: the corpus shard schema's licence field and
  ADR-050's additive key kinds.
- Promote when: a $0 transcript scan (the `git clone` and `gh repo clone` commands and WebFetch calls to
  `github.com` URLs in session transcripts, grouped by upstream repository, since `session-ledger.jsonl` carries no
  URL or clone field) shows one upstream researched in at least 3 sessions within 30 days, across at least 2
  repositories, or the owner names a consumer.
  Baseline read 2026-10-11 (XM-M10, `docs/bench/readings/exploration-maps/f68-baseline.md`): NOT MET, no upstream
  in 3 sessions across 2 repositories; the next read is on a window with a second repository of real agent traffic.
- Drop if: the baseline is not met by 2027-01-31, or, once built, no session reads a reference anchor within 60 days.

## F69. Judged sites offered by default at onboarding, or on whenever a provider is configured

- Confidence: speculative. Horizon: later. Evidence: owner note N9 (2026-10-10), ADR-067 decision 14, ADR-056 R2
  and JF-4 (every judged site opt-in per repository), the spend hold of 2026-09-29.
- Motivation: when a judged site is calibrated and cheap, asking each repository to opt in one site at a time
  leaves value unused. Two steps are possible: pre-selecting the site in the priced section of `fathom init
  --dry-run` (RH-13, one consent per repository), and, further, turning it on whenever a provider is configured.
- Do not build: either step before a site clears the last rung: J0 PASS, a calibration Wilson lower bound at least
  0.90 for its use (ADR-056 R3), a measured cost at most $0.25 per 10,000 files on three subjects, the estimator
  within 2 times of actual on three consecutive runs, a positive consumer A/B, F7 if the output is stored, and the
  spend hold lifted. Never anything with provider none (I42).
- Preserve: JF-4's per-site opt-in list stays the only switch, so pre-selection is a default in the dry run's priced
  section, not a second switch.
- Promote when: two sites have cleared the last rung (pre-selection), and an ADR amending JF-4 and ADR-056 R2 is
  accepted (on whenever a provider is configured).
- Drop if: J0 reads FAIL, or no site clears calibration within 365 days of J0 reading PASS.

## F70. Ref overlays: a branch or pull request read as an overlay over its merge-base index snapshot

- Confidence: plausible. Horizon: later. Evidence: ADR-069 decision 12; the `--cache-from` path
  (`docs/design/index-snapshots.md`); Meta Glean's stacked databases.
- Motivation: a `--cache-from` ingest of a ref copies its merge-base's index snapshot and re-hashes every file. An
  overlay holds only changed files, touched packages and tombstones, keyed (service, ref, merge-base), and reads
  union it over the base.
- Do not build: before IXS-M5; an index of every branch; a published local-branch or uncommitted overlay; a
  merge-ahead notifier in fathom (a CI bot intersecting `blast_radius` across open PRs, gated on IXS-M6).
- Preserve: store format v0 additive; I30; per-package typed-edge replacement; the answer basis.
- Promote when: IXS-M5 reads KEEP (on 20 PRs at least 10% of tool answers for changed symbols differ between base
  and head index, and a cache-from PR ingest exceeds 20% of cold wall time).
- Drop if: IXS-M5 reads CUT twice, six months apart.

## F71. Resilience facts in code: client construction with its literal options and library version

- Confidence: plausible. Horizon: next. Evidence: the concern catalog's rows 1 to 5, 15, 21 and 25
  (`docs/assessments/2026-10-11-reviews-and-incidents.md` section 3); AWS REL05-BP03; the owner's note of
  2026-10-11 (backoff with jitter on things that connect).
- Motivation: the retry, timeout and pool settings that cause cascades live at the call site that constructs a
  client. Fathom stores no third-party call site and skips Go composite-literal keys, so code evidence is
  grep-level today. Library defaults also move with env opt-ins, so the facts carry `pkg@version`.
- Do not build: before WAE-M1 reads BUILD; a library-defaults pack (Review Kit's); a judged site for hand-rolled
  loops before the spend hold lifts; grading of any kind.
- Preserve: facts as observations; coverage on every fact; `pkg@version` from what the toolchain placed on disk
  (I56).
- Promote when: WAE-M1 reads BUILD (at least 30% of hand-labelled client sites carry literal options or a named
  library in the WAE-M0 corpus).
- Drop if: WAE-M1 reads HOLD, or once built the Go lane's precision is under 0.90 on WAE-M0's code labels.

## F72. Versioned cross-repository concern joins across index snapshots

- Confidence: plausible. Horizon: later. Evidence: the concern catalog's rows 1 and 3; ADR-050; SG-2; ADR-069
  decision 9.
- Motivation: the strongest prevention findings span repositories: retries multiplying across proxy hops owned by
  a platform repository, and replicas x pool against the database's `max_connections` in a platform repository's
  IaC.
- Do not build: before RT-M1 PASS, SG-2 and IXS-7 (`import snapshot`); query-time RPC between daemons (ADR-069
  decision 9); a link below the typed tier that gates (I57).
- Preserve: `MatchLinks` as a pure join; the lineup's `service@commit` entries.
- Promote when: RT-M1 reads PASS, SG-2 lands, and a lineup names at least two services.
- Drop if: RT-M1 is still FAIL on 2026-12-31, or no true-positive cross-repository finding within 90 days of
  building.

## F73. Per-extractor epoch salts

- Confidence: speculative. Horizon: later. Evidence: `ExtractorEpoch` 62, 29 changes in 30 days; IXS-M2.
- Motivation: one global salt re-extracts every file of every language on any extractor change, so an index
  snapshot stops matching with each release.
- Do not build: before IXS-M2 reads under 0.5 with the fathom release locked.
- Preserve: `FingerprintHash` as the one hash-gate formula.
- Promote when: IXS-M2 reads under 0.5 with the release locked.
- Drop if: IXS-M2 reads at least 0.5.
