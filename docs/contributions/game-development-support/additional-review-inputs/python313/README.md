## Behavior for review

The adapter ports Sourcegraph's parse/bind traversal to Pyright 1.1.390's URI and parse-node APIs, with Python 3.13 version selection tied to the actual interpreter. It uses selected-interpreter `stdlib_module_names` and package metadata for identities. A project-first resolver repairs local modules shadowing stdlib names when Pyright would prefer bundled typeshed. Import/alias symbol ownership follows resolved URIs: project, stdlib/typeshed, and third-party packages (including `PIL.Image`) have distinct owners. Shared project ownership rules exclude bundled typeshed and third-party sources from emitted project documents while retaining in-root imports. Ambiguous ownership stays local rather than inventing a global package symbol. Hover documentation comes from structured Pyright results. This port is an adaptation of existing producer behavior, with the ownership repairs driven by observed false `python-stdlib` ownership of a local `json.py` in `evidence/runtime-fourth-pass/`.

## Review limits and upstream work

The adapter depends on Pyright 1.1.390 internal APIs and retains parse/evaluator state for SCIP emission; memory and future Pyright upgrades need review. Replacing the full core and typeshed trees makes this a large vendor update, even though only four core files differ from the pinned upstream source. The dependency locks were generated in the local fork; a plain install previously failed because `ts-jest@27.1.4` requires TypeScript below 5 while the candidate pins 5.5.4. A later install used `--legacy-peer-deps` and ignored scripts. The one focused test passed, but broad Jest compatibility and clean-install portability are open. The validation is scoped: no Blender `bpy`, full L4 semantics, general Python 3.13 support, or upstream publication claim. Upstream should resolve the test-stack dependency conflict, review memory cost and vendored-core strategy, and run its complete CI and compatibility matrix before adoption.
