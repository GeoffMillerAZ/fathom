### `readout` — readout rules, offline (ADR-071)

```
fathom readout replay [--days N] [--projects GLOB] [--rules FILE] [--json]
fathom readout explain [--rules FILE] [--mode observe|lean|rich] [--json] '<command>' < output
fathom readout test [file...]
fathom readout report [--since DURATION] [--json]
```

None of the three runs a command or installs a rule. Without `--rules` a verb reads the built-in rules and the user's files (`~/.fathom/readouts.toml`, `~/.fathom/readouts.d/*.toml`); with `--rules FILE` it reads that one file alone. Design: [readouts](../design/readouts.md) §8 to §10.

`replay` reads the local Claude Code transcripts (`$CLAUDE_CONFIG_DIR/projects`, else `~/.claude/projects`; every `*.jsonl` under each project directory `--projects` matches, subagent transcripts included) for the last `--days` days (default 30). It pairs each Bash call with its result, counts a tool-use id once (a resumed session copies its history into a new file), reads the harness's persisted output file when the result names one, and renders every call through the engine in observe. It prints aggregates only, never command text, output text, a path, a session id or a project name:

- `bash`: calls, bytes (stdout and stderr), duplicates skipped, unpaired calls, failures, persisted outputs and how many were read;
- `whole_file_reads`: whole-file source reads (`cat`, `sed -n 1,$p`; never `head` or `tail`) over 200 lines, computed by shape whether or not a rule matches, as a share of Bash bytes;
- `rules`, per rule: hits, bytes in, served readouts, would-remove bytes, raw reasons, protected trips by stream (content, diagnostic), the trips a protected-line rule not scoped by stream would have read, and the offline dropped-line reference rate (a later call within five that names a path or identifier only a dropped line carried) as referenced and evaluated counts with the 95% Wilson lower bound that no dropped line was referenced; `eligible` when at least 200 readouts were evaluated and that bound is at least 0.90;
- `eligible`: those rules' would-remove bytes as a share of Bash bytes;
- `shapes`: per command head (the lexer's first command, with the subcommand for git, go and similar tools; the top 25 by bytes, the rest as `(other)`): calls, bytes, share, simple, piped and list counts and the compound share; `tccutil_reset`: its calls and compound share; `reread`: whole-file reads followed by a `sed -n` of the same file within five calls;
- `window`: the first and last counted call's timestamps, from the data.
- `joins`: how the built-ins' inputs were filled: declared test commands matched from the call's cwd when it exists, else from the built-in test runner list alone; persisted texts missed; `head_stamp`, always missed (a past call's HEAD is unknown); and `read-outline`'s outline, computed in process by fathom's own extractors over the text the read printed (no deadline offline, 150 ms in the hook), or left raw for a file an Edit, Write or MultiEdit touched earlier in the session.

Replay reads every call twice. `as_matched` is what the hook serves: each rule's `match.compound` applied to the command as written, so a simple-only rule never sees `cd <dir> && git log`. `projected` strips the call's leading quiet segments (the heads `projection.quiet` lists: `cd`, `export`, `mkdir -p`, `sleep N`, an assignment alone, `set`, `source`, `.`, `tccutil reset`) and matches its last segment's first command as a simple command over the call's whole output, a projection of a wider quiet list rather than a served readout. Each `rules` row and `eligible` carry every figure under both keys; `effective_shapes` counts calls by that last segment's command beside `shapes`, which keeps the first unit; `unmatched.unreadable_by_reason` counts the commands the lexer cannot read by reason class, with any word of the command written `…`.

`explain` renders one command string and its output (stdin) through the engine and prints the lexing verdict, the rule matched, its stages, lossiness and recovery, raw or readout and why, bytes and lines in and out, dropped lines by class, protected trips, records by kind, the input lines not in the view, and the receipt. Exit 0, 1 for a usage error, 2 when the rules cannot load.

`test` loads each file (none: the built-ins and the user's files) and holds every rule to the contract: its fixtures, each run twice for determinism, a protected-line fixture for each stream a lossy rule reaches, and every lossless stage's inverse. It prints each served rule's lossiness, recovery and fixture count, and each refused rule's reason. Exit 0 when every rule is served, 1 when a rule is refused, 2 when a file cannot load.

`report` reads the readout hook's rows (channel `readout`) in both hook-log generations (`~/.fathom/hooks.jsonl`, then `hooks.jsonl.1`, the one the log keeps when it rotates at 64 MB) and prints, per rule: hits; served readouts; bytes removed, in bytes (in observe, what the readout would remove); est. tokens, bytes/4, labelled an estimate; the dropped-line reference rate; the not-computable count; the recovery rate in lean and net bytes; and a verdict. Rows carry no output text, so for the reference rate the report finds each served row's tool-use id in the local transcripts (the same directory `replay` reads; only files modified inside the window whose path names the row's session), re-renders the call with the loaded rule whose sha256 matches the row's `rule_sha`, recomputes the dropped lines and counts the readout as referenced when one of the next five calls names a path, `path:line` or identifier only a dropped line carried. A row it cannot replay is counted apart as not computable, never as clean, by reason: `transcript gone` (no transcript holds the call and its result), `rule changed` (no loaded rule's text matches the row's hash) or `output differs` (the command or the re-rendered bytes are not the ones the row recorded). Recovery counts lean rows only: a repeat of the command or a read of the same file within five calls, and net bytes are the bytes removed less those calls' result bytes; with no lean rows both read `no lean rows`, never 0. The verdict uses ADR-071's bars: `demote` when the lean recovery rate's 95% Wilson lower bound exceeds 5%; `promote` when at least 200 served readouts were replayed (a not-computable row never counts toward the 200) and the 95% Wilson lower bound that none had a dropped line referenced is at least 0.90; `insufficient` under 200; `keep` otherwise. The report recommends and changes no config. It reads per rule only, sorted by rule: no totals across rules, no per-person or per-session view, never command text, output text, a path or a session id.

`--since DURATION` (`7d`, `36h`) keeps the rows of that last span, the 7-day interim a longer reading sums; the window is asserted from the first row's time, and when the hook log's oldest beat is later than the window's start the report reads `INCOMPLETE` and names how far back the log reaches. `--json` emits the same figures (`recovery` is null with `recovery_note: "no lean rows"`). Exit 0, 1 for a usage error, 2 when the rules cannot load.
