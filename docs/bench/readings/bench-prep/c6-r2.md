# C6 recount under D24

Measured on 2026-10-26 (UTC). No fathom graph was used; C4 remains unrun.
`c6-r2.json` binds every count to the pin and gives three witness symbols (or
the strongest nonqualifying examples), caller units and representative sites.

D24 uses an import package in Go and a directory in Python/TypeScript. Go
external test packages merge into their directory's package. Every call from the
defining unit is excluded, including its tests. A witness needs at least five
remaining call sites and three remaining caller units; a subject needs three
witnesses. These counts are call sites, not distinct caller functions.

Commands (resolved receipts and outputs reside in the job directory):

```sh
python3 calibration/bench/tools/recount.py "$language" "$subject" "$resolved_rows" > "$job/receipts/$subject_id-d24.json"
BENCH_TYPESCRIPT="$oracle_tools/node_modules/typescript" node calibration/bench/tools/c6_ts_project.cjs "$subject" packages/toolkit/tsconfig.json > "$resolved_rows"
```

The Go, Python and original TypeScript resolving programs are documented in
`calibration/bench/tools/README.md`. The recount re-groups their full site lists;
it does not extrapolate from the three examples in the round-1 reading. Python
counts direct resolved imports/re-exports and omits dynamic dispatch. TypeScript
omits interface signatures. These are explicit static lower bounds. The
project-aware TypeScript program reads tsconfig options and disambiguates
same-named declarations by their declaration line. Redux-toolkit's path aliases
raise its resolved D24 count from zero under the generic harness to 26. No C6
refusal is inferred from that generic-harness zero.
