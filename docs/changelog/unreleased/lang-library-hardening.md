### Fixed

- The language library guards the parsers that recurse on nesting, so a file nested past 10,000 levels (HCL brackets, prefix operators, conditionals, splats and open template directives, proto brackets, `-` and comments where a literal is expected, the CUE attribute scanner's own recursion, nginx and Caddyfile block depth) reads `Incomplete` with the reason rather than overflowing the stack, which no recover catches. A few parsers also refuse a shape that cost them hours: a template whose literal pieces meld past a budget (HCL), a run of tokens no statement ends (proto), a flood of lexical errors (CUE) and a TOML document of 40,000 keys. No other shape is promised refused or bounded in time or memory: a read returns by a deadline and `fathom-lang` reads in a process it can kill (see the read deadline note). A panic in a built-in extractor is now one file's `Incomplete` reading. A TOML document of more than 40,000 keys, a YAML mapping that repeats a key, an anchor that does, and a very wide YAML or document-engine mapping no longer cost quadratic time or memory in the shapes tried.
- A Helm template whose if/else branches repeat a key, and a notebook cell the Python reader cannot read within its budget, no longer vanish without a note: the first reads its workload, and both say what they could not read in `Notes`.
- A `Result` withholds the places a credential is found: the userinfo of a URL (never moving its host: an `@` after `?`, `#` or `/` is not userinfo, and the image of a `docker://` reference stays), every string literal bound to a name or a key in a parameter default, a rule value or a fact value, and a script's text, of which only the program is returned. A credential in any other place is returned as written.
- `DialectInfo.Engine` names what reads the dialect: CMake and proto read as `native`, not `tags`, and the `Result` documentation no longer calls SQL a line scanner.
