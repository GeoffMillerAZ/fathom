### Fixed

- The language library guards the parsers that recurse on nesting, so a file nested past 10,000 levels (HCL brackets, prefix operators, conditionals, splats and open template directives, proto brackets, `-` and comments where a literal is expected, the CUE attribute scanner's own recursion, nginx and Caddyfile block depth) reads `Incomplete` with the reason rather than overflowing the stack, which no recover catches. A few parsers also refuse a shape that cost them hours: a template whose literal pieces meld past a budget (HCL) and a TOML document of 40,000 keys. A proto file of tokens no statement ends, and a CUE file of lexical errors, are read, not refused: only the deadline bounds them. No other shape is promised refused or bounded in time or memory: a read returns by a deadline and `fathom-lang` reads in a process it can kill (see the read deadline note). A panic in a built-in extractor is now one file's `Incomplete` reading. A TOML document of more than 40,000 keys or a table header of more than 64 segments, a YAML mapping that repeats a key, an anchor that does, a Chart.yaml field the chart struct reads that holds a mapping, and a very wide YAML or document-engine mapping no longer cost quadratic time or memory in the shapes tried. A mapping that merges itself, or merges that fan out and meet again, are read once, and a proto file with a bracket open at its end is refused instead of hanging the parser.
- A Helm template whose if/else branches repeat a key, and a notebook cell the Python reader cannot read within its budget, no longer vanish without a note: the first reads its workload, and both say what they could not read in `Notes`.
- `DialectInfo.Engine` names what reads the dialect: CMake and proto read as `native`, not `tags`, and the `Result` documentation no longer calls SQL a line scanner.
