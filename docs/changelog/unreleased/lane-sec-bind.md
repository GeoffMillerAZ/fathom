### Security

- The daemon refuses a request whose peer address is not loopback with 403 and the named reason, so a network peer can no longer reach `/rpc` by sending `Host: 127.0.0.1`. A container or VM that reached the host's daemon through a non-loopback address is now refused.
- `fathom daemon install` writes `--addr 127.0.0.1:7575` by default, not `:7575` (every interface), and refuses a non-loopback `--addr` (exit 2): remote serving needs token auth, which fathom does not have yet. `serve-http` given a non-loopback `--addr` or `[daemon].addr` listens on `127.0.0.1` on the same port instead and logs one warning naming the configured address. `daemon install --reconcile` rewrites a wide plist address to loopback, and the new doctor row `daemon_bind` FAILs on a wide plist or a running non-loopback listener and WARNs on a wide `[daemon].addr`, an unreadable user config, or an installed or fathom-named `LaunchAgents` plist it cannot read or parse.
- An existing install (its plist passes `--addr :7575`) keeps serving after the upgrade, on loopback only, until you run `fathom daemon install --reconcile` from your own terminal; a client that reached it through a LAN address must use `127.0.0.1`.
