### Security

- The go commands fathom runs on its own (the typed pass at ingest and in the daemon, the daemon's toolchain shim, ask's module loads and the layer-rules import graph) now run offline with `GOPROXY=off`, `GOSUMDB=off`, `GONOPROXY=,`, `GOTELEMETRY=off` and `GOTOOLCHAIN=local` (ADR-083). `-mod=mod` is dropped from the effective `GOFLAGS` (the environment's or the GOENV file's, quoted forms included) and `GOFLAGS` is never left empty, so `go list` never rewrites a repository's `go.mod` or `go.sum`.
- `fathom receipt verify` (its `go mod download`, go/packages load and `--run-tests` go test) now runs under the same offline environment whatever `go_network` says, keeping `GOWORK=off` and `-mod=readonly`: a `GOPRIVATE` dependency no longer goes to its version control, and a go.mod's `toolchain` line is never fetched (ADR-083 decision 2e).
- A dependency missing from the module cache now fails the typed pass with the module named and `run go mod download in <module dir>` (ADR-083). Later ingests skip the pass until a Go file changes or one of the missing modules appears in the module cache.
- Migration: on a machine whose module cache lacks a repository's dependencies, run `go mod download` in each of its Go modules before ingest, or set `[ingest] go_network = true` in `~/.fathom/config.toml` (user scope only; a repository cannot set it) to let the typed pass download as before.
