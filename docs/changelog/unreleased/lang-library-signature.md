### Changed

- `Symbol.Signature` follows one fail-closed rule in the language library. In a code dialect on a list a test holds (Go, Java, Python, JavaScript, TypeScript, C, C++, CUDA, C#, Rust, Kotlin, Scala, Swift and Dart, each of whose literal forms opens with a quote character) it is kept up to its first quote character (`'`, `"` or a backtick) and reads `***` from there on, with no pairing: a quote that opens no literal (a comment's apostrophe, a digit separator, a quote in a regex) cuts too, and a Rust lifetime stays. Any other code dialect (Ruby, PHP, Elixir and the rest) reads an empty `Signature`. In a dialect that is no code it is empty unless the symbol's `Kind` is one whose `Signature` is a keyword or a declared name, and then it is cut the same way, so the text of a script, a default, a version and an image are not returned there (an image stays in `Reference.To`). A `Fact` value under a key that looks like a credential reads `***`, the userinfo of a URL is dropped with or without its scheme, and a `Note` carries a reason and a line, never the file's text. The library is not a secret scanner.
