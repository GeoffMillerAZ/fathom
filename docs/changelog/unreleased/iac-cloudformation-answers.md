### Added

- With a CloudFormation catalog installed (`fathom iac import --region`), `symbol_context` on a CloudFormation resource carries an `iac` block: the binding (`unversioned`, because a template names no version, with the catalog's region and build date), the unknown, missing-required, read-only-set and deprecated properties, and `replacement_if_changed`, the properties the resource writes that its registry schema lists as create-only (`forces-replacement`) or conditional create-only (`may-replace`). `review_diff` carries `iac.cloudformation` for the changed templates: the same attribute findings, and, when `since` names the base, each changed create-only property (a change that only moves punctuation or whitespace between words reads as no change) as `forces-replacement` and each conditional one as `may-replace`, each citing the schema field, pointer and blob digest. A resource whose type the registry schemas lack (a transform or custom type) reads `unbound`. The list is capped at 200 findings and sits under the 16,000 byte response cap. The schema states the replacement and no change set confirms it, and an answer says so. With no CloudFormation catalog installed neither answer changes (ADR-091 amendment, IF-C3, IF-C4).
