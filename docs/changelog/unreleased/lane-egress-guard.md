### Added

- The egress guard (ADR-083): before a Bash command (Claude Code and Codex) or a Claude Code `WebFetch`/`WebSearch` that sends data to a host off `[guards] egress_allow` (curl or wget uploads, nc/socat, scp/rsync/sftp/ssh, `git push` to an unlisted remote host, `gh gist create`, cloud storage uploads), one advisory line names the rule and the entry that allows it. `[guards] egress = "warn"` is the default, `"enforce"` denies while guard enforcement is on, `"off"` silences it; it is a string-match tripwire, not data-loss prevention, and Codex web search and MCP calls are not intercepted.
- The user sets the egress mode and the user-only allowlist; a repository may tighten the mode and never loosen it, and only `~/.fathom/capabilities.cue` may switch the new `egress-guard` capability off. `fathom doctor`'s `egress_guard` row recommends the guard when it is off and names each harness's own boundary (Claude Code `permissions.deny` and sandbox network allowlist, Codex sandbox network setting).
- Migration: run `fathom init` (or `fathom fleet reconcile --apply`) to wire the new Claude Code `PreToolUse` `WebFetch|WebSearch` entry, then list the hosts you push and fetch to in `egress_allow` in `~/.fathom/config.toml`, or set `egress = "off"` there.
