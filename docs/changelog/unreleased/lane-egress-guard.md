### Added

- The egress guard (ADR-083): before a Bash command (Claude Code and Codex) or a Claude Code `WebFetch`/`WebSearch` that sends data to a host off `[guards] egress_allow` (curl or wget uploads, nc/socat, scp/rsync/sftp/ssh, `git push` to an unlisted remote host, `gh gist create`, cloud storage uploads), one advisory line names the rule and the entry that allows it. `[guards] egress = "warn"` is the default, `"enforce"` denies while guard enforcement is on, `"off"` silences it. A target the guard cannot read (a shell expansion, an unresolvable remote, a git config override or a `GIT_*`/`HOME` change, a curl or wget proxy, pinned address or config file, an ssh jump, forward, config or connection program) matches like an unlisted host, and input it cannot parse (`eval`, a function) that names an egress tool warns, even under `enforce`.
- Limits: it is a string-match tripwire, not data-loss prevention. Codex web search and MCP calls, and Claude Code's MCP fetch and browser tools, are not intercepted; a GET carrying data in its URL passes by design; a command built at run time (`xargs`, a variable as the command word, as in `$c -d @f host`, a sourced script) or a direct write to `.git/config` passes; an agent with shell access can switch the guard off by editing `~/.fathom/config.toml`.
- The user sets the egress mode and the user-only allowlist; a repository may tighten the mode and never loosen it (a repository config that does not load is skipped, so the user's mode and allowlist stay in effect and `fathom doctor` warns naming the file), and only `~/.fathom/capabilities.cue` may switch the new `egress-guard` capability off. That rule covers fathom's own config and capability files only: a repository's harness settings are outside it, so a committed `.claude/settings.json` whose `env` sets `FATHOM_ENFORCE=off` or a `FATHOM_HOME` naming a config the repository controls loosens the guard once the folder is trusted. `fathom doctor`'s `egress_guard` row recommends the guard when it is off and names each harness's own boundary (Claude Code `permissions.deny` and sandbox network allowlist, Codex sandbox network setting).
- Migration: run `fathom init` (or `fathom fleet reconcile --apply`) to wire the new Claude Code `PreToolUse` `WebFetch|WebSearch` entry, then list the hosts you push and fetch to in `egress_allow` in `~/.fathom/config.toml`, or set `egress = "off"` there.
