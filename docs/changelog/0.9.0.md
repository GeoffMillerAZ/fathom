# 0.9.0 — 2026-09-30 — the release where the daemon became a responsible tenant and the agent surface shrank to what is used

The narrative record for `CHANGELOG.md`'s `[0.9.0]` block. Not normative;
plans, ADRs and observations are.

## What this release is for

Two things had to be true before fathom could be left running on an
operator's machine and trusted by agents that never read its changelog.
**One:** the daemon had to stop being able to take the machine. On 2026-09-26
it took about 29 GB (INC-23) after an earlier draft of this record had called
its memory "bounded at the peaks"; the correction is the entry on the
daemon's memory below, and the real bound is the responsible-tenant program
(ADR-047, vision 36): a budget and a shed, refuse and exit ladder, cost-classed
admission, one refresh queue, ingest off the request path and a crash-loop
breaker. **Two:** the surface agents see had to be the surface agents use. The
surface reckoning (ADR-053) read each tool's lifetime calls, cut the default
MCP surface to an eight-tool floor, and removed or folded 39 tools and four
prompts (many had zero lifetime calls); every tool description and schema is
paid for on every session, so the descriptions were cut to what a caller needs
(`tools/list` schema bytes 60,918 to 47,480).

Three rules were tightened on the way. `AGENTS.md` is the one instruction
file fathom writes (ADR-059; a `CLAUDE.md` it meets carries only an
`@AGENTS.md` import). "Done means proven" now means proven **and wired**
(ADR-018 amendment 2026-09-28): `verify --strict` refuses a claimed row whose
Go function a test reaches but no product entry point does. And an
unreadable source is named, never counted as nothing (I38).

The rest of the cycle is the instruments and the surface built on them: the
Observatory became a console (vision 35, ADR-045; waves F0 to G), refactor
conservation (vision 34, ADR-044) and test certification (vision 33,
ADR-043) arrived as proof planes with execution-preferring reading sets,
exploration maps (ADR-056), governance that learns (GL-), doc retrieval
(`search kind: docs`, KR-), change risk receipts and evidence packs
(CX-), a support matrix (SM-), and language breadth (ADR-048): nineteen new
languages and manifest formats, with the dialects that were built and
measured but not yet dispatched named as such.

What is not claimed: nothing here licenses a savings claim, and the language
readings are committed readings against named oracles, not coverage.

## How this record is organised

The block this file replaced held about 400 entries under four headings. Its
`### Breaking` heading also carried the earlier waves' narrative paragraphs
(responsible tenant, console, conservation, substrate), written before the
changelog rules of 2026-08-25 sorted entries by kind. They are kept exactly as
written, in order, under their original headings below. The collapsed
`[0.9.0]` block in `CHANGELOG.md` sorts them again: `Breaking` holds only what
changes a contract (each with its migration note under `docs/upgrades/`, or
the action in its line), and the rest are one line each under `Added`,
`Changed` and `Fixed`.

## Breaking, and the wave narratives filed with it
- **`fathom init`, `fleet reconcile --apply` and the console apply write the fathom stanza into `AGENTS.md` only, for every `--harness` (ADR-059).** A root `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` that exists (and is not `AGENTS.md` itself through a link) gets one marked region holding `@AGENTS.md`, an existing CLAUDE.md stanza region is rewritten to it on the next rewire (receipted; `fleet undo` restores it), `init --harness=gemini-cli` sets `context.fileName` instead of writing `GEMINI.md`, and fathom never creates a CLAUDE file. Migration: `docs/upgrades/0.9.0-agents-md-one-instruction-file.md`.
- **`fathom gen-claude-md` is renamed `gen-agents-md`, writing `workspace/artifacts/AGENTS.md` by default (ADR-059).** The old name still runs through 0.9.x with its old default output and a deprecation line on stderr.
- **Done means proven AND wired: `fathom verify --strict` (the pre-push gate) refuses a claimed row whose Go function a test reaches but no product entry point does (ADR-018 amendment 2026-09-28).** The new `wired` criterion walks the verify call graph from every `package main`'s `main` outside `testdata/` and the `init` and variable initializers of the packages they link; such a row is `library-only` (Unknown: the default gate reports it, `--strict` fails it) unless it declares `library: true` with a `reason:` that predates its claim.
- **`search` refuses a bare `root` outside every indexed service's root (`-32602`), reads at most 1 MiB of ripgrep output (stopping rg), 512 columns a line, `limit`+1 matches a file and 5 context lines, and names a stopped search in `partial` (RT-88, §4.5).** The Go fallback stops at 200 hits (was 20,000) under 64 MiB / 5 s. Pass `service`, or a `root` under an indexed one.
- **`references` searches the caller's own service unless `services` names others; `services: ["*"]` is the fleet (admitted in the `fleet` class, as is a list naming more than one service), and a call with neither a `services` argument nor a resolvable caller is a `-32602` listing the indexed services (RT-86, RT-159, §4.5).** Hooks, the CLI and `serve-mcp` resolve the caller from its working directory (`X-Fathom-Caller` gains `cwd=`); an HTTP agent passes `services`. The text scan streams under 64 MiB / 5 s per call (interface files a bare query reads included) and names a stopped scan in `partial`; definitions come from the store's name lookup, a service the budget never reaches costs only that lookup, and `exact` defaults on when a scanned service has typed edges. Migration: `docs/upgrades/0.9.0-references-own-service.md`.
- **A read of a drifted service answers from the index as it stands and queues the re-ingest; every daemon ingest runs on one refresh queue (RT-97..RT-100, RT-111; ADR-047 §7.1).** Auto-refresh no longer ingests before answering: the envelope says `refresh: {"<svc>": "queued (index_stale) — served from the index at <indexed>; HEAD is <head> …"}` (`refreshing` once it runs) and `staleness_report` adds `refresh`. The queue runs one ingest per service (a request mid-run becomes one follow-up) and one at a time, the most recently queried first, 60 s after a start and one per 30 s during warm-up, pauses background work at shed and refuses at refuse and in store distress (and background work in safe mode or for a quarantined service); the `ingest` tool waits on it and answers `coalesced: true` when it shared a run, and `post-commit-hook` now queues through `POST /refresh-request` (202) and returns instead of running the ingest in its request (a daemon without the route is still asked through the `ingest` tool), and no longer onboards a service the daemon does not index — it prints the `ingest` tool call with a path that does; `post-commit-hook --wait` runs the ingest tool and waits up to `--timeout` (the console's refresh remedy uses it). A read inside a failed refresh's retry backoff says so in its `refresh` note. A queued ingest nobody waits on still notes store distress, busts the identity cache, logs its failure and leaves it as `staleness_report`'s `refresh_failure` until a success. `serve-mcp` runs the `ingest` tool on its auto-refresh queue too. A non-git service's read probes its stats (at most one walk per 5 s) and never recomputes the content manifest; moved stats queue a refresh.
- **The daemon records every start and exit and trips a crash-loop breaker (RT-37..RT-40, RT-156, RT-158, ADR-047 §2.3).** `~/.fathom/daemon/<id>/lifecycle.jsonl` names an unclean predecessor at the next start (with jetsam or resource-report evidence); 3 counted exits (over budget, unclean, a foreign-held port, a failed start) in 30 min start the daemon in safe mode — tree and fleet refused with a named 503 `-32050`, auto-refresh, feeders and the decision port off — and 5 in 60 min stop it (`disabled.json {reason: breaker}`, exit 0; `fathom daemon start` resets it). For 120 s after any start each heavy class holds one slot (a second call is refused under the default `admission = "observe"`), a `batch` is gated by its sub-calls' classes, and auto-refresh ingests nothing inline; `task deploy` writes a `deploy` intent row (`fathom daemon deploy-intent`) so its kickstart is not counted, and `serve-http --lifecycle-id` gives an unmanaged daemon a persistent ledger.
- **serve-http binds before it opens its store and waits for an unavailable store instead of exiting; a held port and SIGTERM exit by rule (RT-41..RT-44, RT-165, §8.4, §8.5).** While waiting `/healthz` is 503 `waiting-for-store: <errno> (<label>)` — a `tcc-wedge` names the daemon binary, its signing identity and the Full Disk Access grant it needs — and tools/call is 503 `store unavailable: …`; a port a managed fathom of the same label serves exits 0, any other holder exits 75, named; the managed daemon's SIGTERM drains within 12 s and exits 0 (runtime fatals to `crash.log`). SQLITE_FULL/IOERR from a read or a write, or a low store volume, refuses ingest and `/refresh-file`, an unmanaged daemon waiting for its store keeps its `--ttl`/`--idle-exit`/`--exit-with-parent`, and `list_services` names an unreadable count as `symbol_count_error` instead of `symbol_count: 0`.
- **serve-http bounds its own memory and exits 70 over budget (RT-29..RT-36, RT-153..RT-155, RT-161, RT-171..RT-173, ADR-047 §2).** A budget (auto: RAM/8, 1–4 GiB; `[tenancy]` in `~/.fathom/config.toml` only — a repository's `[tenancy]` is ignored and named) drives a ladder sampled every 2 s over the daemon's footprint plus its child processes: shed at 0.75× drops console and fleet memos and pauses background work, refuse at 1× drops every cache, cancels in-flight tree and fleet calls and stops whole-tree, fleet and ingest reads, and the exit mark (2×, capped at RAM/4) halts an in-flight ingest, quarantines its service, and exits 70 with an `over_budget` lifecycle row if the next sample is still over. An unmanaged serve-http takes `[tenancy.unmanaged].budget` (512 MiB, exit at 1 GiB): a bench or script whose scratch daemon legitimately needs more sets `FATHOM_TENANCY_BUDGET=<size>` (or `FATHOM_TENANCY_EXIT=off`).
- **Work the ladder stops fails by name, and only a completed explicit `ingest` tool call lifts a quarantine (RT-153, RT-155, RT-172, RT-30, RT-31, RT-32).** An ingest that reaches refuse fails (`over budget: … halted at refuse`) with its prior watermark kept instead of indexing less, obligations reports its halted corpus read as `coverage_skipped`, a call refuse cancels answers a JSON-RPC error with `data.outcome: "abandoned-by-governor"` (call log `outcome`, `/metrics` `fathom_governor_abandoned_total`), a hook's refresh of a quarantined service is refused, and a malformed `gc_hint` / `FATHOM_MEMORY_LIMIT` or `refuse_at` below `shed_at` stops serve-http at start. `/statusz` gains a `tenancy` block (level, marks, unknown readings), and refuse diagnostics are captured at most once per 10 min, keeping 10 captures / 200 MiB.
- **Discovery skips the default cache directories — `.cache`, `.tools`, `target`, `dist`, `build`, `__pycache__`, `.venv`, `.gradle`, `.next`, `.turbo`, `coverage` — and names each one it pruned — in the ingest summary, `--json` and the MCP `ingest` tool's `default_ignored_dirs` (RT-145).** A repository that commits source under one of those names re-includes it with `[connector] include` in its own `.fathom/config.toml` (refused in `~/.fathom/config.toml`, where it would change nothing); a file over 2 MiB is counted under `oversize` on every ingest, not only the first (migration: `docs/upgrades/0.9.0-default-cache-dirs.md`).
- **An unmanaged `serve-http` is a bounded scratch daemon (RT-20..RT-22, ADR-047 §10.1).** Unless started with `--managed` or by launchd under the default label or an installed fathom agent's `Label` (the same rule the kill switch and self-restart use), it exits within 10 s of its parent's death, after 20 min idle (`--idle-exit`) or 8 h (`--ttl`), or when its executable or store is unlinked, logging the reason; it defaults to `--auto-refresh=false`, runs no self-restart watcher or scavenger, and refuses the managed daemon's store and call log — named by its record or its installed plist, under `HOME` and the account's own home — without `--allow-operator-state`, refusing too when the managed daemon's record cannot be read. On SIGTERM, SIGINT or SIGHUP it removes its record and exits 128+signo. A systemd unit or other supervisor running the long-lived daemon must add `--managed`.
- **`concerns.cue` (both scopes) refuses what it used to ignore: an unknown top-level field, a `where:` on a kind that reads no corpus, a check field the kind does not read (`file:` on a `required_pattern`, `pattern:` on a `commands_resolve`, `command:` on a `max_lines`), and an optional (`name?:`) concern or top-level field.** Each loaded and did nothing (`pack:` for `packs:` would have enabled nothing; `file:` on a `required_pattern` scanned the whole corpus instead); the load error names the field and the kinds that read it, and `fathom config audit` and doctor's `concerns` row report it. Remove the named field.
- **`fathom fleet report --json` omits a service's `calls_total` and `calls_agent` when the call log could not be read, and `session_count` counts distinct sessions from the ledger `FATHOM_SESSION_LEDGER` names.** They were `0` beside a note saying "never zero", and ledger rows read from a hardcoded `~/.fathom` path (migration: `docs/upgrades/0.9.0-fleet-report-honest-columns.md`).
- **`serve-http` watches its own binary for self-restart only when it is the managed daemon (`--managed`, or launched by launchd under the installed fathom agent's label), and adopts a new binary by exiting 75 instead of 0 (RT-11, RT-12).** A daemon under your own supervisor no longer self-restarts unless started with `--managed`; exit 75 is what a `KeepAlive {SuccessfulExit: false}` plist or `Restart=on-failure` relaunches on.
- **`review_diff` gains an additive `receipt` section: the change risk receipt over data the call already resolves (CX-5, `docs/plans/change-and-compliance.md` §2).** Blast radius, cross-service link hints, certificates, conservation and active obligations/arch findings feed the band and its cited factors; rows-proven, zone-interest, uncertified-contracts and suggested-reviewers stay at their honest not-yet-wired zero value rather than a fabricated claim.
- **`fathom review --receipt --format sarif|check` renders the change risk receipt through the shared SARIF/check-run emitter instead of the full review (CX-6, GL-20/GL-21).** One result/annotation per fired factor, ruleId/title the factor's own name; the check-run's `conclusion` is always `"neutral"` — fathom never scores a pass/fail verdict from the band (CX-8, ADR-040), CI decides what a band does.
- **`review_diff` additionally emits its `receipt` section as SARIF and a GitHub check-run payload (`receipt_sarif`, `receipt_check`; SR-49, `docs/plans/surface-reckoning.md`).** Same emitter and factor-vocabulary CX-6's CLI path uses, through the new `review.ChangeRiskReceipt`, so an MCP caller gets the code-scanning/Checks-API shapes without a second round trip through `fathom review --receipt`.
- **Every git read that goes through `internal/gitro` (status and diff in the console and review, the connector's log and diff reads, the HEAD fallback) runs with `GIT_NO_LAZY_FETCH=1` and `GIT_TERMINAL_PROMPT=0` beside `GIT_OPTIONAL_LOCKS=0` (incident maps IM-F2).** A service checked out as a partial clone reads an object it does not hold as an error instead of fetching it from the promisor remote, and a read that would prompt for a credential fails instead of waiting.

- **serve-http admits every tool call in its cost class and serves through a hardened `http.Server` (responsible tenant wave B: RT-53..RT-65, RT-152; ADR-047 §3).** Every MCP tool declares a cost class (`point`/`index`/`tree`/`fleet`/`ingest`; `docs/mcp-tools.md`), and `[tenancy].admission` (default `observe`: would-refuse is logged and counted, nothing is refused; `enforce`; `off`) gates each call by per-class slots, per-origin waits and deadline feasibility — an enforced refusal is HTTP 503 with `Retry-After`, `X-Fathom-Busy-Scope` (`class` or `daemon`; hooks back off daemon-wide only on `daemon`) and JSON-RPC `-32050` (`fathom busy: <reason>`), and `batch` now takes at most 16 calls, each admitted in its own class. `/rpc` work now runs under the request's context bounded by the class deadline and `X-Fathom-Deadline`, so a caller already gone is never run (refused `caller_gone`, in either mode) and a call whose client left or whose deadline passed mid-call answers a named `abandoned` error instead of its result (an ingest still runs detached, and no longer hits the 150 s write deadline); every route requires a loopback `Host` and a same-origin `Origin` (a hosted `--modules-token-env` deployment excepted); the managed daemon answers a test binary 409; call-log rows move to `schema_version` 3 with `outcome` on every row (`ok`, `partial`, `refused`, `abandoned`, `abandoned-by-governor`, `error`) plus `class`, `queued_ms`, `bytes_read` and `caller` (migration: `docs/upgrades/0.9.0-admission-and-call-log-v3.md`).

**The typed pass records package initialization as a caller (TypedEdgeEpoch 3).** A non-test `init()` and a non-test file's package-level variable initializers (a route table, `var x = memo.NewGroup[...](...)`, a func literal kept in a var for tests) are keyed `<pkg>.init`, so `find_callers`, `blast_radius` and verify reach what they register; the epoch bump re-resolves every Go package at the first ingest after upgrade.

**The daemon's derived caches share one budget, and whole-repository facts come from ingest (responsible tenant wave C: RT-66..RT-68, RT-72..RT-79, RT-82, RT-160, RT-163; ADR-047 §4–§6).**
- Every symbol snapshot, call graph and layer-coverage path set is an entry in one registry (`internal/memo`): built once per key however many ask, byte-accounted under `[tenancy.caches] fraction`, evicted when its service's watermark moves, trimmed to `shed_trim` at shed (and held there, one rebuild at a time), dropped at refuse (which also cancels the builds in flight) and after `idle_drop` without a call; `fathom serve-mcp` takes the same registry budget. One snapshot and one graph per (service, watermark) now serve the MCP tools, the console's project pages, row evidence and search palette — except `review_diff`'s conservation dimension, which still builds its own graphs from the store per review.
- An ingest writes `file_stats`, `service_summary` and `observation_calls` (new additive store tables; an indexed reverse call lookup) in its final transaction; a store written before them is derived by SQL at first use and once by the daemon after start, with no re-ingest (`file_stats` waits for the next ingest).
- `list_services` answers each service from its summary row — a row not yet derived (or a service whose ingest is in progress or was interrupted, in any process) is `symbol_count_error` naming why, a read-only store derives the row without writing it, unsupported languages come from the row, `root_missing` is one stat — and obligations' layer coverage takes its paths from `file_stats` (a nested guide written since the last ingest is still served by the raw fallback).
- The request path's file reads (the obligations corpus and ancestor-guide probe, the edited file's freshness hash and tokens) go through `internal/corpus`: stat first, an 8 KiB binary sniff (a binary file is skipped by name), and every byte read charged to the call's admission meter.
- The store opens with bounded SQLite memory (8 MiB page cache per connection, 256/512 MiB soft/hard heap, 64 MiB WAL journal limit) and an `(service_id, symbol)` index, and reads a service's observations without a temp B-tree.
- `[connector] respect_gitignore = true` (off by default until RT-M11) discovers a git work tree through `git ls-files -co --exclude-standard`, the always-skipped and default-ignored directories still applied; `fathom ingest --dry-run --stats --respect-gitignore` measures the delta. `pkg/client` gains `ServiceSummary`, `BackfillDerived`, `DerivedState` and `StoreID`.

**Query tools answer from indexes and bounded scans (responsible tenant wave C: RT-71, RT-84, RT-85, RT-87, RT-88, RT-89, RT-90; ADR-047 §4.5, §4.6, §6).**
- Routes and outbound HTTP client calls are extracted at ingest into new additive tables (`service_routes`, `service_http_calls`, `service_refs_state`) — every readable file at a service's first ingest after upgrade, then the changed files — and `blast_radius`, `cross_repo_blast_radius` and `review_diff` join their `service_ref_hops` from those rows instead of reading every service's source per call; a service not re-ingested since is named in `service_ref_unextracted`.
- The dispatch byte-budget backstop measures a result's size without marshaling a copy of it and trims an over-budget map's largest array without the marshal → unmarshal → per-field decode cascade (answers unchanged).
- `find_symbol` and `find_callers` (and every `FindSymbol`/`FindCallers` caller, `fathom verify` included) read only the matching rows — the `(service_id, symbol)` index and the `observation_calls` index — instead of decoding the service's whole observation set; a service whose call index is not complete keeps the old read for callers.
- Cross-service callers (`symbol_context`, `find_callers`, `cross_repo_callers`) are one indexed query over `observation_calls` and cross-service callees one name lookup per service, instead of loading every service whole per call; a service whose call index is not yet complete keeps the old scan.
- `mcp.QueryInterface` has no whole-tree `Sources`: tools that read file contents (`traceability`, `spec_coverage`, `dep_drift`, `traverse`, `secret_scan`, `shell_out`, `http_client_calls`, `cloc`, `stale_docs`, `proto_conformance`, `spec_refs`, `review_diff`, `references`) stream them through `ScanSources` under a 64 MiB / 5 s budget and name a stopped scan in a `partial` field (`review_diff`: `corpus_partial`; `references`: a `degraded` row). `pkg/client` gains `(*Client).ScanSources`.

**The request-path rule is a gate (responsible tenant wave E: RT-91..RT-95, RT-137; ADR-047 §4.7, §4.8).**
- Concurrent cold `obligations` calls read each edited file and each layer guide once between them. Each client single-flights those reads, and a caller that arrives after the read finds the result already stored.
- `read_source`, the integrity dimension of `review_diff`, and the enclosing-symbol lookup in `search` now read through the corpus reader. Their bytes are charged to the call's admission meter (`bytes_read` on the call-log row), and a binary file is refused after the 8 KiB sniff instead of being read whole. `review_diff` and the self-skip in `verify_plan` run git under the call's context, so git stops when the call is cancelled.
- `task validate` runs the tenancy lint (`internal/lint/tenancy`, the `tenancy-lint` task) with an allowlist that may only shrink, `.fathom/tenancy-allow.txt`. It also runs the per-tool cost harness (`internal/mcp/costtest`), which checks every registered tool, cold and warm, against its class ceiling at 1× and 10× fleet scale. Point and index tools may grow at most 1.5× when the fleet grows 10×, and 32 cold concurrent callers must start one build per key and read one walk's bytes. `pkg/client` gains `FleetAdapter`, the daemon's fleet backend, which moved out of `cmd/fathom` so the harness measures the same adapter.

**Admission observes and names (RT-53..RT-65).** `/metrics` gains `fathom_inflight`, `fathom_queue`, `fathom_slots`, `fathom_rejected_total`, `fathom_would_refuse_total`, `fathom_calls_total` and `fathom_test_callers_rejected_total`; the daemon's own console reads are admitted as `console-inprocess` and never trigger an auto-refresh; `/route` and the obligations re-rank are admitted as the egress class and skipped with a disclosure at the refuse rung and in safe mode; waiters on the list_services walk and the console memos leave when their request ends (a walk cut short is never cached as the answer); a registry read refused while a fleet call runs shows the last good registry marked `stale: fathom shedding`; `fathom doctor` gains `admission_mode`, which warns while the daemon serves with admission `off`.

**The console under the tenancy contract (responsible tenant: RT-112..RT-119, RT-121; ADR-047 §14).** A page past the model's 30 s TTL is served the last model at once while one rebuild runs outside the lock (a cold cache waits for that same rebuild, and a rebuild dropped under memory pressure or one that fails never answers an empty model), and the rebuild and Operate read the call log and session ledger as tails; the call-log tails keep the log's all-time fold plus a 35-day ring, never a row per line, and the session ledger is folded as it is read (each session's newest state and a compact row index, never the rows' bytes) for the counts, the sessions table, the activity tab and the replay; the shed rung frees the console's page caches but keeps the tails and the hooks index's offsets, so memory pressure never triggers a whole-log re-read; every console reader of `hooks.jsonl` (session pages, the catches timeline, the impact model's beat-windows, the flywheel's custodian check) reads a per-file index extended by appended bytes, never the whole log. Inside the daemon the console no longer calls itself over loopback HTTP or forks `git` on a page's path (statusz, the agent surface's `tools/list`, `/learn/ask`, plan verification and the intent audit's index oracle run in process, admitted as `console-inprocess`; HEAD is read from the repository's files); plan verification, `/refactors`' conserve and the project index run in one pool (2 workers, queue 32, one flight per key, a superseded queued key dropped, a panicking job finished as a named failure) with git under the page's deadline and a range wider than the new `[console] conserve_max_files` (default 500) refused by name; the event feeders run only while `/events` has a subscriber and read compile runs in record order from a cursor (with none, a page reading a live panel's freshness polls the ledgers first and the store off the request path, at most once per 10 s). A conserve report stopped by its 2-minute deadline is a named failure, never a report with its unfinished planes shown clean, and a request waiting on the project index or a cold model leaves when its client does. Operate gains a Tenancy panel rendering `fathom resources --json` (kept for 2 minutes and refreshed off the request path), which gains `footprint.hourly` and `ladder`, and beside it each tool's p95 per hour from the new `fathom metrics traffic --by tool-hour`.

**Interrupted ingests, deferred auto-refresh and the daemon's own instruments (responsible tenant wave B: RT-109, RT-150, RT-45, RT-46, RT-162; ADR-047).**
- An ingest records its watermark only at its final commit and writes `ingest_state = in_progress` first (a new additive store table), so a killed or halted ingest never looks fresh; auto-refresh re-ingests a service another process left `in_progress` once that process is gone (a running `fathom ingest` is never duplicated), even at the same commit and even for a killed first ingest (the row names the corpus root), unless it is quarantined.
- Auto-refresh runs no inline ingest at shed and above, while paused (safe mode — `daemon pause` now has this effect), during the 120 s warm-up after any start (`[tenancy.breaker].warmup`) or for a quarantined service, and the response envelope says so: `"refresh": {"<service>": "deferred (<reason>) — …"}`.
- The scavenge line reads total−released and `phys_footprint` before and after (the `heap_sys`/`heap_inuse` fields are gone) and is logged on every ladder event as well as the tick; the typed-pass line reads "process heap during pass … with up to N in-flight tickets" from runtime/metrics instead of "peak heap_inuse".
- Bytes written by the daemon and its sampled children (`go list`, git, rg) are kept per minute for 24 h and judged against 2 GiB/day outside explicit ingest: `/statusz` `disk_writes`, `/metrics` `fathom_bytes_written_total{subsystem="self"|"children"}` and `fathom_bytes_written_*` with the window they cover (`fathom_bytes_written_window_seconds` — the ring is in memory, so after a start it is not yet a day), and doctor's new `disk_writes` row (WARN over budget, disclosed, not enforced; names the window).

**What the daemon takes is visible when it is down (responsible tenant wave B: RT-47..RT-52, ADR-047 §13).** `fathom resources [--json] [--since 24h]` renders budget, footprint (self and children) history, lifecycle, quarantine, host, in-flight work, hooks, scratch daemons, disk and the last capture from files — the new fixed-size resource ring (`~/.fathom/daemon/<id>/resources.ring`, a sample a minute for 24 h plus every ladder transition) and the lifecycle ledger — and exits 0 within budget, 1 over budget, crash-looping, breaker-stopped or leaking scratch daemons, 2 when a file is unreadable.
- Doctor's `daemon_footprint` judges phys_footprint from that projection and WARNs with the ring's last sample when the daemon does not answer instead of SKIPping; its "restart the daemon" remedy is gone. New rows: `daemon_lifecycle`, `host_pressure`, `scratch_daemons`, `tenancy_scope`.
- `/statusz`'s `tenancy` block adds mode, the sample time, in-flight work by class and each call's tool and origin, refusals (the admission gate's refused and would-refuse totals with its mode; "not counted" in a process with no gate) and the last diagnostic capture; the session primer adds one ≤160 B line only when the daemon is not normal.
- `resources`, doctor and the primer claim only what their files earn: a lifecycle ledger with no start rows says starts and unclean exits are not recorded (crash-loop detection sees over-budget exits only) instead of "0"; a ring sample older than 5 min is shown with its age but never judged over budget or read as current host pressure; "leaked" scratch daemons are exactly the ones `daemon reap --apply` kills; `host_pressure` judges the resolved `[tenancy.host]` triggers; `tenancy_scope` WARNs on admission `off` and on a `memory_limit` / `gc_hint` conflict.
- The console's Operate page gains a `tenancy` tile (level, footprint of budget, mode, in-flight calls) from the same block, and the block in the page's JSON model; with no governor in the process the tile says so.

**Ingest off the request path, streamed (responsible tenant wave D: RT-97..RT-108, RT-110, RT-111; ADR-047 §7).**
- Auto-refresh, staleness checks and ingest read a work tree's HEAD from `.git/HEAD` and the ref files (loose, `packed-refs`, a linked worktree's `gitdir:`), cached per root until a file moves, instead of forking `git rev-parse HEAD` on every read; a layout the files cannot answer runs git under a 2 s deadline and reads as freshness unknown when it does not answer.
- An ingest stats every file first and reads only those whose size, mtime or inode moved since the daemon's last ingest of the service (and whose stored fingerprint still matches); `fathom ingest --rehash` reads everything. The files it reads stream through a 64 MiB in-flight window in input order — each hashed, extracted and written (observations 256 at a time) and then released — so an ingest's content memory no longer grows with the corpus; the summary reports `stat-skipped` and the peak bytes held.
- The typed Go pass runs only when a `.go`, `go.mod`, `go.sum` or `go.work` file changed (or was deleted) since its last successful pass, and the CUE pass only when a `.cue` file did, under the same one-at-a-time toolchain slot; a skipped pass keeps its stored edges and the ingest summary says `typed-edges: skipped — no input changed since the last successful pass`. A Go pass no longer purges the CUE pass's or the file resolver's stored edges.
- The file-resolve pass (TS/JS/Python import edges) uses the pipeline's own tree-sitter extractors instead of instantiating two new wazero modules per language per ingest that were never closed; `TSExtractor.Close` and `Pipeline.Close` release them (`Client.Close` calls it) and each module's linear memory is capped at 64 MiB (a parse past it is an engine fault, counted like any other).
- The file-resolve pass reads a TS/JS/Python file's imports from the store's new `file_imports` table while the file is unchanged (not read, not parsed), takes its symbols from the rows the ingest stored instead of extracting every file a second time, keeps binary and over-2 MiB files out of the parse, records an import-parse fault against the bytes (not retried until they change) and names every faulted file on each ingest (`FileResolveFaults`, a stderr warning in the CLI summary); it does not run when no such file changed. `fathom purge`, `remove_service`, `rename_service` and the ADR-017 self-heal cover the new table.
- A service whose watermark is a git SHA never falls back to the content manifest (a read of the whole corpus per query) when its HEAD cannot be read: freshness is unknown, disclosed. A non-git corpus's manifest is recomputed only when a file's path, size or mtime moved (a stat walk, no reads); over 20,000 files it is freshness unknown.
- The typed pass's toolchain children (`go list` and the compiles it forks, `go env`) run with `GOFLAGS` `-p` and `GOMAXPROCS` at most 2 (never raising an inherited value; other `GOFLAGS` flags kept; `FATHOM_TOOLCHAIN_PROCS=N|off` moves or lifts the ceiling) and at background priority: serve-http and a CLI `fathom ingest` put a `go` shim first on their PATH that runs the real toolchain under `nice -n 10` (and `taskpolicy -b` on macOS); the shim lives at `$TMPDIR/fathom-toolchain-<pid>`, and a killed process's is removed at the next start.
- `/refresh-file` leaves a file to a whole-service refresh the queue holds for its service (`skipped: "whole-service refresh queued|running …"`) instead of writing beside it.

**Auto-refresh re-ingests survive their requester and run one at a time (responsible tenant wave A: RT-149, RT-151; ADR-047).** The read that triggers an inline auto-refresh re-ingest waits for it only while its own request lives, and every other read of that service meanwhile answers at once from the index as it stands; the ingest runs detached from the request under one ticket shared by all inline auto-refresh ingests (the `ingest` tool and `/refresh-file` do not take it yet). A re-ingest that fails before it records the new commit is retried after 30 s, doubling to at most 30 min, instead of being debounced for that commit forever.

**The self-restart watcher stats its binary and hashes it only when it changed (RT-12).** It hashed the whole binary every 20 s; it now hashes only on a (size, mtime, inode) change, adopts only a binary whose stat held through its `version` check, and keeps a 5-minute cooldown between adoptions across restarts in `~/.fathom/daemon/<label>/lifecycle.jsonl` (when that ledger cannot be read it says so and waits until the process has itself run 5 minutes). A failed hash is logged and retried on the next poll, and a new binary whose `version` check failed is re-verified after the cooldown instead of waiting for the next deploy.

**A failed post-commit refresh says nothing was ingested (RT-170).** It announced a store-direct fallback it never ran; it now names the failure and how to refresh through the daemon once it is back.

**fathom as a responsible tenant — list_services, discovery and whole-tree reads bounded (vision 36, ADR-047; RT-1, RT-2, RT-27, RT-69, RT-70, RT-80, RT-144, RT-146).** `list_services` answers symbol counts and languages from a SQL aggregate cached per store watermark and single-flighted, never a whole-service symbol load, and classifies unsupported languages by file name only; the connector never reads a file over 2 MiB (counted under `oversize`, fingerprinted by size) and stops discovery and fetch when the requester's context ends.
- `GET /indexed?service=` answers "is this service indexed" from one `service_meta` row and the watermark-cached symbol-count aggregate (a service with zero symbols is still "not indexed", so `fathom verify` against it stays exit 2); `fathom verify`, the stop and edit hooks, `fathom plans`, `fathom init` and the console ask it instead of `list_services` (and fall back to `list_services` against an older daemon).
- `fathom ingest --dry-run [--stats] [--json]` reports files, bytes, files over the read cap, pruned directories and the largest files from stats alone, reading no file and opening no store.
- At most two whole-tree `client.Sources` reads are held at once per process; on the daemon a `/rpc` request keeps its slot until its response is written and stops waiting when the client disconnects. A request whose `X-Fathom-Origin` names a hook never waits for one. `obligations` itself no longer takes a whole-tree read (RT-143, RT-81), but a backend that refuses one makes it answer `coverage_skipped: "coverage skipped: whole-tree read in progress"` (and `layer_coverage.status: "skipped"`), which the edit and prompt hooks print as a warning line; `verify_plan` refuses by that name when a row needs spec coverage, and the Stop hook reports it as advisory, never a block. `pkg/client` gains `ServiceSymbolAggregates`, `IsIndexed`, `SourcePackages`, `PackageSymbols`, `WithHookOrigin`, `IsHookOrigin`, `WithSourcesScope` and `ErrSourcesBusy`.
- `POST /refresh-file` stats before it reads: a file over 2 MiB answers `refreshed: false` with `skipped: "oversize (…; not read)"` instead of being read (a file that grew past the cap has its old rows purged and the graph memo dropped), and the memoized graph is patched from the file's own rows, not a whole-service symbol load. A file outside the corpus an ingest walks (always-skipped or default-ignored cache directory, ignore files) answers `skipped: "outside the corpus: …"` instead of being indexed until the next ingest purges it.

**The operator can switch the daemon off, and launchd no longer relaunches it forever (responsible tenant RT-3..RT-6, RT-13..RT-15, RT-147, RT-148, RT-157, RT-167; ADR-047).** `fathom daemon stop [--for 2h]` writes `~/.fathom/daemon/disabled.json`, kills the managed pid behind a pid-reuse guard (SIGTERM, 10 s, SIGKILL) and reports success only once the process is gone and the port closed; the managed daemon (`serve-http --managed`) reads the switch before config, store or bind and exits 0 in under 50 ms (75 until a `--for` expires), scratch daemons ignore it, and `daemon start` undoes it (`status`, doctor and the session primer name it as the remedy while the switch is set, and `task deploy` installs without starting); `daemon pause`/`resume` set and clear a safe-mode flag that has no effect yet (RT-39/RT-150), and say so. Self-restart adoption exits 75 instead of 0, so a schema-2 plist relaunches it. `daemon install` writes plist schema 2 (`KeepAlive {SuccessfulExit: false}`, `ThrottleInterval 60`, `ProcessType Background`, low-priority I/O, `Nice 5`, `ExitTimeOut 20`, `--managed`); `daemon install --reconcile [--adopt]` rewrites only those keys of an installed plist with a backup and receipt under `~/.fathom/daemon/<label>/`, doctor's `daemon_posture` row and `daemon status` name the drift with the exact command, `status` names the running daemon process's signing identity (ad-hoc called out), `version --json` reports `tenancy_contract`, and `task deploy` fails with `fathom-dev signing identity missing` instead of installing an ad-hoc binary.

**Hooks no longer pile up on a slow or dead daemon (responsible tenant, RT-7..RT-10, ADR-047).** Every hook invocation has one deadline — its harness timeout minus max(1 s, 20%) — that every RPC derives from and sends as `X-Fathom-Deadline`, and past which a hook skips its optional local work (`session-hook`'s outbox sync and continuity brief, named in the primer; `doctor --brief`'s remaining checks, counted in a `hook_deadline` row); the service enumeration retries only a refused or reset connection inside it (it used to retry any failure with a fresh 4 s client). Hooks share a per-daemon breaker file (2 failures in 10 s, or a 503 with `Retry-After`, open it; backoff 5 s to 300 s; one `/healthz` prober under a `flock` lease; a good probe keeps the backoff, only a real success resets it; a hook's own client timeout counts as a failure; while it is open hooks are silent and the session primer no longer says "not responding"; `breaker_open`/`busy`/`deadline_spent` beats record what was held off), and a `disabled.json` or `paused.json` in `~/.fathom/daemon/` silences every hook addressing the managed daemon before any RPC — `daemon stop` and `daemon pause` record that daemon's address (`addr`, from `--url`), so a scratch daemon's hooks are never silenced, and a switch file the hook cannot stat (other than absent) still holds.

**`fathom daemon ps` and `fathom daemon reap` (RT-23, RT-24, RT-166, ADR-047 §10.2).** `ps` joins the daemon records — now `~/.fathom/daemon/<id>/record.json` (schema 2; the legacy `~/.fathom/daemons/` is still read this release) — with a live census of every fathom `serve-http` process and names each `ok`, `orphaned`, `idle`, `unlinked`, `no-record` or `stale-record`; `reap` is a dry run unless `--apply`, then kills only unmanaged daemons whose verdict is not `ok` (SIGTERM, 5 s, SIGKILL) — never the managed daemon, and never a `no-record` daemon whose parent is alive (its record is under another HOME) — and prunes stale records whose pid is still gone. A daemon recording itself prunes the records of scratch daemons whose pid is gone; the managed address comes from the installed plist before `[daemon].addr`.

**Tests never reach the operator's daemon (RT-16..RT-19, RT-164, ADR-047 §10.4).** Every request the `fathom` binary sends to a daemon host (loopback, or `FATHOM_HTTP`'s host) carries `X-Fathom-Caller: pid=…;ppid=…;origin=…;session=…;test=0|1`, with `test=1` derived from `FATHOM_TEST=1` as well as a test binary, and the daemon-URL defaults fall back to the unroutable `http://127.0.0.1:1` instead of `localhost:7575` under a test or `FATHOM_TEST=1` when `FATHOM_HTTP` is unset.
