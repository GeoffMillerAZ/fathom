# 0.8.0 — 2026-09-02 — the release where the harness stopped being Claude Code and the instruments stopped trusting themselves

The narrative record for `CHANGELOG.md`'s `[0.8.0]` block. Not normative;
plans, ADRs and observations are.

## What this release is for

Two things had to be true before a second person could get value out of fathom
rather than merely build it. **One:** fathom had to work for whatever harness
that person already runs, without the Claude Code assumptions being welded into
the code. **Two:** every number fathom prints about itself had to survive
someone trying to break it — because 0.7.0's own lesson was that the failures
which matter are the ones invisible to the machine that could have caught them.

Three waves, run as parallel worktrees off `main` and integrated in order:
the harness port and reach parity (ADR-029), proof credibility (ADR-030) and
bench credibility (ADR-031), and the kit consumption that deleted fathom's copy
of two primitives agentic-kit had generalised.

## The harness port (ADR-029, HP-1..HP-25)

fathom's hook table, stanza sentences, envelope encoders and tool
classification were Claude Code literals scattered across `cmd/fathom`. Adding
a harness meant editing all of them and hoping.

`internal/harness` makes the harness **data**: a `Descriptor` carries identity,
detection markers, instruction files, hook files, event bindings with the
documented stdin/stdout field maps, tool classes, per-capability vehicles, fail
mode, scope-merge rule, skills dirs, MCP target, env contract, transcript
availability and `verified_against`. The only per-harness **code** is a
`Codec`.

The discipline that makes this trustworthy is the golden rule: **Claude Code's
entry reproduces the pre-seam hook table event for event, and its codec emits
the exact bytes the four pre-seam encode sites produced.** No pre-existing
golden was edited to make the seam land —
`TestStanzaHookSentencesClaudeByteIdentical`,
`TestLookupClaudeCodeReproducesHookTable` and
`TestClaudeCodecEncodesPreSeamBytes` are what says so.

Wave 2 added real codecs for Codex (`apply_patch` → the patch's first file;
`additionalContext` cut at 8,000 bytes with a named cut) and Gemini CLI
(`systemMessage` where `additionalContext` is unshown; the flat `decision`
field is never emitted), each round-tripped against fixtures that cite their
source in the file header. Cursor and Copilot ship as data rows with no codec —
nobody here runs them, so claiming a vehicle would be the guessed PASS this
plan forbids. Eight further harnesses (Windsurf, OpenCode, Amp, Zed/ACP, Junie,
Warp, Continue, Aider) are ladder rows: instruction file, skills path, MCP
config, `mcp add` line, and an honest "no injection here" line.

**Both new descriptors ship `unverified` with a 60-day demotion clock started
2026-09-02.** `fathom harness capabilities --harness codex --json` says
`"status": "unverified on this machine"` on every capability row, and
`fathom doctor --harness codex`'s `harness_hooks` row reports present/missing
hook entries as `skipped: unverified` — it can never PASS. No Codex or Gemini
CLI session has run on this machine; the codecs are correct against the
documented envelopes and nothing more is claimed.

## Reach parity (RP-1..RP-23)

Thirteen of fifteen surveyed harnesses read `SKILL.md` under `.agents/skills`.
fathom wrote its Codex skills to `~/.codex/prompts/` — a **user-global**
directory serving one harness on one machine, drifting from the shipped source
invisibly with every release. That is the breaking change of this release, and
`docs/upgrades/0.8.0-skills-on-the-standard.md` is its migration note.

The fix that outlives it is that shipped skills became **owned files**:
`wiring.OwnedFile` + `planOwnedFile` make a whole marker-owned file a plan item
in the same plan → apply → receipt pipeline as hooks and stanzas. A
hand-authored file at a skill's path is BLOCKED by name; an edit under the
`fathom:owned` marker is drift, reported and never merged; `fathom fleet undo`
restores it byte-for-byte.

The rest of the wave is docs and CI catching up with the binary. The adoption
docs said `--skills=codex` wrote `.agents/skills` when it wrote
`~/.codex/prompts`; four use-case docs said verbs were "not yet listed by
`fathom help`" three releases after they were; `codex.md` §6 said Codex had "no
hook mechanism" while vision 16 §3 said "Bash-only, ~10 events" — the verified
reference documents eleven Claude-shaped events. All corrected,
`TestNoStaleHelpPhrasesInDocs` forbids the two stale sentences under `docs/`,
and `codex.md` §6 is now generated from the registry.

**`task stranger-check`** is 0.7.0's `clean-clone-check` taken one step
further: copy the tracked tree outside the module, make it its own repo, build
with `GOWORK=off`, start a throwaway daemon on a free port with a temp store,
run `fathom init --harness=none --skills` under a temp HOME, make one
`tools/call` on `/rpc/agent`, then `fathom doctor` — any FAIL row fails the
gate. Measured 26–43 s alone, 65–69 s under `task validate`'s parallel deps, so
it is **in** the gate rather than beside it.

## Proof credibility (ADR-030, PC-1..PC-34) and three root causes

### O20 — the verdict that did not know which binary read the store

The same tree verified 70 claimed / 5 failing against the daemon's store and
75 / 0 against a store built from HEAD. Nothing in the verdict recorded which
binary built which store, so a stale daemon produced **false gate failures**
that looked exactly like real ones — while `fathom doctor`'s `binary_fresh`
reported PASS, because it compared the *local binary* to HEAD and never asked
the daemon anything.

Root cause: a verdict is a function of the store, and the store is a function
of the binary that built it, and no record carried either. Fix: `/statusz`
(schema 2) carries the daemon's own `binary_commit`, `binary_dirty`,
`built_at`; every verify-ledger row carries `daemon_commit`, `store_commit`,
`binary_commit`; `fathom verify` prints one stderr `provenance:` line when the
daemon's build is not this binary's — and never compares against the cwd's
HEAD, because the cwd is not necessarily fathom's checkout (O5). A new
`daemon_fresh` doctor row asks the daemon; `binary_fresh` now says out loud
that it knows only the local binary.

And ADR-027's rule was applied to gate verdicts: a reading from a stale daemon
is marked **`measured-stale`** in `plans status`, `intent audit` and doctor's
`unproven_claims` — a coverage gap, never a failure.

### O21 — a third `package main` refuted five rows it never touched

`cmd/loctruth` (a bench tool, unrelated to anything it broke) was the third
binary in the repo with a `package main` and a `func run`. `core.SymbolNode.Key()`
was `service::package.Name` using the **declared** package name, so all three
`run`s collapsed to one key `fathom::main.run`; `callgraph.Build` kept whichever
was ingested last; `loctruth`'s `run` won and deleted `run → runWithStdin` for
the entire graph. Five previously-verified `ambient-fathom` rows (SP-4, SP-7,
SP-8, SP-9, TH-1) went **refuted**, silently, with no connection to the change
that caused it.

What caught it: the wave-1 integration probe — a `--strict` sweep over all 51
top-level plans against a probe store built from the merged tree, run because
merging branches is exactly when cross-branch collisions appear. A rename
restored truth immediately; the defect was filed as O21 and fixed structurally
in PC-32: keys are `service::<dir>/<package>.Name`, the typed pass derives the
identical key from the declaring file, and `TypedEdgeEpoch` 2 rebuilds stored
typed edges on the next ingest. The old form still resolves as an **input**
wherever it names exactly one symbol; store format v0 is untouched, because
keys are derived from stored `(FilePath, Package, Name)`.

The same commit narrows a plan row's `package:` from a path **prefix** to one
directory — the collision that made `package: internal/contextbench` ambiguous
with `internal/contextbench/publicloc`. That narrowing is the second breaking
line in this release.

### O22 — every ingest said `ok` while the daemon read the wrong tree

A worker worktree's post-commit hook called the daemon's `ingest` tool with its
own directory as `path`. The root-hygiene guard compared the path only against
**other** services' roots, so the fleet's `fathom` service was re-rooted at
`.claude/worktrees/…`. The tool returned `{ok: true}` four times, named no
root, and every "refreshed" verify afterwards read a tree that was not merged
`main`: 0–2 rows verified where a probe store read 16 / 5 / 5 / 9 / 13.

Fix (PC-33, invariant I30 extended): `internal/worktree.CheckReroot` is the one
shared check, applied by both write paths — the MCP handler (a named JSON-RPC
error carrying both paths) and `pkg/client` (the CLI's store-direct path, exit
1). It refuses a linked worktree of the recorded root (git-common-dir equality)
or any `.claude/worktrees/` path; moving a service **back** to its main
checkout stays allowed. The `ok` envelope now carries `root`, and the
post-commit hook run inside a worktree refreshes nothing and names the service
and root it left alone — deliberately naming what it left alone rather than
asserting where the service is rooted, which the hook cannot know.

### The lexical oracle (ADR-030)

Eighteen claimed rows were `[x]` with a `skip:` reason and no contract — docs,
measurements, changelog lines — and the gate could prove nothing about them.
A row may now carry `{oracle: lexical, path, pattern}`: verify reads the path
from the same working tree the plan came from (never `git show HEAD:`, so plan
and evidence are read at the same moment), requires it non-empty, and requires
the pattern to match. Lint and the gate refuse a markdown path without a
pattern and a row carrying both a symbol and an oracle. Nine non-code rows were
converted in the honesty sweep; two of the nine sit under `docs/vision` or
`docs/design`, under ADR-030's own 30% kill line.

### Claim-moment verify, and two more hook rows

The verify gate fired at push and at session end. The **claim** is the `[x]`
edit on a plan file, and the PostToolUse edit hook already sees every one of
them: `claimMomentVerify` diffs the plan against git HEAD and, only when the
edit checked a **new** row, runs the same daemon verify and injects the refusal
as `additionalContext`. Silent on a clean claim, silent on an edit that claims
nothing new (zero daemon traffic), silent on any operational failure (I9).

`InstructionsLoaded` → `session-hook --event instructions-loaded` is the first
harness-side evidence a stanza actually reached a session; `ConfigChange` →
`config audit --hook` audits a config the moment it is edited rather than at
the next session start. Doctor's `stanza_loaded` reads those beats and SKIPs —
never FAILs — when none exist, naming the wiring date.

### Wiring drift

The worst agent incidents are trust-configuration changes. The law-15 digest
ledger now baselines each harness descriptor's **MCP server entry** (argv and
env/header **names**, never values) and every `fathom:owned` skill file.
`fleet reconcile` reports drift by kind and path and never merges;
`--apply` records missing baselines and `--apply --rebaseline` re-records a
drifted one, so a change you made is never silently accepted as a change you
did not.

### The measurements

- **The strict sweep** over all 51 top-level plans, against a probe store built
  by the tree's own binary, went from **628 claimed / 621 verified / 0 refuted**
  at the start of the wave to **672 claimed / 662 verified / 0 refuted** at its
  end. No row changed state as a side effect of the key-qualification fix; the
  remaining unverified rows are claimed rows with no honest contract, each
  naming why.
- **`fathom doctor`** on this repo runs **34 checks** (up from 30), gaining
  `daemon_fresh`, `gate_posture`, `harness_hooks`, `stanza_loaded` and
  `wiring_drift`. On the author's machine at the time of writing it read
  27 pass / 1 warn / 1 fail / 5 skip — and the single FAIL is `daemon_fresh`,
  the row this release added, correctly reporting that the launchd daemon still
  served the pre-release build. That is the row working, not the repo failing.
- **The verify gate figure**, from `fathom research report` on 2026-09-02:
  *the verify gate refused 171 of 3426 recorded runs over 317 plan(s) in 21
  repo(s) between 2026-08-15 and 2026-09-02* — a refusal being one run whose
  verdict carried at least one failing claimed row, never a sum of failing rows
  across runs (709 such row readings exist and are **not** the figure). Run the
  verb; the number moves daily.
- **`fathom fleet reconcile`** (dry run): 20 repositories, 19 drifted, every
  one of them missing the two new hook rows. Nothing was applied.

## Bench credibility (ADR-031, PB-1..PB-20, BC-14/15/16)

Three separate reasons the bench could not be believed by anyone who is not its
author, each fixed independently.

**The corpus was false at HEAD.** H1-T08 named a rule that had moved (and its
`29` token was a substring of anything containing 29), H1-T13's staleness
verdict had inverted, and three premises had moved. The first replicated run
could not have been honest. Every ground-truth token now carries a
`truth_at_head` anchor (file | path | line | form) that `TestHomeCorpusTruthAtHead`
re-derives on **every** `task validate`, so corpus drift is a red gate rather
than an audit finding.

**The truth came from the instrument under test.** Every context-bench ground
truth so far was derived from this repo, and its `find_callers` truth from
fathom's own index — which measures nothing (ADR-031 §2.3). `cmd/loctruth`
computes direct static callers with `go/types` and `go/packages` at
`base_commit`: non-test packages only, interface dispatch excluded, closures
attributed to the enclosing function, sorted and duplicate-free.
`contextbenchscore import` then derives a public Go localization corpus from
**pinned local snapshots** of Multi-SWE-bench (CC0-1.0) and SWE-Explore-Bench
(MIT) with no LLM and no network, under a selection rule registered before the
derivation, emitting a `corpus_sha256` that reproduces bit-for-bit from
shuffled inputs.

**The scoring was passable and the statistics absent.** All-of substring
scoring can be passed by dumping the tree, so criterion **H2-2** requires a
fenced answer block within `max_predicted` and records precision and recall;
H2-1's verdicts stand as history and are never re-scored. A task both arms
answer from memory measures nothing about discovery, so a **`none` arm** (no
tools) is the memorisation floor, and a committed leak rule excludes any task
it passes in 2 of 3 trials. `ComputeReliability`, built on agentic-kit's
`reliability-stats`, puts a seeded task-clustered paired bootstrap 95% CI on
the per-task success difference, a two-sided Wilcoxon signed-rank p on per-task
mean tokens (tokens, because at n=3 success mostly ties), Vargha–Delaney A12,
and per-arm `pass@1` / `pass^3` on **every** ledger row — reported and
**never gating**, pinned by `TestReliabilityNeverGates`.

`contextbenchscore ledger` exits 0 / 1 / 3, and a run where a task ran in only
one arm, or where the thinnest cell fell below the registered replication floor
of 3, is **indeterminate — never a win**. `contextbenchscore regress` compares
the newest ledger row against the previous same-corpus row task by task; a task
flaky in either row is listed, never failed.

## Blast depth (BD-1..BD-6)

The commodity code graphs made depth-bucketed blast radius with per-edge
confidence expected, and fathom had the facts without saying them.
`core.EdgeConfidenceOf` reads `resolved` (typed pass) or `heuristic`
(syntax-only) from the provenance the typed pass already records;
`find_callers` and `references` carry `depth` and `edge_confidence` with a
`by_depth` summary; `find_callers` takes an optional `depth` that adds
`transitive_callers`. `review_diff` and `fathom review` compose `test_impact`:
`affected_tests` cited as file:line, and `test_gap` — the changed symbols no
test reaches. Every field is additive.

Alongside it, the served MCP contract: a client that never reads `CLAUDE.md`
could not learn from `tools/list` what a tool needs, whether it writes, or what
comes back. Every agent-surface description now names its required arguments
and a "Reach for it when" sentence; the 17 tools serve annotations and a
generated `outputSchema`; `initialize` negotiates from a supported table
instead of a hard-coded `2024-11-05`. The cost is stated rather than hidden:
the per-session schema budget grew from ~12.4 KB to **28.7 KB**, 16.0 KB of it
the description sentences, and `TestNarrowProfileSchemaBytes` is re-pinned to
that measurement. `TestServeHTTPNegotiatesWithKitClient` drives `/rpc/agent`
through agentic-kit's Streamable-HTTP client — the first third-party client to
negotiate with the daemon.

## Consuming the kit instead of keeping a copy (PC-34)

agentic-kit generalised fathom's `internal/readset` into
`foundations/telemetry/read-manifest` (its second consumer is the kit's own
constitution-lint) and fathom's reliability statistics into
`foundations/quality/reliability-stats`. Keeping fathom's copies meant two
shapes of "what could I not see" drifting apart — precisely the way ADR-027's
blindness becomes invisible again. `internal/readset` is deleted; fathom keeps
only `internal/readcoverage`, the rendering of a count over an incomplete
manifest, whose wording ADR-027 and the changelog pin and which is
byte-identical: `≥ N noun (k source(s) unreadable: path: errno)`. The four
ADR-027 Done-needs tests keep their names and pass under `-race`.

The visible cost is the third breaking line: `intent audit --json`'s
`coverage.unreadable[]` entries nest the outcome (`{path, outcome: {kind,
detail, bytes}}`) because the kit's `Entry.Outcome` is a struct where fathom's
was a scalar.

## What is NOT proven

Read this section before quoting anything above.

- **The bench was not re-run.** BC-14 — the first replicated home run under the
  3-trial floor — **has not been run**. It spends real LLM tokens and is an
  operator decision, so the ledger holds exactly one backfilled n=1 row from
  2026-07-24, which is **indeterminate** under the floor this release
  registered. Everything shipped here is the instrument, not a result.
- **The public corpus has never been run either.** PB-19 is the public run and
  it is an unclaimed operations row; `docs/bench/public-loc.md` states the
  ~35M-token cost with its denominator, and criterion H2-2 is registered
  *before* run 1 precisely so a loss must be published as-is. Nobody has
  spent it.
- **The fleet apply was not run.** PC-26 is open. `fathom fleet reconcile`
  (dry run) reports 20 repositories, 19 drifted, every one of them missing the
  `InstructionsLoaded` and `ConfigChange` hook rows. The 14-day reading that
  would show the new hooks producing beats across the fleet does not exist
  because nothing was applied.
- **The Codex and Gemini CLI descriptors are unverified on this machine.** The
  codecs are round-tripped against fixtures citing the official envelope
  documentation; no Codex or Gemini CLI session has ever run here. Both carry a
  60-day demotion clock from 2026-09-02, and every capability row says
  `unverified on this machine` rather than PASS.
- **No savings claim is admissible.** G2 is still collecting: the A/B is
  one-armed — one arm has zero admissible units at the last reading — so any
  inferred "fathom saved N tokens" remains unsupported by this repo's own
  evidence. fathom measures what it **spends**.
- **K0 still has 0 human-written annotations.** The evidence plane's demand
  signal (≥3 annotations across ≥2 repos) has not fired; EP-16/17/18 wait on
  it, and the annotations must never be manufactured to close the goal.
- **Still one adopter, one machine, one operating system.** Every measurement
  in this document comes from macOS on the author's workstation. The
  `stranger-check` gate simulates a stranger; it does not replace one.
