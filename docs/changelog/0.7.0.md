# 0.7.0 — 2026-09-01 — the release where fathom became adoptable

The narrative record for `CHANGELOG.md`'s `[0.7.0]` block. Not normative;
plans, ADRs and observations are.

## What this release is for

fathom is getting a second engineer. Everything below was found by doing the
one thing nobody had done: cloning the repository the way a stranger would,
on a machine that had never built it, and following the guide.

## It did not build

```
go: cannot load module ../agentic-kit listed in go.work file
github.com/geoffmilleraz/app-kit@v0.0.0: replacement directory ../app-kit does not exist
```

Two causes, and the same root: **every machine that could have caught this
already had the private sibling checkouts, so the failure was invisible to
everyone in a position to see it.** The one person who could not — a new
adopter — was the one who would hit it first.

- **`go.work` was committed**, listing `../agentic-kit` and `../app-kit`. A
  clone without those siblings failed before compiling a line. It also masked
  missing `go.sum` entries, so the standalone build was broken underneath and
  nothing said so. ADR-019 and the kit's own V1 decision both already said
  go.work is local-dev-only; the repo simply did not follow its own rule.
- **app-kit was never mirrored.** ADR-019 vendored agentic-kit precisely so a
  clone without private access could build. app-kit got a bare
  `replace => ../app-kit` and the guarantee was half-kept for months.

Fixed: `third_party/app-kit` on the same terms (2.6 MB, 318 files),
`scripts/sync-vendor.sh <name>` generalised over both, and each mirror
records `.vendor-commit` — the stamp, not the go.mod pin, is the source of
truth for which commit a mirror *is*, because app-kit has no published
version to derive one from and a stamp needs no network for anyone. Where a
pin IS derivable, vendor-check asserts pin and stamp agree.

**The guard matters more than the fix.** `task clean-clone-check` copies the
tracked tree, drops the workspace and builds with `GOWORK=off`. It is in
`task validate`, not beside it — a check that only runs when someone
remembers would have missed this the same way. It earned itself within the
hour by failing a commit whose new file was still untracked, which is the
same "builds for me, not for you" class.

## Every adopter was told to restart someone else's service

Four user-facing places named one launchd label,
`com.geoffmilleraz.fathom-http`, which exists on exactly one machine:

```
launchctl kickstart -k gui/$(id -u)/com.geoffmilleraz.fathom-http
```

The worst of them is the SessionStart hook, which carries that line into
**every session of every adopter**. Anyone who is not its author got
"Could not find service". Installing the daemon at all was a copy-paste
plist with four paths to hand-edit — the single manual step in adoption and
the one most likely to be done wrong.

`fathom daemon install | status | uninstall` now writes the agent with the
adopter's own resolved binary (symlinks followed, so launchd runs a stable
copy and never a `bin/` output a rebuild would truncate — O25), store, call
log, and a PATH carrying their Go toolchain. Without `go` on that PATH the
daemon's auto-refresh silently degrades Go services to syntax-only edges, so
`install` says so when it cannot find one. It refuses to stack a second agent
on the same port, naming the one already installed and how to keep or replace
it — verified live against the author's own machine, which it correctly
declined to disturb.

`daemonRestartHint()` is the one place that renders "how do I get the daemon
back", and it RESOLVES the label by reading `~/Library/LaunchAgents`. A
foreign plist is never claimed as fathom's: kickstarting an unrelated service
is worse than reporting none.

## What a reviewer is handed

`docs/adoption/README.md` leads with the evidence, both directions:

- **Proven**: the verify gate has caught **540 rows that claimed done and were
  not**, across **2,494 recorded runs over 167 plans**.
- **Not proven**: no savings claim is admissible. The A/B is one-armed — the
  OFF arm has zero admissible sessions — so any inferred "fathom saved N
  tokens" is unsupported by this repo's own evidence, and reporting one is
  treated as a bug.
- Single adopter until now; the intent plane is days old; the experimental
  surfaces are named.

It ends with what would make a review most useful, first item: **try to make
an instrument lie.** Break permissions, point config at nothing, delete a test
a plan row names. Every check is supposed to say "I could not look" rather
than report a clean result — and ADR-027 exists because that is exactly what
failed a week ago.

## Verified end to end

Clean `git clone` → build with no siblings and no workspace → `serve-http` →
`fathom init` on a new repo → `fathom doctor` → a live `find_symbol` returning
the right file and line. The four remaining doctor FAILs on that fresh repo
are all "you have not done this optional step yet", each with an exact
remedy — MCP registration, skills, lefthook, obligations compile.
