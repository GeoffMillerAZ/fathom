# 0.12.0 (2026-10-16): a first visit that reads green, and more of the repository read

The narrative record for `CHANGELOG.md`'s `[0.12.0]` block. Not normative;
plans, ADRs and observations are.

## What this release is for

0.11.0 was the beta for early adopters. This release is about the first hour
with it, and it reads more of a real repository. It lands four waves.

**The first-impression pass.** The README leads with what fathom is, how it
differs and a quick start that was read on a clean clone. The early-testers
guide gives a first run that works on macOS and Linux and names its limits.
`docs/overview.md` is a tour for engineers. The entry pages carry the real
surfaces, counts and limits, with their broken links and one machine's paths
removed. The shipped skills follow the install path and name only tools a
surface serves. A Linux CI gate now runs on every push and pull request.

**The first-impression fixes (fic).** A fresh install reads green in
`fathom doctor`: a repository without lefthook skips the gate row, no model
provider skips the obligations row, and surface traffic warns until the first
call. A broken gate or a provider with no compiled layer still fails. Every
hook is a silent no-op when `fathom` is not on PATH, so a visitor sees no
failing hooks. Help and doctor text carry no internal row ids or moved section
numbers. Through the daemon, `fathom verify` and `plans status` return the
verdicts `--store` returns. MCP `initialize` reports the release instead of a
fixed `1.0.0`.

**Language breadth (lf8).** Kubernetes workloads store their per-container
facts, matched field by field against `k8s.io/api`'s typed structs, and a
Service's selector is a route-ref edge to the workloads it fronts. PowerShell
module imports and dot-sourcing resolve. Jenkins `load` steps are edges.
GitHub Actions and Helm read L3 good, with their ceilings written.
`ExtractorEpoch` is 64, so the first ingest after upgrading re-extracts those
files.

**Evidence and hook paths (war2).** `read_source` takes a `ref` and reads the
file as committed, through git, with every read filter still applied.
`fathom version --json` prints the fathom-side parts of an index snapshot's
cache key. `fathom findings import` hashes cited lines at the finding's own
revision, never the working tree, and names any skew in its receipt. A store
on read-only media mounts. `fathom module pack` clears every machine-local
field. The hook paths were measured first (EW-75): the test-run hook's
`localize` call was abandoned in 385 of 437 fleet calls, so the hook no longer
asks it. The other hook calls run to the hook's own deadline instead of a
fixed 2 s cap. A spending compile asks the decision port's prefilter once per
section instead of twice.

## What was measured and what it decided

- IXS-M0 read CUT. Over 20 recent commits, a cache-from ingest (a copy of the
  previous commit's store plus `fathom remap`) took a median 164.2 s against
  203.7 s cold, 0.81x, above the 0.6x bar. F27 stays deferred, and index
  snapshot phases 1 and 2 do not start. It ran on the owner's machine from
  clean checkouts, not in CI, and the reading says so.
- EW-76's loaded re-reading after the hook fixes reads FAIL, so EW-76 and its
  mirror RES-R1f stay open. The fixes ship because each is correct alone.

## Compatibility review

Nothing on the compatibility surface (`docs/intent/scope.md`) breaks. JSON
gains keys and loses none: `fathom version --json`, the findings-import
receipt's `cites_skew`, `read_source`'s `ref` and `commit`, and
`compile_layer`'s `estimate_only` argument, which defaults to off. The store
format is unchanged. The one upgrade cost is the re-extraction that
`ExtractorEpoch` 64 triggers on the first ingest.
