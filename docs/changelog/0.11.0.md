# 0.11.0 (2026-10-11): the beta for early adopters

The narrative record for `CHANGELOG.md`'s `[0.11.0]` block. Not normative;
plans, ADRs and observations are.

## What this release is for

0.11.0 is a beta for early adopters. 0.10.0 made fathom installable by
someone who did not build it. This release makes the index worth wiring into
a polyglot repository, and it makes the proof stricter where it was soft.

**The index reads more of a real repository, at a measured level.** Against
an independent oracle per language (a SCIP indexer or the language's own
compiler), TypeScript, JavaScript, Python, Java, C#, C, C++, PHP, Rust and
Dart read L4 (typed edges). HTML, CSS, Bash, Ruby, Kotlin, Go, React, Vue and
Astro read L3 (file edges). New dialects read Scala, SCSS, Vue, Svelte and
Astro components, Jenkins pipelines, Composer manifests, Prometheus,
Alertmanager, Grafana and OpenTelemetry Collector configurations. Framework
routes are read from source for Java, Node, PHP and Python frameworks, and
React Router. `docs/languages.md` is the generated board.

**The answers reach production signals.** `localize` takes a pasted stack
trace, error payload or log line to the code that wrote it. An alerting rule
reaches the receivers it pages, a Grafana panel reaches the recording rule it
reads, a CloudWatch alarm reaches the metric filter it watches, and a Lambda
function binds to its handler's symbol. No
secret-bearing field is stored or served.

**The proof is stricter.** `fathom verify`'s `reachable_from` and `wired` now
pass only over typed call edges (RF-5), which is this release's main breaking
change. A repository's `.fathom/config.toml` can no longer name a command, a
key file, a store or a path outside the repository (SEC-1, SEC-2). Every SARIF
fathom writes names its commit and fingerprints its cited lines (EVX-1 to
EVX-3), so a reader checks it with git.

**The build is simpler.** Linux builds are pure Go with `CGO_ENABLED=0`
(ADR-066), and every `go` command fathom runs on its own stays on the local
toolchain (K22).

The records added in this release (ADR-069, vision 44, the index-snapshot
design and the evidence-plane plans) decide a direction and build nothing.
Index snapshots are decided in shape and parked.

What is not claimed: RT-M1, the seven-day reading of the daemon's footprint,
is not yet read; the cloud-session readings in a real VM (CS-M1 to CS-M3)
are still open; Svelte reads no level (L1 unmet), Angular templates are
refused at the grammar gate, PowerShell reads L2 under its L3 target, and zsh
scripts are not read. A non-Go row's `reachable_from` cannot pass until its
language gains a typed pass. Language levels are readings on named subjects,
not coverage, and nothing here licenses a savings claim.

## Breaking

- `api_key_cmd`, `api_key_file` and `api_key_env` in `[decide]` and `[profiles.*]` are read from `~/.fathom/config.toml` only: a repository's `.fathom/config.toml` that sets one has it ignored (it could make fathom run any command), `fathom doctor`'s `key_source_scope` and `fathom config` name the file and field, and the key goes in your user config (SEC-1, ADR-042 amendment 2026-10-09, `docs/configuration.md`).
- A repository's `.fathom/config.toml` chooses behaviour only: `profiles.*.bin`, `profiles.*.endpoint`, `daemon.store`, `daemon.addr`, `daemon.call_log`, `daemon.auto_refresh` and `daemon.memory_limit` are now read from `~/.fathom/config.toml` only, and a repository that sets one has it ignored, named by file and field in `fathom doctor`'s `key_source_scope`, `fathom config` and a daemon's startup log; move them to your user config (SEC-2, ADR-042 amendment 2026-10-09, the scope table in `docs/configuration.md`).
- Repository paths stay inside the repository: `[tests] results_dir`, `[findings] outbox`, `[connector] include` and `[[work.ci_summaries]] path` refuse an absolute path, a `..` escape or a symlink out, by name (an absolute CI summary path was accepted before), and the session hook's outbox sync imports into the user config's `[daemon] store` (SEC-2).
- **`fathom verify`'s `reachable_from` and `wired` pass only through typed call edges (RF-5, I57).** A row reached only through a heuristic-tier edge (a syntax-only call, a reference to a type or constant, a file-resolved import match) now fails with that edge and its tier named; every call edge outside Go's typed pass is heuristic today, so a non-Go row's `reachable_from` no longer passes (its `test_reaches` still reads every edge). `wired` judges the function a row names rather than a same-named type and links a package into a binary by its directory, and the edges stay served with their tier; the nine proven fleet rows this refuses (fathom's TH-1, LB-F377, OC-1, OC-13, CV-24 and TC-10, platform-engineering's P3A-3, P3A-31 and P3A-33) and each one's fix are the migration note in `docs/bench/readings/repository-facts/reach-guard-flips.md` (RF-M6).
