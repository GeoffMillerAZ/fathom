# 0.13.0 (2026-10-16): fathom installs without a clone

The narrative record for `CHANGELOG.md`'s `[0.13.0]` block. Not normative;
plans, ADRs and observations are.

## What this release is for

Until now a stranger could only build fathom from a clone: `go.mod` required
two private kit modules and reached them through `replace` lines pointing at
the in-tree mirrors, and `go install pkg@version` refuses a module with a
`replace`. This release removes that wall (owner decision of 2026-10-16,
ADR-070, plan `docs/plans/distribution.md`). It lands one wave.

**One self-contained module (DS-1, DS-2).** The agentic-kit and app-kit
mirrors under `third_party/` are now packages of fathom's own module.
`cmd/kitrewrite` rewrites their import paths between the upstream and the
in-module form, reversibly and byte for byte (the round trip is a test), and
keeps each mirror's `go.mod` as `go.mod.upstream`. `go.mod` carries no
`replace` and requires no private module. `go run ./cmd/kitrewrite -check`
and a gate test hold it. `task sync-kit` and `task vendor-check` run the
rewrite, so drift detection against upstream still compares exact bytes.

**A smaller app-kit mirror (DS-4).** The mirror ships in every module zip the
Go proxy caches, so it now keeps only fathom's build closure:
`scripts/kit-closure.sh` computes it into `third_party/app-kit.keep`, and
`task scripts-check` fails when the manifest and the computed closure differ
or the mirror holds anything else. The mirror went from 1,806 files to 317,
and nine `go.mod` requirements went with them. The design-asset data, docs
and spikes are gone from the tree, though git history keeps them.

**Prebuilt binaries (DS-3).** Each GitHub release gets darwin and linux
archives for arm64 and amd64 plus a sha256 `checksums.txt`, built by
GoReleaser in `.github/workflows/release.yml`. The darwin builds keep cgo with
`MACOSX_DEPLOYMENT_TARGET=14.0` (ADR-066). They are not signed or notarized.

**A status line that matches archive.** `fathom plans status` used to call a
plan `archivable` when `fathom plans archive` would refuse it, because its
row ids were not absorbed. Status now runs the archive verb's own check and
prints `archive blocked` with the missing ids. A check that cannot run is
also blocked, never a pass.

A `serve-http` whose port is held now records its exit row even when the
holder's command line is very long; before, the overlong ledger line was
skipped on read.

## What was measured

- A module zip check (`golang.org/x/mod/zip.CheckDir`) of the release tree
  reads 8,947 files with no invalid path, 80.2 MiB of the 500 MiB limit.
- `goreleaser release --snapshot` on a Mac built the four archives and
  `checksums.txt`, each binary the right architecture.

## Compatibility review

One break, on `pkg/client`: `WithDecision` and `WithLLM` take kit types that
now come from `github.com/geoffmilleraz/fathom/third_party/agentic-kit/...`
instead of the private `github.com/geoffmilleraz/agentic-kit` path. A consumer
changes that one import. `plans status --json` gains `archive_blocked`,
`unabsorbed_ids` and `archive_check_error` and loses no key. The store format
is unchanged. A local `go.work` no longer substitutes a sibling kit checkout;
`task sync-kit` does.
