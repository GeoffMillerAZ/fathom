# Other harnesses — the adoption matrix

fathom's coupling to a coding harness is one descriptor registry
(`internal/harness`, ADR-029, `docs/vision/25-harness-port.md`). This page is
the registry's **adoption matrix**: for every registered harness, the tier it
sits on today, the instruction file the stanza reaches, where the shipped
skills land, how the MCP server is registered, and — the honest column —
what the descriptor was verified against. A row that says **unverified** is
data copied from that harness's own documentation on 2026-09-02; no session
on this build has run against it on this machine, and `fathom doctor
--harness <id>` says the same on every row it cannot prove.

The table between the markers is generated by `fathom harness matrix` and
pinned by `internal/harness/adoption_test.go` (`TestAdoptionDocMatrixIsGenerated`):
edit the registry, re-run the verb, paste. Never hand-edit the rows.

## The four standards, and which path is which

- **Instruction file.** `AGENTS.md` is native or opt-in on 13 of the 15
  harnesses surveyed, Claude Code included since 2.1.277; `fathom init` writes
  its one stanza into `AGENTS.md` for every harness (ADR-059). A root
  `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` that exists gets one
  marked region holding `@AGENTS.md` (the row's *import* mode); fathom never
  creates one. Gemini CLI reads `GEMINI.md` by default and `AGENTS.md` only
  through a settings key: `init --harness=gemini-cli` sets
  `.gemini/settings.json` `context.fileName` to `["AGENTS.md", "GEMINI.md"]`.
- **Skills path.** `.agents/skills/<name>/SKILL.md` is the Agent Skills
  standard path (agentskills.io) — Codex, Gemini CLI, Cursor, Copilot and
  the rest read it; `.claude/skills` is Claude Code's, and the only one it
  discovers. `fathom init --skills` writes the one real copy into
  `.claude/skills` and, for bare `--skills`, `--skills=codex` and
  `--skills=agents`, links `.agents/skills` to it (ADR-059); the deprecated
  `~/.codex/prompts` twin is `--skills=codex-prompts` only
  (`docs/upgrades/0.8.0-skills-on-the-standard.md`).
- **MCP.** Every harness reaches the same 19-tool `/rpc/agent` surface over
  streamable HTTP; the config file and the `mcp add` spelling differ per
  harness and the row carries the harness's own. `fathom init --harness <id>`
  prints that line and never runs it (user-global configuration is ask-first).
- **Plugin.** `fathom plugin render` emits one tree that loads in Claude Code
  (`.claude-plugin/plugin.json`, `hooks/hooks.json`, `.mcp.json`) and in every
  Agent Plugins 1.0 client (`plugin.json`, `mcp.json`, the same `skills/`).

## Tiers (the degradation ladder)

**A** hooks + injection (Claude Code today; Codex and Gemini CLI document a
Claude-shaped hook contract that this build carries as data but does not
yet drive — *hooks: not wired*). **B** block-only. **C** in-process JS hooks
only (unreachable from a Go binary). **D** no hooks: the pull tier —
`fathom prime` at session start, the `obligations` MCP tool before an edit,
the git-native verify gate as the backstop. `fathom harness capabilities
--harness <id>` prints the per-capability vehicle table for any row.

## Wiring one of these

```sh
fathom init --harness <id> --skills        # stanza + .fathom/ + skills; prints the mcp add line
<the mcp add line from the row above>
fathom doctor --harness <id>               # every row it cannot prove is SKIP with a reason, never PASS
fathom harness capabilities --harness <id> # what fathom delivers on this harness, vehicle by vehicle
```

A harness not in the registry is the `agents` row: `AGENTS.md`,
`.agents/skills`, and whatever `mcp add` it has. Adding a descriptor is data
(`internal/harness/descriptors.go`) plus its `verified_against` line — the
codec that drives its hooks is the only code, and it lands per harness
(`docs/plans/harness-port.md`).

## Maintained

This doc covers: `fathom harness` (`list`/`capabilities`, and the matrix
subcommand whose output the table above is, verbatim), `fathom init --harness`,
`fathom init --skills` (`claude`/`codex`/`agents`/`all`/`codex-prompts`),
`fathom doctor --harness`, `fathom plugin render`. Update it when these change.
